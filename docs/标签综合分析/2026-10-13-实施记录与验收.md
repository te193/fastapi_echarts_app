- 同标签大类取并集、跨大类取交集；数值条件和可售天数区间继续下钻。条件按顺序保存，上层为移除最后一组条件后的群体。
- 总体保留国家、店铺、搜索等基础范围；标签及数值条件仅改变当前与上层群体。净毛利不展示容易误导的贡献百分比，正毛利润与亏损金额分别展示贡献。
- 核心指标卡、比率分子/分母、可售天数中位数及P25/P75、区间分布、按运营状态拆分当前零库存、店铺贡献、标签交叉矩阵。

## 数据链路与关键口径

| 内容 | 来源与处理 |
| --- | --- |
| 标签 | `dashboard_label_detail_snapshot`、`dashboard_label_fact_snapshot`；截止日前最新已发布标签，保留实际标签日期与发布时间 |
| 经营/利润/广告/流量/退货 | `dashboard_product_performance_daily`；SQL先消除local_sku细分导致的重复，再按视角聚合 |
| 当前商品范围 | 标签、Listing、经营记录，以及类别视角的库存/补货对象并集；保留无标签和无经营记录对象 |
| Listing映射 | 按项目已有MSKU规范化口径处理长MSKU；已存在具体国家映射时不额外生成空国家商品；真正无国家的记录单列 |
| 库存 | `dashboard_inventory_daily_snapshot`；负数、缺行、同对象同日重复冲突视为未知；国家共享库存按池去重 |
| 补货 | `dashboard_pur_plan_replenish_data`；只使用当前截止日和上期截止日的精确日期结果，不用今天结果回填历史 |
| 补货支持天数 | 直接复用现有补货服务 `_display_support_days_expr()`；到货支持天数与提前期均有值时按原页面展示表达式，否则读取原支持天数 |
| 补货日销 | 明细保持原 `daily_avg_sales`。经营周期切换不会改写补货自身日销窗口；“周期平均日销量”另列 |
| 普通对象FBA可售天数 | 同日期FBA可售库存÷补货日销；日销缺失/非正、库存缺失均不计算，不使用0.1等分母兜底 |
| 产品组合并 | 按现行国家类别＋ASIN组映射。组级日销未独立持久化，覆盖需求取已发布 `lead_time_demand_qty / effective_purchase_lead_days`，组内一致且提前期有效才可用；保留源表舍入精度和说明。明细继承日销不改变，群体不能把继承值相加 |
| 跟卖 | `fllow_flag=0`为跟卖，1为普通/原链接。无法恢复完整组需求时覆盖未知，不能套用普通链接计算 |
| 多MSKU同池 | 已确认同店铺FNSKU映射按池去重，库存冲突未知；覆盖使用完整映射需求，不随国家/标签筛选分摊库存 |
| 比率 | 毛利率、CTR、ACOS、每千次会话产出等先配对共同有效对象日，再汇总分子分母；不平均商品比率 |
| 缺货 | 分清商品对象日、库存池观察日与自然日；缺行不是缺货，整期零库存仍纳入；只统计已确认有货→零库存的次数 |
| 连续缺货 | 不跨未知日；截止日缺失则未知；历史左边界未确认时为“至少已确认”的下限 |

数据库读取使用只读一致性快照；页面刷新不执行ETL、补货生成、标签生成或业务动作。标签命中证据按需读取，并核对发布批次；批次改变时要求刷新，不把新证据套到旧版本。

## 仍受来源限制的能力

1. 指标目录区分“可计算能力”和“实际样本覆盖”。订单数、订单转化、独立费用、销售成本、同库存范围销量的周转、库龄、浏览量、评分、订单批次退货、标签成员进入退出等保留待接入状态；没有可靠来源时不输出零值。
2. 当前源快照没有可靠的商品创建日期。引擎支持`inception_date`并已测试；真实数据的应观察日暂按完整选择期，新增商品的未知库存日可能偏多。页面说明这一限制；不能把这项称为已完整核验的商品存续期覆盖率。
3. 组级覆盖需求是对现有已发布组结果的还原，受源表精度限制。需要严格无损的组日销时，应在原补货ETL中持久化`group_daily_avg_sales`并接入本页，不新增另一套权重算法。
4. 现有日经营快照上游已含空值转零。本页能够识别缺行和共同样本，不能据来源零值证明所有原始数据完整。
5. 库存池历史按当前可确认映射展示观察统计；未具备独立的历史经营资格和完整映射版本，不能据当前运营标签计算历史“经营商品缺货率”。
6. 日库存快照只说明观察时点。广告统计按选择窗口展示，归因可能回补；会话不能减点击推导自然流量，广告销售额不能直接从总销售额扣出自然销售额。
7. 首次跨视角读取需加载两个等长周期与标签、库存，存在冷加载成本。当前环境一次实测：类别视角约43秒、国家视角约103秒；后续同版本筛选约1—2秒。已按对象打包传输每日数据、复用库存池分组、缓存总体/上层汇总，并只计算所选标签列组；进一步缩短冷加载需要在原日任务发布预聚合结果。当前缓存为进程内，部署多worker前应改为共享缓存或使用粘性路由。
