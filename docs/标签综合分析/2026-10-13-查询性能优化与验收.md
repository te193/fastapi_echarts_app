# 标签综合分析查询性能优化与验收

## 问题和修改

原页面首次查询同时读取当前期、上期经营日数据、库存日历及标签事实。诊断时约117万条结果行经过数据库驱动传回；没有版本的相同请求两分钟后重新读取，读取期间持有服务全局锁。

本次调整限于分析页的只读数据适配、缓存和刷新交互，没有修改指标公式、生成任务、原标签页或数据库结构。

- 商品范围先读取完整身份集合；标签只传输本周期、本视角可用的命中，保留无标签及其他周期商品。库存日历按商品打包传输，缺失值和同日重复记录仍保留。
- 标签发布时间优先使用既有本地发布事务的记录；旧来源没有发布记录时继续使用原查询。侧栏证据读取校验同一发布时间。
- 同条件汇总增加独立缓存；后台加载改为按日期、周期和视角互斥，相同查询合并读取，其他查询和已固定版本的读取不等待全局锁。
- 本地保存已准备的当前期和上期数据，缓存路径为项目下`.codex_tmp/label_analysis/cache`，最多3份，有效期24小时。复用前检查ETL日志、标签发布记录、源表更新时间、标签字典以及计算代码版本；不符合即重新读取。计算公式、商品范围、缺货日历和日销映射全部保留。
- 进程内未指定版本的请求两分钟后检查来源，未变化时复用；固定版本仍在30分钟内保持一致。加载期间发现发布变化，不保存磁盘缓存，并让下一次未固定版本的查询重新检查。
- 点击“刷新数据”显式重新读取底层快照；该标记只传给本次汇总，不写入URL或后续明细请求。浏览器正常重载可复用已核验缓存。

源表更新时间是数据库元信息，不代替业务日历。绕过发布流程的人工数据修改如果没有可靠更新时间，仍需显式“刷新数据”确认，不能宣称缓存能检测任何形式的人工修改。

## 实测

日期2026-10-12、近30天、国家类别视角，所有测试隐藏后台运行。

| 场景 | 耗时 |
| --- | --- |
| 原实现完整首次汇总，未开启性能分析器 | 43.027秒 |
| 优化后完整首次汇总，包含缓存写入 | 35.174秒 |
| 已加载数据，同条件重复汇总 | 0.018秒 |
| 新进程核验并恢复本地结果，再计算汇总 | 4.217秒 |
| 重启8001后的浏览器首屏，包含页面、汇总、明细 | 5.545秒 |
| 浏览器筛选超过180天 | 0.723秒 |
| 同条件重载页面 | 0.324秒 |
| 商品明细翻页 | 0.060秒 |
| 浏览器显式强制底层刷新，验证时有其他只读查询并行 | 39.927秒 |

这些耗时来自本机实测，受网络及数据库负载影响，不是延迟保证。完整新日期、新周期或强制底层刷新仍有首次查询成本；没有把缓存命中耗时冒充完整冷查询耗时。

## 验证

- 69项定向测试通过，包括缓存来源变化、强制读取、缓存损坏、代码变化、加载期间发布变化、并发合并及原标签页回归。
- 优化前后的8,469个对象逐字段核对：原始对象、当前准备指标、上期准备指标全部一致；总体、上层、当前、上期、可售天数分布及库存专项汇总一致。
- 国家视角41,042个对象逐字段核对一致，包括国家标签、经营日记录、库存日历及补货映射。只读适配数据加载分别为59.832秒和44.364秒，验证期间有其他只读查询并行，不据此承诺固定提升比例。
- 无界面浏览器验证默认范围、180天筛选、URL重载、分页、商品侧栏、趋势、CSV和强制刷新。日志保存在`.codex_tmp/label_analysis/`，目录已由项目忽略规则排除。

8001使用原项目的隐藏后台开发服务，保留预览时关闭lifespan的启动方式；不触发ETL或标签生成。
