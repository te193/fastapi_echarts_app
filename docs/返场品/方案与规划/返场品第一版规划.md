# 返场品第一版规划

## 第一版目标

第一版先把返场品的识别、在池管理、阶段流转、退出和预警跑通。

暂不做流量恢复、关键词排名、Review、自动归因和运营动作效果评估。

## 核心统计粒度

唯一统计对象：

```text
店铺 + 国家类别 + MSKU
```

同一个 `店铺 + 国家类别 + MSKU` 可以多次返场。第一版必须按“返场事件”记录，而不是只保留一条 MSKU 当前状态。

建议明细保留：

| 字段 | 说明 |
| --- | --- |
| 返场事件ID | 一次断货恢复生成一条事件 |
| 店铺 | 统计对象维度 |
| 国家类别 | 统计对象维度 |
| MSKU | 统计对象维度 |
| 返场轮次 | 同一统计对象年内第几次返场 |
| 断货发生日期 | 返场开始日期之前最近一次 `FBA可售库存 = 0` 的日期 |
| 返场开始日期 | 断货后首次 `FBA可售库存 > 5` 的日期 |
| 退出日期 | 返场事件结束日期 |
| 退出原因 | 达标退出、未达标退出、待人工判断、二次断货 |

## 返场事件判断

```text
存在某一天 FBA可售库存 = 0
AND
该断货日期之后存在某一天 FBA可售库存 > 5
```

满足后生成一条返场事件。

如果返场期内再次出现 `FBA可售库存 = 0`，当前事件按“二次断货”退出。后续如果再次恢复到 `FBA可售库存 > 5`，生成新的返场事件，返场轮次加 1。

示例：

```text
第1轮：断货 -> FBA可售库存 > 5 -> 返场事件1
返场期内再次断货 -> 返场事件1按二次断货退出
后续再次 FBA可售库存 > 5 -> 返场事件2
```

## 时间口径

第一版采用两个时间口径，不混在一起。

### 1. 返场事件识别窗口

返场事件识别默认回溯 `180 天`。

用途：从库存日快照中识别完整的“断货 -> 恢复”事件，避免看板只选短周期时漏掉仍在池的返场品。

例如：

```text
5月断货
6月恢复
7月仍在 21 天返场监控中
```

用户查看 7 月看板时，这个 MSKU 仍应计入“当前在池”，不能因为断货日期不在 7 月就漏掉。

### 2. 看板统计周期

看板时间筛选只影响周期流转指标：

| 指标 | 时间筛选口径 |
| --- | --- |
| 新进入返场品数 | `返场开始日期在筛选周期内` |
| 退出返场品数 | `退出日期在筛选周期内` |
| 净增返场品数 | `新进入返场品数 - 退出返场品数` |
| 达标退出数 | `退出日期在筛选周期内 AND 退出原因 = 达标退出` |
| 未达标退出数 | `退出日期在筛选周期内 AND 退出原因 = 未达标退出` |
| 待人工判断数 | `退出日期在筛选周期内 AND 退出原因 = 待人工判断` |

当前状态类指标按筛选结束日计算：

| 指标 | 统计口径 |
| --- | --- |
| 当前在池返场品数 | 筛选结束日仍未退出的返场事件数 |
| 阶段分布 | 筛选结束日的观察期、运营干预期、超期未处理分布 |
| 超期未处理数 | 筛选结束日 `已返场天数 > 21 AND 未退出` |
| P0 预警清单 | 筛选结束日仍触发预警的返场事件 |

## 21 天阶段

| 阶段 | 时间范围 | 说明 |
| --- | --- | --- |
| 观察期 | D1-D7 | 看是否自然恢复销售，不急着强干预 |
| 运营干预期 | D8-D21 | 运营可做广告、Coupon、价格等动作 |
| 退出判定 | D22 | 根据恢复率做退出或人工判断 |

已返场天数：

```text
已返场天数 = 统计日 - 返场开始日期 + 1
```

## 销量恢复率

```text
销量恢复率 = 返场后近7天日均销量 / 断货前7天日均销量
```

边界规则：

| 场景 | 处理 |
| --- | --- |
| 断货前7天日均销量 > 0 | 正常计算 |
| 断货前7天日均销量 = 0 | 恢复率记为空，进入人工判断 |
| 返场后不足7天 | 用已有返场天数计算临时恢复率，标记未满7天 |
| 返场期内再次断货 | 当前事件按二次断货退出 |

## 默认退出规则

| 类型 | 条件 | 后续状态 |
| --- | --- | --- |
| 达标退出 | `已返场天数 > 21 AND 销量恢复率 >= 70%` | 转正常在售 |
| 未达标退出 | `已返场天数 > 21 AND 销量恢复率 < 50%` | 转人工处置或清仓 |
| 待人工判断 | `已返场天数 > 21 AND 50% <= 销量恢复率 < 70%` | 运营判断是否延长观察 |
| 二次断货 | 返场期内再次 `FBA可售库存 = 0` | 当前返场事件退出，后续恢复后生成新事件 |

## 第一版页面

第一屏只放 P0：

- 当前在池返场品数
- 今日/本周/本月新进入
- 今日/本周/本月退出
- 净增返场品数
- 达标退出数
- 未达标退出数
- 待人工判断数
- 超期未处理数
- 阶段分布：观察期、运营干预期、超期未处理
- 今日观察期转运营干预期数
- P0 预警清单

## P0 预警

| 预警 | 触发条件 | 优先级 |
| --- | --- | --- |
| 严重超期 | `已返场天数 > 21 AND 未退出` | 最高 |
| 二次断货 | 返场期内再次出现 `FBA可售库存 = 0` | 最高 |
| 干预期严重低恢复 | `8 <= 已返场天数 <= 21 AND 销量恢复率 < 50%` | 高 |
| 干预期未恢复 | `8 <= 已返场天数 <= 21 AND 50% <= 销量恢复率 < 70%` | 中 |

## 第一版暂不做

- 不做自然流量恢复率。
- 不做关键词排名恢复。
- 不做 Review 变化。
- 不做自动归因。
- 不做运营动作效果评估。

这些等返场事件识别和监控闭环稳定后再加。
