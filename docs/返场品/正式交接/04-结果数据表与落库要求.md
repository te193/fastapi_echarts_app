# 结果数据表与落库要求

本文件是最新交付范围：**远端取数 → 返场运营决策计算 → 专用远端结果表**。不开发页面、路由、卡片、详情抽屉或广告价格执行流程。当前交接包只有只读取数和JSON计算；下列落库能力需要新Codex实现，本次未创建数据库表。

广告规则采用[固定ACOS分档](01-返场品完整运营决策.md)。建议证据保留`acos`、`acos_band`、`acos_band_label`、`acos_target=0.20`和`acos_max=0.50`；正常额度申请要求ACOS≤20%，旧成本推导上限不再作为有单动作必填条件。

零单采用[成熟点击分档](01-返场品完整运营决策.md)。保存`zero_order_clicks`中的成熟点击、0订单、点击档位、20／40门槛、试算标记及日期覆盖；另存完整对象身份、成熟窗口、竞价金额及操作核验。不再把试错额度、参考价格、每单成本或预算比例作为零单依据，旧样例保持历史版本。

降价采用[动态访问门槛](01-返场品完整运营决策.md)。结果须保存国家`price_comparison`、建议`price_conversion`的窗口、历史来源、动态所需访问、3件目标、预期与实际销量、70%比例、缺项和最终库存／价格／操作限制。不能只存“可以降价”，也不改写旧50门槛批次。

## 1. 最后要交付什么

1. 建表或迁移SQL，遵循目标项目结果库约定，SQL关键字小写。
2. 全量或分片批量计算任务，接入已有每日数据任务。
3. 专用结果表及真实数据写入，成功后读回核对。
4. 字段字典、常用查询SQL和验收记录。

业务源继续从远端读取，源连接只读；结果写入使用独立连接。允许新建、更新本任务专用结果表，不修改库存、经营、广告、Listing和预算源表，不调用广告或调价平台。

## 2. 推荐三张结果表

以下表名为建议，先核对目标结果库及已有同名表，不覆盖无关数据；结构可遵循现有项目规范。三张表用于处理一商品多国家、多广告对象，不把所有动作硬塞成单条商品字段。

| 表 | 粒度与唯一性 | 用途 |
| --- | --- | --- |
| `dws_return_goods_calc_batch` | 一次完整计算，`batch_id`主键 | 数据日期、设置日期、规则版本、成功失败与质量记录 |
| `dws_return_goods_strategy_result` | 一批次一个返场事件，唯一`batch_id,event_id` | 商品恢复、角色、退出、未退出原因和证据 |
| `dws_return_goods_action_detail` | 一批次一个国家／广告对象建议，唯一`batch_id,suggestion_id` | 具体广告或调价候选、金额、达标状态及限制 |

若目标项目已有合适的专用表，可以映射复用，交付实际表名、结构和映射；不要求另起一套相同表。

## 3. 批次表字段

| 字段 | 建议类型 | 含义 |
| --- | --- | --- |
| `batch_id` | bigint | 计算批次编号 |
| `data_date` | date | 完整库存经营评价日 |
| `settings_date` | date | 当前或历史设置截止日 |
| `rule_version` | varchar(100) | 决策规则版本 |
| `status` | varchar(16) | running／success／failed |
| `started_at/finished_at` | datetime | 任务时间 |
| `quality_json` | json | 源日期、缺数、扫描量、结果数量与警告 |
| `error_message` | text，可空 | 失败原因摘要，不包含密码或连接凭据 |

仅success批次可以作为有效结果。重新计算相同日期可创建新的批次，成功后成为该日期新版；不能按最大batch_id直接消费可能失败的批次。

## 4. 商品结果表字段

| 字段组 | 建议字段 | 存储要求 |
| --- | --- | --- |
| 关联 | batch_id、event_id | event_id沿用事件身份算法，不按MSKU单独去重 |
| 商品 | seller_name_new、country_category、msku、local_sku | 商品粒度为店铺＋类别＋MSKU＋本轮事件 |
| 事件 | stockout_date、confirmed_date、return_date、return_age | 断货首日、确认日、D1、当前D几 |
| 阶段 | phase_code、phase_label | 源`detail.phase`是观察期／干预期／持续干预期中文值；接手方明确映射为稳定编码并保存原说明，不直接当现成枚举字段 |
| 历史 | baseline_start、baseline_end、baseline_days、baseline_role | 实际有效30或14天，缺失保留null |
| 比较 | comparison_start、comparison_end、comparison_days、historical_daily、current_daily、recovery_rate | N／21／30主窗口及同长度销量比较 |
| 利润角色 | order_margin、current_role、current_stock | 当前主窗口利润角色和当日库存 |
| 主判断 | state、state_reason | 一个互斥经营状态与原因 |
| 退出 | exit_target、exit_status、first_exit_date、confirmation_days | tracking／early／normal、首次退出与进度 |
| 原因 | exit_reasons_json、data_issues_json | 所有未满足条件、缺失日期及字段，不能只保存一句摘要 |
| 汇总 | ad_result、price_can_review、price_wait_ad、ready_count、pending_count | 结果查询辅助字段，不要求开发卡片 |
| 证据 | summary_json、detail_json | 保留完整计算结果，包括历史、每日过程和退出证据 |

日销、恢复率、利润率建议用decimal，不存前端四舍五入值；自然日期用date。无法计算为null，真实0保持0。保留完整JSON之外，关键身份、状态、金额及日期需独立列便于SQL查询。

历史来源日期和当前评价日期分开。需要查询累计恢复过程时可从detail_json读取，当前不强制另建每日明细表。

## 5. 国家／对象建议明细字段

| 字段组 | 建议字段 | 含义 |
| --- | --- | --- |
| 关联 | batch_id、event_id、suggestion_id | 对应商品事件及稳定建议键 |
| 站点 | country、currency | 具体国家和金额币种，不用国家类别代替国家 |
| 类型 | kind、action、status | ad／price／general；开启、恢复、竞价、预算、价格、核查或保持；ready／pending／blocked／hold |
| 金额 | current_amount、target_amount、nominal_change_rate、actual_change_rate、target_tier | 调前、调后、名义及实际比例、价格目标档位 |
| 广告对象 | profile_id、campaign_id、ad_group_id、object_type、object_id、object_text | 自动target与手动关键词分别保存，价格建议这些列可空 |
| 原因 | reason、checks_json | 命中条件、受限与待核项 |
| 先后 | deferred、defer_type、defer_reason | 广告优先导致的后续价格暂缓，与自身blocked分开 |
| 日期 | source_date、target_source_date、ladder_date、last_change_date | 当前金额、目标对象、档位及真实调价日期 |
| 证据 | evidence_json | 对象成熟表现、国家经营指标、阶梯、预算配置及核验信息 |

建议键可按事件＋国家＋kind＋action＋对象类型及对象ID等稳定身份生成；同对象多种原因放checks／evidence，不无依据重复生成同一动作。金额空值不改成0元；候选有金额但pending仍不是已达标。

保持、核查、受限与广告优先暂缓都要留记录，以便回答“为什么不能调”。不是只落可调动作，把失败原因丢掉。

## 6. 批次写入、幂等与退出留档

- 先建running批次，再写商品和建议明细；全部检查通过才更新success。
- 同批次重试按唯一键幂等写入，不能重复累加行数；同日期重新回算使用新批次并保留旧记录。
- 失败时批次标failed，消费端继续查上一success；不能清空旧成功结果再开始新计算。
- 同事件首次退出日期及证据在兼容规则下沿用；后续表现变差不撤销。新断货恢复生成新事件，不覆盖旧轮次。
- 只有专用结果表可以写。不能为消除缺数警告擅自修改业务源表。

## 7. 查询与落库验收

交付查询样例至少覆盖：观察期、干预期、提前退出、常规退出；当前可审核升价／降价；广告调整、受限、不可判；每条待核和限制原因。

可审核价格需`kind='price'`、action为price_up／price_down、status为ready／pending且未deferred；严格已达标再限定ready。候选方向、当前可审核和已达标三种数量分别统计，不把它们混成一个“可调价”数字。

验收必须验证：

1. 建表／迁移脚本实际执行，批量计算真实写入，按成功批次读回核对商品和建议。
2. 商品按事件去重，建议保持国家和对象粒度；多对象不重复放大商品数。
3. 保存退出路径、首次日期、未退出全部原因及稳定确认进度。
4. 重跑同批次无重复，模拟失败不改变上一成功结果。
5. 缺数为null、真实0为0、无价格或有效竞价不捏造金额，七国范围准确。
6. 观察期和已退出不生成正常本轮新动作；待核不称已执行或已达标。
7. 记录实际库表名、任务运行方式、源日期、读回数量和典型样例。无法连接结果库时只能标“代码／迁移已完成，真实落库待验证”，不得声称交付完成。

本轮无需页面或浏览器验收。最终完成标志是**数据表中有真实可读回的计算结果及完整解释字段**，不是生成网页或仅写出JSON文件。

## 8. 已有JSON到建议列的映射提醒

| 目标列／证据 | 实际计算输出及接入注意 |
| --- | --- |
| return_age | summary.age或detail.age，不存在可直接复制的return_age源字段 |
| confirmed_date | 可在已确认连续3天事件下由stockout_date加2天派生；原build_events不直接返回该字段，左边界不完整须单独留提示 |
| phase_code、phase_label | detail.phase目前是中文；明确映射观察／干预／持续干预编码，已退出另用exit_status，不能混成一个字段 |
| first_exit_date | exit_date；与exit_target、confirmation_days、exit_evidence一并保留 |
| current_amount、target_amount | 建议current／target；恢复和开启可能没有金额，不填0 |
| nominal_change_rate、actual_change_rate | change_rate在广告中是名义幅度，价格中是取整后实际比例；广告实际比例需target/current－1，按kind解释，不盲目复制到两列 |
| target_tier | 价格建议tier；预算建议target为申请的增量额度，不是调后总预算或每日预算 |
| 广告与价格判断 | ad_result等统计字段在presentation整理后形成，不保证原始summary已带齐；批量统一派生或从建议明细查询 |
| evidence_json | 包含zero_order_clicks／price_conversion／stats、对应国家price_comparison、阶梯和核验项，不能只落reason文字 |

以上属于接手方数据映射工作，当前交接没有建好这些结果表。所有字段名、类型与唯一键须按实际目标库落实并记录。

## 9. 完整结构样例

[当前版本完整结果结构样例](验收资料/当前版本/当前版本完整结果结构样例.json)由本包v14代码离线生成，是合成数据，不能当真实远端商品。示例包含同一事件三个国家：德国成熟零单21点击降10%并暂缓价格；法国动态访问门槛150未满足；荷兰多商品广告对象待核、价格可独立审核。用于核对summary/detail、中文phase、国家price_comparison、建议zero_order_clicks／price_conversion、默认竞价和deferred字段。
