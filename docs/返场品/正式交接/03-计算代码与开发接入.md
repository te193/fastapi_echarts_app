# 计算代码与开发接入

版本：`return-v14-20261012-dynamic-price-visits`。代码可整体复制到目标项目，不依赖原FastAPI项目导入。外部连接和真实表结构必须在目标环境核对。

## 当前入口和输出

| 文件 | 职责 |
| --- | --- |
| `代码/return_goods_data/remote_sources.py` | 远端SQL、清洗、单商品calculate和CLI；源会话只读 |
| `代码/return_goods_data/rules.py` | 事件、角色、窗口、退出、广告和价格纯规则 |
| `代码/return_goods_data/enrichment.py` | 国家和对象表现、价格动态访问证据、建议与限制 |
| `代码/return_goods_data/keys.py` | 店铺／国家／MSKU规范化 |
| `代码/return_goods_data/connection.py` | 从外部配置创建源只读连接，无真实凭据 |
| `代码/return_goods_data/presentation.py` | 统计参考及结果汇总；不要求实现页面 |

`calculate(store, msku, data_date, settings_date)`返回顶层规则版本、日期、警告、`products[]`。每个product保存`summary/detail`，detail包含国家与具体建议。附加`page_data`只是统计参考，不能替代products作为完整结果，也不能将各单商品page_data直接相加作为全量统计。

## 运行顺序

进入本包`代码/`目录，Python建议3.11以上。先安装`requirements.txt`；只读连接沿用目标项目配置或填`config/database.example.ini`的本地副本。实际配置命名`config/database.ini`，不要提交或打包。

```powershell
python -m pip install -r requirements.txt
python -m return_goods_data.remote_sources --store CHOOJEE --msku CJ057b --snapshot-date 2026-10-08 --output result.json
```

这条CLI只读取远端并写本地JSON，不建表、不回写业务源、不操作平台。示例日期和商品为历史验证入口，不能将今日源数据修订后的结果强求等于旧JSON。历史设置日不得晚于评价日。无凭据时仍可运行离线测试，但不能宣称已完成远端取数验证。

测试命令为`python -m pytest tests -q`，**实际必须在隐藏后台运行并输出日志**，不弹终端或浏览器。本包测试用fixture／mock，不连接生产库。正式整理后的测试结果见[正式交接验收记录](验收资料/当前版本/正式交接验收记录.json)。

## 从单商品扩展到批量落库

1. 从库存枚举去重后的店铺＋MSKU，不从旧返场池复制全集。
2. 分片取足够长库存与经营历史；复用设置快照、广告对象和共同完整日期，避免每商品全库扫描。
3. 按现行规则生成最新事件summary/detail；只有兼容版本才沿用已确认首次退出账本。
4. 汇总全部商品后统一检查质量与统计，按04写批次、商品、国家／对象建议明细。
5. 全部成功才发布success；失败保留上一成功批次，按05读回验收。

原项目的首次退出保持会发生在enrich之前；本CLI尚未实现数据库退出账本。接手方须在批量编排中加载既有成功同事件记录，调用`retain_exit()`并停止已退出的新建议；不能仅在落库后覆盖一次exit_date。

## 函数索引和兼容说明

- 事件／恢复／退出：`build_events`、`evaluate_event`、`comparison_days`、`recovery_comparison`、`role`、`retain_exit`。
- 广告：`aggregate_ad_days`、`expand_auto_targets`、`ad_candidate`、`ad_for_country`、`budget_candidate`。
- 价格：`price_conversion_evidence`、`price_candidate`、`adjacent_price`、`attach_price_changes`。
- 核验和分流：`review_checks`、`resolve_direction_conflicts`、`order_country_suggestions`、`allocate_budget`。

`country_budget_usage()`只保留旧版核查，不用于当前零单判断。`allocate_budget()`存在但尚未接真实批量资金编排。`review_checks()`不能用未知值全True来伪造ready。目标项目改代码后须更新规则版本、测试与文档，不把本副本当作自动同步源项目。

代码出处见[源码清单](验收资料/当前版本/代码来源与校验清单.json)；其中source相对路径用于溯源，不是运行依赖。该清单不含真实配置。
