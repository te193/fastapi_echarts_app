# 返场品完整运营决策

版本：`return-v14-20261012-dynamic-price-visits`；整理日期：2026-10-12。本文是唯一主运营规则，按现行代码整合进入、恢复、退出、广告、价格及共同限制。所有幅度、点击档位、3件预期和70%为当前采用的试算规则，不宣称已验证最优经营效果。

阅读主线：**先识别本轮返场 → 判断自然恢复与退出 → 按国家算广告 → 无适用广告动作时独立审价格 → 输出建议、差距和待核证据。**

## 1. 运营先看当前情况，再决定动作

| 当前情况 | 直接处理思路 | 不满足或缺数时 | 何时再判断 |
| --- | --- | --- | --- |
| D1—D7，尚未退出 | 处于观察期，暂不进行人工干预 | 保留利润或库存风险事实，不把观察期写成广告无法判断 | 每天更新；D7检查稳定提前退出 |
| 已退出本轮 | 转日常运营，停止本轮新动作 | 保留首次退出依据；不能因后续变差撤销这轮成功 | 新的连续断货并恢复形成新轮次后再进入 |
| 日销不足1件 | 先修复销量，判断广告和具备转化依据的降价 | 不先用利润不足拦截拉量，库存、预算、样本和复评仍限制 | 每天复核，达到1件后再恢复利润修复判断 |
| 恢复较好，角色达目标 | 保持，继续判断稳定退出 | 不为了“在干预期”强制调整 | 每天评价退出 |
| 恢复较好，但角色差一点 | 检查日销或利润差距，避免机械加广告 | 国家价格仍需自身条件，不保证一定调整 | 每天更新角色与差距 |
| 改善中 | 最长继续观察至D14 | 不是自动降价或加投 | 每天复核，超过D14不继续用改善分支 |
| 恢复不足 | 先计算广告对象能怎么调，再看价格 | 广告数据不足独立解释，不把它当正常 | 成熟报表和必要条件更新后 |
| 日销≥1且毛利率低于5% | 优先利润修复、广告止损或适用提价 | 不直接增加投放 | 查清成本、售价、消耗后 |
| 库存缺失或窗口中连续3天零库存 | 暂停正常拉量，处理库存证据 | 不把库存问题归因于商品恢复能力差 | 有完整库存窗口后 |
| 历史基准缺失／为0 | 不强填恢复率，保留当前表现 | 当前完整角色仍可支持退出 | 当前窗口独立判断 |

“暂不以利润拦截拉量”是经营动作例外，不降低销售角色和退出的利润要求。

## 2. 从库存识别返场事件

商品粒度为店铺＋国家类别＋MSKU；欧洲共享库存不分别为每个国家重复建立事件。

连续3个完整自然日可售均为0，确认断货，断货日期记第一个零库存日。之后首次可售恢复到5件及以上，恢复日记D1。

```python
events = rules.build_events(days)
latest = events[-1]
age = (data_date - latest['return_date']).days + 1
```

| 库存序列 | 预期 |
| --- | --- |
| 0、5 | 不进入，只有1天为0 |
| 0、0、5 | 不进入，只有2天为0 |
| 0、0、0、4、5 | 在最后一天进入；4件不记D1 |
| 0、缺失、0、0、5 | 不进入，不跨缺失拼3天 |
| 已确认0、0、0，后续缺失，随后5 | 原已确认断货仍成立，缺失不造库存，恢复日可确定 |
| 返场后0、0、再恢复 | 不形成新轮次，原D1保留；窗口仍有无货日，影响退出 |
| 返场后0、0、0、再恢复5 | 形成新轮次，新的D1和历史基准 |

最新轮次要求恢复日期位于评价日期往前179天至评价日，共180天。不能只读取180天库存：该轮断货首日可能更早，历史基准也更早。

首次读取就从0开始时，可能无法证明真实断货首日；接手方必须保留左边界证据不完整提示，不能把源表最早一天当作确定真实首日。

## 3. 三种窗口分别解决什么问题

| 窗口 | 用途 | 取法 |
| --- | --- | --- |
| 历史角色基准 | 决定本轮退出目标，也给国家价格提供历史经营参考 | 断货前最后有效30天，必要时14天 |
| 当前主评价与匹配历史窗口 | 计算恢复程度和当前退出角色 | D1—21用N天，D22—29用21天，D30起用30天 |
| 国家近7天与趋势窗口 | 广告价格诊断、展示近7天变化、估算库存覆盖 | 国家近7天；趋势比较近7天与前7天 |

降价转化使用国家当前N／21／30天访问与销量，历史转化使用本轮断货前有效30／14天国家基准。价格的利润修复、提价及部分保持分支仍看近7天；不能把价格所有分支都当成同一窗口。完整降价口径见[动态访问门槛规则](01-返场品完整运营决策.md)。

### 3.1 历史角色基准

从断货首日前往前寻找，先找30个连续完整、有货且毛利率可计算的自然日。如果没有任何有效30天，再找14天。不是30天从所有有货日拼接，也不是取30个离散销售日。

寻找顺序是“30天优先，其次14天”，因此较早有效30天可以优先于较近有效14天。输出实际`start/end/days/evidence`，不要只写“断货前30天”。

紧邻断货前30天的每日表现也另行保留，即使不能形成有效角色。这解决“历史基准为空就看不到断货前原始表现”的问题。

### 3.2 恢复比较

| 评价日 | 当前窗口 | 对比历史窗口 |
| --- | --- | --- |
| D5 | D1—D5，5天 | 断货前最近有效5天 |
| D8 | D1—D8，8天 | 断货前最近有效8天 |
| D21 | D1—D21 | 有效21天 |
| D22 | D2—D22，最近21天 | 有效21天 |
| D29 | D9—D29，最近21天 | 有效21天 |
| D30 | D1—D30，最近30天 | 有效30天 |
| D75 | D46—D75，最近30天 | 有效30天 |

历史结束日必须早于断货首日，并要求连续有货。销量窗口只需销量完整，不因为历史毛利无法计算就丢掉销量比较。恢复率＝当前日销÷同长度历史日销；历史为0或缺失时返回空值，不填0或100%。

## 4. 经营分流的真实优先级

`comparison_state()`按下列顺序决定一个主状态，不能把所有命中原因同时当互斥商品分类。

1. 当前主窗口存在连续至少3天零库存：`stock_interrupted`。
2. 当前主窗口库存缺失：`stock_missing`。
3. 当前销量字段或日期不完整：`data_missing`。
4. D8起，当前窗口完整销量为0：`no_sales`。
5. D8起，0≤日销<1：满足改善且D≤14则`improving`，否则`sales_repair`。
6. 毛利率可计算且<5%：`risk`。
7. D1—D7：`observe`。
8. 毛利率不可计算：`profit_unknown`。
9. 未找到对应长度历史销量窗口：`history_missing`。
10. 对应历史日销为0：`history_zero`。
11. 恢复率≥80%：`good`。
12. 恢复率不足但满足改善且D≤14：`improving`。
13. 其他：`poor`。

因此观察期可能仍有`risk`等事实状态；动作栏必须按时间阶段显示“处于观察期，暂不进行人工干预”。不能用事实状态覆盖观察期动作边界。

### 4.1 改善条件

近7天、近3天和再前3天均完整有货，近7天及近3天毛利率至少5%；近3天毛利率不低于前3天；近3天至少2个出单日。

前3天销量为0时，近3天至少3件；否则近3天销量至少是前3天的120%，且绝对增加至少2件。改善仅提供继续观察的依据，不是广告加价触发器。

### 4.2 零销量分成两种

只有从D1至今所有日期都有销量记录且每天均为0，才能写“返场至今未出单”。当前N／21／30窗口为0但历史返场阶段有销量，应写“近N天无销量”。返场早期记录缺失时，也只能描述当前完整窗口，不推断一直未出单。

## 5. 销售角色计算

```python
daily = sum(qty) / window_days
margin = sum(order_profit) / sum(revenue)  # revenue合计须大于0
```

毛利率先求和再相除，不平均每日毛利率。使用原始精度，界面百分比四舍五入不参与判定。

| 角色 | 日销 | 毛利率 |
| --- | --- | --- |
| 明星 | >5 | >15% |
| 明星 | 1—5，含1和5 | >25% |
| 潜力 | >5 | ≥5%，排除明星 |
| 潜力 | 1—5 | ≥10%，排除明星 |
| 瘦狗 | >0且<1 | >5% |
| 瘦狗 | 1—5 | ≥5%且<10% |
| 问题 | 数据可算但不满足以上 | — |
| 不可判 | 日销或毛利率不能计算 | — |

销售额为0或负数时，毛利率为空；不把它填0%。完整零销量没有有效角色，不能靠毛利调整额达到瘦狗。

## 6. 退出目标和稳定性

| 断货前有效角色 | 本轮最低目标 |
| --- | --- |
| 明星、潜力 | 潜力，潜力或明星均通过 |
| 问题、瘦狗、不可判 | 瘦狗，瘦狗或潜力或明星均通过 |

### 6.1 D7提前退出

同时检查D1—D7每一天的单日角色，以及7天合计日销和毛利率对应的整体角色；全部达到本轮目标，且每天关键数据完整、每天可售>0，在D7记录提前退出。D1—D6不退出。

单日角色按当天销量及当天订单毛利率判。它比7天平均严格：单日0单不能通过，某一天毛利不达标不能用其他天平均掩盖。

### 6.2 常规退出

D7没有提前退出，从D8起每天评一次当前N／21／30窗口的整体角色。连续3个评价日通过，第三天常规退出，最早D10。

例如D8用8天、D9用9天、D10用10天，三次角色都达目标且各自窗口完整有货，D10退出。不是要求D8、D9、D10单日销量都达角色，也不是只检查最后3个单日。

失败、缺数或窗口包含无货日，当天计数归零。D21切D22和D29切D30不自动归零，重新评新窗口后通过则继续累计。

恢复到5件是D1门槛，退出要求每天有货，不要求每天都≥5件。恢复率无需达到80%或100%；不要求已调广告或价格；历史恢复率不能算，也不阻止当前角色完整达标退出。

## 7. 退出留档及再次断货

`evaluate_event()`从D7开始回放，保存该轮第一次通过的日期和证据；原页面批次还能借`retain_exit()`保留先前成功记录。交接包包含此函数，但JSON脚本未自动维护数据库历史退出账本。

接手方批量持久化时，同事件、兼容规则版本的已确认首次退出不能随每天指标波动被覆盖。新规则改变退出条件时，要明确是否重算，不盲目冻结旧版结果。

新一轮连续3天断货并恢复≥5件，应使用新的事件编号、基准和D1；不能重复执行上一轮动作，也不能因新轮次把预算余额自动重置。


## 8. 广告决策与当前ACOS分档

### 1. 每档直接怎么处理

| 当前成熟对象ACOS | 调整方向与单轮幅度 | 条件与限制 |
| --- | --- | --- |
| 0%—20%，包含20% | 需要拉量时竞价候选＋10% | ≥7个成熟有效报表日、≥20点击、≥3单；DOS≥14天。DOS为7至不足14天只＋3%；不足7天不加 |
| >20%—30%，包含30% | 只有主评价日销<1件的销量修复，可候选＋3%；其余保持 | 同样样本要求，DOS≥14天；不新增预算，不因低利润豁免ACOS分档 |
| >30%—40%，包含40% | 保持竞价、控制消耗，暂不增加投放 | 观察下一轮成熟效果；不新增预算 |
| >40%—50%，包含50% | 竞价候选−10% | ≥7个成熟有效报表日、≥3单；不另加20点击要求，不加竞价或预算 |
| >50% | 竞价候选−20%，标记超限止损 | 同样成熟订单要求；禁止加投，不能直接恢复原高消耗暂停对象；不自动暂停全部广告 |

即：20%属于积极档；30%属于谨慎档；40%属于保持档；50%属于−10%档；严格超过50%才−20%。用原始精度分档，不能先把20.0001%显示为20%再当达标。

“积极拉量”只改变单次幅度，不取消商品是否需要干预、对象归属、成熟样本、库存、平台上下限、预算、操作记录和正常复评。日销≥1件的利润风险仍限制正向投放；日销<1件的利润例外仍有效，但高ACOS先控费。



### 1. 先确定这个商品需不需要正常干预

`enrich()`只在本轮未退出、D≥8且满足需要处理的分支时计算国家广告和价格。主要分支为销量修复、恢复不足、利润风险、无销量、历史缺失、历史零销量和利润未知；恢复较好但当前退出角色有差距，也需要复核。

观察期、已退出、正常恢复且角色达目标、改善继续观察、库存缺失或连续断货，不因为存在某个历史建议就强制进入正常调整。

国家当前价<P10属于底线风险，可触发独立检查，但不能突破观察期、库存缺失和经营缺失边界。风险事实保留，不能说“已退出还继续生成本轮提价动作”。

有国家经营记录，但当前Listing没有、近7天没有访问也没有销量时，先核实该站点是否实际经营，不直接建议新建广告。

### 2. 广告判断需要哪些输入

| 输入 | 来源与用途 |
| --- | --- |
| `mapping_count` | 对象关联商品数，必须等于1才能按单个MSKU判断 |
| 活动／组／对象状态 | 任一paused则视为暂停；archived另行核查，不直接恢复 |
| `current_bid/default_bid` | 当前对象价优先，空或0可继承正的默认价；负数无效 |
| `days/mature` | 本轮返场后、完成7天归因、可用于判断的报表日与完整性 |
| `clicks/orders/cost/sales` | 同一对象成熟窗口合计，不用商品总体销售替代广告订单 |
| `dos` | 当前库存÷类别近7天日销；零销量时可用有效历史日销带提示估算 |
| `cost/sales`与固定ACOS分档 | 成熟对象广告花费÷归因销售额，固定目标20%、上限50%；不需要利润推导的`affordable_acos` |
| `zero_order_clicks` | 对象成熟点击数、0订单、20／40门槛、点击档位、试算标记和覆盖核验；无需参考价格或每单成本 |
| 预算及操作记录 | 真实可用余额、平台上下限、近期操作及复评，仍需核验 |

DOS不能算时保持未知，不能设一个很大值当库存无限充足。无货或库存未知日不作为广告评价日；日报缺失也不填0。

### 3. 没有广告、暂停广告、已归档

| 情况 | 输出 | 仍需核实 |
| --- | --- | --- |
| 对象快照成功读取，该经营国家没有对象 | `start_ad`建议开启广告 | 站点可售、有投放资格、没有遗漏活动、另设竞价预算 |
| 具体对象或上层活动／组暂停 | `restore`恢复已有广告候选 | 原因是否断货、原设置是否有效、库存预算与复评 |
| 暂停对象但DOS<14或未知 | `blocked`不能恢复试投 | 库存覆盖 |
| 关联多个MSKU或归属不明 | `check/pending` | 不能把公共对象订单全归给一个商品 |
| 对象已归档 | `check/pending` | 不是直接恢复归档对象 |
| 自动广告只有广告组汇总，没有匹配target | `check/pending` | 真实匹配方式、对象状态与竞价 |

恢复建议不生成虚构新竞价。无对象时没有历史竞价可供恢复，建议开启和恢复已有广告是两个动作。

### 4. 已投放对象的真实判断顺序

`rules.ad_candidate()`依次判断：归属 → 暂停 → 成熟归因 → 必要效果字段 → 无点击 → 零单／有单效率 → 竞价金额。

归因未成熟时，不因为0单直接止损。成熟0点击0单且数据完整时保持竞价，可另查资格、状态与同步；0点击但存在广告订单时先核对归因报表。成熟但样本不足且无其他错误时，归为“暂不调整，继续积累样本”。

#### 4.1 提高竞价

同时满足：

1. 对象单一商品归属，状态允许投放，当前有效竞价可计算。
2. 成熟有效报表日数≥7，订单≥3，点击≥20。
3. 库存覆盖DOS≥7。
4. 对象ACOS≤20%时可积极拉量；20%<ACOS≤30%只允许主窗口日销不足1件的销量修复小步拉量；超过30%不加竞价，低日销也不能绕过。
5. 在`enrich()`外层再次检查：非低日销商品只有恢复不足且近期利润安全条件通过，才能保留正向加投；利润风险不加投。

**ACOS≤20%且DOS≥14时＋10%；DOS7至不足14时最多＋3%。20%<ACOS≤30%的低日销修复要求DOS≥14，幅度＋3%。**均需至少7个成熟报表日、20点击、3单。10%—20%也为＋10%，不再用＋5%。

还要核实真实预算、批准花费、竞价平台上下限和近期操作，故通常是`pending`而非`ready`。

#### 4.2 有订单但广告低效

成熟报表≥7天、订单≥3：40%<ACOS≤50%候选降低10%，ACOS>50%候选降低20%。这里不像加价分支另要求20次点击；不要人为把两个分支条件合并。

低日销只豁免利润门槛，仍服从固定ACOS分档；30%以上不加投，40%以上先控费，不能因为需要拉量忽略超限。

20%<ACOS≤30%非低日销保持；30%<ACOS≤40%均保持。恰为40%不降，恰为50%降10%，严格超过50%才降20%。有订单但归因销售额≤0则ACOS不可算，不设为0%。

#### 4.3 成熟零单止损

对象归因成熟、0订单、日期覆盖可靠：点击0—19次保持，20—39次候选降10%，40次及以上候选降20%。不另加7个报表日要求，日销不足1与正常日销统一，不以花费、CPA、价格或预算消耗决定幅度。20／40和10%／20%均为试算参数。

逐关键词、逐具体自动target统计，不把广告组或其他对象点击加进来。报表缺日期、订单或点击缺失、多商品对象时待核，不补0；零单但归因销售额>0先核查。暂停／归档另判，目标金额仍需有效竞价与可靠币种。预算只作资金限制，不决定零单竞价方向。

点击档位通过后仍核验保护、其他归因订单、真实操作及平台范围；有金额不等于可执行。实际调整后用新成熟数据复评，不能拿同一旧窗口每天重复下调。缺每单成本不再作为零单不可判原因。

### 5. 有效竞价和取整

```python
effective = current_bid if current_bid > 0 else positive_default_bid
raw = effective * (1 + change_rate)
```

以币种最小单位取整：加价向下取整避免超幅度，降价向上取整避免多降；取整后必须>0且不同于当前价。七国常用0.01。

例：0.50提高3%为0.515，按0.01向下取0.51；0.50降低10%为0.45。若0.08提高3%仍取0.08，转为无法生成有效变化金额，不伪造0.09并称仅涨3%。

当前记录`change_rate`可能为名义调整比例，实际比例应从目标／当前−1计算展示。接手前端不能把名义3%当金额取整后的精确涨幅。

### 6. 预算建议

只有样本与经营准入通过、对象ACOS≤20%、DOS≥14且`budget_limited_verified=True`，才能把加竞价分支替换为申请预算；两者不是同一对象一起加。20%以上不新增预算。

```python
configuration_cap = min(monthly_budget * 0.10, weekly_budget * 0.25)
normal_target = min(configuration_cap, verified_pool_remaining, verified_profit_capacity)
sales_repair_target = min(configuration_cap, verified_pool_remaining)
```

月或周配置≤0／缺失时不能给统一兜底金额。缺真实池余额或非低日销时缺利润容量，保留待核且不生成金额。低日销只豁免利润容量，不豁免真实余额。

`allocate_budget()`可在已验证余额上按批次占用，逐条递减，避免同池重复分配；但当前`enrich()`没有自动调用它，远端取数也没有提供真余额，不能声称现有预算已经做完批次联合核验。

`ad_for_country()`不再按动作计数限制建议。每个符合条件的对象均保留，排序优先止损，不截取前几条；同对象重复采集去重、相反方向合并为核查，不同对象可以不同方向。实际预算、库存和复评条件独立生效。

### 7. 先广告后价格，具体是什么意思

每国家先计算广告结果，再独立计算价格候选；随后`order_country_suggestions()`决定哪些价格只能留作后续试算。

| 广告结果 | 价格怎么处理 |
| --- | --- |
| 有开启／恢复／加减竞价／申请预算的具体有效金额候选或状态候选，且ready或pending | 优先核验广告；已命中的价格加`deferred=True/defer_type=ad_priority`，不计“可审核调价” |
| 只是广告数据缺失、归因未完成或利润依据缺失，没有具体适用动作 | 独立审核价格，不用广告缺数单独挡住价格 |
| 已明确无适用广告动作、样本不足保持或广告受限 | 独立审核价格；价格自己仍需库存、档位、利润及复评条件 |
| 价格自身已blocked | 保留价格限制原因，不覆盖成广告优先 |

“优先核验广告”不代表已经操作，不代表处于广告复评等待期。只有真实操作记录才能支持“已调整，等待复评”。当前完整广告操作日志未接入，不能从旧建议推定已执行。



## 9. 国家调价、动态访问与状态核验

### 8. 价格判断先后顺序：不能只列涨价和降价公式

`price_candidate()`顺序决定哪条分支先命中：

1. 已退出或D<8：保持。
2. 当前价无效：待核当前Listing。
3. 当前价<P10：底线修复升至P10优先。
4. 主窗口日销不足1件：看国家转化是否下滑，成立则候选降一档，否则保持。
5. 非低日销，国家近7天数据或利润不可算：待核，未定涨降方向。
6. 国家有销量且近7天毛利率<5%：核实低价原因后候选升一档。
7. 商品近7天角色至少潜力，或D<14且主状态恢复较好：保持。
8. 国家日销1—5且毛利率≥5%但<10%：候选升一档修复角色差距。
9. 恢复不足或适用低销量情况：满足毛利余量、流量和转化条件才候选降一档。
10. 其他：保持并解释未命中的条件。

第7项保持仍用`event.recent`近7天角色，提价／利润仍用国家近7天指标；仅降价转化样本改用`price_comparison`对应N／21／30窗口。不能把价格所有分支都写成同一窗口。

### 9. 哪些商品可以候选降价

在某国家同时满足：

- 当前国家访问和销量按D8—D21返场N天、D22—D29最近21天、D30起最近30天统计，完整有货、销量访问非负。
- 同国家本轮断货前有效30／14天基准完整有货、访问>0、历史销量≥5件，不再要求50次。
- 动态访问门槛＝向上取整（3×历史访问÷历史销量）；当前预期销量＝当前窗口访问×历史销量÷历史访问，至少3件才进入判断。
- 当前实际销量严格小于预期销量的70%才进入候选，等于70%不通过。公式和证据见[12规则](01-返场品完整运营决策.md)。
- 库存覆盖≥14天。
- 当前价和完整档位可计算、币种一致、阶梯正常，可以生成向下相邻金额且不突破P10。
- 未命中正常调价7天间隔限制。

主窗口日销不足1件时暂不要求利润余量，先修复销量。非低日销的恢复不足分支要求国家订单毛利率≥10%，还要核验调后预测利润≥5%。

未达到动态访问门槛表示继续观察，不表示价格正常；基准或对应窗口缺数待核，不用近7天或50次兜底。历史只有4件仍不通过5件样本保护。3件和70%为试算参数，不证明价格造成销量差。

“现在降价卡片0”可能有两种原因：没有任何国家命中方向，或命中但被库存、P10、近期真实调价、广告优先等限制。必须保留候选及限制，不能只返回最终0。

### 10. 哪些商品可以候选提价

| 分支 | 候选方向 | 仍需核验 |
| --- | --- | --- |
| 当前价<P10 | 升至P10 | 价格底线风险，不能把缺数据当已达标 |
| 非低日销，国家毛利率<5%且有销量 | 升相邻档 | 低售价是否真是利润缺口原因，而非成本或广告异常 |
| 非低日销，日销1—5、毛利率5%至不足10%，未被前面的保持分支截获 | 升相邻档 | 角色差距原因、成本广告、预测利润 |

不因“返场”统一提价，不把国家类别下所有国家一起提价。涨价必须有具体国家金额、币种、档位和原因。

### 11. 逐档金额怎么计算

P10/P15/P20/P25/P30/P35是一条站点价格阶梯，档位编号不是涨价百分比。

| 当前价格位置 | 下调 | 上调 |
| --- | --- | --- |
| 恰好P20 | P15 | P25 |
| P15与P20之间 | P15 | P20 |
| 恰好P10 | 禁止继续降 | P15 |
| 低于P10 | 不再向下 | 先审核到P10 |
| 恰好P35 | P30 | 禁止继续升 |
| 高于P35 | 先到P35 | 禁止升 |

所有六档都必须存在且严格递增，即使只需要P20→P15，也不能跳过未核实的其他档位。目标按币种单位向上取整，取整后仍须在P10—P35内且发生真实方向变化；失败则受限。

实际涨跌幅＝目标金额÷当前金额−1。相邻档价差大于5%也按实际档位展示，不截断到中间价。

### 12. 调价复评与例外

上一成功实际调价到评价日不足7天，正常下一次调价`blocked`。没有记录是操作待核，不能假设间隔通过。

当前价<P10或非低日销且毛利率<5%的风险，未满7天可列单独人工审核，不自动执行例外。降价拉量依然受正常7天间隔限制。

代码使用自然日期差，不知道完整生效时段；执行时间靠近当天结束时，日期差等于7不等于已经有7个调后完整日。接手方要确认最终复评日期口径。

### 13. 达标状态不是方向本身

| 状态 | 条件 | 如何展示 |
| --- | --- | --- |
| ready | 所有必要数据和检查已确认通过 | 条件已满足，仍属于建议层 |
| pending | 金额可候选但存在未知检查，或方向尚不能判断 | 逐项列待核，不计达标 |
| blocked | 已知库存、档位、间隔、利润等限制失败 | 暂不调整并显示具体限制 |
| hold | 正常恢复或未命中动作条件 | 保持并说明依据 |

`review_checks()`提供False→blocked、None→pending、全True→ready的通用计算。当前主流水线未接上完整核验值，多数建议默认pending；不能只因为算出目标金额就改成ready。

### 14. 固定ACOS、零单点击分档、真实余额与预测利润

有单效率固定目标20%、上限50%。零单按对象成熟点击分档，正向动作真实余额与预测利润仍需核验：

```python
acos = mature_cost / mature_attributed_sales  # 归因销售额须大于0
acos_target, acos_max = 0.20, 0.50
zero_order_change = -0.20 if mature_clicks >= 40 else (-0.10 if mature_clicks >= 20 else 0)
# 仅用于成熟0单对象；不计算零单ACOS或成本额度。
real_pool_remaining = pool_cap - incurred_spend - future_base_reserve - committed_extra
forecast_margin = (forecast_revenue - forecast_non_ad_cost - forecast_total_ad_spend) / forecast_revenue
```

必须同站点、同币种；税费退款与收入分母一致；非广告成本不重复含广告费；预算预留与承诺不能重叠重复扣减。负余额不当可用资金，缺一项不填0伪装有确定值。

价格档位隐含成本并不等于真实销量预测，不可用“调后到P15所以毛利必然15%”替代联合预测利润。当前预算与预测信息未完整实现，代码会保留待核；不得向接手方声称这些公式已经有可用源表支持。


## 10. 动作数量与同对象方向

### 1. 不限制动作数量

取消国家、国家类别、商品和批次的广告总动作及正向动作数量上限，也取消库存分档中的“仅一个拉量对象”等数量限制。符合条件的关键词、自动匹配方式、恢复投放或预算候选都可以同轮给出建议，不截取前几个、不因名额已满标成受限。

四种自动匹配方式各自达标时可以同时列出四条提高竞价建议；多个对象需要降低竞价时也不只留两条。排序仍可以优先呈现止损，但排序不是数量准入。

### 2. 同一对象不能同时涨和降

- 同一商品同一国家的售价：本轮只形成一个相邻档位目标，不同时提价和降价。
- 同一活动＋广告组＋关键词或自动target：本轮不同时提高和降低竞价。
- 不同对象可以不同方向：关键词A提高、关键词B降低，或者德国提价、法国降价都可以。
- 若已有结果或外部输入对同一对象同时命中两方向，合并为一条人工核查，保留冲突证据，不输出两个相反金额，不任意挑一个方向。
- 对象重复采集仍去重，不能把同一对象复制多条当作“数量不限”。

代码在`ad_for_country()`中去除计数拦截，保留对象去重；`resolve_direction_conflicts()`在国家商品范围内检查相反方向，`order_country_suggestions()`用于新计算及已保存结果的方向整理。

### 3. 数量不限仍遵守哪些条件

进入退出、观察期、成熟样本、固定ACOS分档、零单20／40成熟点击分档、库存覆盖、真实可用资金、同币种、价格P10／P35、逐档幅度、近期实际操作与复评继续生效。

取消的是“能给几条建议”的上限，不表示单个对象可以叠加多轮涨幅或同时恢复、涨竞价、加预算。预算与竞价增加依然按原判断二选一，先广告后价格的分流不变。

真实余额未知时保留待核，不能把一份池余额用于多条完整申请。预算申请仍需按国家商品汇总去重并在批次内核对可分配总额；已有`allocate_budget()`提供余额逐条扣减，未完整接通真余额及批次分配的现状仍明确保留，不宣称已完成真实划拨。
