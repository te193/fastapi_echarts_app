# 远端取数与数据清洗开发文档

本文件回答“到底查什么表、怎样变成决策输入”。全部取数SQL在[remote_sources.py](../../../代码/return_goods_data/remote_sources.py)，当前字段核对留档见[远端表字段](../../../验收资料/历史真实样例/remote-development-table-audit.json)。

## 1. 连接和日期参数

独立包使用PyMySQL字典游标，连接配置由环境变量`RETURN_GOODS_DB_*`或外部`config/database.ini`提供。模板不含真实地址或凭据。连接初始化执行只读会话设置；不调用原项目的建表、写批次或执行动作函数。

| 参数 | 含义 | 约束 |
| --- | --- | --- |
| `store` | 清洗后店铺前缀，如CHOOJEE | 不把多个店铺混算 |
| `msku` | 清洗后MSKU，如CJ057b | 与库存标准MSKU对齐 |
| `cutoff/data_date` | 完整库存经营评价日 | 不超过数据完整日，不直接取当天未完整数据 |
| `settings_date` | Listing、档位、预算、对象设置截止日 | 历史模式≤data_date，默认相同 |
| `common_end` | 广告共同完整报表日 | 从必要日报各自最大日取最小值 |
| `mature_end` | 广告成熟效果截止日 | common_end减7天 |

原页面当前模式可用较新的设置配较早完整经营日；交接包历史重算默认禁止未来设置，不能据此要求两者结果完全相同。若接手方增加当前建议模式，要明确区分经营日与当前设置日，历史模式继续严格过滤。

## 2. 规范化键

事件显示保留原店铺大小写，国家对象查询使用`business_key()`规范为小写匹配键：

```python
business_key('Gangzhh-DE', '德国', 'GZ012a')
# ('gangzhh', 'de', 'gz012a')
```

国家类别按现行经营数据映射：英国→英国站；美国、加拿大、巴西、墨西哥→北美站；其他→欧洲站。该映射沿用现行项目，新增非欧洲地区时必须审查，不能认为默认欧洲适用于全部新市场。

MSKU先取逗号首段；首段长度>16时，按原项目规则取连字符首段并去`amzn.gr.`。该清洗规则保留兼容，不应对新业务编码未经验证直接推广。

库存表已提供`seller_name_new/country_category/seller_sku_adj`，经营表提供原店铺及MSKU，两者通过这些规范化键连接。

## 3. 库存：事件的唯一依据

源表：`etl_datasync.etl_dispose_lx_storage_fba_warehouse_detail`。

```sql
select create_time,country_category,afn_fulfillable_quantity
from etl_datasync.etl_dispose_lx_storage_fba_warehouse_detail
where seller_name_new=%s
  and seller_sku_adj=%s
  and create_time<%s
order by create_time
```

第三个参数是评价日次日，包含评价日整天、不包含次日。取完整可用历史，不先截为180天。

按国家类别、`date(create_time)`分组。一次采集的多个仓库行相加；同日出现多个不同采集时间，交接适配器保留未知，不直接把多个库存时点相加。接手方若能证明统一批次字段或实际快照粒度，应替换为明确的完整采集批次选择。

空值库存保留空值，未出现的日期不生成0记录。不要使用“前一天库存复制到缺失日”“后一天库存倒填”或经营表的库存替代权威日库存。

输出：`day/stock/inventory_only=True`。同类别经营行再通过`attach_inventory_days()`接入该日同一份库存，`merge_days()`取共享库存值而非按国家重复求和。

## 4. 经营日：销量与订单利润

源表：`dwd_datasync.lx_statistics_product_performance`。

| 决策输入 | 原字段 | 说明 |
| --- | --- | --- |
| `day` | `start_date` | 开始与结束自然日相同才入日表 |
| `country` | `country` | 保留国家，用于七国建议 |
| `local_sku` | `local_sku` | 显示和自然键去重，不作为返场事件主键 |
| `qty` | `volume` | 销量，真实0保留，空值不填0 |
| `revenue` | `amount` | 与订单毛利同口径销售额 |
| `profit` | `predict_gross_profit` | 订单利润，不能改用结算`gross_profit` |
| `sessions` | `sessions_total` | 国家转化样本 |
| `ad_spend` | `spend` | 经营参考广告费，不代替对象广告报表 |
| `financial_currency` | `currency_icon` | 不能假设经营金额币种就是Listing币种 |

SQL按店铺前缀、清洗后MSKU、截止日、单日区间过滤。完整SQL及`MSKU_SQL`位于`read_history()`。

日数据可能有后续同步版本。适配器按“日期＋原店铺＋原MSKU＋国家＋ASIN＋local_sku”选最新`create_time/id`，然后求国家日合计。

这一去重键是当前适配选择，必须用接手环境重复样例复核：若真实业务允许相同键多条不同明细，不应任意丢掉；若`relate_id`代表稳定业务键，需要确认后再改，不直接把同步ID当业务主键。

`qty/revenue/profit/sessions/ad_spend`分别判字段完整性。国家一天存在任一参与行对应字段为空，则当天该字段为空。类别销量求和独立于财务完整性，避免历史利润缺失导致销量对比全部消失。

## 5. 币种、金额及历史修订

Listing一般为站点本币，但已核对的经营样例`currency_icon`为人民币符号；不能把售价EUR直接与经营利润人民币相减。

适配器国家日币种不同或类别同一天币种不同，财务字段标未知，不伪造汇率。当前没有全周期统一币种转换，跨日币种发生切换也必须在批量开发中增加校验；当前同日校验不保证一个30天窗口币种始终相同。

降价新增`price_comparison.current`，按`comparison_days(age)`取返场后N／21／30天；`price_comparison.history`取本轮断货前有效30／14天的同国家汇总。两段均使用`comparison_metrics()`，销量、访问与库存完整性单独检查，不因毛利缺失伪造销量。`price_conversion_evidence()`生成动态访问门槛、预期销量及来源日期；详见[12规则](../../../01-返场品完整运营决策.md)。

价格规则当前主要使用利润率、转化率和本币阶梯，不直接做本币价减人民币成本。有单广告使用成熟花费／归因销售额和固定20%／50%分档；竞价金额和预测利润必须使用可靠币种；零单不计算金额比例，只按成熟点击／订单分档。

零单由`ad_candidate()`直接按成熟点击分档，不接入`trial_reference/order_economics`，不区分主窗口日销。`aggregate_ad_days()`逐对象记录成熟点击、订单、窗口及`zero_order_coverage_verified`；有货窗口缺报表或库存日期不能补0。当前完整报表日减7天、最多14个成熟报表日且不早于返场；同一关键词／target单独判断。预算历史仅用于预算业务，`country_budget_usage()`保留为旧版核查工具。具体字段见[零单点击规则](../../../01-返场品完整运营决策.md)。

经营数据可能晚于业务日期同步，或者后续修订。按业务日期筛选可重算当日经营情况，却不能证明数据在当时就已存在。需要“当时已知数据”回放时，另需来源版本留档和可用时间。

## 6. 当前Listing与档位

Listing：`dwd_datasync.lx_sales_mws_listing`。

取`date(create_time)`、清洗后店铺、`marketplace`国家、`seller_sku`、`landed_price`和`currency_code`；按商品国家选截止日前最新日期。同日不同价格保留冲突，不取最大价假装唯一。

档位：`temporary_dwd.在库节点_输出定价表`。

```sql
select `数据日期` snapshot_date,`新店铺` seller_name_new,`国家` country,
       msku seller_sku,`币种` currency,
       `10毛利润价格` margin_price_10,`15毛利润价格` margin_price_15,
       `20毛利润价格` margin_price_20,`25毛利润价格` margin_price_25,
       `30毛利润价格` margin_price_30,`35毛利润价格` margin_price_35
from temporary_dwd.`在库节点_输出定价表`
where `新店铺`=%s and msku=%s and `数据日期`<%s
```

必须用`数据日期`，不能把今天档位贴成历史日期。每条阶梯来自同一条有效记录，不按各档位分别取最大值再拼。不是含广告档位，也不参考断货前Listing售价、优惠券或促销。

校验：当前价>0；P10—P35六档齐全、正数、严格递增；价格与档位币种一致；同日没有冲突。失败时保留原因，不输出目标金额。

## 7. 实际调价及7天间隔

源表：`temporary_APP.lx_sale_adjust_price_queue`。

`read_settings()`只读取`delete_flag=0`、`processing_status_text='调价成功'`、完成时间非空且不晚于设置截止日的调价；使用`date(finish_time)`作为执行日期，不使用建议生成日期。

`attach_price_changes()`继续确认：前后价格均>0且有变化、调后金额等于该国家当前Listing价格、币种一致、调价日不晚于Listing日期。通过才设置`last_change_date/last_change_source_id`。

找不到记录不代表从未调价；只能将近期操作及复评列为待核。当前队列表能找到成功操作，不代表能找到完整销量复评结论。

## 8. 预算配置与真实余额分开

源表：`dws_datasync.dws_monthly_ad_budget_detail`，同时提供月预算与周预算，不另找并不存在的独立周表。

读取`biz_date/country/seller_name_new/seller_sku_adj/currency_code/monthly_ad_budget_original/weekly_ad_budget_original`，按国家商品取截止日前最新配置。

`dws_datasync.dws_ad_budget_pool_daily_history`可参考配置历史及池总额，但不是扣除了未来基础消耗和已承诺动作的真实余额。本交接取数不会从它捏造`verified_pool_remaining`。

需要后续业务核实的字段：`budget_limited_verified/verified_pool_remaining/verified_profit_capacity`。未填这些字段时，不应奇怪“申请预算没有具体金额”，那是核验未接通。

## 9. 广告对象与逐日报表

取数步骤：

1. 从`dws_datasync.dws_sp_bid_object_snapshot_daily`找不晚于设置日的最新全库对象快照日。
2. 在该日按`base_store_name/msku`取商品对象，仅保留七国，避免拉全库127列对象。
3. 得到商品关联的`profile_id/campaign_id/ad_group_id`，所有后续对象和日报查询均限这些组。
4. 从`ods_datasync.lx_advertising_sp_targets`读取auto且未删除、创建和更新不晚于设置日的目标，展开真实匹配方式。
5. 确定必要广告日报共同完整日期，取成熟后最多14天的对象日报。
6. 按返场日截掉返场前数据，按库存日期排除无货或库存未知日。

手动关键词源：`ods_datasync.lx_advertising_sp_keyword_reports`，自然键为profile＋campaign＋ad_group＋keyword＋report_date，最新id去重。

自动匹配源：`ods_datasync.lx_advertising_sp_query_word_reports`，自然键还含target及query；最新id去重后按target日汇总点击、花费、orders_7d、sales_7d和展现。

产品广告与广告组日报只参加完整日期检查，不作为关键词或auto target效果。搜索词日报未必覆盖全部表现，仍保留“具体匹配方式汇总覆盖待核”。

缺截止日前对象快照时直接报错，不宣称无广告；快照读取成功但某国家没有匹配对象，才建议该国家开启广告。该结论依赖当前映射完整性，开户前仍需核实遗漏活动。

## 10. 建议需要的国家范围

事件可以涉及其他国家；正常广告、价格建议只输出德、法、意、西、荷、英、美。加拿大、波兰等不扩大建议范围，但所属国家类别的经营与库存仍影响事件和退出。

当前`enrich()`按历史经营行形成国家集合，不直接对七国全部造记录。若国家只有Listing或广告对象、尚无经营行，目前可能不进入国家详情。接手方应验证“实际经营站点”的完整名单，再决定使用经营、Listing和广告对象的并集，不能把没有开站的国家自动建议开户。

## 11. 批量取数建议

候选全集从库存重建，不使用旧返场池：

```sql
select distinct seller_name_new,seller_sku_adj
from etl_datasync.etl_dispose_lx_storage_fba_warehouse_detail
where create_time<%s
  and seller_name_new is not null and seller_sku_adj is not null
```

这是批量候选枚举示意，交接CLI目前按商品运行。生产批量应分片、复用设置和对象读取、避免每个商品反复扫描共同完整日期；记录每片成功、缺源和总量。不要在点击商品详情时扫描全库。

建议来源日期、规则版本、数据完整性、计算耗时和缺数清单随结果留档。前台只消费完整成功结果；失败时保留上次成功结果并显示失败和实际日期。该发布机制需要接手方实现，不能把本包JSON输出当作已具备生产发布。
