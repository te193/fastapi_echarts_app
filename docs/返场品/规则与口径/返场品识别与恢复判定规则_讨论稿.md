# 返场品识别与恢复判定规则（讨论稿）

## 1. 整体流程

一个 MSKU 从断货到退出返场跟踪，大致经过：

```text
出现断货
-> 库存恢复，生成返场记录
-> D1-D7 观察期
-> D8-D21 运营干预期
-> D21 判断是否达标
-> 达标则在 D22 退出
-> 未达标则从 D22 开始持续干预
-> 后续恢复率首次达到 70% 时退出
```

页面只展示每个 MSKU 最新一轮完整返场记录。

## 2. 断货怎么识别

当某个 MSKU 第一次出现：

```text
FBA 可售库存 = 0
```

就认为这一轮断货开始。

这一天记录为：

```text
断货日期
```

断货以后，即使库存连续多天都是 0，仍然属于同一轮断货，不会每天生成一条记录。

例如：

| 日期 | FBA可售 | 判断 |
| --- | ---: | --- |
| 5月12日 | 2 | 尚未断货 |
| 5月13日 | 0 | 本轮断货开始 |
| 5月14日 | 0 | 仍属于同一轮断货 |
| 5月15日 | 0 | 仍属于同一轮断货 |

这一轮的断货日期固定为 5 月 13 日。

## 3. 返场怎么识别

断货后，第一次出现：

```text
FBA 可售库存 > 5
```

就认为产品已经返场。

这一天记录为：

```text
返场开始日期
返场Day1（D1）
```

当前门槛是严格大于 5，不是大于等于 5。

因此：

| FBA可售 | 是否返场 |
| ---: | --- |
| 0 | 否 |
| 1-5 | 否，仍未恢复到返场门槛 |
| 6及以上 | 是 |

完整返场事件必须同时具备：

```text
前面出现过 FBA 可售 = 0
AND 后面出现 FBA 可售 > 5
```

仅断货但还没有恢复到 6 及以上，不生成新的返场事件。

## 4. 断货日期取哪一天

断货日期取本轮断货段第一次出现库存为 0 的日期，不取返场前最近一次为 0 的日期。

例如：

| 日期 | FBA可售 | 判断 |
| --- | ---: | --- |
| 5月12日 | 1 | 未断货 |
| 5月13日 | 0 | 本轮断货日期 |
| 5月20日 | 0 | 同一轮断货 |
| 5月27日 | 0 | 同一轮断货 |
| 6月26日 | 8 | 返场开始 |

最终记录：

```text
断货日期 = 5月13日
返场开始日期 = 6月26日
```

不是把 5 月 27 日作为断货日期。

## 5. 多轮断货和返场

同一个 MSKU 可以多次断货和返场。

识别过程：

1. 第一次出现库存为 0，开始第 1 轮断货。
2. 后续第一次恢复到库存大于 5，完成第 1 轮返场。
3. 之后再次出现库存为 0，开始第 2 轮断货。
4. 再次恢复到库存大于 5，完成第 2 轮返场。

示例：

```text
库存0 -> 库存8：第1轮返场
再次库存0 -> 库存12：第2轮返场
再次库存0 -> 库存20：第3轮返场
```

每轮分别计算自己的：

```text
断货日期
返场开始日期
断货前销量
返场后销量
恢复率
阶段
退出日期
```

### 页面只取最新一轮

虽然系统能够识别多轮，但当前页面、汇总卡片和标签统计只取：

```text
每个 MSKU 最新一轮已经完成的返场记录
```

旧轮次不再参与当前状态汇总，也不会在主明细中重复展示。

轮次只保留在后台，供历史追溯。

### 再次断货但还没重新返场

如果产品已经完成过一轮返场，后来又断货，但还没有重新恢复到库存大于 5：

```text
新一轮返场记录尚未生成
页面暂时仍展示上一轮完整返场记录
```

等库存再次恢复到大于 5 后，才生成新一轮记录，并替换页面上的上一轮。

## 6. 返场天数怎么计算

返场开始当天是 D1：

```text
返场天数 = 统计日 - 返场开始日期 + 1
```

例如返场开始日期为 7 月 1 日：

| 日期 | 返场Day |
| --- | --- |
| 7月1日 | D1 |
| 7月2日 | D2 |
| 7月7日 | D7 |
| 7月8日 | D8 |
| 7月21日 | D21 |
| 7月22日 | D22 |

产品退出以后，返场天数停留在退出日，不再继续增加。

## 7. 观察期怎么判断

观察期：

```text
D1-D7
```

也就是返场开始后的前 7 个自然日。

观察期主要关注：

- 产品是否开始出单。
- 返场后的累计销量。
- 与断货前相同天数相比，销量恢复了多少。
- 是否出现返场后仍然没有销量。

例如产品当前位于 D4：

```text
返场后对比销量 = 返场后 D1-D4 总销量
断货前对比销量 = 断货日期前 4 天总销量
销量恢复率 = 返场后 D1-D4 总销量 ÷ 断货前 4 天总销量
```

观察期不会因为恢复率低直接退出。

## 8. 运营干预期怎么判断

运营干预期：

```text
D8-D21
```

进入 D8 后，说明产品已经完成前 7 天观察，但还没有到最终的 D21 判断日。

这个阶段继续按照相同天数比较。

例如产品当前位于 D10：

```text
返场后对比销量 = 返场后 D1-D10 总销量
断货前对比销量 = 断货日期前 10 天总销量
销量恢复率 = 返场后 D1-D10 总销量 ÷ 断货前 10 天总销量
```

例如：

```text
断货前10天销量 = 100
返场后D1-D10销量 = 60
销量恢复率 = 60 ÷ 100 = 60%
```

运营干预期内的恢复分层：

| 销量恢复率 | 说明 |
| ---: | --- |
| >= 70% | 当前恢复达标，但仍观察到 D21 |
| 50%-70% | 恢复不足，需要继续动作和补量 |
| < 50% | 严重低恢复，需要重点干预 |
| 空 | 断货前对比销量为 0，暂时无法计算 |

产品在 D8-D21 即使已经达到 70%，也不会立即退出；仍要完成 D21 的固定观察周期。

## 9. D1-D21恢复率的统一公式

返场未满 21 天时：

```text
恢复统计天数 = 当前已返场天数
```

返场达到 21 天时：

```text
恢复统计天数 = 21天
```

统一公式：

```text
销量恢复率
= 返场后相同天数总销量
÷ 断货前相同天数总销量
```

不同返场天数的例子：

| 当前返场日 | 断货前销量范围 | 返场后销量范围 |
| --- | --- | --- |
| D3 | 断货前3天 | 返场后D1-D3 |
| D7 | 断货前7天 | 返场后D1-D7 |
| D10 | 断货前10天 | 返场后D1-D10 |
| D21 | 断货前21天 | 返场后D1-D21 |

这里使用的是总销量，不使用可售日销。

如果断货前相同天数销量为 0：

```text
恢复率 = 空
```

不能直接除以 0，也不能自动认定为达标。

## 10. D21怎么判定

D21是固定观察期的最后一天。

计算：

```text
D21恢复率
= 返场后D1-D21总销量
÷ 断货前21天总销量
```

### D21恢复率达到70%

条件：

```text
D21恢复率 >= 70%
```

结论：

```text
达标退出
```

当前规则是在完成 D21 后，于 D22 退出：

```text
D1-D21：仍处于返场观察和干预流程
D22：达标退出，不再继续追踪
```

### D21恢复率没有达到70%

条件：

```text
D21恢复率 < 70%
```

结论：

```text
不退出
D22开始进入持续干预
```

当前没有“满21天未达标就强制退出”的规则。

### 断货前21天销量为0

此时无法计算 D21恢复率：

```text
D21恢复率 = 空
```

产品进入：

```text
数据不足持续关注
```

当前不会自动退出。

## 11. D22以后怎么持续干预

只有以下产品进入 D22 后持续干预：

```text
D21恢复率 < 70%
OR D21恢复率为空
```

D21已经达到 70% 的产品不进入持续干预。

### 先固定断货前基准

断货前基准固定使用：

```text
断货前21天总销量
```

换算成基准日销：

```text
断货前基准日销
= 断货前21天总销量
÷ 21
```

这个基准后续不再变化。

### 再计算返场后的累计平均销量

```text
返场后累计平均销量
= 返场开始至当前统计日累计销量
÷ 当前已返场天数
```

### 当前累计平均恢复率

```text
当前累计平均恢复率
= 返场后累计平均销量
÷ 断货前基准日销
```

等价公式：

```text
当前累计平均恢复率
= 返场后累计销量 × 21
÷（已返场天数 × 断货前21天总销量）
```

### 具体例子

假设：

```text
断货前21天销量 = 210
断货前基准日销 = 210 ÷ 21 = 10
```

产品当前位于 D30，返场后累计销量为 180：

```text
返场后累计平均销量 = 180 ÷ 30 = 6
当前累计平均恢复率 = 6 ÷ 10 = 60%
```

这里的恢复率是 60%，不是：

```text
180 ÷ 210 = 85.7%
```

因为返场后已经经过 30 天，直接用累计总量相除会受到天数增长影响。

## 12. 持续干预怎么分层

D22以后，按照当前累计平均恢复率分层：

| 当前累计平均恢复率 | 当前状态 | 处理方式 |
| ---: | --- | --- |
| < 50% | 截至目前严重恢复不足 | 继续重点运营干预 |
| 50%-70% | 恢复提升中 | 继续观察和补量 |
| >= 70% | 21天后恢复达标 | 退出持续追踪 |
| 空 | 数据不足持续关注 | 人工核查，不自动退出 |

这些状态会随着后续销量每天重新计算。

例如产品在 D25 时恢复率为 42%，属于严重恢复不足；后续销量改善，到 D35 时恢复率达到 58%，就转为恢复提升中。

## 13. D21以后什么时候退出

D21未达标产品进入持续干预后，每天重新计算当前累计平均恢复率。

第一次满足：

```text
当前累计平均恢复率 >= 70%
```

就退出持续追踪。

记录：

```text
退出原因 = 达标退出
退出日期 = 恢复率第一次达到70%的日期
达标用时 = 返场开始日至退出日期的自然日天数
```

退出后：

- 返场天数停止增长。
- 返场后累计销量停止累计。
- 恢复率冻结在退出日。
- 后续销售数据不再改变本轮结论。

## 14. 近期稳定恢复和回落

这个指标只用于辅助判断近期趋势，不是退出的必要条件。

从 D22 开始，先计算单日销量门槛：

```text
单日销量门槛
= 断货前基准日销 × 50%
```

### 已开始稳定恢复

连续 3 个自然日的单日销量都达到门槛，认为已经开始稳定恢复。

```text
开始稳定恢复日期
= 首次满足连续3天区间的第1天
```

### 当前稳定恢复

截至统计日最近 3 个自然日都达到门槛。

### 恢复后回落

历史上曾满足连续 3 天稳定恢复，但最近 3 天不再全部满足。

缺失日期按当天销量 0 处理。

稳定恢复只说明近期趋势，最终退出仍以：

```text
当前累计平均恢复率 >= 70%
```

为准。

## 15. 再次断货怎么处理

当前规则不会因为返场后再次出现库存为 0，就立即把上一轮标记为“二次断货退出”。

当前处理方式：

### 再次断货但尚未恢复

```text
新一轮尚未形成完整返场记录
页面继续保留上一轮完整返场记录
```

当前断货问题由断货相关指标单独提示。

### 再次断货后重新恢复

当库存再次恢复到大于 5：

```text
生成新一轮返场记录
页面切换为最新一轮
上一轮仅保留作历史记录
```

## 16. 最终退出条件汇总

当前只有达标退出，没有“未达标强制退出”。

### 正常D21达标

```text
D21恢复率 >= 70%
-> D22退出
```

### D21后补恢复达标

```text
D21恢复率 < 70%
-> 进入持续干预
-> 当前累计平均恢复率首次达到70%
-> 当天退出
```

### 不会自动退出的情况

```text
恢复率持续低于70%
断货前21天销量为0导致恢复率为空
近期销量回落
再次断货但还没有重新返场
```

这些情况继续保留在相应跟踪状态中，等待后续恢复或人工处理。

## 17. 一页式规则摘要

| 环节 | 判断规则 | 结果 |
| --- | --- | --- |
| 断货开始 | FBA可售首次等于0 | 记录断货日期 |
| 返场开始 | 断货后FBA可售首次大于5 | 生成一轮返场记录，记为D1 |
| 多轮识别 | 再次0，随后再次大于5 | 生成新一轮，页面只取最新一轮 |
| 观察期 | D1-D7 | 相同天数销量对比，只观察不退出 |
| 运营干预期 | D8-D21 | 相同天数销量对比，执行运营干预 |
| D21达标 | D1-D21销量 ÷ 断货前21天销量 >= 70% | D22退出 |
| D21未达标 | D21恢复率 < 70% | D22进入持续干预 |
| 持续严重不足 | 累计平均恢复率 < 50% | 继续重点干预 |
| 恢复提升中 | 累计平均恢复率为50%-70% | 继续观察和补量 |
| 后续达标 | 累计平均恢复率首次达到70% | 当天退出 |
| 数据不足 | 断货前21天销量为0 | 持续关注，不自动退出 |
