# 广告与调价决策代码对照

这份文档按当前代码的真实判断顺序写。重点是输出可解释的建议，不把尚未接入的财务条件伪装成达标，不自动执行。

2026-10-10更新：广告效率采用固定ACOS分档，目标≤20%、上限50%。完整档位与边界见[固定ACOS分档与广告调整规则](07-固定ACOS分档与广告调整规则.md)，替代旧版利润倒推上限。

2026-10-12更新：零单止损统一为[成熟点击分档](11-零单广告点击分档简化规则.md)：不足20保持、20—39次降10%、40次及以上降20%；不区分日销，不计算CPA、参考金额或预算消耗。

同日更新：取消动作数量上限，保留同一价格／竞价对象的涨降互斥；见[数量与互斥规则](09-取消动作数量限制与涨降互斥规则.md)。

## 1. 先确定这个商品需不需要正常干预

`enrich()`只在本轮未退出、D≥8且满足需要处理的分支时计算国家广告和价格。主要分支为销量修复、恢复不足、利润风险、无销量、历史缺失、历史零销量和利润未知；恢复较好但当前退出角色有差距，也需要复核。

观察期、已退出、正常恢复且角色达目标、改善继续观察、库存缺失或连续断货，不因为存在某个历史建议就强制进入正常调整。

国家当前价<P10属于底线风险，可触发独立检查，但不能突破观察期、库存缺失和经营缺失边界。风险事实保留，不能说“已退出还继续生成本轮提价动作”。

有国家经营记录，但当前Listing没有、近7天没有访问也没有销量时，先核实该站点是否实际经营，不直接建议新建广告。

## 2. 广告判断需要哪些输入

| 输入 | 来源与用途 |
| --- | --- |
| `mapping_count` | 对象关联商品数，必须等于1才能按单个MSKU判断 |
| 活动／组／对象状态 | 任一paused则视为暂停；archived另行核查，不直接恢复 |
| `current_bid/default_bid` | 当前对象价优先，空或0可继承正的默认价；负数无效 |
| `days/mature` | 本轮返场后、完成7天归因、可用于判断的报表日与完整性 |
| `clicks/orders/cost/sales` | 同一对象成熟窗口合计，不用商品总体销售替代广告订单 |
| `dos` | 当前库存÷类别近7天日销；零销量时可用有效历史日销带提示估算 |
| `cost/sales`与固定ACOS分档 | 成熟对象广告花费÷归因销售额，固定目标20%、上限50%；不需要利润推导的`affordable_acos` |
| `zero_order_clicks` | 对象成熟点击数、0订单、20／40门槛、点击档位、试算标记和覆盖核验；无需参考价格或每单成本 |
| 预算及操作记录 | 真实可用余额、平台上下限、近期操作及复评，仍需核验 |

DOS不能算时保持未知，不能设一个很大值当库存无限充足。无货或库存未知日不作为广告评价日；日报缺失也不填0。

## 3. 没有广告、暂停广告、已归档

| 情况 | 输出 | 仍需核实 |
| --- | --- | --- |
| 对象快照成功读取，该经营国家没有对象 | `start_ad`建议开启广告 | 站点可售、有投放资格、没有遗漏活动、另设竞价预算 |
| 具体对象或上层活动／组暂停 | `restore`恢复已有广告候选 | 原因是否断货、原设置是否有效、库存预算与复评 |
| 暂停对象但DOS<14或未知 | `blocked`不能恢复试投 | 库存覆盖 |
| 关联多个MSKU或归属不明 | `check/pending` | 不能把公共对象订单全归给一个商品 |
| 对象已归档 | `check/pending` | 不是直接恢复归档对象 |
| 自动广告只有广告组汇总，没有匹配target | `check/pending` | 真实匹配方式、对象状态与竞价 |

恢复建议不生成虚构新竞价。无对象时没有历史竞价可供恢复，建议开启和恢复已有广告是两个动作。

## 4. 已投放对象的真实判断顺序

`rules.ad_candidate()`依次判断：归属 → 暂停 → 成熟归因 → 必要效果字段 → 无点击 → 零单／有单效率 → 竞价金额。

归因未成熟时，不因为0单直接止损。成熟0点击0单且数据完整时保持竞价，可另查资格、状态与同步；0点击但存在广告订单时先核对归因报表。成熟但样本不足且无其他错误时，归为“暂不调整，继续积累样本”。

### 4.1 提高竞价

同时满足：

1. 对象单一商品归属，状态允许投放，当前有效竞价可计算。
2. 成熟有效报表日数≥7，订单≥3，点击≥20。
3. 库存覆盖DOS≥7。
4. 对象ACOS≤20%时可积极拉量；20%<ACOS≤30%只允许主窗口日销不足1件的销量修复小步拉量；超过30%不加竞价，低日销也不能绕过。
5. 在`enrich()`外层再次检查：非低日销商品只有恢复不足且近期利润安全条件通过，才能保留正向加投；利润风险不加投。

**ACOS≤20%且DOS≥14时＋10%；DOS7至不足14时最多＋3%。20%<ACOS≤30%的低日销修复要求DOS≥14，幅度＋3%。**均需至少7个成熟报表日、20点击、3单。10%—20%也为＋10%，不再用＋5%。

还要核实真实预算、批准花费、竞价平台上下限和近期操作，故通常是`pending`而非`ready`。

### 4.2 有订单但广告低效

成熟报表≥7天、订单≥3：40%<ACOS≤50%候选降低10%，ACOS>50%候选降低20%。这里不像加价分支另要求20次点击；不要人为把两个分支条件合并。

低日销只豁免利润门槛，仍服从固定ACOS分档；30%以上不加投，40%以上先控费，不能因为需要拉量忽略超限。

20%<ACOS≤30%非低日销保持；30%<ACOS≤40%均保持。恰为40%不降，恰为50%降10%，严格超过50%才降20%。有订单但归因销售额≤0则ACOS不可算，不设为0%。

### 4.3 成熟零单止损

对象归因成熟、0订单、日期覆盖可靠：点击0—19次保持，20—39次候选降10%，40次及以上候选降20%。不另加7个报表日要求，日销不足1与正常日销统一，不以花费、CPA、价格或预算消耗决定幅度。20／40和10%／20%均为试算参数。

逐关键词、逐具体自动target统计，不把广告组或其他对象点击加进来。报表缺日期、订单或点击缺失、多商品对象时待核，不补0；零单但归因销售额>0先核查。暂停／归档另判，目标金额仍需有效竞价与可靠币种。预算只作资金限制，不决定零单竞价方向。

点击档位通过后仍核验保护、其他归因订单、真实操作及平台范围；有金额不等于可执行。实际调整后用新成熟数据复评，不能拿同一旧窗口每天重复下调。缺每单成本不再作为零单不可判原因。

## 5. 有效竞价和取整

```python
effective = current_bid if current_bid > 0 else positive_default_bid
raw = effective * (1 + change_rate)
```

以币种最小单位取整：加价向下取整避免超幅度，降价向上取整避免多降；取整后必须>0且不同于当前价。七国常用0.01。

例：0.50提高3%为0.515，按0.01向下取0.51；0.50降低10%为0.45。若0.08提高3%仍取0.08，转为无法生成有效变化金额，不伪造0.09并称仅涨3%。

当前记录`change_rate`可能为名义调整比例，实际比例应从目标／当前−1计算展示。接手前端不能把名义3%当金额取整后的精确涨幅。

## 6. 预算建议

只有样本与经营准入通过、对象ACOS≤20%、DOS≥14且`budget_limited_verified=True`，才能把加竞价分支替换为申请预算；两者不是同一对象一起加。20%以上不新增预算。

```python
configuration_cap = min(monthly_budget * 0.10, weekly_budget * 0.25)
normal_target = min(configuration_cap, verified_pool_remaining, verified_profit_capacity)
sales_repair_target = min(configuration_cap, verified_pool_remaining)
```

月或周配置≤0／缺失时不能给统一兜底金额。缺真实池余额或非低日销时缺利润容量，保留待核且不生成金额。低日销只豁免利润容量，不豁免真实余额。

`allocate_budget()`可在已验证余额上按批次占用，逐条递减，避免同池重复分配；但当前`enrich()`没有自动调用它，远端取数也没有提供真余额，不能声称现有预算已经做完批次联合核验。

`ad_for_country()`不再按动作计数限制建议。每个符合条件的对象均保留，排序优先止损，不截取前几条；同对象重复采集去重、相反方向合并为核查，不同对象可以不同方向。实际预算、库存和复评条件独立生效。

## 7. 先广告后价格，具体是什么意思

每国家先计算广告结果，再独立计算价格候选；随后`order_country_suggestions()`决定哪些价格只能留作后续试算。

| 广告结果 | 价格怎么处理 |
| --- | --- |
| 有开启／恢复／加减竞价／申请预算的具体有效金额候选或状态候选，且ready或pending | 优先核验广告；已命中的价格加`deferred=True/defer_type=ad_priority`，不计“可审核调价” |
| 只是广告数据缺失、归因未完成或利润依据缺失，没有具体适用动作 | 独立审核价格，不用广告缺数单独挡住价格 |
| 已明确无适用广告动作、样本不足保持或广告受限 | 独立审核价格；价格自己仍需库存、档位、利润及复评条件 |
| 价格自身已blocked | 保留价格限制原因，不覆盖成广告优先 |

“优先核验广告”不代表已经操作，不代表处于广告复评等待期。只有真实操作记录才能支持“已调整，等待复评”。当前完整广告操作日志未接入，不能从旧建议推定已执行。

## 8. 价格判断先后顺序：不能只列涨价和降价公式

`price_candidate()`顺序决定哪条分支先命中：

1. 已退出或D<8：保持。
2. 当前价无效：待核当前Listing。
3. 当前价<P10：底线修复升至P10优先。
4. 主窗口日销不足1件：看国家转化是否下滑，成立则候选降一档，否则保持。
5. 非低日销，国家近7天数据或利润不可算：待核，未定涨降方向。
6. 国家有销量且近7天毛利率<5%：核实低价原因后候选升一档。
7. 商品近7天角色至少潜力，或D<14且主状态恢复较好：保持。
8. 国家日销1—5且毛利率≥5%但<10%：候选升一档修复角色差距。
9. 恢复不足或适用低销量情况：满足毛利余量、流量和转化条件才候选降一档。
10. 其他：保持并解释未命中的条件。

第7项保持仍用`event.recent`近7天角色，提价／利润仍用国家近7天指标；仅降价转化样本改用`price_comparison`对应N／21／30窗口。不能把价格所有分支都写成同一窗口。

## 9. 哪些商品可以候选降价

在某国家同时满足：

- 当前国家访问和销量按D8—D21返场N天、D22—D29最近21天、D30起最近30天统计，完整有货、销量访问非负。
- 同国家本轮断货前有效30／14天基准完整有货、访问>0、历史销量≥5件，不再要求50次。
- 动态访问门槛＝向上取整（3×历史访问÷历史销量）；当前预期销量＝当前窗口访问×历史销量÷历史访问，至少3件才进入判断。
- 当前实际销量严格小于预期销量的70%才进入候选，等于70%不通过。公式和证据见[12规则](12-降价动态访问门槛与对应窗口规则.md)。
- 库存覆盖≥14天。
- 当前价和完整档位可计算、币种一致、阶梯正常，可以生成向下相邻金额且不突破P10。
- 未命中正常调价7天间隔限制。

主窗口日销不足1件时暂不要求利润余量，先修复销量。非低日销的恢复不足分支要求国家订单毛利率≥10%，还要核验调后预测利润≥5%。

未达到动态访问门槛表示继续观察，不表示价格正常；基准或对应窗口缺数待核，不用近7天或50次兜底。历史只有4件仍不通过5件样本保护。3件和70%为试算参数，不证明价格造成销量差。

“现在降价卡片0”可能有两种原因：没有任何国家命中方向，或命中但被库存、P10、近期真实调价、广告优先等限制。必须保留候选及限制，不能只返回最终0。

## 10. 哪些商品可以候选提价

| 分支 | 候选方向 | 仍需核验 |
| --- | --- | --- |
| 当前价<P10 | 升至P10 | 价格底线风险，不能把缺数据当已达标 |
| 非低日销，国家毛利率<5%且有销量 | 升相邻档 | 低售价是否真是利润缺口原因，而非成本或广告异常 |
| 非低日销，日销1—5、毛利率5%至不足10%，未被前面的保持分支截获 | 升相邻档 | 角色差距原因、成本广告、预测利润 |

不因“返场”统一提价，不把国家类别下所有国家一起提价。涨价必须有具体国家金额、币种、档位和原因。

## 11. 逐档金额怎么计算

P10/P15/P20/P25/P30/P35是一条站点价格阶梯，档位编号不是涨价百分比。

| 当前价格位置 | 下调 | 上调 |
| --- | --- | --- |
| 恰好P20 | P15 | P25 |
| P15与P20之间 | P15 | P20 |
| 恰好P10 | 禁止继续降 | P15 |
| 低于P10 | 不再向下 | 先审核到P10 |
| 恰好P35 | P30 | 禁止继续升 |
| 高于P35 | 先到P35 | 禁止升 |

所有六档都必须存在且严格递增，即使只需要P20→P15，也不能跳过未核实的其他档位。目标按币种单位向上取整，取整后仍须在P10—P35内且发生真实方向变化；失败则受限。

实际涨跌幅＝目标金额÷当前金额−1。相邻档价差大于5%也按实际档位展示，不截断到中间价。

## 12. 调价复评与例外

上一成功实际调价到评价日不足7天，正常下一次调价`blocked`。没有记录是操作待核，不能假设间隔通过。

当前价<P10或非低日销且毛利率<5%的风险，未满7天可列单独人工审核，不自动执行例外。降价拉量依然受正常7天间隔限制。

代码使用自然日期差，不知道完整生效时段；执行时间靠近当天结束时，日期差等于7不等于已经有7个调后完整日。接手方要确认最终复评日期口径。

## 13. 达标状态不是方向本身

| 状态 | 条件 | 如何展示 |
| --- | --- | --- |
| ready | 所有必要数据和检查已确认通过 | 条件已满足，仍属于建议层 |
| pending | 金额可候选但存在未知检查，或方向尚不能判断 | 逐项列待核，不计达标 |
| blocked | 已知库存、档位、间隔、利润等限制失败 | 暂不调整并显示具体限制 |
| hold | 正常恢复或未命中动作条件 | 保持并说明依据 |

`review_checks()`提供False→blocked、None→pending、全True→ready的通用计算。当前主流水线未接上完整核验值，多数建议默认pending；不能只因为算出目标金额就改成ready。

## 14. 固定ACOS、零单点击分档、真实余额与预测利润

有单效率固定目标20%、上限50%。零单按对象成熟点击分档，正向动作真实余额与预测利润仍需核验：

```python
acos = mature_cost / mature_attributed_sales  # 归因销售额须大于0
acos_target, acos_max = 0.20, 0.50
zero_order_change = -0.20 if mature_clicks >= 40 else (-0.10 if mature_clicks >= 20 else 0)
# 仅用于成熟0单对象；不计算零单ACOS或成本额度。
real_pool_remaining = pool_cap - incurred_spend - future_base_reserve - committed_extra
forecast_margin = (forecast_revenue - forecast_non_ad_cost - forecast_total_ad_spend) / forecast_revenue
```

必须同站点、同币种；税费退款与收入分母一致；非广告成本不重复含广告费；预算预留与承诺不能重叠重复扣减。负余额不当可用资金，缺一项不填0伪装有确定值。

价格档位隐含成本并不等于真实销量预测，不可用“调后到P15所以毛利必然15%”替代联合预测利润。当前预算与预测信息未完整实现，代码会保留待核；不得向接手方声称这些公式已经有可用源表支持。
