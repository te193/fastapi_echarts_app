# 接手开发步骤与验收清单

这份清单把“已有代码能计算什么”和“接手方还要开发什么”分开，不以测试通过推定整个远端页面已经上线。

最新要求为**数据表交付，不做页面**。本文件的页面展示案例仅保留为原规则参考；必须实施的落库与验收以[06-数据表交付与落库验收要求](06-数据表交付与落库验收要求.md)为准。

## 1. 接手后按这个顺序开发

### 第一步：核对连接和源数据

复制独立代码，安装依赖，配置外部只读账号；核对全部远端表字段。先运行CJ057b等单商品，确认日期、币种、库存合计、订单利润与去重，再扩大范围。

拿同一业务日期、同一设置日期比较；不能拿今天更新后的远端数据强求等于几天前页面旧批次。必要时分别列源修订、补数、清洗差异、规则差异和候选范围差异。

### 第二步：建立完整候选和批量取数

从库存表枚举商品，不从旧返场池抄全集。读取足够长历史，构建最新事件；共享库存按国家类别合并。用稳定分片保证不同批次漏数、重复和失败可追踪。

将单商品适配函数扩展为批量查询或流式分组；复用Listing、档位、预算和对象数据，避免逐商品重复计算全库广告共同日期。SQL性能优化应先解释执行计划，不通过改变业务粒度换速度。

### 第三步：发布完整计算结果

按依赖顺序：库存及经营完整日 → 当前设置及日报 → 独立事件 → 恢复和退出 → 广告价格 → 专用结果表落库。

结果要有计算日期、设置日期、规则版本、批次成功状态、质量警告、每商品summary/detail。只在所有需要的数据读取和计算成功后发布；失败保留上一成功批次并说明日期及失败提示。

本包当前只有JSON输出，接手方必须实现数据库结果持久化。源只读连接和结果写入连接分离，禁止源表写回；消费端只查询成功批次，本轮不开发消费页面。

### 第四步：补首次退出持久化

同一事件优先保留已确认首次退出及目标、基准、证据。纯计算重放能给当前数据下的首次日期，但源修订可能改变历史，不等于不可变事实。

兼容规则版本才沿用退出；发生规则目标变更时明确回算迁移策略。新一轮事件另建，不能覆盖旧事件。

### 第五步：核对结果表字段与查询

按06文档落商品结果和国家对象建议，提供观察／干预／提前退出／常规退出、可调价、广告受限和待核原因的查询样例。

观察期结果记录阶段和不干预原因，仍保留库存与利润事实；建议明细记录当前金额、目标金额、限制及待核项。

不开发页面、HTTP路由或浏览器交互。用数据库读回结果验收，不能只返回JSON文件。

### 第六步：接上财务与操作核验

有单ACOS按固定分档；零单直接按成熟点击20／40分档，不需要Listing参考金额或每单成本适配。提供对象成熟窗口、覆盖、点击档位、真实操作复评证据；正向动作真实余额与联合预测利润仍需核验。

这些值不能用“月预算还很大”“已经有建议”“档位P15”替代。接完后再调用达标核验函数推进pending→ready，并检查同池批次占用。仍然只给建议，平台执行不在本轮范围。

## 3. 已知实现限制，不能被文档掩盖

1. **旧版真实样例包含远端缺数。**2026-10-10只读取数时，CJ057b的10月1日库存及GZ012a的部分主窗口库存未齐。这是历史样例记录，不是交接当天重新查库的结论；接手时先复查，不能因本机曾补数就断言远端已补。
2. **当前表不等于历史快照。**旧样例查询到10月10日Listing记录，不支持倒填10月8日；广告对象与target也可能缺早期版本。真实源表可能已更新，须按目标评价日核对。
3. **多次库存采集保守标缺失。**需要接手方确认完整批次粒度，不能永远误判所有多仓库时间差为缺数。
4. **经营去重键须验证。**当前以日、原店铺、原MSKU、国家、ASIN和本地SKU选最新版本；真实多明细不能被错误覆盖。
5. **只校验日内财务币种。**跨日币种改变还需全窗口检查及可靠汇率换算。
6. **国家集合来自经营历史。**只在Listing或对象上存在的经营站点可能漏出详情，需要补实际经营站点定义。
7. **价格部分保持条件仍用近7天。**退出用主窗口，不代表价格每个判断也主窗口化。
8. **竞价幅度先分档再受DOS限制。**有单按固定ACOS，≤20%＋10%且DOS7—13天压至＋3%；零单所有日销统一20—39点击降10%、40次及以上降20%。不是按报表天数决定幅度。
9. **动作数量不设上限。**所有达标对象均保留；同一价格或竞价对象涨降互斥，不同对象方向可不同。实际资金、库存、复评及去重仍核验，不设置隐性名额。
10. **财务达标未自动核验。**月周预算配置已接入，但真实池余额、完整操作记录和预测利润仍缺核验，多数动作仍pending。零单已按点击分档，旧预算对比不参与现行竞价。
11. **预算不重复分配函数尚未接主线。**`allocate_budget()`存在不等于真实批次已经分配过。
12. **广告日报完整日期仍须分对象验证。**有单分支按实际出现且有货的报表日计数；零单须单独核对该对象窗口内全部有货日期和库存记录，`zero_order_coverage_verified=False`不能确认为零单；其他对象不改变它的点击档位。缺日期不能补0。
13. **价格日期差不等于完整生效日数。**需要明确调价晚间完成的7天复评口径。
14. **底线风险与卡片可能不完全一致。**`enrich()`可给恢复较好商品生成P10底线核查，但`decision_branches()`对非通常干预分支不展示常规价格分支；接手方应单独检查底线风险入口。
15. **原页面与远端包不是已切换同一数据链。**两套来源可能产生不同缺数和数量；交接包可运行不等于生产页面已迁移。

这些是当前代码审阅得出的限制或待接入事项，不是擅自新增业务门槛。改变业务判断应更新规则版本，并用同日期对照验收。

## 6. 页面统计验收

每个计数同时核对筛选返回的event_id集合，不只验证数字。

- 阶段四类相加等于总事件；两个年龄段分布各自等于观察或干预总数。
- 第一步互斥经营分类相加等于干预期；零销量拆分不重复计。
- 第二步综合广告结果一个商品一个值，具体动作分布可以重叠。
- 第三步可审核价格不纳入广告优先暂缓或自身blocked；升降方向可在不同国家重叠。
- 原因折叠展开、点击原因，主表联动准确；不重复展示第二份商品表。
- 观察期和已退出不纳入干预卡片；已退出按提前／常规显示。
- 近30天无单不写返场75天一直无单；缺早期销量不推断至今未出单。
- 原始断货前每日表现可查看，历史基准为空时仍显示有记录部分。
- 一条国家动作不能被显示成整类别所有国家执行；缺金额不能出现0元。

## 7. 真实样例与测试记录

交接时在独立`代码`目录隐藏后台运行`python -m pytest tests -q`，包含纯规则、数据统计、远端适配及固定ACOS档位回归。最新数量以实际日志记录为准；旧76项是前一版基线，测试不执行平台动作。

| 样例 | 已核实结果 | 解释 |
| --- | --- | --- |
| CJ057b／CHOOJEE／欧洲站，业务日10月8日 | 8月30日断货，10月4日恢复，D5，跟踪 | 断货前8月有库存不矛盾；那是断货前，不是断货期间 |
| GZ012a／Gangzhh／欧洲站，业务日10月9日 | 远端重建最新恢复7月29日，D73，库存缺失 | 数据来源不同，不直接套旧本机数量或完整性 |

样例是2026-10-10上一轮远端只读运行保留的结果，交接包另用其回放页面统计；不把它们当当前全量数量。接手方部署时重跑完整日期并解释差异。

交接目录附代码来源、校验和、源表字段及样例。测试和结构检查不证明阈值最优或调整已经带来收益；最后交付边界仍为“计算建议与解释结果”。
