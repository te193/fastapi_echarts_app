# 页面统计筛选与输出字段

页面的数据展示不是把建议行相加。其规则在[presentation.py](代码/return_goods_data/presentation.py)，不需要HTTP服务即可复现统计和筛选。

最新交付为数据表，不做页面。本文件保留为结果字段和统计口径参考，页面展示、折叠、联动、动作列等不是本轮开发要求；落库按[06文档](06-数据表交付与落库验收要求.md)。

## 1. 输出分成计算结果和页面结果

```python
result = calculate(store, msku, data_date, settings_date)
result['products']  # 每个最新事件的summary和detail
result['page_data'] # 默认跟踪清单及全阶段卡片统计
```

批量时先合并商品事件，再统一调用`prepare_page_data()`。不能把多个单商品`page_data`直接求和当全量统计，原因分组、筛选条件和去重键必须统一。

外层字段：`rule_version/data_date/settings_date/scope/source/database_writes/warnings/products/page_data`。经营、设置来源日期和失败提示要能直接展示，不让用户把旧结果当最新。

## 2. 商品主表字段

| 字段 | 含义及来源 | 展示要求 |
| --- | --- | --- |
| `event_id` | 店铺、类别、MSKU、断货首日、恢复日组合的SHA1 | 明细关联键，不按MSKU单独查另一轮 |
| `seller_name_new/country_category/msku/local_sku` | 商品身份 | 三维事件去重，本地SKU辅助搜索 |
| `stockout_date/return_date/age/phase` | 断货、恢复、D几、时间阶段 | 已退出按退出状态归类，不再次计入干预 |
| `state/state_label/state_reason` | 一个主经营判断及原因 | 时间阶段与经营判断分列 |
| `recent_days/comparison_start/comparison_end` | 当前N／21／30主窗口 | 明确日销和利润究竟是哪段时间 |
| `historical_daily/recent_daily/recovery` | 同长度销量比较 | 缺数显示空，不用横线代表真实0 |
| `margin/role` | 当前主窗口订单毛利率和角色 | 百分比用合计相除，展示取整不影响判断 |
| `trend7` | 近7天对前7天的日销和利润变化 | 提醒，不能自动触发动作 |
| `exit_target/exit_status/exit_date` | 目标、未退出／提前／常规、首次日期 | 不能只显示是否退出而漏掉路径 |
| `exit_reasons/confirmation_days` | 所有差距和0—3天进度 | 主表摘要，详情展示全部 |
| `no_sales_scope/no_sales_previous_sales` | 全返场零销量还是窗口零销量 | 不把近30天无单说成75天从未出单 |
| `ad_result/ad_result_label` | 商品广告综合判断 | 观察期动作栏覆盖为“处于观察期，暂不进行人工干预” |
| `ad_diagnostic_reasons/ad_limit_reasons` | 对象异常／缺数／限制原因合集 | 折叠后仍能点击筛选对应商品 |
| `candidate_actions` | 至少存在一条ready或pending的具体方向 | 包含后续价格候选，不能当当前可调价 |
| `price_review_actions` | 不暂缓的价格方向集合 | 用于第三步“审核升／降一档” |
| `price_wait_ad/price_can_review` | 是否全部候选暂缓、是否有可审核候选 | 国家可能不同，商品不只有一个统一价格状态 |
| `ready_count/pending_count` | 商品的建议条数 | 顶部按是否>0转换为商品数 |
| `suggestion_summary/priority` | 当前建议摘要及排序 | 优先显示当前动作，不把暂缓价格当立即调价 |

金额采用Decimal计算，独立包JSON金额以字符串保存精度。接手界面可使用明确的数字转换展示，但不可用前端低精度反向决定角色或金额。

## 3. 阶段卡片及分布

`stage_of()`先判断退出，再判断时间阶段：

```python
if exit_status != 'tracking':
    stage = exit_status  # early或normal
else:
    stage = 'observe' if 1 <= age <= 7 else 'intervene'
```

阶段恒等式：

- 全部最新事件＝观察期＋干预期＋提前退出＋常规退出。
- 跟踪中＝观察期＋干预期。
- 已退出＝提前退出＋常规退出。
- 观察期D1—D7的分布相加＝观察期总数。
- 干预期D8—D14、D15—D21、D22—D30、D31—D60、D61以上分布相加＝干预期总数。

分段D22—D30是展示年龄分组，不意味着D30仍用21天窗口。窗口由`comparison_days()`单独决定。

概览“条件已满足的建议”按`ready_count>0`的商品计数；“待核建议”按`pending_count>0`计数，同商品两种可以同时存在，不能把两个数字相加当处理商品总量。

## 4. 三步卡片怎样计算

### 第一步：自然恢复情况

只纳入D≥8且未退出，每商品一个主状态。恢复较好、改善中、恢复不足、销量修复、利润风险、历史不足、历史零销量、数据缺失、库存缺失、库存中断、利润未知和两种零销量分支组成互斥分布。

`no_sales`展示拆为`no_sales_since_return/no_sales_window`，计算总数时不能再加一遍未拆分`no_sales`。

历史旧批次有`unknown`时单独保留。缺数原因列表可能重叠，但主状态只能一个。因此第一步分类之和应等于同口径干预期总数。

### 第二步：广告结果

`display_ordered_suggestions()`收集七国全部对象结果，按商品输出一个综合广告结果：

1. 至少一个具体广告候选，状态ready或pending：`adjust`。
2. 否则至少一个广告核查pending：`unknown`。
3. 否则至少一个广告blocked，或库存缺失／中断：`limited`。
4. 否则有广告保持记录：`hold`。
5. 没广告建议且处于正常恢复分支：`no_need`；其他仍未知。

顺序有意义：同一商品德国有受限对象、法国有无法判断对象，综合可能归unknown；德国受限明细仍须保留，不能丢掉。

“开启广告、恢复广告、提高竞价、降低竞价、申请预算”是下方动作分布，一个商品可在不同国家有多个动作。其数量不可相加当广告商品总数。

### 第三步：当前可审核价格

- 有具体price_up／price_down且ready或pending、`deferred`不为真：进入相应审核卡片。
- 所有价格候选都广告优先暂缓：进入“优先广告，暂缓价格”。
- 自身blocked不进入可审核卡片，详情保留方向、目标和限制。
- 仅缺当前价、档位或币种：保留核查，不变成升／降一档。

一商品不同国家同时升和降，会同时命中两个方向；因此第三步不能直接相加。三步描述的是同一批商品不同判断层，也不能把第一步、第二步和第三步合起来。

## 5. 折叠原因怎样与清单联动

`ad_reason_details()`把商品的综合受限或无法判断原因转换为稳定键：

```python
key = 'ad_reason_' + sha1((category + '|' + reason).encode()).hexdigest()[:16]
```

`filter_payload()`把原因键加入该商品`decision_branches`，生成`ad_reason_groups`：原因、数量、对应商品身份。卡片默认折叠，点击原因设置`focus=原因键`，下面清单只显示该原因命中的商品。

同一商品可以多个原因，一个原因对一个商品只算一次；原因数量不相加。无需在每个原因下再展开一份重复商品表，主表联动即可。

库存缺失受限原因描述为快照缺商品记录；库存中断区分当前仍断货、已经恢复少量库存或当前库存未知。若源数据只证明部分日期缺失，详情应列真实日期，不能笼统要求“先补数据”替代广告判断。

## 6. 筛选作用域及数量为什么变化

函数先形成`base`：国家类别、店铺、商品关键词、经营判断、建议动作类型；阶段卡片、概览和三步数量在这份基础范围上算。

随后才对明细追加：退出状态、阶段、年龄段、focus分支、ready／pending建议类型、分页。

这样点击“干预期”或“某个原因”时，卡片仍显示完整基础范围，用户知道筛选在整体中占多少；不能随着点击把所有其他卡片归零。

`recommendation`在当前实现中也是明细筛选，未加入base；若接手方希望顶部数字随建议类型变化，应明确改统计作用域并验证，不能只改文案称已经联动。

`all_rows=True`返回筛选后全体清单，排序和列筛选才能由AG Grid作用于完整结果。服务分页后让前端只排序一页，会产生“产品去哪了”和数量错觉。

## 7. 商品详情顺序及字段

### 先解释为什么未退出

展示目标角色、当前主评价起止日、日销、订单毛利率、角色、连续确认进度、所有缺失日和无货日。已退出显示首次日期、路径、退出窗口、三个常规确认窗口或D7依据。

对应字段：`baseline/exit_target/current_evaluation/exit_status/exit_date/exit_reasons/exit_evidence/exit_confirmation`。

### 再展示国家广告和价格建议

`countries[]`每条包含：国家、`recent`近7天、`historical`基准窗口、`price_comparison`的当前N／21／30与历史30／14天国家样本、Listing、完整ladder及日期、预算配置、suggestions。

降价建议的`price_conversion`保存`required_sessions/expected_unit_target=3/expected_qty/conversion_ratio/enough_visits/weak_conversion`、当前／历史窗口起止与天数、访问销量、试算标记和状态原因。用于直接解释“还差多少访问、应卖几件、实际卖几件”，见[12规则](12-降价动态访问门槛与对应窗口规则.md)。

零单建议的`zero_order_clicks`保存成熟点击、0订单、点击档位、20／40门槛、试算标记及覆盖核验。`stats`保留对象窗口和日报；不再输出零单成本额度或预算比较。完整协议见[零单点击规则](11-零单广告点击分档简化规则.md)。

建议字段：`kind/action/label/status/reason/checks/current/target/currency/change_rate/tier/source_date/last_change_date/deferred/defer_type/defer_reason`。

广告另包含`profile_id/campaign_id/ad_group_id/object_id/object_type/object_text/campaign/ad_group/stats/target_source_date`。恢复展示当前状态及建议恢复，不把null target渲染成0元。

同国家广告优先的价格放折叠“后续价格试算”；独立可审核价格正常显示。缺价、受限、保持都显示具体理由。

### 最后展示恢复过程及断货前表现

`pre_stockout`和`pre_stockout_timeline`是紧邻断货前30天的原始经营表现；`baseline`是最后有效历史角色窗口，两者可能日期不同，必须分清。

`comparison`保留对应长度历史与当前窗口；`timeline`保留D1至今库存、销量、毛利率、单日角色和完整性；`trend7`仅变化提醒。

缺失日走势图留空而非画到0，表格分别显示真实0和无记录。标题标明区间，避免把“断货前有库存”误读为断货期间有库存。

## 8. 必须保留的显示覆盖

当前原页面在动作列用时间阶段覆盖文字：跟踪且D1—D7显示“处于观察期，暂不进行人工干预”。独立统计包保留原始经营事实和数据字段，不在`state`中改掉利润风险；接手展示仍须实现该覆盖。

无需新增执行按钮或操作表单。结果层应支持解释、筛选及导出，任何ready都不是已经调用平台。
