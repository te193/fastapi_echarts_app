## 1. 代码与运行

交付代码：[远端取数与计算脚本](../../../scripts/return_goods_remote_decision.py)。在项目根目录执行：

```powershell
python -m scripts.return_goods_remote_decision --store CHOOJEE --msku CJ057b --snapshot-date 2026-10-08 --output outputs/return-goods-strategy/remote-decision-CJ057b.json
```

店铺和MSKU限定本次商品取数范围，日期显式指定，选完整经营日。可在批量任务中调用 `calculate(store, msku, cutoff, settings_date)`，逐商品计算。

只查询远端源表，输出本地JSON，不写业务表或结果表，不执行广告和调价。连接沿用现有数据库配置，文档及结果不保存凭据。默认设置日期等于评价日期；`--settings-date`不得晚于评价日期，历史评价不借用未来价格或广告设置。

## 3. 清洗和缺数

- 店铺取原名第一个连字符前的前缀；MSKU沿用现行逗号首段和长编码规则。商品粒度为店铺＋国家类别＋MSKU，动作落到国家和具体广告对象。
- 经营仅取开始与结束日期相同的单日数据。按日期、原店铺、原MSKU、国家、ASIN、本地SKU保留最新采集时间与ID版本，再汇总，避免重复同步累加。
- 同日同次库存采集的仓库行相加；出现多次采集或库存空值则保留缺失，不能相加或擅取最大值。
- 缺失日期、空值和真实0分别处理；缺库存不当断货，缺经营不当零销量。
- 币种无法统一时不计算类别利润，销量仍单独保留。脚本尚未接入汇率换算。
- 同日价格或档位不同的记录标冲突，不拼接虚构阶梯。
- 广告读取失败终止本次计算，不变成“该国家没有广告”。

日期过滤不等于完整历史还原：源表可能被后续修订，当前设置表也可能没有旧版本。缺旧快照时标缺失；不承诺还原当时已知数据。

## 4. 决策代码流程

```python
histories = read_history(conn, store, msku, cutoff, warnings)
listings, ladders, budgets = read_settings(conn, store, msku, settings_date)
ads = read_ads(conn, store, msku, cutoff, settings_date, warnings)

for country_category, rows in histories.items():
    days = evaluation_days(rows)
    events = rules.build_events(days)
    if not events:
        continue
    detail = rules.evaluate_event(days, events[-1], cutoff)
    summary, detail = enrich(
        detail, (store, country_category, msku), rows,
        listings, ladders, budgets, ads, cutoff,
    )
```

完整脚本还筛选最近180天内返场的最新轮次。纯规则复用[return_goods_strategy_rules.py](../../../app/services/return_goods_strategy_rules.py)，版本 `return-v14-20261012-dynamic-price-visits`。`enrich()`只做内存计算，绝不调用同模块会写数据库的`run()`。

## 5. 进入、恢复和退出达标

| 项目 | 判断条件 |
| --- | --- |
| 进入 | 连续3个完整自然日可售为0，之后首次恢复≥5件记D1；缺日不当0 |
| 历史角色 | 断货前最后有效完整有货30天，必要时14天兜底；毛利率不能算时不可判 |
| 恢复窗口 | D1—D21比较返场N天与有效历史N天；D22—D29用21天；D30起用最近30天 |
| 恢复判断 | 恢复率≥80%结合利润、角色、库存判断；日销不足1件优先销量修复，暂不以利润阻止加投或降价 |
| 观察期 | D1—D7处于观察期，暂不进行正常人工干预 |
| 提前退出 | D7时每天角色及7天整体角色均达目标，数据完整、每天有货 |
| 常规退出 | D8起每天按N／21／30天窗口判角色，连续3次达目标且窗口完整、每天有货；最早D10 |

退出目标：历史潜力、明星至少潜力；历史问题、瘦狗及不可判至少瘦狗。恢复率不是退出门槛。完整历史回放计算首次退出日期；本脚本不做不可变的数据库退出留档。

角色判断：

| 角色 | 日销及订单毛利率 |
| --- | --- |
| 明星 | 日销>5且毛利率>15%；或1≤日销≤5且毛利率>25% |
| 潜力 | 排除明星后，日销>5且毛利率≥5%；或1≤日销≤5且毛利率≥10% |
| 瘦狗 | 0<日销<1且毛利率>5%；或1≤日销≤5且5%≤毛利率<10% |
| 问题 | 数据可计算，未达到以上角色 |
| 不可判 | 日销或毛利率不能计算 |

详情保留实际窗口、每日表现、退出目标、连续达标进度及所有未满足条件。

## 6. 广告与价格的达标代码

广告、价格只判断德法意西荷英美七国。按自然恢复 → 国家广告对象判断 → 必要时价格审核计算。

广告使用`ad_for_country()`及`rules.ad_candidate()`：

- 无国家广告记录：建议开启广告，不虚构金额。暂停对象检查恢复原因、原设置和库存。
- 已投放对象只统计返场后成熟效果，多商品共用对象不按单个MSKU判断。
- 加竞价需要成熟观察≥7天、点击≥20、订单≥3。ACOS≤20%且库存覆盖≥14天候选+10%，库存7—13天最多+3%；20%<ACOS≤30%仅低日销修复且DOS≥14候选+3%；其他不加投。非低日销仍须经营利润安全。
- 有单且成熟≥7天、≥3单，40%<ACOS≤50%降10%，超过50%降20%；30%—40%保持。成熟零单统一按对象自己的点击判断：不足20保持、20—39降10%、40次及以上降20%；不区分日销，不需要价格、每单成本或预算比较。归因和日期覆盖、保护、有效竞价及实际操作仍核验。口径见[固定ACOS分档](../开发交接/07-固定ACOS分档与广告调整规则.md)及[成熟点击分档规则](../开发交接/11-零单广告点击分档简化规则.md)。
- 无点击、归因不完整、匹配缺失、归属不清分别解释，不视为广告正常。
- 不设国家、商品或批次的动作数量上限，达标对象全部保留；同价格或竞价对象涨降互斥，冲突合并核查，不同对象可方向不同。

价格使用`rules.price_candidate()`：

- 当前价向相邻档位调，一次一档，底线P10，涨价上限P35。
- 低日销先修复销量，满足流量、历史销量和转化下降条件可候选降价，暂不要求利润门槛。
- 降价条件：同国家断货前有效有货30／14天基准访问>0、销量≥5，计算卖3件所需访问；返场后N／21／30窗口预期销量≥3且实际低于预期70%，再审核降一档。不固定当前或历史50次访问；库存覆盖≥14天、P10、正常间隔和利润例外继续检查，见[动态访问门槛](../开发交接/12-降价动态访问门槛与对应窗口规则.md)。
- 利润风险可候选提价，仍需核实原因及限制。
- 实际已完成调价未满7个完整自然日，正常调价受限；建议记录不当作操作记录。
- 有具体可处理广告动作时优先广告，价格保留暂缓原因；广告只有缺数或无适用动作时独立审核价格。
- 缺当前金额、币种不一致、阶梯缺失或冲突时不生成虚构金额。

每项建议输出动作、状态、原因、当前金额、目标金额、涨跌幅、待核项和来源日期。`ready`为已达标、`pending`为待核、`blocked`为受限、`hold`为保持。待核不算达标。

## 7. 待接入财务门槛

以下是核验公式，不是本脚本已取到的数据，不填猜测值：

```python
affordable_cpa = net_sales_per_order - non_ad_cost_per_order - net_sales_per_order * 0.05
affordable_acos = affordable_cpa / net_sales_per_order
real_budget_remaining = budget_cap - incurred_spend - future_base_reserve - committed_extra
forecast_margin = (forecast_revenue - forecast_non_ad_cost - forecast_total_ad_spend) / forecast_revenue
```

统一币种、税费及退款口径，非广告成本不能重复包含广告费。预算配置和池总额不是余额，预留与承诺占用不能重复扣。缺真实余额不生成虚构预算金额；缺预测利润保留待核。
