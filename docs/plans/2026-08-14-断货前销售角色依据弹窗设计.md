# 断货前销售角色依据弹窗设计

## 目标

在标签看板“经营明细与问题定位”表格中，为已命中 20 前缀断货前销售角色标签的 MSKU 提供按需查看依据的入口。运营人员不需要阅读原始 JSON，就能快速确认何时断货、断货前经营表现、角色判定结果以及计算来源，同时保留原始 JSON 供审计。

## 交互

- 在“当前标签”后增加“断货前依据”列。
- 当前行存在所选周期的 2001–2004 标签时显示“查看明细”；没有依据时显示“暂无依据”。
- 点击后按需请求该 `data_date + country_category + store + msku + label_period` 对应的 `evidence_json`，打开居中大弹窗。
- 弹窗包含“断货时间线、断货前表现、角色判定、计算与来源、原始 JSON”五个页签。
- 支持右上角关闭、底部关闭、遮罩点击与 Esc 关闭；切换页签不重复请求。

## 数据口径

- 只读取父标签 20 的子标签 2001–2004，不使用站点维度父标签 21。
- 首屏表格接口不携带完整 JSON，避免列表响应膨胀；点击时通过独立只读接口获取。
- 接口原样返回 `evidence_json`，并补充标签、周期和 MSKU 身份字段。
- 前端从 `oos`、`window`、`metrics`、`matched_rule`、`calculation`、`source_sales_role` 渐进取值；缺字段显示“暂无”，不阻断弹窗。

## 视觉

- 采用已选第三版：约 960px 宽的居中弹窗，背景表格轻度变暗。
- 顶部为身份、角色、周期和四项摘要；中部页签切换；底部显示 schema/规则版本与操作按钮。
- 沿用现有蓝白色、紧凑字号、轻边框和状态色，不新增插画或重型阴影。

## 验收

- 只对存在对应周期断货前角色的 MSKU 提供可点击入口。
- JSON 字段完整、部分缺失和 JSON 字符串三种输入均能稳定展示。
- 所有新增自动化测试后台运行；浏览器验证使用 headless 后台模式，不抢占前台窗口。
