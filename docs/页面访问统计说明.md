# 页面访问统计

2026-10-26 10:04（北京时间）启用，观察满30天为2026-11-25。仅增加访问记录与统计页面，未调整ETL或业务计算。

入口：左侧「页面使用统计」，地址 `/page-usage`。

## 统计口径

- 覆盖18个现有业务页面及统计页，共19个页面，包含补货追踪、国家标签看板、调价日期等菜单外入口。
- 页面首次可见时上报一次；直接网址、菜单和浏览器后退返回均可记录。后台标签页等待变为可见后再记录。
- 同一匿名浏览器、同一页面、同一访问环境，30秒内重复打开只计一次；后端事务避免多标签页并发重复。
- 近7天/30天按北京时间自然日统计，包含今天。浏览器数为近30天去重编号数，活跃天数为近30天有访问的日期数。最近访问时间取所选环境的全部历史记录。
- 所有登记页面都展示，零访问在前；尚未满30天时标注「仅供观察」，不能单凭零访问停任务。
- 匿名编号存浏览器本地，不记录姓名、IP、商品、搜索条件或业务参数。同一人换浏览器/设备/访问域名或清理存储会形成不同编号；禁用存储时编号只在当前页面有效。因此浏览器数不等于人数。
- 页面内接口请求、筛选和数据定时刷新不增加访问量；打开HTML页面才采集。纯HTTP请求不执行脚本，不算浏览器访问。

## 正式与测试访问

默认只统计正式访问。8001端口、服务环境 `DASHBOARD_USAGE_ENV=test`、浏览器自动化标记及页面参数 `?usage_test=1` 均进入测试环境。

`?usage_test=1` 在当前标签页保持，后续跳转也标记测试；用 `?usage_test=0` 可恢复正式标记。自动化或8001端口仍然视为测试。统计页可以切换「正式访问 / 测试访问 / 全部访问」。此次验收均使用测试标记。

## 保存与维护

- 独立存储：`data/page_usage.sqlite3`，由网页服务读写，无新增每日ETL。该文件及SQLite WAL辅助文件已加入Git忽略规则，普通服务重启不会清空历史。
- 可通过 `DASHBOARD_USAGE_DB_PATH` 指定持久化路径；所有提供同一看板的本机进程应使用同一文件。不要用新路径覆盖一个月的观察历史。
- 时间取服务端北京时间，浏览器不能指定记录日期。统计按请求实时聚合。
- 上报独立异步执行，失败不阻塞业务页面；统计存储故障时统计页提示重试。统计页不加载无用的图表/表格第三方脚本。
- 页面清单在 `app/services/page_usage.py` 的 `PAGE_REGISTRY`。新增HTML页面时补登记；路由覆盖测试会检查清单与现有页面的一致性。
- 一个月后根据访问次数、浏览器数、活跃天数和实际业务频率筛选候选页面，再核查页面/导出/接口/任务的共享依赖，单独决策ETL停用。
