# 产品运营建议验收样例集（首批候选与确认模板）

## 1. 用途与当前状态

本文件为 [产品运营建议通用数据开发流程](2026-09-20-产品运营建议通用数据开发流程.md) 配套的验收夹具。新销售角色接入时，应复用“公共闸门夹具”，再补充该角色的路径、价格、广告和成本样例。

“候选样例”和“已确认样例”必须区分：候选样例由真实快照筛选而来，但在业务负责人确认预期输出前，不得被用作上线通过依据。已确认样例必须冻结日期、输入、预期产品表行、预期广告表行和确认人。

## 2. 确认流程

每个候选依次完成以下四步后才变为已确认样例：

1. 核验标签与广告为 `D-1`、成本/定价/库存/预算为 `D` 的固定节奏，并确认 DWD FBA 明细的期末库存/可售 DOS 映射。
2. 固定 `data_date`、`strategy_scope` 与 `rule_version`，保存输入快照及来源日期。
3. 业务负责人确认“应进入的路径、应输出/不得输出的动作、是否进入成本诊断”。
4. 开发将实际运行结果与预期逐字段比对；通过后登记确认人、确认时间和回归状态。

每个已确认样例至少保存以下字段：

| 字段 | 说明 |
|---|---|
| `case_id` | 永久样例编号，不因规则版本变化而重用。 |
| `strategy_scope`、`rule_version`、`data_date` | 可重放的角色、版本与日期。 |
| 产品/广告身份 | 国家、店铺、MSKU、ASIN、广告实体与对象键。 |
| 输入摘要 | 日销、利润率、TACOS、当前价/P 线、FBA 可售/DOS、广告表现、预算、历史状态。 |
| 预期产品表行 | `strategy_rule_id`、`rule_code`、`decision_type`、价格方向、建议价、成本标记、状态。 |
| 预期广告表行 | 行数、`action_type`、对象、建议值/改变量、被拦截原因。 |
| 确认信息 | 确认人、确认时间、备注、是否可进入回归集。 |

## 7. 回归判定

样例重跑时按以下顺序比对：

1. `data_status`、`history_strategy_status` 与预期完全一致；
2. 产品表主键行数、`strategy_rule_id`、`rule_code`、`decision_type`、价格方向、成本诊断标记一致；
3. 广告表原子动作数、`action_type`、对象定位、建议值和 `change_rate` 一致；
4. 明确禁止的动作不存在；
5. 同日同版本第二次重跑，产品表和广告表的主键行数不增加；
6. 仅允许 `updated_time` 与按业务变化的证据内容更新。

如果同一个角色阈值、动作上限或历史窗口变更，应增加 `rule_version`，保留旧版本预期样例，不得静默改写旧样例的期望结果。
