# 代码整理与发布说明

## 本轮范围

本轮将当前工作区已有的业务代码、SQL、测试及交接文档一并整理到现有 `test/dashboard-test` 分支，并保留本地与远端已存在的功能。没有批量改写业务规则、移动既有文档或重算远端数据。

| 模块 | 内容与入口 |
| --- | --- |
| 补货 | 统一销售角色、低毛利国家核查、库容匹配与体积预警、清货硬拦截与精简明细，相关入口见[清货规则](补货/规则与口径/2026-10-15-清货名单禁止生成补货规则.md)、[角色规则](补货/规则与口径/2026-10-13-销售角色与低毛利导出核查说明.md)、[库容规则](补货/规则与口径/2026-10-14-补货库容额度匹配与预警规则.md) |
| 标签 | 本地标签生成、生命周期与运营状态补齐、历史销售角色SQL、综合分析页面及有界刷新，入口见 `etl/label_local_generation.py`、`etl/label_analysis_refresh.py`、`app/label_analysis_routes.py` 和 `docs/标签综合分析/` |
| 返场品 | 策略计算、页面、数据来源、价格与广告判断、交接代码，入口见 `etl/return_goods_strategy_update.py`、`app/services/return_goods_strategy_rules.py` 和 `docs/返场品/` |
| 广告分析 | 问题与瘦狗产品分析脚本、只读核查SQL、运营策略文档；源代码与交接资料按现有路径保留 |
| 每日任务 | 标签综合分析预计算进入既有每日ETL，保留各模块原有参数契约，不把发布代码等同于ETL已经成功 |

## 仓库边界

- 纳入业务源代码、测试、可复用SQL及现有业务文档；不以删除本机文件的方式整理。
- `outputs/`、`node_modules/`、日志、后台进程状态和本机数据库配置不纳入新增提交。已经跟踪的历史截图不在本轮擅自删除。
- 文档中 `outputs/` 下的验收结果、Excel样例和过程日志是本机生成产物，不是其他电脑检出后必须存在的仓库资源。
- 默认测试不能通过导入其他模块的数据库fixture绕过显式开启条件；`LABEL_LOCAL_MYSQL_TEST` 和 `PRODUCT_ROLE_HISTORY_MYSQL_TEST` 未开启时跳过对应数据库集成测试。

## 验证与运行

发布前使用隐藏后台进程执行 `python -m pytest tests -q --tb=short`、JavaScript语法检查及现有Node测试；合并远端后重新验证最终代码。敏感信息核查覆盖待发布文本和交接压缩包，不在日志中输出疑似凭据值。

合并后全量测试1825项通过、93项按条件跳过；Node测试4项通过，226份Python源文件、27份JavaScript和19份模板语法验证通过。数据库集成测试未显式开启，不执行远端业务库写入。

开发依赖明确使用当前Starlette测试客户端导入的 `httpx`，修正原 `httpx2` 条目；Windows运行环境补充 `tzdata`，确保 `Asia/Shanghai` 时区可用。保留远端对V47原始SQL的字节保护，防止换行转换破坏基线校验。

服务代码发布后仍需按目标机器的环境变量或 `config/database.ini` 配置数据库。新增表结构、标签本地重算、历史SQL任务及清货规则生效由对应运行流程负责，本轮Git推送不执行这些数据库操作。旧补货快照仍显示“命中清货名单，待重新生成”，不得理解为已经剔除。
