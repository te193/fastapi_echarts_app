# 看板功能与数据更新说明

更新时间：2026-05-30

## 1. 系统概览

本项目是一个 FastAPI + ECharts 的产品结构与调价复盘看板。前端页面由 `app/templates` 和 `app/static/js` 提供，后端接口集中在 `app/main.py`，业务数据主要通过本地 MySQL 库 `etl_datasync_test` 读取。

看板采用“远端只读、本地落表、本地聚合”的模式：

- 远端库只用于每日 ETL 拉取基础数据。
- 本地库保存看板明细表、每日快照表、周期聚合表和调价复盘结果表。
- 前端页面只访问本地 API，不直接查询远端库。

当前服务地址默认：

- Web 服务：`http://127.0.0.1:8000`
- 本地库：`127.0.0.1:3306 / etl_datasync_test`
- 远端源库：通过 `scripts/dashboard_env.ps1` 配置，只读查询。

## 2. 页面与功能

### 2.1 总览页 `/`

页面名称：产品分层看板

主要功能：

- 支持观察周期筛选：7 天、14 天、30 天、90 天、上月、自定义日期区间。
- 支持国家站点、店铺、是否超限价、日销分层、毛利率分层筛选。
- 展示全年销售目标与达标情况。
- 展示月度目标完成情况，用于按月对比销售额、销量、毛利润、毛利率的目标与实际完成。
- 展示核心指标卡片，包括销售额、销量、毛利润、毛利率、SKU 数等。
- 展示产品结构概览，用于判断整体产品健康度。

数据接口：

- `/api/meta`
- `/api/dashboard`
- `/api/dashboard/monthly-goals`

重要说明：

- 顶部年度目标不跟随页面筛选周期变化，固定基于年度目标快照表展示全年销售额和达标情况。
- 月度目标模块不跟随页面筛选条件变化，固定使用全量口径。
- 页面上的周期指标来自本地周期快照表，优先使用预设周期快照，必要时生成自定义周期快照。

月度目标计算规则：

- 目标来源：`dashboard_monthly_goal`。
- 实际来源：`dashboard_product_performance_daily`。
- 销售额实际：按月汇总 `sales_amount`。
- 销量实际：按月汇总 `sales_qty`。
- 毛利润实际：按月汇总 `order_gross_profit`。
- 毛利率实际：`sum(order_gross_profit) / sum(sales_amount)`。
- 历史月份：按整月实际 / 整月目标计算完成率。
- 当前月份：按截至本地最新数据日的进度目标计算完成率，例如 `当月目标 / 当月天数 * 已有数据天数`。
- 未来月份：展示目标，不展示实际完成率。

数据接口：

### 2.5 调价复盘页 `/price-review`

页面名称：调价效果复盘

主要功能：

- 内置调价日历，展示最近 30 天每日调价数量。
- 支持调价日期、对比周期、国家、店铺、调价幅度、价格带、关键词筛选。
- 支持对比调价前后 7 天、14 天、28 天经营指标。
- 展示核心指标：销量、日销、销售额、毛利润、毛利率、Sessions、排名等。
- 展示 SKU 分层迁移矩阵：
  - 日销分层
  - 毛利率分层
  - 排名分层
  - 销量分层
- 展示国家站点表现对比。
- 展示不同调价幅度的 SKU 分布与效果对比。
- 展示 Top 榜单：
  - 销量增长 Top
  - 销量下降 Top
  - 排名改善 Top
  - 排名恶化 Top
- 展示全量调价 SKU 明细。
- 支持识别二次调价 SKU，即同一 SKU 在前序已有调价事件后又再次调价。
- 支持查看二次调价发生时间。
- 全量调价 SKU 明细表支持表头字段筛选。
- 支持导出当前榜单和全部明细 CSV。

数据接口：

- `/api/price-adjustments/daily-counts`
- `/api/price-review/overview`
- `/api/price-review/drop-range`
- `/api/price-review/matrices`
- `/api/price-review/countries`
- `/api/price-review/top-lists`
- `/api/price-review/skus`
- `/api/price-review/top-lists/export`
- `/api/price-review/skus/export`

重要说明：

- 页面导航栏已保留调价复盘入口，不再单独显示“调价日历”入口。
- 独立 `/price-adjustments` 页面仍保留路由和模板，但当前导航不展示。
- 调价复盘计算只基于本地表，不直接在页面请求远端库。

核心计算规则：

- 调价事件来源：本地 `price_review_adjustment_source`。
- 调价前后指标来源：本地 `dashboard_product_performance_daily` 和 Listing 快照。
- 复盘周期：7 天、14 天、28 天。
- 周期未满时，接口返回空数据或 `period_incomplete`，避免展示不完整结果。
- 销量变化：调价后周期销量 - 调价前周期销量。
- 日销变化：调价后周期日均销量 - 调价前周期日均销量。
- 销售额变化：调价后周期销售额 - 调价前周期销售额。
- 毛利率变化：调价后订单毛利率 - 调价前订单毛利率。
- Sessions：读取产品日表 `sessions_total` 聚合。
- 排名：读取产品日表 `ranking`，按周期平均值对比，排名数字越小代表越好。
- 二次调价：同一 SKU、店铺、国家在当前调价事件之前存在更早调价事件时标记为二次调价。

### 2.6 异常预警页 `/alerts`

页面名称：异常预警工作台

主要功能：

- 支持站点、店铺、预警类型、关键词筛选。
- 支持观察维度切换：近 7 天、近 14 天、近 30 天。
- 支持多指标联动筛选：
  - 销量趋势：全部、下降、上涨、无明显变化。
  - 排名趋势：全部、下降、上涨、无明显变化。
  - 毛利状态：全部、低毛利、非低毛利。
  - 库存状态：全部、库存偏低、库存正常。
- 支持组合筛选，例如“销量下降但排名上涨”“销量下降且排名下降”“销量下降 + 排名下降 + 低毛利”。
- 展示当前命中数量、各预警类型命中数量和分页明细表。
- 支持导出当前筛选下的全部预警明细 CSV。

数据接口：

- `/api/alerts`
- `/api/alerts/export`

数据来源：

- 周期汇总快照表：由当前筛选周期通过 `_resolve_window()` 确定，来源包括 7/14/30/90 天预设快照或自定义周期快照。
- 产品每日表现表：`dashboard_product_performance_daily`。

计算规则：

- 低毛利：
  - 当前周期销售额 `sales_amount >= 1000`。
  - 当前周期订单毛利率 `order_gross_margin < 8%`。
- 库存偏低：
  - 当前周期日销 `daily_sales >= 1`。
  - FBA 可售库存大于 0。
  - 可售天数 `fba_sellable_inventory / daily_sales < 14`。
- 销量下降：
  - 近 N 天销量较前 N 天下滑超过 30%。
  - 前 N 天销量不少于 10。
- 销量上涨：
  - 近 N 天销量较前 N 天上涨超过 30%。
  - 近 N 天销量不少于 10。
- 排名下滑：
  - 近 N 天平均排名较前 N 天至少差 5 名。
  - 且排名数字增幅不少于 20%。
  - 排名数字越大表示越差。
- 排名上涨：
  - 近 N 天平均排名较前 N 天至少改善 5 名。
  - 且排名数字降幅达到约 20%。
  - 排名数字越小表示越好。

导出说明：

- 导出内容为当前筛选条件下的全部命中明细，不只导出当前分页。
- CSV 表头为中文。
- 导出字段包括：统计周期、对比周期、类型、MSKU、店铺、国家、销量趋势、排名趋势、毛利、库存。

## 4. 调价复盘数据表

### 4.1 调价队列本地源表

`price_review_adjustment_source`

用途：

- 保存远端调价队列在本地的调价事件。
- 是调价复盘计算的事件来源。

远端来源：

- `temporary_APP.lx_sale_adjust_price_queue`

更新逻辑：

- 每日只从远端拉最近 20 天调价队列。
- 本地对最近 20 天调价事件执行覆盖更新。
- 查询条件使用 `finish_time >= 开始时间 and finish_time < 结束时间`，避免 `date(finish_time)` 导致索引失效。

### 4.2 调价复盘结果表

`price_review_sku_tracking`

用途：

- 保存每个调价 SKU 在调价前后 7/14/28 天的复盘结果。
- 直接支撑调价复盘页面所有图表、榜单和明细。

计算来源：

- 调价事件：`price_review_adjustment_source`
- 销售表现：`dashboard_product_performance_daily`
- Listing 快照：`dashboard_listing_price_daily_snapshot`

计算窗口：

- 调价事件重算窗口：最近 80 天。
- 复盘周期：7 天、14 天、28 天。

为什么是 80 天：

- 产品日明细默认每日回滚刷新最近 50 天。
- 调价复盘最长要看调价后 28 天。
- 为了覆盖“销售明细被回滚刷新后可能影响到的历史调价事件”，调价复盘需要重算约 `50 + 28 = 78` 天范围内的调价事件。
- 因此取整为 80 天。

示例：

- 今天本地销售明细刷新最近 50 天。
- 某个 56 天前的调价事件，其调价后 28 天窗口可能有一部分落在最近 50 天内。
- 这些基础销售数据被重刷后，该调价事件的复盘结果也可能变化，所以需要被重新计算。

### 4.3 兼容源表

以下两张表当前保留表结构和中文备注，但主计算逻辑已改为直接使用本地基础表：

- `price_review_product_performance_source`
- `price_review_listing_source`

当前调价复盘主链路不依赖这两张表。

## 5. 每日 ETL 更新逻辑

主入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_daily_update_task.ps1
```

实际执行：

```powershell
python -m etl.dashboard_daily_update
```

默认步骤顺序：

1. `product_performance_daily`
2. `annual_goal_snapshot`
3. `restock_snapshot`
4. `inventory_snapshot`
5. `listing_price_snapshot`
6. `limit_price_snapshot`
7. `period_preset_snapshots`
8. `price_review_source_load`
9. `price_review_tracking`

### 5.1 业务日期与快照日期

默认规则：

- `biz_date`：昨天。
- `snapshot_date`：今天。
- 默认看板周期：最近 90 天。
- 产品明细回滚刷新：最近 50 天。

例子：

- 如果任务在 `2026-05-21` 运行：
  - `biz_date = 2026-05-20`
  - `snapshot_date = 2026-05-21`
  - 产品日表刷新 `2026-04-01` 到 `2026-05-20`

### 5.2 基础数据更新

产品日表：

- 删除本地最近 50 天数据。
- 从远端产品表现表重新拉取最近 50 天。
- 如果本地为空，则自动全量加载。

补货、库存、Listing：

- 按当天 `snapshot_date` 删除后重建。

限价：

- 每天从远端限价源表查出全量。
- 本地限价表全量替换。

年度目标：

- 基于本地产品日表重算今年年初到 `biz_date` 的目标达成情况。

### 5.3 周期快照更新

每日生成：

- 最近 7 天
- 最近 14 天
- 最近 30 天
- 最近 90 天
- 上月

每个预设周期同时生成：

- 当前周期
- 上一个对比周期
- 矩阵汇总数据

保留策略：

- 预设周期快照只保留最近 2 个 `snapshot_date`。
- 矩阵周期快照只保留最近 2 个 `snapshot_date`。

### 5.4 调价复盘更新

调价复盘分两步：

1. `price_review_source_load`
   - 远端只拉最近 20 天调价队列。
   - 覆盖更新本地 `price_review_adjustment_source` 最近 20 天数据。

2. `price_review_tracking`
   - 不访问远端。
   - 基于本地 `price_review_adjustment_source`、`dashboard_product_performance_daily` 等表。
   - 重算最近 80 天调价事件的 7/14/28 天复盘结果。

补跑调价复盘：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_daily_update_task.ps1 --steps price_review_source_load,price_review_tracking
```

只重算调价复盘结果，不重新拉远端队列：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_daily_update_task.ps1 --steps price_review_tracking
```

## 8. 运维注意事项

1. 远端库只读  
   ETL 对远端库只执行查询，本地库负责建表、删除、插入和更新。

2. 不创建数据库备份表  
   当前约定是只做代码备份，不再创建数据库备份表。

3. 限价表是全量替换  
   因为远端限价源表不是每天都有新增日期，所以本地每天替换整表，而不是只取最新一天。

4. 调价队列只拉 20 天  
   这是为了减少远端查询压力。80 天只用于本地复盘重算，不用于远端调价队列拉取。

5. 预设快照只保留最近两天  
   历史预设快照当前看板用不上，保留最近两天用于容错和对比。

6. 如果远端当天未更新完成  
   本地产品日表或快照可能仍停留在前一天，需要等远端完成后补跑 ETL。

7. 调价复盘最大可计算日期  
   受本地产品日表最大日期限制。例如本地产品日表最大日期为 `2026-05-20`，7 天复盘最多只能计算到 `2026-05-13` 的调价事件，14 天和 28 天会更早。
