# 产品分层看板每日更新任务设计方案

> 本方案只做设计说明，不做代码实现。依据文件：`sqlcode/原始.sql`。

## 1. 设计目标

当前 SQL 是一次性脚本，会 `drop table` 后重建中间表。每日更新后建议改造成：

- 中间表长期保留，不每天整表删除。
- 每天按业务日期写入昨天数据。
- 支持指定日期重跑，重复执行不会产生重复数据。
- 默认首页可以快速读取最近一次快照。
- 用户自定义周期时，可以基于日粒度中间表重新聚合。

## 2. 日期定义

建议区分两个日期：

| 日期 | 含义 | 建议默认 |
| --- | --- | --- |
| `biz_date` | 业务数据日期，通常是销售/广告表现日期 | `current_date - interval 1 day` |
| `snapshot_date` | 价格、库存、补货建议、限价的快照日期 | 需要确认，可能是 `current_date` 或 `biz_date` |
| `period_start` | 页面默认统计周期开始日期 | `biz_date - interval 89 day` |
| `period_end` | 页面默认统计周期结束日期 | `biz_date` |

当前 SQL 中：

- 产品表现使用 `@start_date` 到 `@end_date`。
- 库存、补货、现价、限价都使用 `curdate()`。

因此每日任务最需要确认的是：价格/库存/限价到底应该按今天快照，还是昨天业务日快照。我的建议是先用：

```text
biz_date = 昨天
snapshot_date = 今天
```

因为你的 SQL 当前就是用 `curdate()` 取现价、库存、限价。

## 3. 推荐中间表拆分

### 3.1 商品表现日聚合表

建议表名：

```text
etl_datasync.dashboard_product_performance_daily
```

替代当前：

```text
etl_datasync.product_performance_90_days
```

粒度：

```text
dt_date + country + country_category + seller_name_new + seller_sku_adj + local_sku
```

每日任务：

```sql
delete from etl_datasync.dashboard_product_performance_daily
where dt_date = :biz_date;

insert into etl_datasync.dashboard_product_performance_daily (...)
select ...
from dwd_datasync.lx_statistics_product_performance
where start_date >= :biz_date
  and start_date < date_add(:biz_date, interval 1 day)
  and seller_sku not like 'Amazon.Found%'
group by ...;
```

该表负责保留：

- 销量
- 销售额
- 销售额_不含税
- 原订单毛利润
- 订单毛利润
- 是否异常
- 结算毛利润
- afn_fulfillable_quantity
- 广告花费
- 广告订单量
- 广告销售额
- 广告点击量
- 广告曝光量

### 3.2 补货建议每日快照表

建议表名：

```text
etl_datasync.dashboard_restock_daily_snapshot
```

替代当前：

```text
etl_datasync.month_end_data_补货建议
```

粒度：

```text
snapshot_date + country_category + seller_name_new + seller_sku_adj
```

每日任务：

```sql
delete from etl_datasync.dashboard_restock_daily_snapshot
where snapshot_date = :snapshot_date;

insert into etl_datasync.dashboard_restock_daily_snapshot (...)
select
    date(create_time) as snapshot_date,
    country_category,
    seller_sku_adj,
    seller_name_new,
    max(sc_quantity_local_valid)
      + max(sc_quantity_purchase_shipping)
      + max(sc_quantity_purchase_plan)
      + max(sc_quantity_local_qc) as local_quantity
from etl_datasync.etl_dispose_lx_replenishment_suggest_restocking
where date(create_time) = :snapshot_date
group by
    date(create_time),
    country_category,
    seller_sku_adj,
    seller_name_new;
```

### 3.3 库存每日快照表

建议表名：

```text
etl_datasync.dashboard_inventory_daily_snapshot
```

替代当前：

```text
etl_datasync.month_end_data_库存明细
```

粒度：

```text
snapshot_date + country_category + seller_name_new + seller_sku_adj
```

每日任务：

```sql
delete from etl_datasync.dashboard_inventory_daily_snapshot
where snapshot_date = :snapshot_date;

insert into etl_datasync.dashboard_inventory_daily_snapshot (...)
select
    date(create_time) as snapshot_date,
    country_category,
    seller_sku_adj,
    seller_name_new,
    sum(total) as total,
    sum(total_price) as total_price,
    sum(available_total) as available_total,
    sum(available_total_price) as available_price,
    sum(afn_fulfillable_quantity) as afn_fulfillable_quantity,
    sum(reserved_fc_transfers) as reserved_fc_transfers,
    sum(reserved_fc_processing) as reserved_fc_processing,
    sum(reserved_customerorders) as reserved_customerorders,
    sum(afn_unsellable_quantity) as afn_unsellable_quantity,
    sum(afn_inbound_working_quantity) as afn_inbound_working_quantity,
    sum(stock_up_num) as stock_up_num,
    sum(afn_researching_quantity) as afn_researching_quantity,
    sum(total_fulfillable_quantity) as total_fulfillable_quantity
from etl_datasync.etl_dispose_lx_storage_fba_warehouse_detail
where date(create_time) = :snapshot_date
group by
    date(create_time),
    country_category,
    seller_sku_adj,
    seller_name_new;
```

### 3.4 Listing 现价每日快照表

建议表名：

```text
etl_datasync.dashboard_listing_price_daily_snapshot
```

粒度：

```text
snapshot_date + country_category + country + seller_name_new + seller_sku
```

每日任务：

```sql
delete from etl_datasync.dashboard_listing_price_daily_snapshot
where snapshot_date = :snapshot_date;

insert into etl_datasync.dashboard_listing_price_daily_snapshot (...)
select
    date(l.create_time) as snapshot_date,
    l.seller_name_new,
    l.seller_name,
    l.seller_sku,
    l.country_category,
    l.marketplace as country,
    l.price,
    l.org_currency_icon,
    round(l.price * c.rate_org, 2) as price_cny
from etl_datasync.etl_dispose_lx_sales_mws_listing l
left join dwd_datasync.lx_basic_currency c
  on l.org_currency_icon = c.name
 and c.date = date_format(:snapshot_date, '%Y-%m')
where date(l.create_time) = :snapshot_date;
```

### 3.5 限价每日快照表

建议表名：

```text
etl_datasync.dashboard_limit_price_daily_snapshot
```

粒度：

```text
snapshot_date + country_category + country + seller_name_new + seller_sku + local_sku + shipping_method + target_margin
```

每日任务：

```sql
delete from etl_datasync.dashboard_limit_price_daily_snapshot
where snapshot_date = :snapshot_date;

insert into etl_datasync.dashboard_limit_price_daily_snapshot (...)
select
    date(create_time) as snapshot_date,
    sku as local_sku,
    msku as seller_sku,
    store as seller_name_new,
    country,
    case
        when country = '英国' then '英国站'
        when country in ('美国', '加拿大', '巴西', '墨西哥') then '北美站'
        else '欧洲站'
    end as country_category,
    shipping_method,
    target_margin,
    currency,
    tax_inclusive_price,
    tax_inclusive_price_noad,
    tax_inclusive_price_adj
from temporary_APP.yd_product_pricing_schedule
where date(create_time) = :snapshot_date
  and target_margin = 0.35
  and shipping_method = '铁路';
```

## 4. 页面服务宽表

建议表名：

```text
etl_datasync.dashboard_product_period_snapshot
```

用途：

- 保存“某一天生成的默认周期看板宽表”。
- 默认首页直接读取最新 `snapshot_date` + 默认 `period_start/period_end`。
- 自定义周期仍可以从 `dashboard_product_performance_daily` 实时聚合。

粒度：

```text
snapshot_date + period_start + period_end + country + country_category + seller_name_new + seller_sku_adj + local_sku
```

每日任务：

```sql
delete from etl_datasync.dashboard_product_period_snapshot
where snapshot_date = :snapshot_date
  and period_start = :period_start
  and period_end = :period_end;

insert into etl_datasync.dashboard_product_period_snapshot (...)
select
    :snapshot_date as snapshot_date,
    :period_start as period_start,
    :period_end as period_end,
    ...
from etl_datasync.dashboard_product_performance_daily a
left join etl_datasync.dashboard_restock_daily_snapshot b
  on b.snapshot_date = :snapshot_date
 and a.country_category = b.country_category
 and a.seller_sku_adj = b.seller_sku_adj
 and a.seller_name_new = b.seller_name_new
left join etl_datasync.dashboard_inventory_daily_snapshot c
  on c.snapshot_date = :snapshot_date
 and a.country_category = c.country_category
 and a.seller_sku_adj = c.seller_sku_adj
 and a.seller_name_new = c.seller_name_new
left join etl_datasync.dashboard_listing_price_daily_snapshot p
  on p.snapshot_date = :snapshot_date
 and a.country_category = p.country_category
 and binary a.seller_sku_adj = binary p.seller_sku
 and a.seller_name_new = p.seller_name_new
 and a.country = p.country
left join etl_datasync.dashboard_limit_price_daily_snapshot lp
  on lp.snapshot_date = :snapshot_date
 and a.country_category = lp.country_category
 and a.seller_sku_adj = lp.seller_sku
 and a.seller_name_new = lp.seller_name_new
 and a.country = lp.country
 and a.local_sku = lp.local_sku
where a.dt_date between :period_start and :period_end
group by
    a.seller_name_new,
    a.seller_sku_adj,
    a.country_category,
    a.country,
    a.local_sku;
```

## 5. 每日任务顺序

推荐顺序：

1. `load_product_performance_daily`
2. `load_restock_daily_snapshot`
3. `load_inventory_daily_snapshot`
4. `load_listing_price_daily_snapshot`
5. `load_limit_price_daily_snapshot`
6. `build_dashboard_product_period_snapshot`
7. `write_task_log`

依赖关系：

```text
product_performance_daily
restock_daily_snapshot
inventory_daily_snapshot
listing_price_daily_snapshot
limit_price_daily_snapshot
        ↓
dashboard_product_period_snapshot
        ↓
FastAPI dashboard/detail API
```

## 6. 幂等与补跑策略

每个任务都按日期先删后插：

```sql
delete from target_table where biz_date = :biz_date;
insert into target_table select ...;
```

对于快照表：

```sql
delete from target_table where snapshot_date = :snapshot_date;
insert into target_table select ...;
```

对于周期宽表：

```sql
delete from etl_datasync.dashboard_product_period_snapshot
where snapshot_date = :snapshot_date
  and period_start = :period_start
  and period_end = :period_end;
```

这样可以支持：

- 当天失败后重跑。
- 指定历史日期补跑。
- 源表延迟后重新刷新。
- 默认周期口径变化后批量重建。

## 7. 数据保留策略

建议：

| 表 | 保留周期 |
| --- | --- |
| `dashboard_product_performance_daily` | 至少 18 个月 |
| `dashboard_restock_daily_snapshot` | 至少 6-12 个月 |
| `dashboard_inventory_daily_snapshot` | 至少 6-12 个月 |
| `dashboard_listing_price_daily_snapshot` | 至少 6-12 个月 |
| `dashboard_limit_price_daily_snapshot` | 至少 6-12 个月 |
| `dashboard_product_period_snapshot` | 至少 3-6 个月，或只保留最近默认快照 |
| 任务日志表 | 至少 12 个月 |

如果只服务当前看板，周期宽表可以少保留；日事实表建议多保留，因为自定义周期和趋势都依赖它。

## 8. 任务日志表建议

建议新增：

```text
etl_datasync.dashboard_etl_task_log
```

字段：

```text
id
task_name
biz_date
snapshot_date
period_start
period_end
status
affected_rows
started_at
finished_at
error_message
created_at
```

每个任务写一条日志，方便排查每日更新是否成功。

## 9. 调度方式建议

短期：

```text
Windows 任务计划程序 / Linux cron + Python 脚本
```

中期：

```text
Airflow / DolphinScheduler
```

不太建议直接用 MySQL Event 承载全部逻辑，因为这条链路包含多张表、多步依赖、日志和补跑，放在调度工具里更好排查。

## 10. 推荐执行时间

建议每日凌晨源表同步完成后运行，例如：

```text
每天 06:00
```

但最终时间应以这些源表的完成时间为准：

- `dwd_datasync.lx_statistics_product_performance`
- `etl_datasync.etl_dispose_lx_replenishment_suggest_restocking`
- `etl_datasync.etl_dispose_lx_storage_fba_warehouse_detail`
- `etl_datasync.etl_dispose_lx_sales_mws_listing`
- `temporary_APP.yd_product_pricing_schedule`

## 11. 当前需要确认的问题

| 问题 | 为什么重要 |
| --- | --- |
| 价格/库存/限价快照用 `curdate()` 还是 `biz_date` | 直接影响现价、限价、库存是否和销售周期对齐 |
| 默认首页看滚动 90 天、自然月、还是用户指定周期 | 决定 `period_start/period_end` 默认值 |
| `product_performance_90_days` 是否要继续保留这个表名 | 如果每日增量，表名叫 90 days 容易误导 |
| `month_end_data_*` 是否改名 | 当前 SQL 实际取的是当天快照，不是月末 |
| SKU 清洗和店铺清洗是否所有源表一致 | 关联不上会导致价格/库存/限价为空 |
| 商品名、ASIN、品牌、负责人从哪里补 | 页面明细字段需要这些维度 |

## 12. 推荐落地顺序

第一阶段先做：

1. 商品表现日聚合表。
2. 库存/补货/现价/限价每日快照表。
3. 默认周期看板宽表。
4. 任务日志。

第二阶段再做：

1. 自定义日期实时聚合。
2. 商品维表补充 ASIN、品牌、负责人。
3. 历史快照对比。
4. 更精细的失败重试和数据质量校验。

## 13. 结论

看板每日更新的核心不是每天重建 `product_performance_90_days`，而是把当前 SQL 拆成稳定的日事实表和每日快照表。默认页面读取最新周期宽表，自定义日期再按日表聚合。这样既能每日自动更新，也方便补数和排查。
