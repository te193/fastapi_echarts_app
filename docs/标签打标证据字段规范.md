# 标签打标证据字段规范

## 1. 目的

在不改变 `dws_datasync.dws_标签表` 现有“一条标签事实一行”结构的前提下，为每条标签结果保存本次打标使用的关键指标和规则版本，使标签看板能够解释：

- 该 MSKU 为什么命中当前子标签。
- 同一父标签在 `7d / 14d / 30d / 90d` 不同周期下为什么结果不同。
- 两个标签日期之间，哪些指标跨过阈值并导致标签变化。
- 本地重算结果与远端标签事实是否一致。

证据仅用于审计和解释，不参与重新打标，也不替代远端标签事实。

## 2. 保持不变的标签事实粒度

现有标签表字段保持不变：

```text
data_date
country_category
country
store
msku
label_id
label_period
created_time
```

一条记录代表：某个经营单元在某个标签日期、某个统计周期内命中了一个具体子标签。

逻辑粒度为：

```text
data_date
+ country_category
+ country
+ store
+ msku
+ label_id
+ label_period
```

其中：

- `label_id` 是具体子标签 ID，父标签通过 `dws_标签详情表` 关联获得。
- `label_period` 保存 `7d / 14d / 30d / 90d / current` 等真实统计周期。
- 同一 MSKU 可以在不同周期下命中不同子标签，必须分别保存，不能互相覆盖。
- 不按统计周期计算的标签统一使用 `current`，不留空。

## 3. 建议新增字段

在现有标签表增加以下三个可空字段：

| 字段 | 建议类型 | 说明 |
|---|---|---|
| `rule_version` | `VARCHAR(32)` | 本次打标使用的规则版本，例如 `sales_role_v3` |
| `evidence_status` | `VARCHAR(20)` | 证据状态：`complete / partial / missing` |
| `evidence_json` | `JSON` | 本次打标实际使用的指标、统计窗口和命中阈值 |

参考定义：

```sql
ALTER TABLE dws_datasync.dws_标签表
    ADD COLUMN rule_version VARCHAR(32) NULL COMMENT '打标规则版本',
    ADD COLUMN evidence_status VARCHAR(20) NULL COMMENT 'complete/partial/missing',
    ADD COLUMN evidence_json JSON NULL COMMENT '本次打标使用的指标和命中阈值';
```

以上 SQL 仅用于结构说明，实际执行前应在测试环境确认 MySQL 版本、字段顺序和发布方式。

## 4. 证据 JSON 通用结构

每条标签只保存自己真正使用的指标，不要求所有标签具有相同字段。

```json
{
  "schema_version": "1.0",
  "type": "sales_role",
  "window": {
    "start": "2026-06-23",
    "end": "2026-07-22",
    "period": "30d",
    "days": 30
  },
  "metrics": {},
  "matched_rule": {}
}
```

字段说明：

| JSON 字段 | 说明 |
|---|---|
| `schema_version` | 证据 JSON 的结构版本，与业务规则版本分开管理 |
| `type` | 证据类型，例如 `sales_role`、`inventory_level`、`traffic_structure` |
| `window` | 本次计算实际使用的日期窗口和标签周期 |
| `metrics` | 本标签本次计算实际使用的指标值 |
| `matched_rule` | 最终命中的关键阈值快照，用于历史解释 |

不在 JSON 中重复保存 `MSKU`、国家、店铺、`label_id` 等表中已有字段。

## 5. 销售角色证据示例

### 5.1 30 天问题产品

```json
{
  "schema_version": "1.0",
  "type": "sales_role",
  "window": {
    "start": "2026-06-23",
    "end": "2026-07-22",
    "period": "30d",
    "days": 30
  },
  "metrics": {
    "period_sales_qty": 24,
    "daily_sales": 0.8,
    "sales_amount": 7600.0,
    "tag_gross_profit": 357.2,
    "tag_margin_rate": 4.7
  },
  "matched_rule": {
    "daily_sales": "< 1",
    "tag_margin_rate": "< 5%"
  }
}
```

指标含义：

```text
周期销量 period_sales_qty = 24
周期天数 days = 30
日销 daily_sales = 24 / 30 = 0.8
```

`period_sales_qty` 必须明确表示周期销量，不使用容易被误解为当天销量的 `sales_qty`。

### 5.2 同一 MSKU 的多周期结果

同一 MSKU 可以同时存在：

| label_id | 子标签 | label_period | 关键证据 |
|---:|---|---|---|
| 102 | 潜力产品 | 7d | 7 天周期销量、7 天日销、7 天打标毛利率 |
| 104 | 问题产品 | 30d | 30 天周期销量、30 天日销、30 天打标毛利率 |
| 101 | 明星产品 | 90d | 90 天周期销量、90 天日销、90 天打标毛利率 |

每个周期独立保存一条标签事实和一份证据 JSON。

## 7. 父标签与子标签处理

### 7.1 正常情况

标签表每行对应一个最终子标签。证据 JSON 保存该子标签本次判定实际使用的指标。

```text
父标签：销售角色
子标签：潜力产品
周期：30d
证据：日销、周期销量、销售额、打标毛利润、打标毛利率
```

### 7.2 同一父标签命中多个子标签

如果业务允许同一父标签、同一周期命中多个非互斥子标签，则保留多行，每行保存各自的判断证据。

如果父标签配置为互斥，但同一经营单元、同一周期产生多个子标签，则：

- 原始标签事实全部保留。
- 每行继续保存对应证据。
- 看板额外标记为互斥冲突。
- 不在写入阶段擅自删除其中一条事实。

## 8. 证据状态

`evidence_status` 使用固定枚举：

| 状态 | 含义 |
|---|---|
| `complete` | 本次打标所需指标和阈值均已保存 |
| `partial` | 标签事实有效，但部分辅助指标缺失 |
| `missing` | 仅有标签结果，无法提供打标证据 |

旧数据新增字段为空时，读取端按 `missing` 处理，不得误报为证据完整。

## 9. 两日标签变化解释

比较标签变化时，必须按以下条件匹配：

```text
country_category
+ country
+ store
+ msku
+ 父标签
+ label_period
```

不直接使用 `label_id` 匹配，因为子标签发生变化后 `label_id` 本身会改变。

示例：

```text
2026-07-21：销售角色 / 30d / 问题产品
日销 0.8，打标毛利率 4.7%

2026-07-22：销售角色 / 30d / 潜力产品
日销 1.3，打标毛利率 12.1%
```

页面可生成：

```text
问题产品 -> 潜力产品
日销：0.8 -> 1.3，跨过 1
打标毛利率：4.7% -> 12.1%，跨过 10%
变化说明：日销和毛利率同时跨过潜力产品阈值。
```

只有两天的 `evidence_status` 都为 `complete`，且 `rule_version` 可比较时，才输出确定性原因。否则仅展示标签事实变化，并提示证据不完整或规则版本不同。

## 10. 写入与兼容规则

- 新增字段全部允许为空，避免影响历史数据和现有查询。
- 写入 SQL 必须显式列出字段，禁止依赖表字段顺序。
- 标签事实与证据在同一次标签生成过程中写入，避免事后使用其他指标口径反推。
- `rule_version` 在规则阈值、指标定义或计算口径变化时必须升级。
- `schema_version` 只在 JSON 结构变化时升级。
- 金额、比率和日销保留足够精度，展示层再格式化，写入时不提前四舍五入为字符串。
- 缺失指标使用 JSON `null` 或直接省略，并将 `evidence_status` 标为 `partial`；禁止使用 `0` 冒充缺失值。
- 标签详情表仍然负责标签名称、业务定义、负责人和规则说明；证据 JSON 只保存本次实际输入和阈值快照。

## 11. 验收标准

- 原有标签表查询在不读取新增字段时行为不变。
- 同一 MSKU 的不同 `label_period` 证据不会互相覆盖。
- `period_sales_qty / days` 与 `daily_sales` 在允许误差内一致。
- 每条 `complete` 证据都能关联到一个真实标签事实。
- 两天同父标签、同周期的证据可以生成指标前后变化。
- 互斥冲突不因新增证据字段被隐藏或删除。
- 缺失证据与指标值为零能够被正确区分。
