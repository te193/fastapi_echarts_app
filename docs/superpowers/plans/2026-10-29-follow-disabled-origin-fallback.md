# 跟卖店铺不补货时回退原链接实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 单个跟卖店铺命中不补货时，回退允许补货的原链接，避免两边被拦截。

**范围更正（用户最新指示）:** 仅一个跟卖店铺时回退；多个跟卖店铺完全沿用原逻辑，不增加原链接候选。

**Architecture:** 保留品牌归属/跟卖关系；同 ASIN 同国家类别仅有一个跟卖店铺时，若该方不可承接，则选择未被禁补/清货排除的原链接。回退原链接退出合并补货计算，使用自身库存、销量、层级、箱规及成本；其他链接为零补货。原链接也不可补货则不分配。多个跟卖店铺的候选、排序和零补货拦截保持原逻辑。

**Tech Stack:** Python、MySQL SQL、pytest、SQLite SQL 回归、隔离 MySQL 验证。

**Spec:** 用户当前截图和“按照这个思路修改一下代码”：跟卖方不补货则回原链接，原店铺未命中不补货则补。

## Global Constraints

- 不修改品牌归属或源配置；不强制库存充足/无销量原链接补货。
- 清货、禁补、MOQ、箱规与金额校验继续生效。
- 不跨国家类别/ASIN 回退，一组最多一条正补货量。
- 按同 ASIN、同国家类别中归一化跟卖店铺数量判断单店，不是按 MSKU 条数；多店铺不回退。
- 当前工作区有既有 ETL 改动，窄范围就地修改，不提交其他工作。

## Review Focus

- 单家禁补回原；多家全部禁补仍按原逻辑不回退。
- 有允许跟卖方时保持跟卖优先和原日期排名。
- 原链接也禁补/清货时无目标，量/箱数/成本全部为零。
- 禁补跟卖方库存不令原链接回退后仍被压零。
- 清货审计和实际分配共用选择逻辑，MOQ 不绕过。
