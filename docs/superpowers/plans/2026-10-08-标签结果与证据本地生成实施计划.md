# 标签结果与证据本地生成实施计划

> 使用 superpowers:executing-plans 在当前会话逐项实现。用户已于 2026-10-08 确认设计并要求开始后续工作。

**目标：** 完整 V47 在本地 MySQL 计算标签与证据，替换远端标签成品复制入口。

**架构：** 业务源只读同步到本地专用源表；显式映射 V47 的表和过程名称；计算工作表与页面发布表分离。保留原版规则，历史不足显式报告。

**技术：** Python、PyMySQL、MySQL 8、pytest。

**设计：** [重构设计](../specs/2026-10-08-标签结果与证据本地生成重构设计.md)

## 全局约束

- 原版 V47 为基线，不部署接收中规则修复。
- 源连接只读；禁止读取远端标签结果及 evidence_json，包括历史种子。
- 新编写 SQL 使用小写；保留归档 SQL 原件。
- 本地写入限定于专用标签源表、工作表、日志与发布表。
- 测试、数据同步和计算均隐藏后台运行，日志可轮询。
- 保留用户其他未提交改动，不推送。

## 重点核验

- SQL 里字符串、注释与带引号的表名须正确区分，未映射依赖立即失败。
- 原始列类型、字符排序规则和排序字段不能因同步而变化。
- 过程内部提交失败不能污染正式页面快照。
- 前日历史缺失不能伪造连续计数或断货前沿用。
- 每日与手动刷新并发、同日重跑及中断重试须幂等。
