# 加权日销 DWS 分层性能优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将加权日销一次性 CTE 查询改为两张会话临时表和一张 DWS 正式表的分层刷新脚本，使产品表现只扫描最近 30 天、Listing 只扫描最新同步日，并保持全部指标口径不变。

**Architecture:** 先用 `CREATE TEMPORARY TABLE` 物化产品表现 30 天周期指标和 Listing 最新日售价，再从两张会话临时表生成最终加权日销 `_building` 表。最终表使用 `RENAME TABLE` 原子切换；正式脚本在测试时通过内存表名映射写入 `opt_db.tmp_*`，直接验证真实 DDL、结果、自动释放和耗时。

**Tech Stack:** MySQL 8 多语句 SQL、会话临时表、CTAS、用户变量、窗口函数、InnoDB 索引、pytest、opt_db PyMySQL 测试连接。

## Global Constraints

- 正式会话临时表和结果表使用 `dws_datasync`，只有最终结果表持久化。
- 产品表现只读取 `biz_date` 当天及此前 29 天。
- Listing 只读取 `MAX(DATE(create_time))` 对应的最新同步日。
- 产品表现读取强制使用 `idx_osp_performance_dashboard_cover`。
- 原有周期销量、可售天数、平滑日销、新品/老品、加权日销和广告预算公式保持不变。
- 最终结果先写 `_building`，完成后原子切换。
- 不修改五张远端源表，不把用户的规则文档或 `outputs/` 纳入提交。

### Task 2: 将单查询改为三层 DWS 刷新脚本

**Files:**
- Modify: `data/补货页面加权日销计算.sql`

**Interfaces:**
- Consumes: 五张远端源表和 `@biz_date/@product_start_date/@product_end_date/@listing_date/@listing_end_date`。
- Produces: 两张会话临时表以及 `dws_datasync.dws_replenishment_weighted_daily_sales` 正式结果表。

- [ ] **Step 1: 固定产品和 Listing 日期边界**

将 SQL 开头改为：

```sql
SET @biz_date = (
    SELECT DATE(MAX(start_date))
    FROM dwd_datasync.lx_statistics_product_performance
);
SET @product_start_date = DATE_SUB(@biz_date, INTERVAL 29 DAY);
SET @product_end_date = DATE_ADD(@biz_date, INTERVAL 1 DAY);
SET @listing_date = (
    SELECT DATE(MAX(create_time))
    FROM dwd_datasync.lx_sales_mws_listing
);
SET @listing_end_date = DATE_ADD(@listing_date, INTERVAL 1 DAY);
```

- [ ] **Step 2: 构建产品表现 30 天周期临时表**

使用 `CREATE TEMPORARY TABLE dws_datasync.tmp_replenishment_weighted_sales_product_30d AS` 创建会话临时表。源表必须写为：

```sql
FROM dwd_datasync.lx_statistics_product_performance AS p
FORCE INDEX (idx_osp_performance_dashboard_cover)
WHERE p.start_date >= DATE_FORMAT(@product_start_date, '%Y-%m-%d')
  AND p.start_date < DATE_FORMAT(@product_end_date, '%Y-%m-%d')
```

保留现有国家、店铺、MSKU 标准化规则。内层按以下字段逐日聚合：

```text
dt_date + country_category + country + seller_name_new + seller_sku_adj
```

外层再按国家、店铺、MSKU 直接计算 3/7/14/30 天销量和可售天数，只写约 1.9 万行周期指标。该临时表不建立宽索引，避免为一次读取支付额外建索引成本。

- [ ] **Step 3: 构建 Listing 最新日售价临时表**

使用 `CREATE TEMPORARY TABLE dws_datasync.tmp_replenishment_listing_price_latest AS` 创建会话临时表。先按以下边界过滤：

```sql
WHERE l.create_time >= @listing_date
  AND l.create_time < @listing_end_date
```

仅在最新日数据中执行 `ROW_NUMBER()`，每个国家、店铺、MSKU 保留 `price_rank = 1`。沿用币种映射和月度 `rate_org`，CTAS 后增加主键：

```sql
ALTER TABLE dws_datasync.tmp_replenishment_listing_price_latest
    ADD PRIMARY KEY (country_category, country, seller_name_new, seller_sku_adj);
```

- [ ] **Step 4: 从两张临时表生成最终 building 表**

保留现有品牌、接收次数、`adjusted_daily_sales` 和 `weighted_metrics` 公式，只把周期指标源改为 30 天临时表、Listing 源改为最新日临时表。最终字段继续包含：

```text
biz_date, country_category, country, seller_name_new, seller_sku_adj,
max_brand_name, receiving_cnt, product_type,
3/7/14/30 天销量、可售天数、周期日销、daily_avg_sales,
listing_price, currency_code, exchange_rate_cny, listing_price_cny,
ad_budget_original, ad_budget_cny
```

创建 `dws_datasync.dws_replenishment_weighted_daily_sales_building` 并增加主键：

```sql
ALTER TABLE dws_datasync.dws_replenishment_weighted_daily_sales_building
    ADD PRIMARY KEY (
        biz_date, country_category, country, seller_name_new, seller_sku_adj
    );
```

- [ ] **Step 5: 原子切换最终结果表**

使用 building 表保证首次运行和后续运行都可切换：

```sql
CREATE TABLE IF NOT EXISTS dws_datasync.dws_replenishment_weighted_daily_sales
LIKE dws_datasync.dws_replenishment_weighted_daily_sales_building;

DROP TABLE IF EXISTS dws_datasync.dws_replenishment_weighted_daily_sales_old;

RENAME TABLE
    dws_datasync.dws_replenishment_weighted_daily_sales
        TO dws_datasync.dws_replenishment_weighted_daily_sales_old,
    dws_datasync.dws_replenishment_weighted_daily_sales_building
        TO dws_datasync.dws_replenishment_weighted_daily_sales;

DROP TABLE dws_datasync.dws_replenishment_weighted_daily_sales_old;
```

脚本不自动拉取全量结果，避免额外排序和网络传输；下游直接查询正式结果表。
