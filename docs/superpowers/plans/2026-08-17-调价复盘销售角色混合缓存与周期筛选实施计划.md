# 调价复盘销售角色混合缓存与周期筛选 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 支持调前、调后独立选择 3/7/14/30/90 天销售角色，并通过远端近两日滚动缓存与调价产品固化结果稳定呈现角色迁移。

**Architecture:** 页面和接口只读取本地数据库。每日价格复盘源同步阶段将远端 `1301–1304` 的最新两个数据日缓存到本地；角色追踪阶段只为调价产品生成调前/调后周期组合，优先使用精确日期的远端缓存，3 天及远端缺口按本地 v47 规则重算并固化。

**Tech Stack:** FastAPI、Jinja2、原生 JavaScript、CSS、PyMySQL、MySQL 8、pytest、Playwright。

## Global Constraints

- 所有修改留在 `test/dashboard-test`，不创建新分支或工作树。
- 调价范围从 `2026-08-01` 开始，不回填此前数据。
- 支持周期固定为 `3 / 7 / 14 / 30 / 90` 天；默认调前 30 天、调后 3 天。
- 调价当天 D 排除；调前窗口为 `D-pre_days` 至 `D-1`，调后窗口为 `D+1` 至 `D+post_days`。
- 页面不得直接连接远端数据库；远端异常不能导致页面接口失败。
- 远端缓存只保留最新两个实际 `data_date`，历史只固化调价产品。
- 远端标签表只读，不执行任何写入。
- 自动化测试、ETL 验证、服务和浏览器验收必须隐藏后台运行；测试日志放在 `.codex-runtime` 并在验收后清理。
- 不覆盖或回退工作区现有修改；每次提交只暂存本任务列出的文件。

```python
SUPPORTED_ROLE_PERIODS = (3, 7, 14, 30, 90)
REMOTE_ROLE_PERIODS = (7, 14, 30, 90)
REMOTE_ROLE_LABELS = {1301: "star", 1302: "potential", 1303: "dog", 1304: "problem"}

def tracking_windows(adjust_date: date, pre_days: int, post_days: int) -> TrackingWindows:
    if pre_days not in SUPPORTED_ROLE_PERIODS or post_days not in SUPPORTED_ROLE_PERIODS:
        raise ValueError("Unsupported station role period")
    return TrackingWindows(
        pre_start=adjust_date - timedelta(days=pre_days),
        pre_end=adjust_date - timedelta(days=1),
        post_start=adjust_date + timedelta(days=1),
        post_end=adjust_date + timedelta(days=post_days),
        pre_days=pre_days,
        post_days=post_days,
    )
```

`normalize_remote_role_snapshot` 接受 JSON 字符串或字典；将远端百分数毛利率除以 100，输出角色、指标、规则版本、源日期和远端创建时间。`build_station_role_tracking_row` 在传入精确远端快照时使用其角色和证据，否则保留本地分类；分别输出 `pre_role_source / post_role_source` 和 `pre_source_freshness / post_source_freshness`。
