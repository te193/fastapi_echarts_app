# 补货导出爆单持续高亮实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在完全不改变补货计算结果的前提下，识别同 ASIN 产品组的疑似单日爆单与爆单后回落状态，并在异常仍影响30天日销时持续标黄实际补货目标行。

**Architecture:** 新增独立的纯 Python 稳健异常检测模块，使用30天逐日销量、中位数和 MAD 计算异常状态；90天历史只由独立校准脚本只读回放并生成固定配置。补货 ETL 完成原结果表写入后刷新只读爆单字段，导出服务把这些字段作为隐藏元数据传给 Excel 构建器，Excel 构建器只决定填充颜色，不参与任何销量或补货数量计算。

**Tech Stack:** Python 3.13、标准库 `statistics`/`dataclasses`/`json`、PyMySQL、FastAPI、openpyxl、MySQL、pytest/unittest。

## Global Constraints

- 只修改导出高亮；原始销量、加权日销、库存支撑天数、补货层级、补货数量、箱数、货值均不得变化。
- 日常异常识别只使用最近30个完整销售日；有效历史不足14天时不运行 MAD 新规则，由现有3天/7天规则兜底。
- 最新完整销售日命中异常阈值时立即进入 `suspected`，不等待3天。
- 异常后3个完整销售日回落才进入 `confirmed_recovered`；持续高位进入 `sustained_growth`，不保留一次性爆单长期高亮。
- 90天数据仅用于只读校准和影子回放；正式ETL读取固定配置，不在每日运行时动态重算90天阈值。
- 异常维度为 `country_category + max_asin`，高亮只落在展示补货层级1/2/3且最终导出补货数量大于0的行。
- Excel继续使用浅黄色 `FFF2CC`，不增加可见导出列。
- 当前销量数据为T+1口径；不宣称能够在自然日当天实时识别未同步订单。
- 不新增第三方依赖。
- 不修改或覆盖用户当前未提交的 `docs/补货/规则与口径/current_follow_replenishment_rules.md`。

- [ ] **Step 3: 实现最小数据类型和 MAD 计算**

在 `etl/replenishment_sales_spike.py` 实现以下公开类型；所有 `Decimal` 转换必须通过 `Decimal(str(value))`，不得引入浮点误差：

```python
from dataclasses import dataclass
from datetime import date
from decimal import Decimal
from enum import Enum
from pathlib import Path
from statistics import median
from typing import Sequence


ROBUST_SCALE_FACTOR = Decimal("1.4826")


class SpikeStatus(str, Enum):
    NORMAL = "normal"
    SUSPECTED = "suspected"
    CONFIRMED_RECOVERED = "confirmed_recovered"
    SUSTAINED_GROWTH = "sustained_growth"


@dataclass(frozen=True)
class DailySalesPoint:
    day: date
    sales_qty: Decimal


@dataclass(frozen=True)
class SpikeBand:
    baseline_upper: Decimal | None
    suspected_score_threshold: Decimal
    recovery_mean_upper: Decimal


@dataclass(frozen=True)
class SpikeCalibration:
    lookback_days: int
    min_history_days: int
    scale_floor: Decimal
    bands: tuple[SpikeBand, ...]


@dataclass(frozen=True)
class SpikeDetection:
    status: SpikeStatus
    highlight: bool
    spike_date: date | None = None
    spike_qty: Decimal = Decimal("0")
    baseline: Decimal = Decimal("0")
    score: Decimal = Decimal("0")
    reason: str = ""


def median_and_mad(values: Sequence[Decimal]) -> tuple[Decimal, Decimal]:
    center = Decimal(median(values))
    deviations = [abs(value - center) for value in values]
    return center, Decimal(median(deviations))
```

- [ ] **Step 4: 实现状态机，不在检测器中读取数据库**

实现细节必须满足：

```python
def robust_score(value: Decimal, baseline: Decimal, mad: Decimal, scale_floor: Decimal) -> Decimal:
    scale = max(ROBUST_SCALE_FACTOR * mad, scale_floor)
    return (value - baseline) / scale


def select_band(baseline: Decimal, calibration: SpikeCalibration) -> SpikeBand:
    for band in calibration.bands:
        if band.baseline_upper is None or baseline <= band.baseline_upper:
            return band
    raise ValueError("爆单校准配置缺少兜底销量分组")
```

`detect_sales_spike` 只看最后 `lookback_days` 个输入点；逐个候选日计算时从基线样本中排除候选日，选择最近一个达到所属体量组 `suspected_score_threshold` 的候选日。候选日之后不足3天为 `suspected`；满3天且三天都未再次达到疑似阈值、三日平均不超过 `recovery_mean_upper` 时为 `confirmed_recovered`；否则为 `sustained_growth`。未命中或历史不足返回 `normal`。

- [ ] **Step 3: 实现确定性校准算法**

校准过程使用以下固定方法，避免手写“3倍”：

- 对每个历史产品组滚动计算30日基线、MAD和异常分数。
- 按基线日销的P25、P50、P75把样本划成4个销量体量组；最后一组 `baseline_upper=None`。
- 每组 `suspected_score_threshold` 取该组正异常分数的P99.5。
- 每组 `recovery_mean_upper` 取该组非异常连续3日平均销量的P95。
- 分位数使用线性插值，结果以字符串形式序列化为Decimal，配置键顺序固定。
- 样本不足以形成4组时合并相邻空组，但始终保留最后的无上限兜底组。

实现并单测以下公开接口，函数名和类型不得另行改名：

- `decimal_quantile(values: Sequence[Decimal], quantile: Decimal) -> Decimal`
- `calibrate_spike_bands(samples: Sequence[CalibrationSample]) -> SpikeCalibration`
- `write_spike_calibration(calibration: SpikeCalibration, path: Path, calibrated_at: date) -> None`
- `load_spike_calibration(path: Path) -> SpikeCalibration`

`decimal_quantile` 使用以下线性插值实现，其他三个接口严格按本步骤前述4分组、P99.5、P95和Decimal字符串序列化规则组合，不得增加固定销量倍数分支：

```python
def decimal_quantile(values: Sequence[Decimal], quantile: Decimal) -> Decimal:
    ordered = sorted(values)
    if not ordered:
        raise ValueError("分位数样本不能为空")
    position = quantile * Decimal(len(ordered) - 1)
    lower_index = int(position)
    upper_index = min(lower_index + 1, len(ordered) - 1)
    fraction = position - Decimal(lower_index)
    return ordered[lower_index] + (ordered[upper_index] - ordered[lower_index]) * fraction
```
