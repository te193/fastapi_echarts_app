# 返场页面扩展每页条数实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为返场列表增加 200 条、500 条和全部数据选项，使选择“全部”后 AG Grid 可以对当前业务筛选结果做全量排序和列筛选。

**Architecture:** 前端用 `page_size=0` 表示“全部”，API 接受 0 到 500 的参数范围，服务层用一个纯分页解析函数把请求值转换为查询页码、SQL limit、响应 page_size 和总页数。普通分页保持服务端切片，“全部”以当前筛选总数作为 SQL limit 并固定为单页。

**Tech Stack:** FastAPI、Python 3、Jinja2、原生 JavaScript、AG Grid、pytest/unittest

## Global Constraints

- 默认每页条数保持 `20条`。
- 仅修改返场页面，不调整其他页面的分页选项。
- “全部”只覆盖当前业务筛选结果，不绕过日期、国家、店铺、关键词、快捷筛选或库存状态筛选。
- 不新增服务端 AG Grid 列排序或列筛选协议。
- 保留用户现有未提交改动，不纳入本功能提交。

```python
def _resolve_pagination(page: int, page_size: int, total: int) -> tuple[int, int, int, int]:
    safe_page = max(1, int(page or 1))
    requested_page_size = int(20 if page_size is None else page_size)
    if requested_page_size == 0:
        return 1, max(1, total), 0, 1
    safe_page_size = max(10, min(500, requested_page_size))
    total_pages = max(1, math.ceil(total / safe_page_size))
    return min(safe_page, total_pages), safe_page_size, safe_page_size, total_pages
```
