# 断货前经营画像明细弹窗实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有标签看板 MSKU 明细弹窗内实现“断货前经营画像”，集中展示断货事件、历史主导角色、断货前角色、稳定性、全部历史节点和近期指标变化。

**Architecture:** 继续复用 `/api/label-hub/stockout-before-role-evidence`，由服务层一次查询标签 evidence 与断货历史结果并整理为面向弹窗的结构化对象；前端只做格式化和交互，不重新计算角色或稳定性。弹窗改为单条纵向明细，历史轨迹保留原有横向节点样式并在最左侧增加断货事件。

**Tech Stack:** FastAPI、Python 3、MySQL、原生 JavaScript、CSS、pytest、Playwright CLI。

**Spec:** `docs/superpowers/specs/2026-08-26-断货前经营画像明细弹窗设计.md`

## Global Constraints

- 该功能保留在现有 MSKU 明细弹窗中，不新增页面或路由。
- 只实现 MSKU 维度，不新增国家维度切换。
- 不修改销售角色、稳定性或组合大标签的计算规则。
- 不新增独立可信度模块，不提供补货或运营优先级建议。
- 历史节点全部平铺，最新在左，越向右时间越早，断货事件固定在最左侧。
- 测试和浏览器验收必须在后台、无界面模式运行。
- 当前工作区包含本轮前序改动；所有编辑必须保留现有未提交内容。

- [ ] **Step 3: 扩展查询字段并新增纯格式化助手**

查询 `dashboard_stockout_historical_operating_snapshot` 的断货日期、角色、稳定性和组合标签字段。新增：

```python
def _stockout_evidence_result(row: Mapping[str, Any], history: Mapping[str, Any]) -> dict[str, Any]:
    event_date = _date_text(row.get("oos_start_date"))
    method = str(row.get("oos_start_method") or "")
    confidence = str(row.get("oos_start_confidence") or "")
    if not event_date:
        date_kind, date_label = "pending", "断货起点待确认"
    elif method in {"first_observed", "observed_boundary"} or confidence in {"observed_boundary", "low"}:
        date_kind, date_label = "observed_since", "最早观察到断货"
    else:
        date_kind, date_label = "recent_start", "最近断货开始日"
    metric_nodes = sorted(
        (node for node in history.get("nodes", []) if node.get("is_valid")),
        key=lambda node: (node.get("window_end") or node.get("node_date") or ""),
    )[-3:]
    return {
        "stockout_event": {
            "date": event_date,
            "date_kind": date_kind,
            "date_label": date_label,
            "method": method,
            "confidence": confidence,
        },
        "pre_oos_role": {
            "code": str(row.get("pre_oos_role") or ""),
            "source_date": _date_text(row.get("role_source_date")),
            "evidence_status": str(row.get("role_evidence_status") or ""),
        },
        "historical_primary_role": {
            "code": str(row.get("dominant_role") or ""),
            "share": float(row.get("dominant_role_share") or 0),
            "valid_node_count": int(row.get("valid_window_count") or 0),
        },
        "stability": {
            "code": str(row.get("historical_stability") or "insufficient"),
            "role_switch_rate": float(row.get("role_switch_rate") or 0),
            "role": str(row.get("role_stability") or ""),
            "sales": str(row.get("sales_stability") or ""),
            "margin": str(row.get("margin_stability") or ""),
        },
        "combined_conclusion": {
            "code": str(row.get("combined_label_code") or ""),
            "label": str(row.get("combined_label") or ""),
            "recent_trend": str(row.get("recent_trend") or ""),
            "daily_sales_trend": str(row.get("daily_sales_trend") or ""),
            "margin_trend": str(row.get("margin_trend") or ""),
        },
        "metric_trend_nodes": metric_nodes,
    }
```

`date_kind` 按 `oos_start_method` 和 `oos_start_confidence` 映射为 `recent_start`、`observed_since` 或 `pending`。节点数据直接来自 `historical_role_history.nodes`，按日期降序取最近三个有效节点用于指标解释。
