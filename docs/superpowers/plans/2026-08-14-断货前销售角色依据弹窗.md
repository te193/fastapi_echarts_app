# 断货前销售角色依据弹窗 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在标签看板明细表增加按需查看断货前销售角色 `evidence_json` 的完整分层弹窗。

**Architecture:** 后端新增单条只读依据接口，以 MSKU 业务键、日期和周期精确查询父标签 20 的一条事实记录并安全解析 JSON。前端 AG Grid 新增操作列，点击后请求接口并在模板内的无障碍弹窗中按五个页签渲染，原始 JSON 作为最后一级审计信息。

**Tech Stack:** FastAPI、Pydantic、PyMySQL 数据访问封装、原生 JavaScript、AG Grid、Jinja2、CSS、pytest。

## Global Constraints

- 只使用 MSKU 维度父标签 20、子标签 2001–2004；不展示父标签 21。
- 所有 pytest、浏览器和本地服务验证必须在后台或 headless 模式运行，不影响用户前台工作。
- 保留现有脏工作区中的无关修改，只修改本功能直接相关文件。
- 文件和字段缺失时降级显示“暂无”，不得伪造数据。
