# 断货前经营大标签重构 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有断货前历史经营旧模型替换为以每日库存快照识别断货、以30天有效经营窗口计算销售角色，并输出历史稳定性、近期趋势和组合大标签的MSKU维度模型。

**Architecture:** 当前断货商品池只由标签304提供，标签命中即确认当前断货，不再使用当天库存或旧销售角色标签进行二次准入；每日库存快照只负责反推最近断货日及历史断货、恢复时间线，每日经营明细只负责销量、销售额和毛利。纯计算函数在 `app/services/stockout_historical_operating.py` 中完成节点、窗口、稳定性和标签计算，ETL负责装载、聚合和保存，同一结果表通过新增字段兼容迁移，接口和页面只消费新字段。

**Tech Stack:** Python 3、MySQL、FastAPI服务层、原生JavaScript、pytest。

**Spec:** `docs/标签看板/规则与口径/2026-08-25-断货前经营角色与历史稳定性规则梳理.md`

## Global Constraints

- 历史观察范围固定为2026-01-01至本次断货前一日T0。
- 第一版只输出 `business_unit`（国家大区+店铺+MSKU）结果，不生成国家维度结果。
- 当前断货商品池只取标签304；本计划不修改标签304本身的断货识别门槛，也不根据库存或旧销售角色标签重新判断当前是否断货。
- 历史中途断货的技术时间线按每日库存快照中MSKU可售库存最大值为0识别；该判断集中封装，后续调整断货门槛时只替换一处。
- MSKU每日 `afn_fulfillable_quantity` 取最大值，不求和。
- 经营明细缺行不得反推“当天未断货”；库存日期缺失应标记数据边界或异常。
- 销售角色仅保留明星、潜力、瘦狗、问题四类，不新增零销量角色。
- 历史稳定性只统计互不重叠的正常30天窗口；沿用和恢复观察节点不重复计数。
- 历史稳定：主导角色占比≥70%且角色切换率≤35%；轻度波动：主导角色占比≥60%且角色切换率≤50%并且未达到历史稳定；其余为历史波动。
- 最近趋势只使用最近3个有效窗口；角色一致时才使用日销、毛利判断组合标签。
- 日销明显变化必须同时满足相对变化>20%和绝对变化≥0.2件/天；前值为0时只看绝对变化是否≥0.2件/天。
- 毛利率变化超过3个百分点才算明显变化，±3个百分点以内视为稳定。
- 指标主结论优先级固定为：下降 > 波动 > 改善 > 稳定。
- 本模块不输出补货建议、恢复优先级或补货行动队列。
- 不新建独立明细表；沿用现有结果表，通过新增字段和 `evidence_json` 保存新证据。
- 保留用户当前未提交改动，不重置、不覆盖；执行前先逐个查看相关文件现有差异并做增量修改。
- 由于相关文件已有未提交改动，计划执行期间不自动提交；每个任务完成后提供可审查检查点，得到用户授权后再提交。
- 所有pytest、回归测试和页面验证均使用隐藏后台进程；后台进程必须满足 `CreateNoWindow=true`、`WindowStyle=Hidden`，并将标准输出和错误写入独立日志后轮询结果。

    if (1 <= daily_sales <= 5 and 0.05 <= margin_rate < 0.10) or (0 < daily_sales < 1 and margin_rate > 0.05):
        return "dog"
    return "problem"
