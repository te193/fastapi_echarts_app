# 断货前经营表现多周期与国家维度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改变“当前断货”和现有 30 天可评价口径的前提下，为可评价记录增加断货前趋势，并提供 MSKU 汇总/国家维度双视图。

**Architecture:** 后端统一构造以各记录断货日前一天为锚点的 7/14/30/90 天证据索引，30 天角色固定作为正式基线，趋势由非重叠销量区间派生；国家视图从国家明细全集左连接父标签 21，避免缺失角色记录从分母消失。汇总、成员筛选、明细和导出复用同一派生结果。前端只切换 `scope` 和证据查看周期，不在浏览器重算经营结论。

**Tech Stack:** FastAPI、Python、原生 JavaScript、CSS、pytest

**Spec:** `docs/superpowers/specs/2026-08-19-断货前可评价经营表现多周期基线设计.md`

## Global Constraints

- 30 天是唯一正式基线；7/14/90 天按钮只切换证据展示，不改变一级卡片数量。
- 所有窗口截止到每条记录的 `oos_start_date - 1 day`，不得按当前日期倒推。
- MSKU 汇总使用父标签 20（2001～2004），国家维度使用父标签 21（2101～2104）和小类排名，两个粒度禁止互相聚合角色。
- 国家记录全集来自国家明细并左连接角色；角色缺失必须进入依据不足。
- 自动化测试与浏览器验收均在隐藏后台运行；保留现有 `outputs/` 和无关文件。
