# 同 ASIN 补货承接 MSKU 时效性设计

## 背景

补货 ETL 会把同一国家大区、同一 ASIN 的补货需求合并到一个跟卖链接。当前承接目标主要按被跟卖状态、停售状态、采购成本、库存和近 30 天销量排序，没有优先判断 MSKU 最近是否仍有产品表现数据。

2026-07-27 最新补货快照中，共发现 11 组当前承接 MSKU 的产品表现日期落后于同 ASIN 其他候选链接。其中 2 组正在产生补货数量，另外 9 组当前补货数量为 0。

## 目标

同 ASIN 存在多个可承接跟卖链接时，优先选择产品表现日期最新的 MSKU，避免补货数量和货值承接到已经停止更新的旧 MSKU。

本次不修改补货层级、需求量、销量、库存、箱规、货值和同 ASIN 合并计算公式。

## 选择规则

1. 仅在现有可承接候选链接中选择，不扩大候选范围。
2. 为每个候选链接取得本地产品表现表中的最新 `dt_date`。
3. 承接目标排序时，最新产品表现日期更晚的候选优先。
4. 产品表现日期相同时，继续沿用现有排序：
   - 优先未被其他链接跟卖的候选。
   - 优先非停售候选。
   - 优先采购成本字段完整的候选。
   - 优先有支持库存的候选。
   - 优先近 30 天有销量的候选。
   - 最后按店铺和 MSKU 稳定排序。
5. 候选没有产品表现日期时排在有日期候选之后。

## 预期结果

- `B0DP3ZL1RL` 的承接目标从 `YuanJinRong/YJR015a` 切换到 `YuanJinRong/5L-KMVA-BDDG`。
- `B0DP9CD47N` 的承接目标从 `YuanJinRong/YJR023a` 切换到 `YuanJinRong/Q8-XW1Y-P3G6`。
- 另外 9 组当前补货数量为 0 的旧承接目标也会按同一规则切换，避免未来触发补货时继续使用旧 MSKU。
- 同一 ASIN 的合并补货总数量和总货值口径不变，只改变最终承接行。

## 数据流

在补货结果 SQL 的同 ASIN 承接目标阶段，使用已有产品表现表按国家大区、店铺和 MSKU 聚合最新日期，并把该日期加入 `tmp_asin_merge_targets` 的窗口排序。

不新增正式表字段，不修改接口和前端。重跑补货 ETL 后，当天结果表中的承接目标、承接行补货数量及货值随新规则更新。

## 测试

1. SQL 回归测试确认承接目标排序包含最新产品表现日期，且该条件位于现有排序条件之前。
2. SQL 回归测试确认候选仍限制为现有可承接跟卖链接。
3. 运行补货 SQL 相关测试和完整测试集。
4. 重跑 2026-07-27 补货 ETL。
5. 核对两个指定 ASIN 的承接目标、补货数量和货值。
6. 复查 11 组时效落后记录，确认新承接目标日期等于各组候选最新日期。

## 风险控制

- 产品表现日期仅决定承接目标优先级，不参与补货需求量计算。
- 日期相同的候选继续使用原排序，减少对已有稳定结果的影响。
- 不手工更新结果表，所有结果通过补货 ETL 重算，保证后续每日任务一致。
