# 调价复盘销售角色周期与固化设计

## 1. 目标

调价复盘允许分别选择调前和调后销售角色周期，并优先复用远端 DWS 已生成的站点销售角色。远端没有对应周期或历史日期时，使用本地明细按同一规则重算。

本方案解决三个问题：

- 调前周期不再固定为 30 天。
- 远端标签更新后能够在每日 ETL 中及时同步，同时页面稳定性不依赖远端数据库。
- 不建设全量历史标签仓库，只固化实际参与调价复盘的产品。

## 2. 已确认事实

- 远端结果表为 `dws_datasync.dws_标签表`。
- 站点销售角色标签为 `1301–1304`，粒度是 `data_date + country + store + msku + label_period`。
- 远端已有周期为 `7d / 14d / 30d / 90d`，没有 `3d`。
- 远端每个数据日、每个周期当前约 40,592 条站点记录，业务键无重复。
- 当前观察到远端在次日约 07:18–07:19 批量生成上一数据日的四个周期；实现仍按远端可能重跑和修正设计。
- 当前远端历史从 2026-08-15 开始，早于该日期的调价角色不能依赖远端历史回填。
- 调价复盘只处理 2026 年 8 月及之后的调价记录。

## 3. 用户可选口径

调前周期和调后周期分别独立选择，统一提供：

- 3 天
- 7 天
- 14 天
- 30 天
- 90 天

默认值为“调前 30 天、调后 3 天”。原 `decision_30d / equal_window` 对比模式不再作为用户筛选项；等周期对比由用户直接选择相同的调前、调后周期实现。

窗口定义保持不变：

- 调前 N 天：`D-N 至 D-1`。
- 调后 N 天：`D+1 至 D+N`。
- 调价当天 D 不进入任何窗口。
- 远端角色的 `data_date` 必须等于对应窗口结束日：调前为 `D-1`，调后为 `D+N`。

页面必须显示实际日期，例如：

> 调前 30 天（07/08–08/06） 对比 调后 3 天（08/08–08/10），调价日 08/07 已排除。

## 4. 数据来源优先级

调前和调后分别解析来源，不要求两侧使用同一种存储来源，但必须使用相同角色规则语义。

每一侧按以下顺序取值：

1. 已存在该调价产品、截止日期和周期的固化结果时，直接使用固化结果。
2. 周期为 7/14/30/90 天，且远端近两日缓存中存在精确 `data_date + label_period + country + store + msku` 时，使用远端结果并立即固化。
3. 周期为 3 天时，使用本地销售明细按 `station_sales_role_v47_local` 重算并固化。
4. 远端缺少目标历史日期或精确业务键时，使用本地销售明细按同一规则重算并固化。
5. 本地明细不足时标记数据不足，不使用其他日期、其他周期或当前标签代替。

来源枚举：

- `remote_dws`：远端标签同步结果。
- `local_recomputed`：本地明细重算结果。
- `unavailable`：远端和本地均无法得到可靠结果。

数据新鲜度与来源分开记录：远端同步失败后沿用的旧缓存仍属于 `remote_dws`，但新鲜度必须标记为 `stale`，不得伪装成最新数据。

## 5. 两层本地存储

### 5.1 远端近两日滚动缓存

新增 `station_sales_role_recent_cache`，只保留远端最新两个不同的 `data_date`，缓存标签 `1301–1304` 的 7/14/30/90 天结果。

主键：

`data_date + label_period + country + store + msku`

其中远端 `store` 必须通过确定性映射转换为调价复盘使用的 `station_store`；匹配始终使用 `country + station_store + msku`，不得模糊匹配或跨国家复用。

保存字段：

- `label_id`、标准化角色代码和角色名称。
- `evidence_json`。
- 远端 `created_time`。
- 本地 `synced_at`。
- 同步批次号和同步状态。

缓存按远端最新两个实际数据日滚动，不按本地自然日推算，以兼容远端延迟。

### 5.2 调价产品固化结果

调整现有 `price_review_station_role_tracking`，其业务唯一粒度改为：

`adjust_date + pre_period_days + post_period_days + country + station_store + msku`

只保存调价队列中的产品，不保存远端全量站点历史。

新增或明确保存：

- 调前、调后周期和实际窗口日期。
- 调前、调后角色、角色等级及迁移结果。
- `pre_role_source / post_role_source`。
- `pre_source_freshness / post_source_freshness`。
- `pre_source_data_date / post_source_data_date`。
- 远端源记录创建时间和本地固化时间。
- 调前、调后日销、销售额、订单毛利、毛利率和排名证据。
- 数据成熟状态、缺失原因和规则版本。
- 调前价、调后价及财务定价区间。

原 `comparison_mode` 可在兼容期内保留为派生字段，但不再参与新页面口径选择或新唯一键。

## 6. ETL 时序

每日总 ETL 中增加以下步骤：

1. 读取远端标签表最新两个不同的 `data_date`。
2. 将标签 `1301–1304` 的 7/14/30/90 天结果写入临时表。
3. 校验每个日期和周期的行数、业务键唯一性、国家和店铺缺失率。
4. 校验通过后，在事务中覆盖本地缓存对应日期；失败时保留上次成功缓存并记录告警。
5. 找出尚未固化调前角色或调后窗口刚成熟的调价产品。
6. 按数据来源优先级解析角色，只将这些调价产品写入固化事实表。
7. 对 3 天周期及远端历史缺口执行本地重算。
8. 更新规则漂移对账结果和数据新鲜度状态。

不在页面请求期间直接连接远端数据库。需要临时更新时，提供后台“同步最近两日标签”任务或管理命令，完成后页面仍读取本地库。

## 7. 更新与修正规则

- 最近两个数据日每次 ETL 都重新拉取并覆盖，因此远端对上一日的修正会自动进入本地缓存。
- 已固化的 `remote_dws` 结果在其源日期仍位于近两日缓存时允许更新，记录新的远端 `created_time`。
- 源日期移出近两日后，固化结果不再因当前远端标签变化而改变，保证历史复盘可复现。
- 本地重算结果随本地明细补齐允许重新计算，直到数据状态成熟；成熟后仅在规则版本变化或人工指定重算时更新。
- 规则版本变化不得静默覆盖旧结果，需要记录新版本并触发对账告警。

## 8. 页面表达

筛选区改为独立的“调前周期”和“调后周期”，删除“调前 30 天 → 调后 N 天”等内部术语。

页面状态行显示：

- 实际调前、调后日期范围。
- 调前和调后各自的数据来源。
- 远端缓存数据日期和同步时间。
- 规则版本。

SKU 明细对两侧分别显示来源标识：

- 远端标签
- 本地重算
- 数据不足

来源只作为可追溯信息，不改变角色上升、保持和下降的计算方式。

## 9. 异常与降级

- 远端不可用：ETL 保留上次缓存并告警；页面继续读取本地，不阻塞看板。
- 远端最新数据不完整：整批缓存不覆盖，避免半批数据进入复盘。
- 精确业务键缺失：仅该产品回退本地重算，不使用模糊店铺或跨国家匹配。
- 本地明细不足：标记数据不足，不计入角色下降。
- 调后窗口未成熟：标记待观察，不提前生成调后角色。

## 10. 验收与测试

- 验证调前、调后周期可以独立选择 3/7/14/30/90 天。
- 验证 D 不进入任一窗口，远端 `data_date` 与窗口结束日精确一致。
- 验证远端缓存只保留最新两个实际数据日。
- 验证同一业务键远端重跑后能够覆盖近两日缓存及未冻结固化结果。
- 验证只有调价产品进入历史固化事实表。
- 验证 3 天周期始终本地重算。
- 验证远端历史缺口回退本地重算。
- 验证远端异常不会导致页面接口失败。
- 验证数据不足和待观察不计入角色下降。
- 验证调前、调后来源、规则版本和同步时间可追溯。
- 验证 KPI、迁移矩阵与明细数量一致。

## 11. 非目标

- 不建设全量、长期的远端标签历史仓库。
- 不让页面接口直接查询远端 DWS。
- 不修改远端标签表或标签规则。
- 不回填 2026 年 8 月以前的调价复盘。
