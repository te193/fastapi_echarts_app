# 高风险业务链路回归测试设计

## 目标

在现有 419 条测试基础上，围绕最近新增功能和高风险业务口径补充约 20 条回归测试。测试重点是阻止错误业务结果进入页面或每日任务，不以单纯增加测试数量为目标。

本次覆盖国家画像、补货货值与跟卖继承、每日 ETL 调度三条链路。默认只增加测试；如果新增测试暴露真实缺陷，先定位根因，再以最小改动修复并补充验证。

## 测试范围

### 国家画像

- 同一 MSKU 在不同店铺之间必须严格隔离。
- 国家明细按国家去重，不能因多标签、多周期产生重复国家行。
- 日均销量使用周期销量除以有库存天数；库存天数为 0 时返回 0。
- 7 天、14 天、30 天、90 天指标周期必须原样传递到经营指标查询和响应口径。
- 当前 listing 价格落在毛利阶梯边界时，归入以该边界为下限的区间。
- 价格缺失、毛利阶梯缺失或无有效阶梯时，毛利区间返回 `--`。
- 7 天、14 天、30 天、90 天国家销售角色必须分别展示，不能串用周期。
- 国家排序优先按销量降序，同销量时使用稳定国家顺序。
- 聚合汇总中的覆盖国家数、销量、销售额和数据完整性计数必须与国家明细一致。
- 国家画像 API 必须正确传递参数，并把业务未找到映射为 404、数据服务异常映射为 503。

### 补货货值与跟卖继承

- 当前链接有采购价和运费时优先使用自身字段。
- 当前链接缺少采购字段时，允许从跟卖原始链接继承采购价和运费。
- 原始链接没有箱规但有采购价和运费时，仍能计算补货货值，箱数保持 0。
- 只有采购价或只有运费时，不生成伪造货值。
- 同 ASIN 合并后补货数量为 0 的行，货值必须同步为 0。
- 历史兜底恢复补货数量时，展示货值使用恢复数量乘以有效单位成本。

### 每日任务

- 标签证据快照、补货结果、补货追踪汇总和返厂 ETL 的调用顺序必须稳定。
- 远端数据预检失败时，不得继续执行后续写库 ETL。
- dry-run 或测试模式不得写库、不得发送钉钉消息。
- 通知脚本失败不得覆盖 ETL 原始退出码和业务结果。

## 实现边界

- 优先扩展现有测试文件，不新增与现有测试结构重复的测试框架。
- 数据服务测试使用内存夹具或假连接，不访问远端数据库。
- SQL 与调度测试读取生成 SQL 或 PowerShell 脚本文本，不执行写库语句。
- API 测试使用 FastAPI `TestClient` 或直接替换服务对象，不依赖 8000 端口。
- 前端契约只验证关键 DOM、字段和事件绑定，不对整份 HTML 或 JavaScript 做大段快照。

## 验收标准

- 新增测试名称能直接说明保护的业务规则。
- 新增用例与现有测试没有重复断言。
- 定向测试全部通过。
- 完整测试集全部通过，测试总数预计由 419 增加至约 439。
- 测试执行不写数据库、不修改业务数据，也不发送钉钉通知。
