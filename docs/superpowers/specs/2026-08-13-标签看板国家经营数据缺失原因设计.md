# 标签看板国家经营数据缺失原因设计

## 目标

让国家明细中没有经营指标的行表达得更准确，并在 CSV 导出中说明缺失属于“仅当前国家缺失”还是“整个 MSKU 都缺失”。

## 状态文案

国家标签事实存在、但未匹配到国家经营日表行时，`经营数据状态` 从“暂无国家经营数据”调整为：

> 仅有国家标签，暂无经营指标

该文案明确区分“国家明细不存在”和“国家明细存在但经营指标缺失”。经营数据源整体不可用时仍使用现有“国家经营指标暂不可用”，不混为单行数据缺失。

## 缺失原因分类

国家明细行新增内部字段 `metric_missing_reason`，CSV 中文列名为“经营数据缺失原因”。判断只依据当前经营周期查询实际返回的经营行：

- 当前行已匹配经营数据：原因留空。
- 当前行未匹配经营数据，但同一“店铺 + MSKU”在其他国家匹配到经营数据：`该 MSKU 仅当前国家暂无经营数据`。
- 当前行未匹配经营数据，且同一“店铺 + MSKU”在所有国家都未匹配到经营数据：`该 MSKU 暂无任何国家经营数据`。
- 国家经营数据源整体不可用：`国家经营指标源暂不可用`。

同一 MSKU 在不同店铺下分别判断，防止把其他店铺的数据误当作当前店铺的数据。国家类别不作为产品存在性分组键，因为同一店铺/MSKU 的国家经营覆盖判断需要跨国家类别识别；当前行的精确经营关联仍保持“国家 + 国家类别 + 店铺 + MSKU”。

## 数据流

国家经营指标查询完成后，先从所有返回的经营行建立 `(店铺, MSKU)` 集合，再处理标签行：

1. 精确四字段键匹配成功的行标记为有经营数据，缺失原因为空。
2. 未精确匹配的标签行查询 `(店铺, MSKU)` 是否存在于经营集合，生成两类缺失原因。
3. 公共明细服务保留该字段。
4. 国家明细 CSV 增加“经营数据缺失原因”；MSKU 维度不增加该国家站点原因列。

不使用售价、限价或 Listing 快照判断经营数据是否存在。Listing 有价格并不代表领星经营表现表存在该国家记录。

## 边界与兼容

- 不删除仅有标签的国家行。
- 不改变筛选、排序、分页、价格、ACOS/TACOS 或库存口径。
- 不新增数据库查询，原因在现有结果集内存计算。
- SKU 继续来自国家经营日表；没有经营行时保持空值。
- 已有经营数据的行原因列为空，不输出“正常”等冗余文本。

## 测试与验收

- 构造同一店铺/MSKU 的美国有经营行、加拿大只有标签行：加拿大原因应为“该 MSKU 仅当前国家暂无经营数据”。
- 构造另一店铺/MSKU 在所有国家均只有标签行：原因应为“该 MSKU 暂无任何国家经营数据”。
- 已匹配经营数据的行原因为空，状态仍为“国家经营指标可用”。
- 数据源整体不可用时原因是“国家经营指标源暂不可用”。
- 国家明细 CSV 含“经营数据缺失原因”列，MSKU 维度不含该列。
- 全量标签看板测试通过；真实国家明细导出中两类原因数量可统计且总和等于无经营数据行数。
