# 补货列表交期信息紧凑展示设计

## 目标

在补货 SKU 列表中直接说明采购交期对库存的影响，让使用者能够一眼看出：当前库存还能支撑多久、采购交期是多少、货物到达时库存还能支撑多久，以及交期内是否存在断货风险。

页面不能为了展示这些信息连续增加多列表格字段。导出文件也不增加重复的组合展示列，继续使用已有的原始指标字段。

## 已选方案

采用“一列浓缩展示”。将当前表格中的“支撑天数”列升级为“库存 / 交期”列，列宽由约 118px 调整为约 170px，不增加新的可见表格列。

单元格默认分为两行：

- 第一行：当前库存支撑天数，以及交期风险状态。
- 第二行：采购交期和到货时库存支撑天数，格式为“交期 10 天 → 到货 82.86 天”。

正常状态示例：

```text
92.86天                         安全
交期10天 → 到货82.86天
```

存在交期断货风险时：

```text
7.40天                  预计断货2.60天
交期10天 → 到货−2.60天
```

## 指标口径

页面只消费 ETL 已经计算并落库的指标，不在浏览器端重复推导业务公式。

| 展示内容 | 数据字段 | 说明 |
|---|---|---|
| 当前库存支撑天数 | `inventory_support_days` | 当前支撑库存量除以计算日销 |
| 采购交期 | `effective_purchase_lead_days` | 有效采购交期；未配置时按 0 天处理 |
| 到货时支撑天数 | `arrival_inventory_support_days` | 当前支撑天数减去采购交期，允许为负数 |
| 交期预计消耗 | `lead_time_demand_qty` | 采购交期内预计销售数量 |
| 到货时预计库存 | `arrival_inventory_qty` | 当前支撑库存扣除交期预计消耗后的数量；沿用现有 ETL 口径，最低显示为 0 |
| 预计断货天数 | `lead_time_stockout_days` | 采购交期超过当前支撑天数的部分 |
| 交期断货状态 | `lead_time_stockout_flag` | 标记交期内是否存在断货风险 |
| 交期状态 | `purchase_lead_status` | 标识交期来自配置还是默认值等现有状态 |

## 交互与视觉状态

“库存 / 交期”单元格提供两个信息层级：

1. 默认状态只显示当前支撑天数、有效采购交期、到货支撑天数和风险标记。
2. 鼠标悬停或点击单元格时，显示交期预计消耗、到货时预计库存、预计断货天数和交期状态。

风险标记使用现有页面的状态标签风格：

- `lead_time_stockout_flag = 0`：绿色“安全”。
- `lead_time_stockout_flag = 1`：红色“预计断货 N 天”。
- 无法计算：中性灰色提示，不显示成安全或断货。

单元格内容保持右对齐数字的可扫描性；第二行使用较小、较弱的文字颜色。到货支撑天数为负数时保留负号并使用风险色，不截断为 0。

## 异常与边界情况

- 采购交期未配置：展示“未配置（0天）”，不扣减库存支撑天数，并在明细中展示现有交期状态。
- 日销小于或等于 0：显示“无法计算支撑天数”，不将其误判为交期安全或预计断货。
- 到货支撑天数为负数：原值展示，用于说明预计断货天数；到货预计库存沿用现有 ETL 结果，最低为 0。
- 指标值为空：对应位置显示短横线，不在前端自行补算。

## 数据流与改动范围

1. 补货列表查询补充读取现有交期指标字段。
2. 列表接口序列化这些字段，保留两位小数；状态字段保持原始语义。
3. 前端将原“支撑天数”列替换为“库存 / 交期”复合单元格。
4. 排序仍以 `inventory_support_days` 为主，避免改变现有“按支撑天数排序”的使用习惯。
5. 导出逻辑不新增组合展示列；已有原始交期指标继续按当前导出机制保留。

本次不修改 ETL 计算公式、不修改补货分层、不修改补货数量，也不调整其他补货追踪页面。

## 测试与验收

后端测试覆盖：

- 列表查询包含全部交期指标。
- 序列化结果保留负数，并按两位小数输出数量和天数。
- 空值与日销为 0 时不会被前端数据错误替代。

前端测试或静态契约测试覆盖：

- 表格只保留一个“库存 / 交期”列，不额外堆叠五个交期列。
- 正常、预计断货、无法计算三种状态使用正确文案。
- 明细信息包含交期预计消耗、到货预计库存、预计断货天数和交期状态。

页面验收覆盖：

- 在 8002 测试页面检查正常 SKU 和交期内断货 SKU。
- 检查列宽、两行信息密度、横向滚动和表头筛选状态。
- 确认现有支撑天数排序仍然有效。
- 确认导出没有增加重复的组合展示列。
