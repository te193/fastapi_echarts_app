# 标签看板远端联动卡片独立周期设计

## 目标

在三个“远端标签结构”联动卡片中分别增加标签周期选择器。用户查看运营状态群体时，可以将销售角色切换为 `7d`、`14d`、`30d` 或 `90d`，同时让库存水平、流量结构保留各自适用的周期。

本次只扩展远端标签联动卡片；顶部“标签周期”仍只控制当前分析标签，本地经营卡片继续由顶部“经营周期”控制。

## 交互规则

- 每张远端卡片同时提供“切换维度”和“标签周期”两个选择器。
- 周期选项来自该父标签在当前标签事实中的实际可用周期，并补充“全部周期”。
- 切换卡片维度时，若原周期在新维度中不可用，则自动回退到“全部周期”。
- 三张远端卡片的周期互相独立，不改变顶部当前标签周期。
- 选择周期后立即刷新该卡片分布、KPI、问题概览、矩阵和明细。
- 点击卡片中的子标签时，筛选条件同时携带该卡片周期；删除标签条件时一并删除对应周期。
- 同一个父标签不会同时出现在多个远端卡片中，因此一个父标签在一次分析中只有一个联动周期。

## URL 与接口

前端继续使用 `analysis_parent_ids` 保存三个联动维度，并新增：

```text
analysis_periods=7d|current|30d
```

三个周期值与 `analysis_parent_ids` 按位置对应。空值或无效值统一归一为 `all`。

`GET /api/label-hub` 新增 `analysis_periods` 参数。服务端按联动父标签建立周期映射：

- 计算远端卡片分布时，只读取该父标签对应周期的子标签。
- 应用该父标签的 `conditions` 时，使用相同周期，保证展示口径与点击筛选口径一致。
- 未传 `analysis_periods` 时全部按 `all` 处理，兼容旧 URL 和现有调用方。

响应中的每个远端 breakdown 增加：

- `label_period`：当前生效周期。
- `periods`：该父标签可用周期列表。

## 数据口径

标签周期过滤只作用于远端标签事实中的 `_by_parent_period`，不重新计算标签，也不改变本地经营指标周期。销售额、毛利润等经营指标仍来自顶部所选本地周期快照。

同一 MSKU 在所选周期内命中多个子标签时，继续沿用当前父标签配置的优先级，只保留优先级最高的子标签参与聚合。

## 验证

- 运营状态作为当前标签时，销售角色卡片分别选择 `7d`、`14d`、`30d`、`90d`，分布随周期变化。
- 三张远端卡片可保存不同周期，互不覆盖。
- 点击周期化子标签后，KPI、问题概览、矩阵和明细使用相同周期条件。
- 切换到不支持当前周期的维度时回退到“全部周期”。
- 刷新页面可以从 URL 恢复三个周期。
- 未携带新参数的旧链接保持现有“全部周期”行为。
