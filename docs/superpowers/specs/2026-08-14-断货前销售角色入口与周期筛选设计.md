# 断货前销售角色入口与周期筛选设计

## 背景

标签中心首页按 MSKU 分析口径展示，不适合把站点维度的父标签21“断货前销售角色(站点)”作为普通分析卡片长期陈列。但运营人员需要从“当前断货中”商品出发，快速查看这些商品在断货前属于哪类销售角色，并继续进入经营明细核查。

本设计采用已确认的方案1：在“运营状态 → 断货中”卡片内增加入口，点击后就地展开断货前角色汇总，并提供 7天、14天、30天、90天四个角色周期。

## 目标

- 入口范围与用户当前看到的“断货中”数量保持一致。
- 展示当前断货店铺商品在指定周期下的四类断货前销售角色分布。
- 支持从任一角色或全部角色继续进入现有经营明细。
- 保持标签21不出现在首页 MSKU 分析卡片、当前分析标签和对比选择器中。
- 直接读取开发校正后的远端标签20、21数据，不在页面端补算或覆盖标签结果。

## 非目标

- 不修改标签20、21的生成 SQL、远端表结构或数据修复流程。
- 不新增独立页面。
- 不把标签21重新纳入通用首页分析和多维联动。
- 不改变“断货中”标签304及运营状态卡片的现有口径。

## 用户流程

1. 用户在“当前分析标签 → 运营状态”看到“断货中”卡片。
2. 卡片底部显示“查看断货前角色”入口。
3. 点击后，在卡片下方就地展开“断货前角色分布”面板。
4. 面板默认使用当前页面经营周期；若当前周期不属于四个可选值，则默认30天。
5. 用户可切换 7天、14天、30天、90天，四类角色数量、占比和数据覆盖提示同步刷新。
6. 点击某一角色行，带着“当前断货中 + 对应角色 + 当前角色周期”进入下方经营明细。
7. 点击“查看全部明细”，带着“当前断货中 + 四类角色 + 当前角色周期”进入下方经营明细。
8. 再次点击入口、点击面板外部或按 Esc 可收起面板。

## 界面设计

### 入口

- 入口放在“断货中”卡片底部，位于“返场期再次断货”提示下方。
- 文案固定为“查看断货前角色”；展开后可显示向上的收起箭头。
- 当标签21没有任何可用周期数据时，入口保留但呈禁用状态，提示“断货前角色数据暂不可用”，避免用户误以为功能消失。

### 汇总面板

- 面板与“断货中”卡片保持视觉连接，不使用弹窗或侧边抽屉。
- 标题为“断货前角色分布”，同时显示当前范围，例如“断货中 358”。
- 标题右侧放置单选周期：7天、14天、30天、90天。
- 四行固定对应标签2101—2104：明星产品、潜力产品、瘦狗产品、问题产品。
- 每行展示角色名称、店铺商品记录数、占当前断货范围比例和轻量进度条。
- 面板底部提供“查看全部明细”。角色行与明细入口均可通过键盘聚焦和触发。

### 加载与异常状态

- 首次展开和切换周期时只让面板进入加载态，不阻塞整个标签中心页面。
- 请求失败时在面板内显示“断货前角色汇总加载失败，请重试”，保留重试按钮。
- 若当前周期没有角色事实，显示空状态，不沿用上一周期结果。
- 若远端数据未完全覆盖当前断货范围，显示“已识别 X / 当前断货 Y，未识别 Z”。四类占比仍以当前断货总记录数 Y 为分母。
- 若同一店铺商品在同一周期命中多个2101—2104标签，作为冲突记录单独提示，不重复计入四类汇总。

## 数据口径

### 当前断货范围

当前断货集合由数据日期下父标签3、子标签304“断货中”的事实确定，并继承页面当前的国家类别、店铺和关键词公共筛选。

统计主键固定为：

`国家类别 + 店铺 + MSKU`

标签21是站点维度标签，因此不能只按 MSKU 去重。同一 MSKU 在不同店铺或国家类别下应保留为不同店铺商品记录。

### 角色周期

角色周期使用远端事实中的 `label_period`：

| 页面文案 | 请求值 |
| --- | --- |
| 7天 | `7d` |
| 14天 | `14d` |
| 30天 | `30d` |
| 90天 | `90d` |

周期只约束父标签21的角色事实，不改变父标签3“当前断货中”的 current 口径，也不改变页面经营指标周期。

### 汇总关系

设当前断货集合为 S，指定周期下标签21的有效角色事实为 R：

- 通过 `国家类别 + 店铺 + MSKU` 关联 S 与 R。
- 四类角色数量统计关联后唯一店铺商品记录数。
- 每类占比 = 该角色记录数 / 当前断货总记录数。
- 已识别数 = 四类互斥角色记录数之和。
- 未识别数 = 当前断货总记录数 - 已识别数 - 冲突数。
- 数据正常时，四类角色数之和应等于当前断货总记录数，冲突数和未识别数均为0。

## 服务接口

### 汇总接口

新增按需加载接口：

`GET /api/label-hub/stockout-before-roles`

请求参数：

- `data_date`
- `role_period`：仅允许 `7d`、`14d`、`30d`、`90d`
- `country_category`
- `store`
- `keyword`

响应至少包含：

- 当前断货总记录数与唯一 MSKU 数
- 当前角色周期
- 2101—2104四类角色的记录数、唯一 MSKU 数、占比
- 已识别数、未识别数、冲突数和覆盖率
- 可用周期列表

接口在用户展开面板或切换周期时调用，不增加标签中心首页首次加载成本。缓存键必须包含数据日期、角色周期及公共筛选。

### 经营明细

复用现有 `POST /api/label-hub/details` 与导出接口，不复制一套明细页面。为明细请求增加专用字段：

- `stockout_before_role_period`
- `stockout_before_role_ids`
- `current_stockout_only`

入口下钻时：

- `current_stockout_only = true`
- `stockout_before_role_period` 等于面板当前周期
- 点击某一角色时只传对应2101—2104；点击全部明细时传四个角色ID
- 明细行增加“断货前角色”和“角色周期”展示，CSV导出保持相同口径

不复用全局 `label_period` 表达角色周期，因为全局字段属于首页当前分析标签，若直接复用会错误影响父标签3和其他分析条件。

## 前端状态

新增独立的面板状态，不写入首页通用分析状态：

- 是否展开
- 当前角色周期
- 汇总请求状态和结果
- 当前下钻角色

周期默认值优先取页面 `metric_period`，仅当其为四个允许值之一；否则使用 `30d`。切换页面数据日期、国家类别、店铺或关键词时，清空旧汇总并按需重新请求。

下钻后，经营明细顶部应出现可移除的活动筛选标签，例如：

`当前断货中`、`断货前角色：明星产品`、`角色周期：30天`

## 可访问性与交互约束

- 入口、周期按钮、角色行和明细入口均使用真实按钮元素。
- 周期选择使用单选语义，并提供清晰的选中态。
- 面板展开状态通过 `aria-expanded` 暴露。
- 加载区域使用 `aria-busy`，错误和空状态可被读屏识别。
- 键盘焦点不因面板刷新而丢失；点击角色进入明细后，焦点或滚动位置落到经营明细标题。

## 测试与验收

### 服务层

- 只统计当前标签304“断货中”的店铺商品记录。
- 标签21按所选周期过滤，四个周期相互独立。
- 同 MSKU 不同站点不被错误合并。
- 正常、缺失、冲突三类数据覆盖状态计算正确。
- 公共筛选、缓存键和参数校验正确。

### API

- 汇总接口返回四个固定角色及覆盖信息。
- 非法周期返回400。
- 明细和导出正确携带当前断货、角色ID及角色周期。
- 标签21继续不出现在首页分析分类和 overview 中。

### 前端

- “断货中”卡片可展开和收起汇总面板。
- 默认周期及四周期切换正确。
- 切换周期不沿用旧结果，失败和空状态清晰。
- 点击角色或全部明细后，经营明细筛选、表格和导出口径一致。
- 页面刷新或公共筛选变化后不会展示过期汇总。

## 验收标准

- 用户最多两次点击即可从“断货中”进入指定周期的断货前角色明细。
- 汇总面板的当前断货总数与“断货中”卡片在同一公共筛选下完全一致。
- 四类角色、未识别和冲突记录之间没有重复计数。
- 标签21仍只在本入口和下方明细筛选中使用，不回到首页 MSKU 分析入口。
- 明细页面及 CSV 导出能明确看到断货前角色和角色周期。
