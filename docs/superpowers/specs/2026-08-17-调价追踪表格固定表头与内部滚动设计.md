# 调价追踪表格固定表头与内部滚动设计

## 目标

将调价追踪页的四个主表改为固定可视区域：表头保持可见，表体在组件内部纵向滚动，宽列在组件内部横向滚动，避免长表持续撑高整页。

## 范围

- 二次调价日期、Top 榜单、SKU 明细三个 AG Grid 使用页面级固定高度模式。
- 国家站点对比表保留原生 HTML 表格，通过限定外层高度复用现有 sticky 表头。
- SKU 明细继续使用现有每页 20 条的服务端分页。
- 矩阵展开指标表、国家展开指标表等短小辅助表不强制增加独立滚动区。
- 不修改后端接口、筛选、排序、导出和分页口径，也不改变其他页面共用的 AG Grid 默认行为。

## 实现设计

1. 给四个主表容器增加仅属于调价追踪页的语义化滚动类，并区分紧凑表、榜单表和明细表的高度。
2. 三个 AG Grid 创建时显式覆盖全局 `domLayout: "autoHeight"`，改为 `domLayout: "normal"`。AG Grid 自身负责固定表头、纵向视口和横向滚动。
3. 国家站点表的外层容器设置响应式最大高度和 `overflow: auto`，继续使用现有 `thead th { position: sticky; top: 0; }`。
4. 高度使用 `clamp()` 约束，桌面端展示足够行数，小屏端不占满整个视口；空数据状态仍保留最小可视高度。
5. 所有样式限定在 `body[data-page="price_review"]` 下，避免影响补货、返场等复用表格组件的页面。

## 验收标准

- 四个主表均具有明确的内部滚动容器。
- 滚动表体时表头不随内容离开视口。
- 列宽超过容器时可横向滚动，AG Grid 已固定的关键列继续正常显示。
- SKU 明细仍显示原分页栏，页大小仍为 20。
- 调价追踪现有前端测试通过；新增测试能约束页面级滚动类、AG Grid 固定布局配置和国家表 sticky 表头。
- Headless 浏览器检查桌面视口下不存在由主表无限撑高导致的异常页面布局。

## 风险与处理

- AG Grid 在 `normal` 布局下要求宿主元素有确定高度；模板类与页面级 CSS 必须同时存在，并由测试覆盖。
- 国家表存在展开详情行；展开内容保留在同一滚动视口中，不引入嵌套纵向滚动。
- 不将服务端分页替换为无限滚动，避免扩大接口、缓存和排序一致性的改造范围。
