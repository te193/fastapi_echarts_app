# 标签看板经营单元流转统计设计

## 目标

标签汇总、标签变化和流转明细统一以“国家类别＋店铺＋MSKU”作为唯一经营单元。不再把同一 MSKU 在不同国家或店铺的标签合并为一个主标签，确保每个国家经营单元的真实变化都能被统计和追溯。

## 统计口径

- 经营单元唯一键：`(country_category, store, msku)`。
- 标签数量、本期进入、本期离开、标签切换、流转矩阵和变化明细均以经营单元计数。
- 唯一 MSKU 数仅作为辅助指标，不用于标签流转计数或去重。
- 国家筛选后仍保留店铺和 MSKU 维度；进入国家明细页后，再按该国家的 SKU、站点等更细维度展开。

## 后端设计

### 两期数据组织

`LabelHubChangeDataService` 保留当前远端标签快照来源，但将变化比较的主键从 `msku` 改为经营单元唯一键。当期和上期分别构建：

```text
business_unit_key -> 该经营单元的标签签名
```

两期使用同一键直接对比，不再跨国家、跨店铺收集子标签，也不在变化统计中使用 `REMOTE_PARENT_CHILD_PRIORITY` 选择跨经营单元的主标签。

### 变化关系

- 上期无、本期有：新增经营单元。
- 上期有、本期无：移除经营单元。
- 两期都有且目标标签不同：标签切换。
- 两期都有且目标标签相同：保持不变。

层级进入、离开和流转矩阵直接按经营单元累计。例如 `QL0052b` 同时产生两条独立记录：

- 欧洲站 / QINGLEE / QL0052b：成长期 → 成熟期。
- 英国站 / QINGLEE / QL0052b：成熟期 → 成长期。

### API 返回

变化明细每行必须返回：

- `country_category`
- `store`
- `msku`
- `business_unit_key`
- `previous_label`
- `current_label`
- `change_type`

汇总中保留原有字段名以降低前端改动，但其数值语义统一改为“经营单元数”。额外返回 `unique_msku_count` 作为辅助信息。

## 前端设计

- 变化汇总标题和提示中明确标注“经营单元”，避免与唯一 MSKU 数混淆。
- 流转卡片使用经营单元数，当前数据应显示“成熟期 → 成长期 14”和“成长期 → 成熟期 28”。
- 点击流转行后，明细表固定展示国家类别、店铺、MSKU、上期标签和本期标签。
- 如需同时显示唯一 MSKU 数，使用次要文案“涉及 N 个 MSKU”，不参与主数值计算。

## 边界情况

- 国家类别、店铺或 MSKU 任一缺失时，仍以原始空值组成稳定键，并在页面显示“未标记”；不将不同空值单元合并到其他正常单元。
- 同一经营单元、同一周期命中多个互斥子标签时，不用跨单元优先级掩盖；将该单元标记为标签冲突，并保留全部原始标签供排查。
- 筛选条件必须在两期使用同一口径，避免将筛选变化误认为标签变化。

## 验证标准

1. 最近两期底层经营单元流转矩阵与 API 汇总完全一致。
2. `QL0052b` 在变化明细中出现两条相反流转，不再被合并为“保持成熟期”。
3. 当前数据的成熟期 → 成长期为 14 个经营单元，成长期 → 成熟期为 28 个经营单元。
4. 同一 MSKU 跨国家或店铺标签不同时，不丢失任何经营单元的变化。
5. 国家、店铺、关键词、标签组合和变化类型筛选仍正常工作。
6. 无变化的经营单元仍可用于两期数量对账，但不混入默认变化明细。

## 不在本次范围

- 不修改远端 `dws_datasync.dws_标签表` 的生命周期打标规则。
- 不在本地重新计算生命周期标签。
- 不改变国家明细页内部的更细标签口径。
