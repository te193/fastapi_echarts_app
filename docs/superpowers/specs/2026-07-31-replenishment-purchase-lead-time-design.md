# 补货计算引入采购交期设计说明

## 1. 文档目的

本文定义如何将领星产品资料中的“采购交期”纳入补货分层和补货数量计算。

本方案只调整计算口径设计，不在本文阶段修改代码。目标是让补货结果回答两个不同问题：

1. 按当前销售速度，新采购的货到达时，现有库存预计还剩多少天。
2. 为了让新货到达后库存重新达到 120 天目标，本次需要采购多少数量。

## 2. 核心结论

采购交期需要同时影响：

- 补货分层：交期越长，新货到达时旧库存越少，补货紧迫度越高。
- 补货数量：采购等待期间仍会发生销售，因此本次采购需要补回交期内预计消耗的数量。

不采用“固定扣除 30 天”或“只处理超过 30 天的交期”方案。30 天只是现有 `120 天目标 - 90 天计划补货线` 的差值，不是数据库中的真实采购周期，也没有独立业务配置支撑。

推荐直接使用每个 SKU 的实际采购交期：

```text
到货时剩余支撑天数 = 当前库存可支撑天数 - 有效采购交期

若现有库存能够支撑到新货到达：

最终基础补货需求
= 原基础补货需求 + 交期内预计销量
= (120 + 有效采购交期) × 预测日销 - 当前库存池

若现有库存不能支撑到新货到达：

最终基础补货需求
= 120 × 预测日销

交期内预计缺货量只作为风险指标，不再重复加入采购数量
```

## 3. 当前规则基线

### 3.1 当前补货目标

当前补货 ETL 将补货目标固定为 4 个月：

```text
补货目标月份 = 4
补货目标天数 = 4 × 30 = 120 天
```

### 3.2 当前补货分层

当前系统按照库存可支撑天数分层：

| 库存可支撑天数 | 补货分层 | 排序值 |
|---:|---|---:|
| `≤ 35` | 紧急补货 | 1 |
| `> 35 且 ≤ 65` | 建议补货 | 2 |
| `> 65 且 ≤ 90` | 计划补货 | 3 |
| `> 90` | 库存充足 | 4 |
| 预测日销 `≤ 0` | 日销为0 | 5 |

### 3.3 当前库存池

当前补货主计算使用：

```text
当前库存池 I
= FBA 可用库存 available_total
 + FBA 在途/备货 stock_up_num
 + 本地库存池 local_quantity
```

其中 `local_quantity` 已经包含本地有效库存、采购在途、采购计划和本地质检等组成项。这些组成项不能再额外相加，否则会重复计算库存。

### 3.4 当前预测日销

记预测日销为 `D`。

新品使用：

```text
D = 3 天调整日销 × 50% + 7 天调整日销 × 50%
```

其他产品使用：

```text
D = 7 天调整日销 × 60%
  + 14 天调整日销 × 20%
  + 30 天调整日销 × 20%
```

调整日销已经考虑可售天数、短窗口数据不足、跟卖销量继承等现有规则。采购交期设计不修改日销算法。

### 3.5 当前基础补货需求

当前基础补货需求为：

```text
当前基础补货需求 Q0 = 120 × D - I
```

该公式中的“补足 120 天”是计算时点的账面目标，没有扣除从下单到新货到达期间的销售消耗。

## 4. 采购交期数据

### 4.1 字段来源

采购交期来自：

```text
dwd_datasync.lx_product_local_product_info.cg_delivery
```

关联键：

```text
补货记录的本地 SKU = lx_product_local_product_info.sku
```

该 DWD 表当前为一行一个 SKU，适合按 SKU 直接关联。

### 4.2 字段含义

本设计将 `cg_delivery` 直接解释为采购等待天数：

```text
从本次采购开始，到采购货物可以进入后续库存链路所需的天数
```

不再拆分供应商生产、国内快递等子周期。

### 4.3 有效采购交期

定义：

```text
原始采购交期 L_raw = cg_delivery
```

有效采购交期 `L` 的规则：

```text
当 L_raw > 0 时：
    L = L_raw

当 L_raw 为空、为 0 或小于 0 时：
    L = 0
    采购交期状态 = 未配置
```

未配置时使用 0，而不是默认 10 天，原因是当前大量 SKU 的 `cg_delivery` 为 0。如果统一回填 10 天，会同时改变大量产品的分层和补货量，风险过大。未配置 SKU 保持当前计算结果，同时在结果中明确暴露“采购交期未配置”。

如果未来业务决定未配置交期必须使用默认值，应将默认值做成显式配置，而不是隐藏在 SQL 中。

### 4.4 数据现状

当前 DWD 数据分布：

| `cg_delivery` | SKU 数量 |
|---:|---:|
| 0 | 7,884 |
| 10 | 4,035 |
| 20 | 1 |
| 35 | 1 |
| 84 | 1 |

因此上线时必须同时观察：

- 已配置采购交期的覆盖率。
- 未配置 SKU 的补货金额和补货数量占比。
- 采购交期加入后，各补货分层的迁移数量。

## 5. 新增指标定义

### 5.1 当前库存可支撑天数

```text
当前库存可支撑天数 S = I ÷ D
```

前提：

```text
D > 0
```

当 `D ≤ 0` 时，`S` 为空，继续沿用“日销为0”及现有历史恢复规则。

### 5.2 交期内预计销量

```text
交期内预计销量 QL = L × D
```

业务含义：从现在开始采购到新货到达期间，预计会销售掉的数量。

### 5.3 到货时剩余支撑天数

```text
到货时剩余支撑天数 R = S - L
```

等价数量公式：

```text
到货时旧库存预计剩余数量
= I - L × D
```

当 `R < 0` 时，表示按照当前日销和交期估算，新货到达前存在断货风险。负值绝对值表示理论上的缺货天数。

为了避免后续公式把“已经卖不到的货”当成负库存继续扣减，还需要定义：

```text
预计交期缺货天数 G = max(-R, 0)

预计交期损失销量 M = G × D

到货时旧库存预计剩余数量 IA = max(I - L × D, 0)
```

其中：

- `G` 用于表达大约会提前断货多少天。
- `M` 用于表达在“不接受欠单”的前提下，交期内理论上少卖多少件。
- `IA` 最低只能取 0，不能把理论负库存带进补货数量。
- 亚马逊普通零售场景下，断货期间未成交的需求通常不会形成必须日后补发的欠单，因此 `M` 是风险指标，不是采购数量。

### 5.4 原基础补货需求

```text
原基础补货需求 Q0 = max(120 × D - I, 0)
```

该指标用于解释如果不考虑采购交期，当前规则会补多少。

### 5.5 采购交期追加需求

```text
采购交期追加需求 QL = L × D
```

该指标用于解释因为等待采购到货，需要额外补多少。

注意：`QL` 适合解释现有库存能够撑到到货日的情况。若 `R < 0`，交期内有一部分需求已经无法成交，不能把全部 `QL` 直接叠加到采购数量中。

### 5.6 加入采购交期后的基础补货需求

需要根据现有库存能否撑到到货日，分成两种情况。

#### 情况一：`R ≥ 0`，现有库存能撑到到货

```text
交期调整后基础补货需求 Q1
= max((120 + L) × D - I, 0)
= max((120 - R) × D, 0)
```

此时原来的“120 天缺口 + 交期内销量”思路成立。

#### 情况二：`R < 0`，现有库存会在到货前售罄

```text
交期调整后基础补货需求 Q1 = 120 × D
```

原因是到货时旧库存按实际最多只能剩 0，新到的货只需重新建立 120 天库存：

```text
到货时旧库存预计剩余数量 IA = 0

IA + Q1
= 0 + 120 × D
= 120 × D
```

不能继续使用 `(120 + L) × D - I` 作为采购量，因为它会把交期内没有成交的损失销量 `M` 也补回来。除非业务确认存在真实欠单、预售订单或必须补发的订单，否则这部分不应加入本次采购数量。

因此统一写法为：

```text
Q1 = max(120 × D - IA, 0)

其中 IA = max(I - L × D, 0)
```

## 6. 新补货分层规则

### 6.1 分层使用哪个指标

原分层直接使用 `S`，即当前库存可支撑天数。

新分层使用 `R`，即到货时剩余支撑天数：

| 到货时剩余支撑天数 `R` | 补货分层 | 业务解释 |
|---:|---|---|
| `R ≤ 35` | 紧急补货 | 新货到达时旧库存预计只剩不超过35天，或已经发生理论断货 |
| `35 < R ≤ 65` | 建议补货 | 到货时库存余量偏低，需要尽快安排 |
| `65 < R ≤ 90` | 计划补货 | 到货时仍有一定库存，可以按计划安排 |
| `R > 90` | 库存充足 | 即使等待采购交期，到货时预计仍有超过90天库存 |
| `D ≤ 0` | 日销为0 | 无法用日销计算支撑天数 |

其中 `R < 0` 虽然仍归入“紧急补货”，但建议在紧急补货内部增加“交期内预计断货”标识。这一批不能只靠正常采购解决近期风险，还应同步考虑加急采购、国内库存调拨、物流提速或临时降速销售。

### 6.2 为什么原阈值不改

35、65、90 天仍然表达同一套业务紧迫度。变化的不是阈值，而是判断视角：

```text
原来：看今天库存还能卖多久
现在：看新货到达时旧库存还剩多久
```

因此不需要同时修改阈值和支撑天数，避免重复放大采购交期影响。

### 6.3 分层边界

边界必须固定为：

```text
R = 35  → 紧急补货
R = 65  → 建议补货
R = 90  → 计划补货
R > 90 → 库存充足
```

## 7. 补货数量完整计算顺序

采购交期只插入现有补货主链，不改变后续箱规、季节性、跟卖、ASIN 合并和 MOQ 的既有顺序。

推荐顺序如下：

```text
1. 计算预测日销 D
2. 汇总当前库存池 I
3. 读取有效采购交期 L
4. 计算当前支撑天数 S = I / D
5. 计算到货时剩余支撑天数 R = S - L
6. 使用 R 判断补货分层
7. 计算到货时旧库存 `IA = max(I - L × D, 0)`
8. 计算预计缺货天数 `G = max(-R, 0)` 和预计损失销量 `M = G × D`
9. 计算基础补货需求 `Q1 = max(120 × D - IA, 0)`
10. 应用历史销量变化调整系数
11. 应用历史恢复兜底
12. 应用同 ASIN 合并和补货目标链接规则
13. 按箱规或最小50件取整
14. 计算补货成本
15. 应用供应商 MOQ 门槛
16. 输出计算补货量、风险指标和最终可执行补货量
```

### 7.1 季节性调整

沿用现有 `sales_adj_factor`：

```text
季节调整后需求 Q2 = Q1 × sales_adj_factor
```

采购交期不改变同比窗口、有效有货天数门槛和调整系数上下限。

### 7.2 箱规取整

当有效箱规 `B > 0`：

```text
补货箱数
= max(round(Q2 ÷ B), 1)

补货数量
= 补货箱数 × B
```

当箱规为空或不大于 0：

```text
补货箱数 = 0
补货数量 = max(round(Q2), 50)
```

只有进入紧急补货、建议补货或计划补货的记录才生成正常补货量。被跟卖原始链接、同 ASIN 非目标链接等既有拦截规则继续优先将补货量置零。

### 7.3 历史恢复

历史恢复条件和一箱/50件兜底保持现状。采购交期只影响正常补货分层和正常基础需求，不改变历史恢复的证据门槛。

### 7.4 MOQ

MOQ 继续在所有数量计算完成后执行：

```text
计算补货量 < 供应商 MOQ
→ moq_status = below_minimum
→ 可执行补货量 = 0
→ 保留计算补货量和 MOQ 差额
```

## 8. 同 ASIN 合并时的采购交期

同一 `country_category + ASIN` 下可能有多个店铺/MSKU，但最终只允许一个目标链接承接补货。

采购交期必须与实际采购字段来源保持一致：

1. 优先使用最终补货目标所采用的有效采购 SKU。
2. 如果 ASIN 合并时箱规、采购价、头程成本继承自其他有效采购记录，采购交期也应从同一条采购记录继承。
3. 不允许箱规来自 SKU A、采购价来自 SKU B、采购交期来自 SKU C。
4. 如果最终有效采购记录没有交期，则 `L = 0`，并标记采购交期未配置。

这样可以保证最终补货数量、箱数、采购成本和采购交期描述的是同一采购对象。

## 9. 详细示例

为便于理解，以下示例均假设：

```text
预测日销 D = 1 件/天
补货目标 = 新货到达后 120 天库存
没有季节调整、箱规、跟卖、ASIN 合并和 MOQ 干预
```

### 9.1 10 天交期、当前库存 95 天

输入：

```text
I = 95 件
S = 95 天
L = 10 天
```

到货时剩余支撑天数：

```text
R = 95 - 10 = 85 天
```

分层：

```text
65 < 85 ≤ 90
→ 计划补货
```

数量：

```text
原基础需求 Q0 = 120 - 95 = 25 件
交期追加需求 QL = 10 × 1 = 10 件
最终基础需求 Q1 = 25 + 10 = 35 件
```

到货验证：

```text
10 天后旧库存 = 95 - 10 = 85 件
新货 = 35 件
到货后总库存 = 120 件
```

### 9.2 35 天交期、当前库存 95 天

输入：

```text
I = 95 件
S = 95 天
L = 35 天
```

到货时剩余：

```text
R = 95 - 35 = 60 天
```

分层：

```text
35 < 60 ≤ 65
→ 建议补货
```

数量：

```text
Q0 = 120 - 95 = 25 件
QL = 35 × 1 = 35 件
Q1 = 60 件
```

到货验证：

```text
35 天后旧库存 = 60 件
新货 = 60 件
到货后总库存 = 120 件
```

### 9.3 35 天交期、当前库存 68 天

输入：

```text
I = 68 件
S = 68 天
L = 35 天
```

到货时剩余：

```text
R = 68 - 35 = 33 天
```

分层：

```text
33 ≤ 35
→ 紧急补货
```

数量：

```text
Q0 = 120 - 68 = 52 件
QL = 35 件
Q1 = 87 件
```

到货验证：

```text
35 天后旧库存 = 33 件
新货 = 87 件
到货后总库存 = 120 件
```

### 9.4 35 天交期、当前库存 160 天

输入：

```text
I = 160 件
S = 160 天
L = 35 天
```

到货时剩余：

```text
R = 160 - 35 = 125 天
```

分层：

```text
R > 90
→ 库存充足
```

数量：

```text
Q1 = max(155 - 160, 0) = 0
```

即使交期为35天，到货视角下仍有125天库存，因此无需补货。

### 9.5 采购交期大于当前支撑天数

输入：

```text
S = 20 天
L = 35 天
D = 10 件/天
I = 200 件
```

到货时剩余：

```text
R = 20 - 35 = -15 天
```

含义：

```text
预计新货到达前会断货约15天

预计交期损失销量
= 15 × 10
= 150 件
```

分层仍为紧急补货，但结果应额外输出：

```text
交期断货风险 = 是
预计交期缺货天数 = 15
预计交期损失销量 = 150
```

到货时旧库存按 0 计算，因此本次基础补货量为：

```text
Q1 = 120 × 10 = 1200 件
```

不能计算成：

```text
(120 + 35) × 10 - 200 = 1350 件
```

多出来的 150 件正好是交期内理论损失销量。因为这 150 件没有成交，也没有形成需要补发的欠单，所以不应在新货到达后再补回来。

采购补货本身已经来不及消除近期风险，需要结合现有本地库存调拨、加急采购或物流加速处理。如果未来业务存在真实预售或欠单，则应另行读取“实际待履约数量”加入补货量，不能直接用理论损失销量替代。

### 9.6 当前负值批次的处理建议

按 2026-07-31 快照，在“预测日销大于0且采购交期已配置”的记录中，共有 54 条满足 `R < 0`，也就是预计新货到达前会售罄。其中：

- 46 条当前库存支撑天数为0。
- 8 条仍有库存，但支撑天数小于采购交期。
- 54 条按新分层口径均属于紧急补货。

这 54 条不能简单全部生成采购单，应继续服从现有后置规则：

| 当前处理原因 | 数量 | 建议 |
|---|---:|---|
| 同 ASIN 库存充足 | 29 | 明细不重复下单；风险汇总到实际补货目标链接或 ASIN 层查看 |
| 跟卖或原始链接受限 | 14 | 最终可执行补货量仍为0，但保留缺货风险供运营处理 |
| 产品组补货目标 | 6 | 需求合并到产品组实际目标后再下单 |
| 无上述阻断 | 5 | 按 `Q1 = 120 × D` 计算基础需求，并优先检查加急、调拨和物流提速 |

当前结果中有 11 条最终补货量大于0，合计 1087 件；这些数值只是旧逻辑快照，不能直接作为新方案的验收结果。上线前应按本文新公式重算，并逐条核对“风险归属链接”和“实际下单链接”，避免同一风险在明细和合并目标上重复采购。

## 10. 建议输出字段

为保证页面和导出结果可解释，建议保留以下中间指标：

| 字段 | 含义 |
|---|---|
| `purchase_lead_days_raw` | DWD 原始采购交期 |
| `effective_purchase_lead_days` | 实际参与计算的采购交期 |
| `purchase_lead_status` | `configured` 或 `unconfigured` |
| `inventory_support_days` | 当前库存可支撑天数 `S` |
| `arrival_inventory_support_days` | 到货时剩余支撑天数 `R` |
| `arrival_inventory_qty` | 到货时旧库存预计剩余数量 `IA`，最低为0 |
| `lead_time_demand_qty` | 交期内预计销量 `QL` |
| `base_replenish_need_qty` | 不含交期的原基础需求 `Q0` |
| `lead_adjusted_replenish_need_qty` | 含交期的基础需求 `Q1` |
| `lead_time_stockout_flag` | 交期内是否存在理论断货 |
| `lead_time_stockout_days` | 理论缺货天数 |
| `lead_time_lost_sales_qty` | 理论损失销量 `M`，仅作风险指标 |

页面至少应同时展示：

```text
当前库存可支撑天数
采购交期
预计到货时剩余天数
预计交期缺货天数
预计交期损失销量
```

不能只展示修正后的分层，否则用户无法判断产品为什么提前进入建议或紧急补货。

## 11. 异常及边界处理

### 11.1 日销为0

```text
D ≤ 0
→ 不计算 S 和 R
→ 补货层级保持“日销为0”
→ 继续执行现有历史恢复逻辑
```

### 11.2 采购交期未配置

```text
cg_delivery ≤ 0 或为空
→ L = 0
→ 保持当前分层和数量结果
→ 标记 purchase_lead_status = unconfigured
```

### 11.3 异常大交期

不在计算层静默截断真实正数交期。对于异常大值，应：

- 保留原始值。
- 使用原始正数参与计算。
- 增加数据质量告警。
- 由业务确认是否修正源数据。

如果未来需要上限，应使用显式配置并保留“原始值、计算值、截断原因”。

### 11.4 负库存或负需求

库存组成项按现有规则空值转0。到货时旧库存和基础需求均不得小于0：

```text
IA = max(I - L × D, 0)

Q1 = max(120 × D - IA, 0)
```

如果 `I - L × D < 0`，负数部分表示理论未满足需求，不表示数据库里存在可继续扣减的负库存。它应进入 `lead_time_lost_sales_qty`，而不是继续放大采购数量。

### 11.5 数量精度

支撑天数和交期销量在中间计算中保留小数。只在最终箱规/件数阶段执行现有取整，避免多次取整造成累计偏差。

## 12. 为什么采用本方案

### 12.1 直接对应真实时间线

采购等待期间库存会继续销售，因此：

```text
到货时旧库存 = max(当前库存 - 交期内销量, 0)
```

旧库存能撑到到货时，将交期销量加回补货需求；旧库存提前售罄时，从到货时的实际 0 库存重新建立 120 天库存。这样不会把未成交需求当成欠单重复采购。

### 12.2 不依赖未经确认的固定30天

方案使用每个 SKU 的真实 `cg_delivery`，不把 `120 - 90` 推断成所有产品统一的采购周期。

### 12.3 分层和数量口径一致

如果数量考虑交期、分层不考虑交期，会出现：

```text
产品被判断为库存充足
但按到货时点看库存已经偏低
```

新方案使用相同的 `L` 同时修正分层和数量，避免两个结果互相矛盾。

### 12.4 保持现有后置规则

方案不重写日销、季节性、箱规、跟卖、ASIN 合并、历史恢复和 MOQ，只在主计算中增加交期维度，影响范围清晰。

### 12.5 未配置数据保持兼容

`L = 0` 时：

```text
R = S
Q1 = max(120 × D - I, 0)
```

结果与当前规则一致，便于灰度比较和回归验证。

## 13. 验证与验收规则

### 13.1 公式一致性

对任意 `D > 0`、`I ≥ 0`、`L ≥ 0` 的记录，先计算：

```text
IA = max(I - L × D, 0)
Q1 = max(120 × D - IA, 0)

IA + Q1
= 120 × D
```

前提是基础需求大于0且没有季节性、箱规、跟卖、ASIN 合并、历史恢复或 MOQ 干预。

当 `R < 0` 时，还应满足：

```text
Q1 = 120 × D
M = (-R) × D
```

并确认 `M` 没有被再次加入 `Q1`。如果明细因跟卖、同 ASIN 合并或补货目标链接规则被阻断，最终可执行补货量仍应按现有规则为 0，风险指标则保留用于解释和运营处理。

### 13.2 向后兼容

当 `L = 0` 时：

- 补货分层与当前结果一致。
- 基础补货需求与当前结果一致。
- 后续箱规、成本和 MOQ 结果一致。

### 13.3 边界测试

必须覆盖：

```text
R = 35、35.01
R = 65、65.01
R = 90、90.01
R = -0.01、0
D = 0
L = 0
L 为空
L > S
Q1 = 0
有箱规和无箱规
MOQ 达标和低于 MOQ
普通单链接和同 ASIN 合并
```

### 13.4 数据对账

上线前应按同一快照输出旧规则和新规则的对照数据：

- 分层未变化、升级、降级的 SKU 数量。
- 原补货量、新补货量及差额。
- 因采购交期从库存充足进入补货池的 SKU。
- 交期内预计断货的 SKU。
- `R < 0` 的 SKU 数量、理论损失销量及最终可执行补货量。
- 验证理论损失销量没有重复加入采购数量。
- 因跟卖、同 ASIN 合并或补货目标链接而未下单的断货风险 SKU。
- 未配置采购交期的 SKU 数量及补货金额占比。
- 采购交期增加的采购数量和采购金额。

### 13.5 业务抽样

至少抽查以下类型：

- 10天交期、普通库存。
- 35天以上长交期。
- 采购交期大于库存支撑天数。
- 库存充足但扣除交期后进入计划补货。
- 扣除交期后进入建议补货。
- 扣除交期后进入紧急补货。
- 同 ASIN 多链接且采购字段发生继承。

## 14. 当前方案边界

本方案使用现有聚合库存池 `I`，没有模拟不同库存批次的准确到达时间。

因此：

- `stock_up_num` 和 `local_quantity` 仍按当前规则统一计入库存池。
- 已存在的采购在途、采购计划和 FBA 在途不会按各自 ETA 展开时间轴。
- 采购交期只描述本次新增采购等待时间。

如果未来需要准确回答“现有每一批在途是否能在断货前到达”，应升级为批次时间轴模型，按采购单/FBA货件逐批模拟。本设计不包含该扩展。

## 15. 最终推荐口径

```text
I = 当前库存池
D = 预测日销
L = 有效采购交期
S = I / D
R = S - L
IA = max(I - L × D, 0)
G = max(-R, 0)
M = G × D

补货分层：
R ≤ 35           → 紧急补货
35 < R ≤ 65      → 建议补货
65 < R ≤ 90      → 计划补货
R > 90           → 库存充足
D ≤ 0            → 日销为0

原基础补货需求：
Q0 = max(120 × D - I, 0)

采购交期追加需求：
QL = L × D

交期调整后基础补货需求：
Q1 = max(120 × D - IA, 0)

等价分段表达：
R ≥ 0 → Q1 = max((120 + L) × D - I, 0)
R < 0 → Q1 = 120 × D

其中：
G = 预计交期缺货天数
M = 预计交期损失销量，仅作风险指标，不加入 Q1
```

一句话解释：

> 先判断新货到达时旧库存还剩多少天，以此确定补货紧迫度；能撑到到货时补齐交期消耗，撑不到时从零库存重新补足120天。交期内未成交的理论损失销量单独预警，不重复加入采购量。
