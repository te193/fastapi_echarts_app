# 补货导出爆单持续高亮设计

## 1. 目标与边界

本次优化只调整补货明细导出 Excel 的高亮判断，用于提醒业务人员复核可能受单日爆单影响的补货建议。

明确保持不变的内容：

- 不修改原始销量和各周期销量。
- 不修改加权日销公式。
- 不修改库存支撑天数、补货层级和同 ASIN 合并规则。
- 不修改补货需求量、补货箱数、补货货值及最终补货数量。
- 不改变页面主表数据，只影响导出文件的提醒样式和说明。

本设计与 `docs/补货/方案与规划/方案8-低销量SKU单日大跳变拦截详细规划.md` 相互独立。后者会保护补货分层并可能影响补货决策，本设计只提供人工复核提醒。

## 2. 当前问题

当前导出使用以下规则标黄：

```text
补货层级属于紧急补货、建议补货或计划补货
且 7天销量不少于10
且 3天销量达到7天销量的70%
```

该规则可以及时发现刚进入最近3天窗口的集中销量，但异常日一旦退出3天窗口，高亮会立刻消失，即使异常销量仍在7天、14天和30天窗口中持续抬高补货日销。

### 2.1 JC029b 实际案例

`JC029b` 所在产品组的关键数据如下：

| 项目 | 数值 |
| --- | ---: |
| 站点分组 | 欧洲站 |
| 同 ASIN | `B0CX51133J` |
| 异常日期 | 2026-08-03 |
| 异常日产品组销量 | 168 |
| 其余29天平均销量 | 4.59 |
| 其余29天中位数 | 5 |
| 异常日相对中位数 | 33.6倍 |
| 异常后3天销量 | 5、2、2 |
| 2026-08-07计算日销 | 21.19 |
| 实际补货目标链接 | `meeloo / KQ-UFY7-HWK2` |
| 2026-08-07补货数量 | 2295 |

`JC029b` 自身因同 ASIN 合并而补货为0，实际补货数量由目标链接承接。2026-08-04至2026-08-06目标链接能够命中旧高亮规则，2026-08-07异常日退出3天窗口后不再标黄，但异常销量仍在7天、14天和30天日销中。

## 3. 设计原则

### 3.1 识别单日异常，不把持续增长当作爆单

不能简单把“3天对7天”改成“3天对30天”，也不直接写死“高于常态3倍”。不同产品的销量体量、间歇性和正常波动不同，固定倍数容易在低销量产品上产生大量误报。

新规则使用产品自身的逐日销量建立稳健基线，并结合异常后的回落情况区分：

- 一次性爆单：单日显著异常，随后恢复常态。
- 持续增长：后续销量继续保持高位，不作为一次性爆单长期提醒。

### 3.2 新发生的异常必须立即提醒

不能等满3天确认回落后才提醒。最新完整销售日出现显著异常时，先进入“疑似爆单”状态并立即标黄；后续再根据销量是否回落确认或解除。

### 3.3 提醒周期与补货计算影响周期对齐

当前补货日销同时使用7天、14天和30天销量，最长影响窗口为30天。确认属于一次性爆单后，只要异常日仍在当前30天销量窗口内，就持续标黄；退出30天窗口后自动解除。

### 3.4 按产品组传播提醒

异常识别维度使用：

```text
country_category + max_asin
```

同 ASIN 产品组任一链接发生爆单，异常状态传播到该产品组的实际补货目标链接。导出时只对最终补货数量大于0的有效目标行标黄，避免只标记补货量为0的被合并链接。

## 4. 时间窗口

| 窗口 | 长度 | 用途 |
| --- | ---: | --- |
| 日常异常识别窗口 | 最近30个完整销售日 | 建立产品自身基线并搜索异常日 |
| 回落确认窗口 | 异常日后的3个完整销售日 | 区分一次性爆单和持续增长 |
| 高亮保留窗口 | 异常日起最多30天 | 与补货日销最长影响窗口一致 |
| 规则校准数据范围 | 最近90天 | 离线校准统计阈值和抽查误报，不参与每日补货计算 |

不使用180天作为每日识别或首轮校准范围，避免陈旧销售阶段影响当前判断。

### 4.1 数据时效

当前补货快照使用已经完成同步的销售日数据，实际为T+1口径。例如2026-08-07补货快照的最新完整销售日是2026-08-06。

因此，现实中当天发生的爆单会在下一次销售数据同步后的补货导出中进入“疑似爆单”状态。除非后续接入实时订单数据，否则不能在自然日当天实时识别。

## 5. 异常阈值校准

### 5.1 不使用单一固定倍数

异常分数基于每个产品组最近30个完整销售日的中位数和 MAD（中位绝对偏差）计算。中位数和 MAD 不容易被单个极端值抬高，适合识别一次性爆单。

概念公式：

```text
基线 = 最近30日销量中位数
稳健波动 = 1.4826 × MAD
异常分数 = (单日销量 - 基线) / max(稳健波动, 最小稳定项)
```

最终异常分数阈值不在业务代码中直接写死。使用最近90天的产品组逐日销量进行只读回测，按正常销量体量分组统计异常分数分布，并从分布的极端尾部选择阈值。

阈值校准必须同时满足：

- `JC029b` 这类人工确认的严重单日爆单能够命中。
- 持续增长样本不会因为某一天略高而长期标记为一次性爆单。
- 低销量产品偶发1件销量不会形成大面积高亮。
- 每日新增疑似爆单数量和仍在提醒中的产品组数量处于业务可复核范围。

校准结果保存为明确的配置参数和校准日期；每日ETL只读取参数，不重复扫描90天来动态改变阈值。

回落判断复用同一套校准参数，不另设固定倍数：异常日后的3个完整销售日均不得再次达到异常分数阈值，同时这3日的平均销量不得超过识别时所属销量体量组的正常日销上界。正常日销上界与异常阈值一起由90天回测生成并保存。

### 5.2 数据不足时的兜底

产品组有效历史不足14个完整销售日时，不运行稳健统计异常识别，继续使用现有“3天销量占7天销量70%”规则提醒。历史达到要求后自动进入新规则。

## 6. 状态机

每个“站点分组 + ASIN”维护以下状态：

### 6.1 正常

最近30天没有统计异常事件，且当前不命中旧3天/7天集中销量规则。

导出结果：不因爆单规则标黄。

### 6.2 疑似爆单

最新完整销售日或最近尚未完成回落观察的日期显著偏离产品自身基线。

导出结果：立即标黄，不等待3天。

### 6.3 已确认爆单后回落

异常日后的3个完整销售日均未再次达到异常分数阈值，且3日平均销量未超过校准得到的正常日销上界，确认属于一次性爆单。

导出结果：持续标黄，直到异常日退出30天窗口。

### 6.4 持续增长

异常后的3个完整销售日没有回落，销量持续保持在新的高位区间。

导出结果：解除“一次性爆单”长期提醒；如果仍命中现有短期集中销量规则，继续按旧规则标黄。

### 6.5 自动过期

异常日不再进入当前30天销量窗口后，疑似或确认状态自动过期。

## 7. 最终导出高亮条件

一行同时满足以下有效性条件时，才参与爆单高亮：

```text
展示补货层级排序属于1、2、3
且 最终导出补货数量 > 0
```

在有效行基础上，满足以下任一提醒条件时整行标黄：

```text
条件A：命中现有3天/7天集中销量规则
条件B：所在同ASIN产品组处于“疑似爆单”状态
条件C：所在同ASIN产品组处于“已确认爆单后回落”状态，且异常日仍在30天窗口内
```

高亮判断只读取结果字段，不回写或重新计算补货数量。

## 8. 建议字段

在补货结果数据中增加只读提醒字段：

| 字段 | 含义 |
| --- | --- |
| `sales_spike_status` | `normal`、`suspected`、`confirmed_recovered`、`sustained_growth` |
| `sales_spike_flag` | 当前是否需要持续高亮 |
| `sales_spike_date` | 最近一次仍有效的异常日期 |
| `sales_spike_qty` | 异常日产品组销量 |
| `sales_spike_baseline` | 识别时的稳健日销基线 |
| `sales_spike_score` | 识别时的稳健异常分数 |
| `sales_spike_reason` | 可读的判断原因 |

这些字段只用于导出提醒、解释和测试，不参与补货数量公式。

## 9. Excel 展示

### 9.1 颜色

继续使用现有浅黄色 `FFF2CC` 对整行填充，不引入第二种颜色，避免业务人员重新学习颜色含义。

### 9.2 表头说明

更新“3天销量”表头批注，说明以下规则：

```text
黄色提醒包括：
1. 当前3天销量集中；
2. 最新完整销售日疑似单日爆单；
3. 近30天内已确认爆单后恢复正常，但异常销量仍影响当前补货日销。
黄色仅用于人工复核，不修改补货数量。
```

不新增业务导出列；具体异常日期、异常销量和基线保留在结果字段及测试/排查查询中，避免继续扩大已经较宽的导出文件。

## 10. 数据流

```text
逐日销量表
-> 按站点分组 + ASIN聚合每日销量
-> 最近30日稳健基线与异常候选
-> 疑似爆单 / 回落确认 / 持续增长状态
-> 将状态传播到同ASIN补货目标链接
-> 写入补货结果的只读提醒字段
-> 导出接口读取最终补货数量和提醒状态
-> 仅设置Excel整行黄色填充
```

异常识别应在ETL中完成，Excel生成函数不查询逐日销量，也不在导出请求期间执行30天统计，避免导出变慢并保证同一快照结果稳定。

## 11. 测试与验证

### 11.1 单元测试

- 最新完整销售日发生极端异常时立即进入 `suspected`。
- 疑似状态不需要等待3天即可高亮。
- 后续3天恢复正常后进入 `confirmed_recovered`。
- 后续3天持续高位时进入 `sustained_growth`，不保留一次性爆单长期提醒。
- 异常日退出30天窗口后状态过期。
- 有效历史不足14天时使用旧3天/7天规则兜底。
- 补货数量为0的被合并链接不标黄。
- 同 ASIN 异常能够传播到补货数量大于0的目标链接。
- 高亮前后导出的补货数量、箱数和货值完全一致。

### 11.2 JC029b 回归案例

至少验证以下快照：

| 快照日期 | 预期状态 | 预期结果 |
| --- | --- | --- |
| 2026-08-04 | 疑似爆单 | 目标链接标黄 |
| 2026-08-05 | 疑似爆单 | 目标链接标黄 |
| 2026-08-06 | 疑似爆单或确认中 | 目标链接标黄 |
| 2026-08-07 | 已确认爆单后回落 | 目标链接继续标黄，补货数量仍为2295 |

### 11.3 90天影子回测

上线前只读回测最近90天，不修改历史补货结果：

- 按销量体量统计每天新增疑似数量、确认回落数量和持续增长数量。
- 抽查异常分数最高、临界命中和临界未命中的样本。
- 专门检查低销量偶发1件、新品、促销持续增长及断货恢复样本。
- 对比高亮优化前后的导出补货数量汇总，必须完全一致。

## 12. 上线与回滚

### 12.1 影子验证

第一阶段只计算异常字段和统计日志，不改变导出颜色。确认阈值和每天提醒数量可接受后再启用新高亮条件。

### 12.2 正式启用

保留旧3天/7天规则，同时启用疑似爆单和确认回落的持续高亮。

### 12.3 回滚

提供独立高亮开关。关闭新规则后，导出恢复为旧3天/7天高亮条件；补货计算无需回滚，因为新规则从未参与补货计算。

## 13. 验收标准

- `JC029b` 所在产品组在2026-08-07导出时，实际补货目标链接仍然标黄。
- 目标链接补货数量保持2295，其他补货字段与优化前一致。
- 最新完整销售日发生明显异常时，下一次T+1补货导出立即标黄。
- 一次性爆单恢复正常后，在异常仍影响30天日销期间持续标黄。
- 持续增长不会被长期误标为一次性爆单。
- 同 ASIN 合并场景只突出实际补货目标行，不突出补货量为0的合并行。
- 新品或历史不足的产品仍有旧规则兜底。
- 关闭新高亮开关后可恢复旧行为，不影响补货结果。
