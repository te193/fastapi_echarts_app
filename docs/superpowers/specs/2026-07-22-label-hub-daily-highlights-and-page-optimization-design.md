# 标签看板“今日重点变化”与页面优化设计

## 1. 背景

现有标签看板已经具备标签覆盖、问题概览、多维联动、标签关系矩阵、每日变化、MSKU 明细、标签画像和国家画像等完整分析能力。当前主要问题不再是功能缺失，而是页面信息较多，用户仍需逐卡比较后才能判断“今天最值得先看什么”。

本设计新增“今日重点变化”摘要，并记录已经讨论确认的其他页面优化方向，作为后续实施依据。

## 2. 目标与边界

### 2.1 目标

- 自动识别当前筛选群体中变化最明显的标签或问题组合。
- 优先展示变化明显的事件，其次展示需要立即处理的经营风险。
- 每条摘要都说明入选原因，并能一键筛选或查看变化明细。
- 不引入不可解释的综合评分。
- 不阻塞现有标签看板首屏加载。

### 2.2 明确边界

- “暂无经营数据”不作为重点问题、风险条件或入选原因。
- 本期不解决远端标签与本地经营数据覆盖不足问题。
- 不新增远端数据表，不修改远端标签生成逻辑。
- 不回写标签，不增加治理、导出和处置记录。
- 普通标签看板先实施，国家标签看板后续复用。

## 3. 分析口径

### 3.1 比较日期

- 今日使用远端标签表最新 `data_date`。
- 上次使用次新的 `data_date`。
- 日期连续时显示“较昨日”。
- 日期不连续时显示“较上次数据”，并标注相隔天数。

### 3.2 筛选范围

- 没有联动条件时分析全局群体。
- 存在标签、经营分类或问题条件时，只分析当前筛选群体。
- 今日与上次分别应用相同的公共筛选、标签周期和联动条件。
- 同一分类多选为 OR，不同分类之间为 AND。
- 数量沿用现有去重 MSKU 口径，变化明细继续保留经营单元。

### 3.3 缺失经营数据处理

- 不生成“暂无经营数据增加”等摘要。
- 不允许“暂无经营数据”参与组合候选。
- 纯远端标签流转仍可参与结构变化统计。
- 纯标签事件缺少本地经营指标时，只展示 MSKU 数量，不展示销售额或利润影响。

## 4. 事件模型

### 4.1 单项事件

候选范围包括：

- 销售角色、生命周期、库存水平、流量结构、客户体验、退货情况等远端标签分类。
- 问题产品、日销为 0、订单毛利润为负、低毛利等本地经营问题。
- 当前多维联动区域已经展示的其他有效分类项。

### 4.2 组合事件

组合最多包含三个不同分类的条件，例如：

```text
成熟期 + 高库存
问题产品 + 订单毛利润为负
成熟期 + 高库存 + 问题产品
自然流量 + 潜力产品
```

为避免组合爆炸，只生成以下候选：

- 当前已经选中的条件与一个新增分类的组合。
- 已配置为重点风险的标签之间的二项或三项组合。
- 今日或上次实际存在，并达到触发阈值的组合。
- 同一分类内的多个子标签不组成 AND 组合。

### 4.3 事件类型

- `surge`：某标签或组合明显增加。
- `worsening`：风险群体新增或扩大。
- `new_combination`：上次不存在、今日首次达到有效规模。
- `improvement`：风险群体明显减少或转向正常分类。
- `structural_change`：普通标签结构发生明显增减。
- `disappeared`：上次存在、今日完全消失。

## 5. 触发规则

### 5.1 普通明显变化

满足任意一条即可进入候选：

- 绝对净变化不少于 10 个 MSKU。
- 变化率不少于 20%，同时绝对变化不少于 5 个 MSKU。
- 上次数量为 0，今日数量不少于 5 个 MSKU。
- 上次数量不少于 5，今日数量为 0。

### 5.2 重点风险变化

以下风险新增不少于 3 个 MSKU 即可进入候选：

- 订单毛利润为负。
- 日销为 0。
- 问题产品。
- 高库存。
- 高退货率或严重退货。
- 高度依赖广告。
- 后续明确配置为风险项的其他标签。

### 5.3 明显改善

满足任意一条即可进入候选：

- 风险群体减少不少于 10 个 MSKU。
- 风险群体减少比例不少于 20%，同时绝对减少不少于 5 个 MSKU。

### 5.4 配置方式

触发阈值、风险标签和展示上限统一放在后端配置中，不写死在前端。首版默认最多展示 5 条重点变化。

## 6. 固定排序规则

系统不计算综合得分，使用可解释的排序元组：

1. 绝对变化数量从高到低。
2. 新出现或完全消失的组合优先。
3. 变化率从高到低。
4. 风险新增优先于普通结构变化。
5. 风险改善随后展示。
6. 数量和变化率相同时，按影响销售额绝对值从高到低。
7. 仍相同时，按稳定的事件编码排序，保证结果可复现。

此顺序体现“变化明显优先，立即处理风险次之”的业务偏好。

## 7. 页面设计

### 7.1 页面位置

“今日重点变化”放在“群体问题”和“多维联动”之间。页面主数据先渲染，该区域异步加载。

### 7.2 区域头部

展示：

- 标题：今日重点变化。
- 比较日期：例如 `07-20 → 07-21`。
- 当前分析范围：全局或当前条件数量。
- “查看全部变化”入口。

### 7.3 事件行

每条事件展示：

- 事件类型：突增、恶化、新出现、改善、结构变化或消失。
- 标签或组合条件，使用现有条件标签样式。
- 上次数量、今日数量、净变化和变化率。
- 新增、离开数量。
- 有本地指标时展示销售额和毛利润影响。
- 明确的入选原因。
- “筛选该群体”和“查看变化明细”两个操作。

示例：

```text
突增  成熟期 + 高库存
245 → 263    增加 18（+7.3%）
新增 23 · 离开 5 · 销售额 ¥18.6 万
入选原因：较上次增加 18 个 MSKU
```

### 7.4 视觉规则

- 突增和普通结构变化使用现有蓝色体系。
- 恶化使用低饱和风险红色。
- 改善使用绿色。
- 新出现使用蓝紫色或现有强调色。
- 不使用大面积高饱和告警底色。
- 不依赖颜色单独表达事件类型，必须同时显示文字。

### 7.5 空态和异常态

- 没有达到阈值的变化：显示“当前群体较上次整体稳定”。
- 远端仅有一个标签日期：显示“暂无可比较的上次标签数据”。
- 重点摘要接口失败：显示轻量错误提示，不影响现有页面。

## 8. 交互设计

### 8.1 筛选该群体

- 将事件对应条件加入现有条件条。
- 更新问题概览、多维联动、矩阵和明细。
- URL 恢复规则沿用现有条件序列化逻辑。
- 再次点击已选条件可以取消。

### 8.2 查看变化明细

复用现有变化抽屉，不新增另一套抽屉。抽屉展示：

- 上次数量、今日数量。
- 本期进入、本期离开和净变化。
- 从哪些同维度标签转入。
- 离开后转向哪些同维度标签。
- 变化 MSKU 和经营单元明细。

### 8.3 查看全部变化

展开完整候选列表，支持按以下类型切换：

- 全部。
- 明显增加。
- 风险恶化。
- 明显改善。
- 结构变化。

## 9. 服务与接口设计

### 9.1 服务边界

新增独立的重点变化服务，避免继续扩大现有主聚合函数。该服务负责：

- 复用最新两天标签事实索引。
- 复用本地经营指标缓存。
- 构造单项和有限组合候选。
- 执行触发规则和固定排序。
- 返回轻量摘要。

### 9.2 新接口

```text
GET /api/label-hub/highlights
```

接收现有公共筛选、标签条件、本地经营分类、问题条件和标签周期参数。

响应示例：

```json
{
  "scope": {
    "current_date": "2026-07-21",
    "previous_date": "2026-07-20",
    "gap_days": 1
  },
  "summary": {
    "candidate_count": 18,
    "displayed_count": 5
  },
  "events": [
    {
      "event_id": "lifecycle:mature|inventory:high",
      "event_type": "surge",
      "conditions": [],
      "previous_count": 245,
      "current_count": 263,
      "added_count": 23,
      "removed_count": 5,
      "net_change": 18,
      "change_rate": 0.073,
      "sales_amount": 186000,
      "profit_amount": 24000,
      "trigger_reason": "较上次增加 18 个 MSKU"
    }
  ],
  "excluded_event_keys": ["missing_local_metrics"],
  "rule_version": "v1"
}
```

### 9.3 性能

- 主接口完成后异步请求重点变化。
- 摘要接口不返回完整 MSKU 行和流转矩阵。
- 点击变化明细后才请求现有变化接口。
- 两日标签索引和本地指标继续缓存 5 分钟。
- 缓存后目标不超过 500 毫秒，冷请求目标不超过 2 秒。

## 10. 测试与验收

- “暂无经营数据”不会成为重点事件或组合条件。
- 单项、二项和三项组合触发结果正确。
- 所有事件都有明确入选原因，不存在隐藏评分。
- 固定排序稳定、可复现。
- 当前筛选和联动条件变化后摘要同步更新。
- 今日、上次、新增、离开和净变化能够对账。
- 点击“筛选该群体”后页面数量与事件口径一致。
- 点击“查看变化明细”打开正确的现有变化抽屉。
- 无上次数据、无明显变化和接口失败状态正确。
- 重点变化异步加载，不降低现有首屏速度。
- 桌面、平板和窄屏布局可用，键盘焦点清晰。

## 11. 其他已讨论页面优化

以下内容同时记录，但不与“今日重点变化”强制捆绑上线。

### 11.1 统计口径常驻提示

- 页面持续显示当前主口径是去重 MSKU 还是经营单元。
- 标签覆盖、问题概览和明细标题明确单位。
- 避免用户直接比较不同口径的数字。

### 11.2 二级分析折叠与页面锚点

- 增加“覆盖 / 问题 / 联动 / 关系 / 明细”页内导航。
- 标签关系矩阵和规则说明默认作为二级分析折叠。
- 保持用户下钻后能够快速返回当前分析位置。

### 11.3 明细表字段预设

- 保留综合视图。
- 增加经营视图和标签视图预设。
- 固定国家类别、店铺、MSKU 和问题提示等关键列。
- 用户切换视图不改变筛选和分页口径。

### 11.4 变化接口性能优化

- 将摘要与完整变化明细拆开请求。
- 完整变化明细只在打开抽屉时加载。
- 复用两日索引，减少重复构造流转矩阵和明细行。

### 11.5 画像抽屉自适应

- 国家画像只有一个国家时使用紧凑详情布局。
- 多国家时继续使用固定表头的横向表格。
- 标签画像中多周期销售角色可合并为紧凑周期行，规则摘要按需展开。

### 11.6 窄屏和可访问性优化

- 窄屏将左侧导航折叠为可展开入口，释放内容宽度。
- 提高次要灰色文字对比度，避免关键数据使用过小字号。
- 选中、风险和改善状态同时使用文字与颜色。
- 表格、条件按钮、抽屉关闭按钮补齐键盘焦点和可访问名称。

## 12. 实施顺序

### 第一阶段

1. 今日重点变化服务和接口。
2. 页面摘要区域。
3. 筛选与现有变化抽屉联动。
4. 功能、口径和性能测试。

### 第二阶段

1. 统计口径常驻提示。
2. 页面锚点与二级区域折叠。
3. 明细表字段预设优化。

### 第三阶段

1. 画像抽屉自适应。
2. 窄屏导航与响应式优化。
3. 字号、对比度和键盘操作完善。

## 13. 默认决策

- 重点变化最多展示 5 条。
- 明显变化优先于立即处理风险。
- 不使用综合评分。
- 摘要跟随当前页面全部有效条件。
- 组合最多三个不同分类。
- “暂无经营数据”不参与重点摘要。
- 完整变化仍通过现有抽屉查看。
- 首版仅在普通标签看板实施。
