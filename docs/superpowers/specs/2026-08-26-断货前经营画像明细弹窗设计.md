# 断货前经营画像明细弹窗设计

## 一、设计目标

重做标签看板现有 MSKU 明细中的“断货前销售角色依据”弹窗，使运营人员打开明细后能够快速看清：

1. 商品最近一次断货从何时开始；
2. 商品长期由什么销售角色主导；
3. 断货前处于什么销售角色；
4. 历史表现是否稳定；
5. 断货前相对历史是持续、升为还是降为；
6. 当前组合大标签由哪些近期角色、日销或毛利变化形成；
7. 每一个历史角色节点的实际状态及其计算口径。

弹窗服务于商品级经营结论查看与证据追溯，不提供补货、恢复库存或运营优先级建议。

## 二、范围边界

- 保留现有 MSKU 明细入口，点击“查看明细”后展开弹窗。
- 不新增独立页面、路由或第二套商品列表。
- 关闭弹窗后保留主页面原有筛选、分页和滚动位置。
- 只处理 MSKU 维度，不增加国家维度切换。
- 不修改销售角色、历史主导角色、稳定性和组合大标签的底层计算规则。
- 不新增独立的“结论可信度”模块；历史不足、周期不足等情况在对应结论位置直接说明。
- 原始 JSON 仅用于技术追溯，不作为一级内容入口。

## 三、现有弹窗的问题

现有弹窗以“断货时间线、断货前表现、角色判定、历史角色轨迹、计算与来源、原始 JSON”六个页签组织内容，存在以下问题：

- 断货前角色、历史主导角色、稳定性和组合大标签分散，无法形成一条完整结论链。
- 顶部仅展示断货日期和天数，没有展示角色关系与结论变化。
- 历史轨迹包含大量节点，但参与计算、沿用和不可判断节点缺少足够明显的区分。
- “日销改善”“毛利下降”等组合标签缺少连续指标依据。
- 计算信息和原始 JSON 与运营结论处于相同层级，增加首次查看成本。

## 四、整体交互形式

弹窗改为“单条纵向明细＋顶部定位导航”，不再保留原六个一级页签。

弹窗从上到下依次为：

1. 商品身份与断货状态；
2. 综合结论关系链；
3. 历史稳定性；
4. 全部历史角色节点；
5. 近期指标变化；
6. 完整计算依据与原始 JSON。

顶部定位导航提供“综合结论、历史轨迹、指标变化、计算依据”四个锚点。点击后只在弹窗内部滚动，不改变主页面状态。

## 五、商品身份与断货日期

弹窗标题改为“断货前经营画像”。标题区域展示国家类别、店铺和 MSKU，并保留当前运营状态与断货前角色标签。

日期摘要固定展示：

- 断货日期；
- 已断货天数；
- 断货前角色计算窗口。

断货起点按证据情况使用三种名称：

| 条件 | 展示名称 |
|---|---|
| 能确认最近一次从有货切换为断货 | 最近断货开始日 |
| 商品从首次出现数据时就已经断货 | 最早观察到断货 |
| 起点证据不足 | 断货起点待确认 |

需要同时保留数据日期、角色来源日期、窗口起止日期和历史范围起止日期，但这些辅助日期放在对应区域，不全部挤入顶部摘要。

## 六、综合结论关系链

顶部核心结论采用一条关系链展示：

> 历史主导角色 → 断货前角色 → 组合结论

每一段展示：

### 历史主导角色

- 历史主导角色名称；
- 主导角色占有效节点比例；
- 有效历史节点数量。

### 断货前角色

- 断货前角色名称；
- 正式30天窗口或14天兜底窗口；
- 角色来源日期；
- 窗口起止日期；
- 是否为断货期间沿用结果。

### 组合结论

- 组合大标签；
- 断货前角色相对历史主导角色的变化：持续、升为或降为；
- 角色变化优先级沿用“明星＞潜力＞瘦狗＞问题”。

示例：

> 历史主导瘦狗（占比80%） → 断货前潜力（30天正式窗口） → 潜力·日销改善（断货前升为潜力）

## 七、历史稳定性

历史稳定性采用“结论常显、详细依据展开”的方式。

默认展示：

- 综合稳定性：稳定、波动或依据不足；
- 有效历史节点数；
- 历史主导角色占比；
- 角色切换率；
- 角色稳定性；
- 日销稳定性；
- 毛利稳定性。

点击展开后展示稳定性判断阈值和参与计算的节点说明。

页面中的“稳定”继续合并历史稳定与轻度波动：

- 有效且不重复节点少于3个：依据不足；
- 主导角色占比不低于70%，且角色切换率不高于35%：历史稳定；
- 主导角色占比不低于60%，且角色切换率不高于50%：轻度波动，页面合并展示为稳定；
- 其他情况：波动。

不增加独立可信度卡片。若存在断货前周期不足、历史节点不足或无有效历史角色，直接在对应角色或稳定性位置说明。

## 八、全部历史角色节点

历史轨迹保留原有横向节点样式，所有节点继续平铺展示，不隐藏不可判断或沿用节点。

### 排列规则

- 最新节点在左，越向右时间越早；
- 节点区域支持横向滚动；
- 最近断货事件固定放在轨迹最左侧；
- 断货前选中节点紧邻断货事件，并重点高亮。

### 节点状态

| 节点类型 | 展示要求 |
|---|---|
| 参与计算的有效节点 | 使用明确的角色颜色和角色名称 |
| 断货前选中节点 | 增加描边和“断货前选中”文字标识 |
| 断货期间沿用节点 | 保留角色名称，同时说明来源日期和“不重复计入” |
| 周期角色不可判断 | 灰色展示，并说明经营天数不足或其他实际原因 |
| 被排除节点 | 保留展示，并说明未参与稳定性计算 |
| 断货事件 | 展示断货日期和“开始断货”，与角色节点形成明显分界 |

每个节点至少展示：

- 节点日期；
- 销售角色或不可判断状态；
- 窗口起止日期；
- 有效经营天数；
- 是否参与稳定性计算；
- 沿用来源日期或未参与原因。

节点默认突出角色主结论；点击有效节点后，在节点详情中展示日销、毛利率和角色命中依据。

## 九、近期指标变化

指标区域用于解释组合大标签，不创建新的趋势计算口径。

默认展示用于当前组合标签判断的连续有效节点，并延伸到断货前角色窗口：

> 较早有效节点 → 最近有效节点 → 断货前角色窗口

每个节点展示：

- 日销；
- 毛利率；
- 销售角色；
- 节点日期或窗口日期；
- 是否达到日销或毛利变化阈值。

沿用现有指标变化阈值：

- 日销单次变化至少0.2，且前值非0时相对变化超过20%，才计为有效变化；
- 毛利率单次变化超过3个百分点，才计为有效变化；
- 最近有效节点不足3个时，组合趋势为依据不足；
- 角色等级出现变化时，优先使用角色改善、退化或波动结论；
- 角色保持不变时，再使用日销和毛利变化形成持续稳定、改善、下降或波动标签。

## 十、完整计算依据

弹窗底部保留“查看完整计算依据”折叠区，默认收起。

展开后展示：

- 断货前角色命中的具体规则；
- 计算方式和计算状态；
- 首次计算日期；
- 沿用角色来源日期；
- 库存与运营状态来源；
- 规则版本和 schema 版本；
- 原始 evidence JSON。

原始 JSON 放在该区域内的二级折叠中，不再占用一级页签。

## 十一、接口与数据组织

继续使用现有接口：

`GET /api/label-hub/stockout-before-role-evidence`

不新增独立页面接口。现有接口除标签 evidence 外，需要同时返回对应 MSKU 的断货历史经营结果字段。

接口响应调整为以下结构：

```json
{
  "identity": {},
  "stockout_event": {},
  "pre_oos_role": {},
  "historical_primary_role": {},
  "stability": {},
  "combined_conclusion": {},
  "historical_nodes": [],
  "metric_trend_nodes": [],
  "calculation": {},
  "raw_evidence": {}
}
```

接口需要补充或整理的结果字段包括：

- `oos_start_date`、`oos_start_method`、`oos_start_confidence`、`observed_oos_since_date`；
- `history_window_start`、`history_window_end`；
- `pre_oos_role`、`role_source_date`、`role_evidence_status`；
- `dominant_role`、`dominant_role_share`、`valid_window_count`、`role_switch_rate`；
- `historical_stability`、`role_stability`、`sales_stability`、`margin_stability`；
- `recent_trend`、`daily_sales_trend`、`margin_trend`；
- `combined_label_code`、`combined_label`；
- 节点的有效性、沿用状态、来源日期和排除原因。

前端不重新计算销售角色或稳定性，只负责解释接口返回的结果。

## 十二、加载、异常与空状态

- 打开弹窗后按当前 MSKU 延迟加载数据，不阻塞主列表。
- 加载期间保留商品身份，并显示明确的加载状态。
- 接口失败时允许重试或关闭弹窗，不清空主页面筛选。
- 无断货前角色时仍展示断货日期和历史节点，并在关系链对应位置显示实际原因。
- 无历史主导角色时不生成持续、升为或降为结论。
- 稳定性依据不足时展示有效节点数和不足原因，不误显示为波动。
- 原始 JSON 解析失败只影响技术追溯区，不应使整个运营结论区域不可用。

## 十三、响应式与可访问性

- 桌面端弹窗保持大尺寸居中展示，内部独立纵向滚动。
- 窄屏下关系链改为上下排列，历史节点仍保留横向滚动。
- 顶部导航保持可见，但不遮挡内容。
- 所有结论不能只依赖颜色区分，必须同时显示文字状态。
- 弹窗支持键盘关闭、焦点限制和关闭后焦点返回原明细按钮。
- 历史轨迹支持键盘横向滚动，节点的参与状态和排除原因提供可读文本。

## 十四、测试与验收

### 数据对账

- 弹窗断货日期与历史结果表一致；
- 断货前角色、历史主导角色、组合大标签和汇总区域一致；
- 有效节点数、主导角色占比和切换率与结果表一致；
- 参与计算、沿用和不可判断节点数量能够对账；
- 指标变化节点与组合标签实际使用的节点一致。

### 前端验收

- 弹窗默认展示综合结论，不需要切换页签；
- 历史轨迹中每一个节点都能够显示；
- 最新节点位于左侧，横向滚动可以查看更早节点；
- 断货事件、断货前选中节点、有效节点和未计入节点能够通过文字与视觉共同区分；
- 关闭弹窗后主列表筛选、分页和滚动位置不变；
- 技术计算和原始 JSON 默认收起；
- 桌面端和窄屏无内容截断、横向页面溢出或交互失效。

### 自动化验证

- 接口测试覆盖完整结果、无角色、无历史主导角色和依据不足场景；
- 前端测试覆盖默认结论、锚点定位、轨迹节点顺序和技术依据折叠；
- 使用真实 `2026-08-25` 结果进行无界面页面验收；
- 浏览器自动化与截图验收使用后台无界面模式运行。

## 十五、最终确认口径

- 该功能是现有 MSKU 明细弹窗重设计，不是新页面。
- 顶部先展示“历史主导角色 → 断货前角色 → 组合结论”。
- 稳定性结论常显，详细阈值按需展开。
- 不设置独立结论可信度模块。
- 历史轨迹保留原横向节点样式，所有节点平铺显示。
- 最新角色节点在左，越向右时间越早。
- 断货开始事件保留在轨迹最左侧。
- 指标变化用于解释现有组合标签，不新增计算规则。
- 计算来源和原始 JSON 统一放在底部折叠区。
