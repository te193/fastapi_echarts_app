# 返场页面扩展每页条数设计

## 目标

在“返场 MSKU 最新状态”列表的每页条数下拉框中增加 `200条`、`500条` 和 `全部`，使用户选择“全部”后，表格列排序和列筛选可以作用于当前业务筛选条件命中的完整数据集。

## 交互设计

- 保留现有 `20条`、`50条`、`100条`，默认值仍为 `20条`。
- 在下拉框末尾依次增加 `200条`、`500条`、`全部`。
- 切换每页条数后回到第 1 页并重新加载数据。
- 选择“全部”时只显示一页，上一页和下一页按钮均不可用。
- “全部”仅表示当前日期、国家、店铺、关键词、快捷筛选和库存状态等业务筛选结果的全部记录，不绕过这些业务筛选。

## 数据流与接口

- 前端继续通过 `page_size` 请求参数传递每页条数。
- `200` 和 `500` 按普通服务端分页处理。
- “全部”使用 `page_size=0` 作为明确的接口语义。
- API 允许 `page_size=0`，同时将普通分页上限提高到 `500`。
- 服务层先计算当前筛选结果总数；当 `page_size=0` 时，以总数作为查询条数、将页码固定为第 1 页，并返回单页结果。
- 空结果时不执行无效的零条限制查询，分页信息仍保持稳定。

## 排序与筛选行为

当前 AG Grid 的列排序和列筛选只处理已经加载到浏览器的行。因此：

- 选择 `20`、`50`、`100`、`200` 或 `500` 时，列排序和列筛选作用于当前加载页。
- 选择“全部”时，后端返回当前业务筛选结果的所有行，AG Grid 对这些完整行执行排序和列筛选，从而实现全量排列。
- 不在本次改动中新增服务端列排序或列筛选协议。

## 验证

- 前端回归测试检查下拉框包含 `200条`、`500条` 和 `全部`，且“全部”映射为 `page_size=0`。
- API 测试检查 `0`、`200`、`500` 可通过参数校验，超过 `500` 的普通分页值被拒绝。
- 服务层测试检查普通分页不再被截断为 `100`，以及 `page_size=0` 返回全部记录并固定为单页。
- 运行返场页面前端、API 和服务层相关测试。

## 非目标

- 不改变默认每页条数。
- 不修改返场业务筛选口径。
- 不改造为服务端驱动的 AG Grid 排序或列筛选。
- 不调整其他页面的分页选项。
