# 加权日销返回列精简与 SQL 小写设计

## 目标

精简 `data/补货页面加权日销计算.sql` 的最终查询结果，并统一 SQL 书写风格，不改变现有加权日销和广告预算计算口径。

## 返回字段调整

最终 `select` 删除以下四个周期日销展示列：

- `daily_sales_3d`
- `daily_sales_7d`
- `daily_sales_14d`
- `daily_sales_30d`

继续返回各周期销量和可售天数：

- `sales_3`、`r_3d_salable_days`
- `sales_7`、`r_7d_salable_days`
- `sales_14`、`r_14d_salable_days`
- `sales_30`、`r_30d_salable_days`

最终加权日销 `daily_avg_sales` 保留。四个周期日销仍在查询内部参与新品、老品加权计算，只是不再作为最终结果列输出，因此加权公式和广告预算结果不变。

## SQL 书写风格

整份 SQL 的关键字和内置函数统一使用小写，包括 `select`、`from`、`case`、`round`、`date` 等。已有表名、字段名、别名和中文业务值保持不变。

## 验证标准

1. 最终结果不包含四个周期日销列，仍包含周期销量、可售天数和 `daily_avg_sales`。
2. 原有临时表、国家维度、新老品判断、汇率和广告预算逻辑不变。
3. 在 `opt_db` 同一连接中可以完整执行，返回行数和关键样例的加权日销、广告预算与修改前一致。
4. 连接关闭后不遗留临时表或结果表。
5. 项目测试全部通过。
