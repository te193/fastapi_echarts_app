# 同 ASIN 产品组补货指标统一展示设计

## 结论

同一国家大区、同一 ASIN 且进入合并补货的所有链接，本质上属于同一个产品组。页面不再展示各链接自身的库存支撑和补货层级，统一展示产品组合并后的库存、当前支撑天数、采购交期、到货时支撑天数和补货层级。

补货数量仍只由一个目标链接承接，其他链接保持0，并继续展示“被跟卖点不补货”或“同ASIN已合并至主链接”等原因。

## 统一口径

产品组指标按 `country_category + max_asin` 计算：

```text
产品组库存 = 组内所有链接支持库存之和
产品组日销 = 现有同 ASIN 合并规则计算出的组日销
产品组当前支撑天数 = 产品组库存 ÷ 产品组日销
产品组到货时支撑天数 = 产品组当前支撑天数 - 产品组有效采购交期
产品组补货层级 = 按产品组到货时支撑天数套用35/65/90天阈值
```

阈值不变：

| 到货时支撑天数 | 产品组补货层级 |
|---:|---|
| `≤ 35` | 紧急补货 |
| `> 35 且 ≤ 65` | 建议补货 |
| `> 65 且 ≤ 90` | 计划补货 |
| `> 90` | 库存充足 |
| 产品组日销 `≤ 0` | 日销为0 |

## 页面规则

对于进入同 ASIN 合并的所有链接：

- “库存 / 交期”主数值显示产品组当前支撑天数。
- 到货时支撑显示产品组到货时支撑天数。
- 采购交期显示产品组实际采用的有效采购交期。
- 左侧补货层级显示产品组补货层级。
- 层级筛选、排序和顶部层级统计使用同一产品组层级。
- 单链接自身库存支撑天数和自身原始层级不再作为补货主页面展示口径。

不进入同 ASIN 合并的普通单链接继续使用自身指标。

## 补货执行规则

本次不改变同 ASIN 补货决策和数量分配：

- 产品组补货需求仍只计算一次。
- 目标链接继续承接整组补货数量、箱数和货值。
- 非目标链接补货数量、箱数和货值继续为0。
- 被跟卖原始链接继续不承接补货。
- 目标链接选择顺序、箱规、成本、MOQ和历史恢复规则不变。

## 数据落地

现有 `tmp_asin_merge_assignments` 已经为组内每条链接带有产品组支撑、到货指标和产品组层级排序值。最终结果落表时，对所有 `asin_merge_flag = 1` 的行使用这些产品组字段，而不是只对 `asin_merge_target_flag = 1` 的目标行替换。

最终结果中的以下字段对同一产品组保持一致：

```text
inventory_support_days
effective_purchase_lead_days
arrival_inventory_support_days
arrival_inventory_qty
lead_time_demand_qty
base_replenish_need_qty
lead_adjusted_replenish_need_qty
lead_time_stockout_flag
lead_time_stockout_days
lead_time_lost_sales_qty
support_replenish_level
support_replenish_level_sort
```

补货数量相关字段仍按目标链接规则分配，不要求组内一致。

## 页面兼容调整

当前接口会把“已合并且补货量为0”的部分链接强制显示为“库存充足”。该覆盖规则需要取消，改为直接读取 ETL 已统一的产品组层级；“为什么不补货”继续由独立原因字段解释。

MOQ不足和历史恢复等既有页面优先级保持不变，除非其规则本身明确覆盖补货层级。

## 示例：QP122b

欧洲站同 ASIN 两条链接库存分别为120件和60件：

```text
产品组库存 = 120 + 60 = 180件
产品组日销 = 2.244762件/天
当前支撑 = 180 ÷ 2.244762 = 80.19天
采购交期 = 10天
到货时支撑 = 80.19 - 10 = 70.19天
产品组层级 = 计划补货
```

两条链接均显示80.19天、到货70.19天和“计划补货”。只有 `Quankezhan/QP122b` 承接产品组补货数量，另一条链接补货量为0并显示对应阻断原因。

## 验收标准

- 同一 `country_category + max_asin` 合并组内，所有链接的上述产品组指标和层级完全一致。
- QP122b 欧洲站所有链接均显示当前支撑80.19天、到货时支撑70.19天、计划补货。
- 同一合并组最多只有一个正补货目标。
- 被跟卖原始链接最终补货量仍为0。
- 普通单链接结果与修改前一致。
- 页面层级统计、筛选、排序和表格标签口径一致。
- 只重算 `etl_datasync_replenishment_test`，不写正式库。
