# 加权日销会话临时表性能优化设计

## 目标

将一次性大 CTE 查询拆为两张 MySQL 会话临时表和一个最终 `SELECT`，减少大表扫描及历史 Listing 排序，同时不持久化任何过程表或结果表。国家站点粒度、加权日销和双币种广告预算口径保持不变。

## 已确认的性能瓶颈

- 产品表现源表约 470 万行，最近 30 天约 56.9 万行。
- 原查询对产品表现选择全表扫描；使用 `FORCE INDEX (idx_osp_performance_dashboard_cover)` 后可改为日期范围扫描。
- Listing 业务只需要最新同步日，无需对历史日期执行窗口排序。
- 原单查询实测约 28.3 秒；会话临时表方案在 `opt_db` 实测约 16.6 秒。

## 执行结构

### 临时表一：产品表现最近 30 天周期指标

正式执行名称：

```text
dws_datasync.tmp_replenishment_weighted_sales_product_30d
```

使用 `CREATE TEMPORARY TABLE` 创建，只在当前数据库连接内存在。

处理过程：

1. `@biz_date = DATE(MAX(start_date))`；
2. 只读取 `biz_date - 29 天` 至 `biz_date`；
3. 强制使用 `idx_osp_performance_dashboard_cover`；
4. 内层先按日期、国家、店铺、MSKU 聚合，保证一天只计算一个可售日；
5. 外层直接生成每个业务键的 3/7/14/30 天销量和可售天数。

临时表约 1.9 万行，不落 56.9 万行日明细，也不创建一次性宽索引。

### 临时表二：Listing 最新日售价

正式执行名称：

```text
dws_datasync.tmp_replenishment_listing_price_latest
```

使用 `CREATE TEMPORARY TABLE` 创建，只读取 `MAX(DATE(create_time))` 对应的一天数据。在当天数据内按国家、店铺、MSKU 取最新有效 `landed_price`，并关联同月官方汇率 `rate_org`。

保留：

- 原币售价和 `currency_code`；
- 原币兑人民币汇率；
- 人民币售价；
- SEK 对应汇率表中的“瑞典”。

### 最终 SELECT

最终计算直接读取两张临时表，并通过 CTE 连接品牌和接收次数、判断新品/老品、计算平滑日销和加权日销，最后返回全部结果。

不再执行：

- `CREATE TABLE ... weighted_daily_sales_building`；
- 最终结果表主键创建；
- `RENAME TABLE` 原子换表；
- 任何普通 DWS 结果表写入。

数据库连接关闭后，两张临时表由 MySQL 自动释放，数据库中不留下本任务产生的表。

## 输出字段和公式

输出字段保持：

- 业务日期、国家类别、国家、店铺、MSKU；
- 品牌、接收次数、新品/老品；
- 3/7/14/30 天销量、可售天数、周期日销；
- 加权日销；
- Listing 原币售价、币种、汇率、人民币售价；
- 原币广告预算、人民币广告预算。

```text
ad_budget_original = listing_price × 5% × daily_avg_sales × 30
ad_budget_cny      = listing_price × exchange_rate_cny × 5% × daily_avg_sales × 30
```

## 测试映射

测试时只在内存中替换两张临时表的完整限定名称：

```text
dws_datasync.tmp_replenishment_weighted_sales_product_30d
=> opt_db.tmp_replenishment_weighted_sales_product_30d

dws_datasync.tmp_replenishment_listing_price_latest
=> opt_db.tmp_replenishment_listing_price_latest
```

测试连接关闭后，`opt_db` 中也不应留下任何测试表。

## 验证标准

1. 完整 SQL 在 `opt_db` 测试映射下成功执行并直接返回结果。
2. 产品窗口为业务日期当天及此前 29 天，Listing 只来自最新同步日。
3. 产品表现执行计划使用指定日期索引和范围扫描。
4. 新旧 SQL 输出行数相同，全部输出字段逐行一致。
5. 原币和人民币广告预算公式差异不超过最终舍入误差 0.01。
6. 数据库连接关闭后，产品、Listing 和最终结果测试表均不存在。
7. 项目完整回归测试通过。
