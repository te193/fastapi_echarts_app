# 低于最小起订量独立分类与参考值展示设计

## 目标

低于供应商 MOQ 的商品不进入紧急补货、建议补货、计划补货三个正常执行层，但在明细和导出中仍展示计算得到的补货数量、箱数和货值，供采购人员判断是否凑单或调整采购方案。

## 核心口径

- `moq_status = below_minimum` 时，数据库可执行数量、可执行箱数、可执行货值继续保持 0，避免误计入正常采购执行。
- 新增并持久化计算箱数、计算货值；计算补货量继续使用现有 `calculated_replenish_qty`。
- 页面和导出的“补货数量、箱数、补货货值”对低于 MOQ 商品展示计算值，而不是可执行值。
- 顶部“需要补货 MSKU、补货数量、补货货值”及紧急/建议/计划层级汇总继续只统计可执行值，不包含低于 MOQ 商品。
- 供应商 MOQ 只读取 `is_primary = '是'` 的首选供应商报价；同一首选供应商存在阶梯报价时取最小正数 MOQ。

## 独立层级

- 新增展示层级“低于最小起订量”。
- 当 `moq_status = below_minimum` 时，该展示层级优先于原库存支撑层级。
- 点击紧急补货、建议补货、计划补货时，低于 MOQ 商品不会出现在结果中。
- 页面右侧现有“低于最小起订量”预警卡继续作为该分类入口。
- 补货层级筛选中增加“低于最小起订量”，支持直接筛选该分类。
- 原始紧急/建议/计划等库存支撑判断字段不改，便于追溯商品在 MOQ 拦截前所属层级。

## 数据与 API

- 补货结果表新增：
  - `calculated_replenish_box_qty`
  - `calculated_replenish_cost`
- ETL 在 MOQ 门禁步骤同时写入计算值与可执行值：
  - 达到 MOQ 或 MOQ 未配置：可执行值等于计算值。
  - 低于 MOQ：可执行值为 0，计算值保留。
- API 明细对低于 MOQ 商品将计算值映射到现有 `replenish_qty / box_qty / cost` 返回字段，同时继续返回 MOQ 状态与差额。
- 导出使用与页面一致的展示口径；低于 MOQ 的行导出计算数量、箱数和货值。
- 汇总查询继续明确使用可执行字段，避免展示口径影响正常补货汇总。

## 兼容与安全

- 历史快照没有新计算字段时，沿用现有历史兜底计算，避免显示为空或 0。
- 生产同步只增加和更新 MOQ 相关字段，不覆盖原补货数量、层级或成本字段。
- 不修改补货追踪数据与追踪逻辑。

## 验收标准

- 低于 MOQ 商品的层级显示为“低于最小起订量”。
- 其明细与导出中的补货数量、箱数、货值均为计算参考值。
- 紧急、建议、计划三个筛选结果均不包含低于 MOQ 商品。
- 顶部及三层汇总不包含其参考数量和货值。
- 预警卡数量、计算补货量与该分类明细一致。
- MOQ 等于计算量时正常放行；MOQ 为 0、NULL 或未匹配时不拦截。
- 完整自动化测试、后台 API 验证和后台浏览器验证通过。
