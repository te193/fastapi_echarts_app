# 全部标签分组多选面板设计

## 1. 背景与目标

经营明细筛选区当前使用 SlimSelect 展示“全部标签”。所有子标签以“标签大类 · 子标签”的形式平铺在一个长列表中，虽然支持搜索和多选，但大类边界不明显，浏览与定位成本较高。

本次将该控件改为与现有“角色原因”一致的自定义分组复选面板，采用连续分组列表结构：

- 保留标签搜索；
- 按标签大类分组展示子标签；
- 支持跨大类多选；
- 保留现有“应用筛选”统一提交方式；
- 不修改后端接口、筛选参数和业务逻辑。

## 2. 范围

### 2.1 本次包含

- 经营明细筛选区“全部标签”控件的触发框、搜索框、分组列表、复选状态和空结果状态；
- 与现有原生多选 `select`、明细筛选状态、已选条件 Chip、重置操作的双向同步；
- 点击外部、按 `Esc`、窄屏布局等基础交互；
- 前端契约测试和真实浏览器回归验证。

### 2.2 本次不包含

- 后端查询、接口字段和条件序列化格式调整；
- 标签分类规则、标签名称和数据口径调整；
- 大类全选、反选、收藏、最近使用等扩展功能；
- 其他 SlimSelect 筛选框的统一重构。

## 3. 选定方案

采用“连续分组列表”结构。面板从上到下依次为：

1. 固定搜索区；
2. 维度和多选提示区；
3. 标签大类分组；
4. 每组内两列子标签复选项；
5. 搜索无结果提示。

该结构与现有角色原因面板保持同一套视觉语言，同时允许用户连续查看不同标签大类，不需要在分类导航或折叠面板之间反复切换。

## 4. 组件结构

### 4.1 触发框

触发框替代当前 SlimSelect 的可视化部分，原生多选 `select` 保留为隐藏状态，用于兼容现有状态读取和参数构建。

触发框文案规则：

- 未选择：`全部标签`；
- 选择 1 项：显示该子标签名称；
- 选择多项：显示 `已选 N 项`。

存在已选项时沿用当前筛选控件的浅蓝色强调状态。展开时箭头向上并强化边框，不改变筛选工具栏整体高度。

### 4.2 搜索区

搜索框固定在面板顶部，面板内容滚动时保持可见。输入内容去除首尾空格并按不区分大小写的包含关系匹配。

搜索规则：

- 命中子标签名称：只显示命中的子标签；
- 命中标签大类名称：显示该大类下全部子标签；
- 未命中的大类整体隐藏；
- 搜索只改变显示结果，不改变任何已选状态；
- 清空搜索后恢复全部大类和子标签。

### 4.3 分组列表

分组数据直接来自现有 `meta.categories` 与 `meta.excluded_categories`，保持接口返回顺序。每个大类包含标题和子标签复选项。

- 桌面端子标签使用两列布局；
- 面板设置最大高度并在内部纵向滚动；
- 分组之间使用轻量分隔线，不增加高饱和色块；
- 窄屏下降为单列，避免文字挤压；
- 不提供大类级“全选”，防止一次加入过多 AND/OR 条件造成误解。

### 4.4 空结果状态

搜索没有任何匹配项时，在分组区域显示 `未找到匹配标签`。清空搜索即可恢复，不关闭面板、不清除选择。

## 5. 交互规则

- 点击触发框切换面板展开状态；
- 点击复选框立即更新待提交选择和触发框摘要，但不请求接口；
- 点击现有“应用筛选”后，继续由 `collectDetailFilters()` 收集状态并执行查询；
- 点击面板外部或按 `Esc` 关闭面板；
- 关闭后再次打开，保留复选状态；搜索词重置为空，重新展示完整标签结构；
- 点击“重置”清除原生 `select`、自定义复选框、触发框摘要和搜索词；
- 点击已选条件 Chip 删除标签后，自定义面板在下一次渲染时同步取消对应复选框；
- 面板操作不影响销售角色、角色原因及其他筛选控件。

## 6. 状态与数据流

### 6.1 数据来源

现有 `detailLabelOptions()` 的扁平返回值改为保留大类结构的前端数据：

- 大类：`id`、`label`；
- 子标签：`id`、`label`；
- 原生选择值继续使用 `父标签ID:子标签ID`。

### 6.2 状态同步

自定义面板不新增后端状态，复用现有链路：

```text
复选框
  → 隐藏的 labelHubDetailLabels 原生 select
  → collectDetailFilters()
  → serializeDetailConditions()
  → detailState.detail_conditions
  → /api/label-hub/details
```

反向同步链路：

```text
URL/重置/Chip 删除/重新填充控件
  → detailState.detail_conditions
  → 原生 select selected 状态
  → 自定义面板复选状态与触发框摘要
```

原有接口参数、条件序列化和值格式保持不变。

## 7. 前端实现边界

新增“全部标签”专用控件，不把所有 SlimSelect 一次性改造成通用组件，避免扩大回归范围。实现职责拆分为：

- 标签分组数据构建；
- 面板内容渲染；
- 搜索过滤；
- 原生选择同步；
- 触发框摘要更新；
- 展开、关闭和重置。

样式优先复用角色原因面板的尺寸、边框、阴影、字号和复选框语言，并使用独立类名避免相互影响。

## 8. 异常与边界情况

- 无标签数据：面板显示 `暂无可用标签`，触发框保持可用但不产生选择；
- 已选值在新元数据中不存在：同步时忽略该值，避免渲染失效选项；
- 标签名称较长：单行省略，悬停通过原生 `title` 查看完整名称；
- 面板接近视口边缘：保持当前工具栏定位方式，限制最大宽高并允许内部滚动；
- 重复打开：不得重复绑定全局点击和键盘事件；
- 搜索后勾选：仅改变目标选项，不影响被搜索隐藏的已选项。

## 9. 测试与验证

### 9.1 自动化测试

- 模板包含触发框、搜索框、面板、隐藏原生多选和分组容器；
- 标签分组渲染保留父子结构与 `父ID:子ID` 值；
- 复选变化同步原生 `select`；
- 搜索大类、搜索子标签和无结果三种状态正确；
- 多选摘要、重置、Chip 删除和重新填充状态正确；
- 现有 `collectDetailFilters()` 与参数序列化契约保持不变。

### 9.2 浏览器验证

- 桌面端展开结构与已确认的方案 A 一致；
- 可跨大类勾选多个标签，点击应用后明细数量发生对应变化；
- 关闭再打开选择仍保留；
- 搜索不会丢失隐藏的已选项；
- 点击外部和 `Esc` 均可关闭；
- 重置后摘要和筛选 Chip 同步清空；
- 窄屏子标签切换为单列；
- 浏览器控制台无新增错误。

## 10. 验收标准

- “全部标签”不再显示为无层级的长列表；
- 所有标签按真实大类连续分组，子标签可跨组多选；
- 搜索框始终保留，并同时支持大类和子标签名称搜索；
- 筛选提交时机、参数和值格式与当前版本完全一致；
- 视觉风格与角色原因面板及经营明细筛选工具栏一致；
- 不影响其他筛选项、明细视图切换和页面业务逻辑。
