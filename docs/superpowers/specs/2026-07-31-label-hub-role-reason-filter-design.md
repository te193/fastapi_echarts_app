# 标签看板经营明细“角色原因”筛选设计

## 1. 目标

将“经营明细与问题定位”高级筛选区中的“销售趋势 / 全部趋势”替换为“角色原因 / 全部角色原因”，让用户能直接按销售角色诊断子标签筛选明细。

本次只调整经营明细筛选入口及其筛选参数，不改变销售角色、诊断标签的生成规则，也不改变日销段、毛利段、排名等现有筛选逻辑。

## 2. 选定视觉方案

采用方案 1“联动分组下拉”：

- 保留现有“销售角色 / 全部角色”多选框。
- 右侧原“销售趋势 / 全部趋势”改为“角色原因 / 全部角色原因”。
- 控件尺寸、边框、圆角、字号、展开方向和 SlimSelect 交互与现有高级筛选保持一致。
- 未选择销售角色时，下拉选项按明星产品、潜力产品、瘦狗产品、问题产品分组展示。
- 已选择销售角色时，只展示所选角色对应的诊断原因。
- 下拉顶部显示当前筛选口径：
  - MSKU 维度：`MSKU维度 · 全站诊断`
  - 国家明细：`国家明细 · 国家站点诊断`

## 3. 数据口径

### 3.1 MSKU 维度

使用父标签 15“全站点销售角色-产品问题标签”的子标签：

- 明星产品：已达标
- 潜力产品：低毛利、日销或毛利待突破
- 瘦狗产品：低毛利、低日销、日销毛利双低
- 问题产品：低毛利、零动销

### 3.2 国家明细

使用父标签 16“站点销售角色-产品问题标签”的全部子标签。除日销、毛利原因外，国家口径还包含排名不足、排名无效以及组合原因。

选项仍按销售角色分组；“数据异常-无法判断”单独放在“数据异常”分组中。

### 3.3 维度切换

- 从 MSKU 维度切换到国家明细时，控件自动改用父标签 16。
- 从国家明细切回 MSKU 维度时，控件自动改用父标签 15。
- 切换维度时清空已经选择的角色原因，避免父标签和子标签 ID 跨口径残留。
- “销售角色”以及其他高级筛选项保持不变。

## 4. 联动与筛选语义

### 4.1 销售角色联动

- 未选销售角色：展示当前口径下的全部角色原因。
- 选择一个角色：仅展示该角色对应原因。
- 选择多个角色：展示这些角色对应原因，并继续分组。
- 修改销售角色后，自动移除与新角色集合不兼容的已选原因。

“明星产品 / 潜力产品 / 瘦狗产品 / 问题产品”的展示名称以当前系统的销售角色名称为准；底层继续使用现有销售角色 code。

### 4.2 组合关系

- 销售角色和角色原因之间使用 AND。
- 同一“角色原因”下多选多个子标签时使用 OR。
- 角色原因与国家类别、店铺、国家、日销段、毛利段、排名等筛选条件之间使用 AND。
- 继续使用已有标签事实 `_by_parent` / `labels` 判断命中，不重新计算销售角色规则。

示例：

`销售角色 = 潜力产品` 且 `角色原因 = 低毛利 OR 日销或毛利待突破`

表示只返回属于潜力产品，并且命中任意一个所选诊断原因的记录。

## 5. 界面状态

### 5.1 默认状态

- 控件标题：`角色原因`
- 占位文字：`全部角色原因`
- 未选择时不产生筛选条件。

### 5.2 已选状态

- 多选控件沿用当前“已选 N 项”的紧凑显示方式。
- 下方“已选条件”区域显示可单独移除的条件：
  - `角色原因：潜力产品-低毛利`
  - `角色原因：潜力产品-日销或毛利待突破`
- 高级筛选数量徽标计入角色原因的已选数量，不再计算销售趋势数量。

### 5.3 空选项与异常

- 当前角色没有可用诊断原因时，控件禁用并显示“当前角色暂无诊断原因”。
- 元数据未返回父标签 15 或 16 时，控件禁用并显示“角色原因暂不可用”，其余筛选继续工作。
- 接口收到不属于当前口径父标签的子标签 ID 时返回参数错误，不静默忽略。

## 6. 前后端边界

### 6.1 前端

- 用 `role_reason_ids` 替代高级筛选中的 `sales_trends` 状态和请求字段。
- 从已有标签元数据的排除分类中读取父标签 15、16，不维护重复的固定选项表。
- 根据 `detail_view` 选择诊断父标签，并根据 `sales_roles` 过滤可见子标签。
- 维度或销售角色变化时同步清理不兼容选择。
- 重置、筛选标签移除、筛选数量、原生 select 与 SlimSelect 状态同步均覆盖新字段。

### 6.2 后端

- 明细接口新增 `role_reason_ids: list[int]`。
- 根据 `detail_view` 限定允许的父标签：
  - `business_unit` 只允许父标签 15 的子标签。
  - `country` 只允许父标签 16 的子标签。
- 在现有 `row_matches` 中按当前父标签执行“所选子标签任一命中”判断。
- 从明细接口的 `applied_filters` 返回 `role_reason_ids`。
- 移除该明细入口对 `sales_trends` 的使用；其他页面和经营趋势展示不受影响。

## 7. 验证范围

### 7.1 服务测试

- MSKU 维度可按父标签 15 子标签筛选。
- 国家明细可按父标签 16 子标签筛选。
- 同一父标签多选原因采用 OR。
- 角色与原因组合采用 AND。
- 非当前口径子标签 ID 被拒绝。
- 无诊断标签的记录不会误命中。

### 7.2 前端测试

- 页面不再显示“销售趋势 / 全部趋势”高级筛选。
- 显示“角色原因 / 全部角色原因”。
- 角色选择会裁剪原因选项和失效选择。
- 明细维度切换会切换父标签并清空已选原因。
- 重置、应用、移除筛选标签和数量徽标均正确。

### 7.3 后台视觉验证

- 使用独立无头浏览器验证，不操作用户正在使用的前台浏览器。
- 检查默认、展开、已选、多选、无选项、MSKU/国家维度切换状态。
- 检查 1600px、1366px 和窄屏横向滚动场景，确保下拉不被表格或容器裁切。

## 8. 不在本次范围

- 不修改标签表中的诊断规则或证据 JSON。
- 不修改角色诊断抽屉。
- 不修改销售趋势的计算与其他页面展示。
- 不增加新的销售角色或诊断原因。
- 不改变经营明细表格字段和排序逻辑。
