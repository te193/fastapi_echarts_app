# 标签看板国家排名筛选设计

## 目标

在标签看板明细筛选区增加“排名”多选筛选，仅用于国家明细视图，帮助按国家级商品排名快速定位产品。

## 数据口径

- 底层使用 `dashboard_product_performance_daily.ranking`。
- 排名取当前国家明细指标统计窗口结束日的国家级值。
- `ranking` 为正整数时视为有效排名；空值、0 或负数统一视为“暂无排名”。
- 不使用 `small_category_ranking` 作为接口或界面名称。

## 筛选档位

- 前10：`1–10`
- 11–20：`11–20`
- 21–50：`21–50`
- 51–100：`51–100`
- 100名后：`>100`
- 暂无排名：空值、0 或负数

排名档位支持多选，同一字段内为 OR；与国家、店铺、标签、问题等其他筛选字段之间为 AND。

## 交互设计

- 在“更多筛选”区域增加“排名”多选控件，沿用现有紧凑筛选样式。
- 仅切换到国家明细时启用排名筛选。
- 切回经营单元视图后保留已选排名，但不参与查询，并显示为“排名（已保留）”。
- 已选排名出现在筛选条件标签区域，可单独移除或随“重置”清空。
- 国家明细表增加“排名”列；无有效排名显示“暂无”。

## 接口与服务

- `POST /api/label-hub/details` 请求新增 `ranking_bands` 数组。
- 合法值为：`top10`、`11_20`、`21_50`、`51_100`、`gt100`、`missing`。
- `ranking_bands` 仅在 `detail_view=country` 时参与筛选；经营单元视图只回显条件。
- 国家级指标查询返回 `ranking`，并参与服务端筛选、排序和分页。
- 响应的 `applied_filters` 回显 `ranking_bands`。
- 国家指标源不可用且选择了排名筛选时，返回明确的不可筛选错误，不把异常当作“暂无排名”。

## 验证

- 验证六个档位的边界值：1、10、11、20、21、50、51、100、101、空值、0、负数。
- 验证排名多选为 OR，与其他字段之间为 AND。
- 验证排名只影响国家视图，经营单元视图保留但不生效。
- 验证指标源不可用时的错误提示。
- 验证排名列、筛选标签、重置和视图切换状态。
- 全量回归确保现有标签、问题、国家、店铺和指标筛选不受影响。
