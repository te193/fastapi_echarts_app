# docs 文档分阶段整理设计

## 背景

整理前盘点时，`docs/` 共有 79 个文件，其中 24 个文件直接位于根目录，内容混合了业务规则、指标口径、方案规划、排查记录、部署说明和实施交接。`docs/superpowers/specs/` 与 `docs/superpowers/plans/` 已经分别保存设计和实施过程记录，不需要重新拆分。

本次整理采用“一级按业务模块、二级按文档类型”的精简矩阵结构。只有确实存在文档时才创建二级目录，避免产生大量空目录。

## 目标

- 让使用者先按业务模块定位，再按文档用途查找。
- 通过 `docs/README.md` 区分当前有效、讨论中和历史过程文档。
- 分阶段迁移，确保每一步都容易审查和回退。
- 保留现有文件名，降低链接失效和 Git 历史追踪成本。
- 保留 `superpowers/` 作为研发过程记录，与当前业务口径分开导航。

## 非目标

- 首轮不移动、重命名或删除现有业务文档。
- 不在没有业务确认的情况下合并内容相似的文档。
- 不把历史实施计划当作当前业务规则的唯一依据。
- 不为尚不存在的文档类型预建空目录。

`archive/` 仅在后续确认存在失效文档时创建。若某个二级分类没有文件，也不创建对应目录。

## 分类规则

1. 先依据文档服务的业务对象确定一级目录。跨模块文档放到承担主要维护责任的模块，并在总索引中添加其他入口。
2. 再依据文档的主要用途确定二级目录。标题中出现“方案”不自动决定分类，应以正文的实际用途为准。
3. 同一主题的 Markdown 与 HTML 配套产物放在同一目录，避免展示文件和源文档分离。
4. 讨论稿保留在对应业务分类中，并在索引状态列标注“讨论中”，不因状态不确定而直接归档。
5. 只有已被新文档替代、停止使用且完成业务确认的文件才能进入 `archive/`。

## 总索引设计

`docs/README.md` 作为唯一总入口，按业务模块分节。每个条目至少包含以下信息：

| 字段 | 说明 |
| --- | --- |
| 文档 | 使用相对路径链接到文件 |
| 用途 | 一句话说明文档解决的问题 |
| 状态 | `当前有效`、`讨论中` 或 `历史过程` |
| 更新日期 | 优先取文档明确标注的日期，否则使用最近一次 Git 修改日期 |

索引首先展示当前有效文档，其次展示讨论中文档。`superpowers/specs/` 和 `superpowers/plans/` 只提供目录级说明，不把所有过程文件逐条铺到总索引中。

## 分阶段实施

### 第一阶段：建立逻辑结构，不迁移文件

- 不单独创建 Git 无法跟踪的空目录；先在 `docs/README.md` 中说明目标结构和分类规则。
- 重写 `docs/README.md`，使用现有路径建立完整索引和状态说明。
- 将本设计中的迁移清单作为后续批次的唯一范围基线。
- 检查索引中的每个相对链接都能定位到现有文件。

### 第二阶段：按模块逐批迁移

建议批次顺序为：项目运维与数据源、返场品、标签看板、产品分层看板、补货。每个批次执行以下步骤：

1. 使用 `git mv` 移动文件，不修改文件名和正文。
2. 随首个文件迁移自然创建该模块所需的实际目录。
3. 同步更新 `docs/README.md`、仓库根 `README.md` 以及仓库内其他引用。
4. 校验全部 Markdown 相对链接。
5. 单独提交该业务模块，确保问题可以按批次回退。

### 第三阶段：确认有效性并归档

- 由业务或文档维护者确认内容相似文件之间的现行与历史关系。
- 对被明确替代的文档，在新文档中补充替代关系或迁移说明。
- 创建 `archive/`，按业务模块存放已确认失效的文档。
- 更新总索引；归档文档不出现在“当前有效”区域。

## 命名与新增文档约定

- 本次迁移保留所有现有文件名。
- 新增时优先使用清晰的中文主题名；需要体现时间的排查记录、部署记录和阶段性交接使用 `YYYY-MM-DD-主题.md`。
- 避免仅用 `新方案`、`最终版`、`v2` 表示时效；版本关系应在文档开头和总索引中说明。
- 业务规则文档开头应逐步补充状态、维护范围和替代关系，但该内容治理不纳入前两阶段的批量移动。

## 安全与回退

- 每次仅迁移一个业务模块，并在迁移前确认 Git 工作区无无关改动。
- 不通过复制后删除的方式迁移；统一使用 `git mv` 保留历史可追踪性。
- 不删除内容文件。唯一计划删除的是迁移后为空的旧目录，Git 本身不跟踪空目录。
- 任一批次出现无法确认的引用或文档归属时，保留原位置并记录到迁移清单，不擅自判断。

## 验收标准

- `docs/` 根目录只保留 `README.md`、业务分类目录和独立的 `superpowers/` 过程记录目录。
- 现有 79 个文件除经确认归档外均可从总索引或过程目录说明中找到。
- 仓库根 `README.md` 中的文档链接和 `docs/README.md` 中的相对链接全部有效。
- 文件迁移前后名称和正文不变，Git 能识别为重命名或移动。
- `superpowers/specs/` 与 `superpowers/plans/` 保持现有职责和结构。
- 没有未确认的删除、合并或归档操作。
