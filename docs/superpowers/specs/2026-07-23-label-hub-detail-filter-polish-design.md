# 标签看板明细筛选区视觉优化设计

## 目标

将当前占据大量纵向空间的原生多选列表，改造成参考图风格的横向紧凑筛选工具栏，同时保持标签看板现有的浅灰蓝背景、圆角卡片和蓝色强调色。

## 布局

筛选区分为三层：

1. 主操作行：批量 MSKU/SKU 输入、问题关系、应用筛选、清空筛选、更多筛选。
2. 核心条件行：问题、国家类别、店铺、国家四个常用多选控件。
3. 高级条件区：标签、销售角色、销售趋势、日销段、毛利段，默认折叠，由“更多筛选”展开。

批量编码输入采用单行/双行紧凑输入形态，不再占据左侧整列高度。桌面端尽量保持一至两行；窄屏按字段自然换行。

## 控件与状态

- 多选控件使用现有 SlimSelect 能力，呈现为白底、细描边、紧凑高度的下拉框。
- 控件未选中时显示字段名称；选中后显示首个选项和数量，例如“负毛利等 3 项”。
- 已生效条件在筛选区底部显示为可移除的紧凑标签。
- 国家条件在经营单元视图中保留但不生效，使用橙色状态提示。
- “更多筛选”显示当前高级条件数量，展开后按钮保持蓝色激活状态。
- 未识别编码继续在操作区右侧显示，使用风险色但不阻断查询。

## 视觉语言

- 主体沿用页面现有浅灰蓝面板背景和 8–12px 圆角。
- 核心筛选控件采用参考图的紧凑白色按钮式外观，激活边框和文字使用现有品牌蓝。
- 控件高度统一，减少大文本框、大留白和原生列表滚动条。
- 操作按钮分为蓝色主按钮、普通描边按钮和文字清空按钮。

## 行为与兼容性

- 不修改后端筛选契约和数据口径。
- 应用筛选时统一读取主行、核心条件和高级条件。
- 清空仅清除明细专属条件，保留当前经营单元/国家视图。
- 视图切换继续记忆；折叠状态仅保留在当前页面会话。
- 保持每页条数、字段预设、服务端排序和画像下钻行为不变。

## 验收

- 默认状态不出现常驻长列表或列表滚动条。
- 1440px 桌面宽度下筛选区不超过两行（高级条件收起时）。
- 768px 以下自动换行且按钮可点击、标签不溢出。
- 多选、更多筛选、问题任一/全部、国家保留状态、清空操作均正常。
- 静默运行前端契约测试、完整 pytest 和 JavaScript 语法检查。
