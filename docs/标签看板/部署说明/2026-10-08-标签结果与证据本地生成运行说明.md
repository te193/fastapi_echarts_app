## 入口与代码位置

- `etl/label_local_sources.py`：只读同步业务源；不允许远端标签事实表作为源。

- `etl/label_local_store.py`：工作表、压缩历史、发布事务和运行批次。
- `etl/label_local_contracts.py` 与 `etl/label_local_dictionary.json`：历史覆盖、库存日期与字典身份合同。

## 输入与历史

业务源在同一只读事务内读取，将所需字段复制到专用本地输入表。完整输入表与批次标记以一次原子改名一起生效；读到半批输入会失败，不回退到远端标签。源、目标服务 UUID 必须不同。

连接中断后的显式接续可以复用已经完成的 Listing、产品表现暂存表；复用前核对来源白名单、字段、索引和准确行数，保留原读取内容哈希。暂存表不得从未完成的部分行数恢复。其他源在新只读事务读取，输入清单会明确记为 `input_consistency=resumed_across_transactions` 和 `reused_completed_stage`，不能称为同一时刻快照。接续仍在全部输入完成后一次原子换批。连接使用 TCP keepalive，增加当前会话写出等待时间；断连清理不会覆盖原始错误。

运营库存从远端 `dwd_datasync.lx_storage_fba_warehouse_detail` 读取完整可用历史，标签专用输入保留 V47 所需九个原始字段并派生四个身份字段。日期归一到零点；仓库名去中文得到完整店铺，再取连字符前缀得到基础店铺；长 MSKU 处理保留既有规则，短的 `JKM-008a-2`、`KQ-UFY7-HWK2` 不截断。国家类别依据仓库所属区域归入英国、北美或欧洲。库存数量原值保留。

该来源切换不修补、覆盖或改造共享 `etl_dispose_lx_storage_fba_warehouse_detail`、`dashboard_inventory_daily_snapshot` 等表。仅刷新标签专用库存输入时，其余源沿用已验证批次，记录 `reused_input_batch`，不能声称所有源在同一新事务重新采集。完整同步仍从一个只读事务采集全部源。

产品表现完整保留可用历史。原版部分基础指标从 2026-01-01 开始，但断货前和广告窗口可以使用更早数据，因此不能把整个源截到 2026 年。用户于 2026-10-09 明确选择首次只计算最近两期，之后从成功日期续算；不再要求先从 1 月 1 日回算。计算范围内缺少业务日期仍阻断发布。标签 23 的连续计数及依赖旧标签的历史沿用从本地初始化日开始，不能视为已完整恢复远端历史。

Listing、产品表现、FBA、补货建议、订单、产品资料、库存宽表、价格及字典等关键源不能为空；关系标签和待调价队列允许为空。每个计算日还必须有 FBA 与补货快照，防止把缺失数据当成零库存。

字典合同于 2026-10-08 从规则元数据核对后保存，仅包含父子 ID、名称、启用状态与打标方式。V47 使用的字典族发生缺失、停用、改名或方式变化会阻断生成；合法规则调整需要同时审阅原版规则和合同。

本地历史表按日保存标签与同轮 evidence_json 的压缩块、校验和、输入哈希与规则版本。恢复时校验压缩块，然后丢弃可能只完成半轮的工作数据。同日重跑可以沿用该日原有 V47 断货前证据；回算过去日期必须在独立库中重建，防止后续连续计数继续使用旧链。

**历史语义限制：** Listing、当前价格及最新货件等并非历史不可变快照。因此按原版代码回算是“使用当前可得业务源重算历史”，不能声称完全复原当时结果。批次会返回 `historical_point_in_time=false` 和覆盖范围；不复制远端旧标签补齐历史。

## 运行命令

以下命令必须通过隐藏后台进程执行并读取日志，不直接在前台运行。

```powershell
python -m etl.label_local_generation
```

默认同步业务源，自动日期要求产品表现最大业务日期等于上海时区前一天。首次只计算该日期及前一天，此后从最后成功日期续算；最终一次性发布最近两天。批次保留实际 `history_start`，标记 `history_coverage=recent_periods_only` 和 `historical_carry_complete=false`，不会将短历史标为全历史回放。

2026-10-09 用户将执行顺序调整为“只算最近两期，先切换，再与远端对比”。默认保持原 V47，新增生命周期扩展的自动发布已停止。扩展保留为显式 `--complete-lifecycle` 选项，版本为 `local_v47_lifecycle_coverage_20261009`，待数据源切换后再处理。需要仅预演时使用 `--no-publish`。已有不同版本历史不得直接续算。规则、证据及验收见 [生命周期覆盖补齐实现与验收](../2026-10-09-生命周期覆盖补齐实现与验收.md)。

已有完整输入、需要计算重试时：

```powershell
python -m etl.label_local_generation --reuse-inputs --date 2026-10-07
```

隔离库中做短期预演时，可指定 `--schema`、`--bootstrap-start`、`--no-publish`。该库必须预先具备完整本地业务输入。最近两期可以按用户已确认的口径正式发布，但必须保留真实历史起点及不完整历史标记。

## 发布与失败

过程内部的提交只作用于工作表。发布事务同时更新页面事实、字典、销售角色证据和批次标记；失败时全部回滚。销售角色证据直接取同轮 V47 JSON，状态为 `generated`，不再运行旧 Python 分类器与远端结果核对。

刷新成功会失效页面缓存；每日任务产生新发布批次后，页面的轻量检查也会读取批次 ID，识别同一天的重复生成。

查看 `dashboard_label_local_runs` 获取失败信息，`dashboard_label_local_days` 获取最后成功日期，`dashboard_label_local_publication` 获取页面实际使用批次。修复源问题后重新运行；不要手工改旧发布表或导入远端标签作为恢复种子。
