# 生命周期覆盖补齐实现与验收

用户批准：同批销售角色商品池中的每个国家类别＋店铺＋MSKU，都必须有且只有一个生命周期分类。目标数量随每日商品池变化，不固定为 6,380。

**后续安排更新：** 用户随后明确先暂停业务规则调整，优先按原 V47 重算并与远端新批次核对。原自动发布链已停止；默认生成恢复原规则，生命周期补齐仅保留为显式选项。本页原实施记录不代表已发布。

## 规则

已有 201–205 生命周期保持 V47 原规则。仅对未命中原生命周期的商品补齐：运营状态为 306（停售）时归入 206（归档产品），其他状态或缺失时归入 207（生命周期待判定）。两个扩展均为父标签 2、周期 `current`。

归档不增加库存、销量或停售时长条件，不删除商品、不改变运营状态。每日重新计算；出现原生命周期时删除补齐分类，停售转为其他状态时改为待判定。站点生命周期不扩展，接收中归断货修复另行处理。

## 实现入口

- [本地补齐模块](../../etl/label_lifecycle_completion.py)：在 V47 完成后生成扩展及证据，共用货件投影校验同批运营状态、首次收货日期、候选日期和判定原因。
- [生成编排](../../etl/label_local_generation.py)：默认启用补齐，版本为 `local_v47_lifecycle_coverage_20261009`；`--baseline-only --no-publish` 可验收原版基线。历史版本不一致时拒绝续算，必须独立重建。
- [校验和发布](../../etl/label_local_store.py)：逐商品键检查恰好一个分类；扩展定义仅进入本地发布字典，源字典占用 206/207 即阻断。最近两期事实、字典、证据审计及发布标记在同一事务内提交。
- [看板读取](../../app/services/label_hub_data.py)：生命周期优先级包含 206/207；现有动态字典提供分布、筛选与规则说明。卡片按 MSKU 去重，商品明细按店铺记录展开。

首次收货依据为完整保留的 `dwd_datasync.lx_fba_shipment`，没有人为下限。未来收货日期只作为候选记录，有效首次收货日期为 null。未匹配货件、无有效日期、日期晚于标签日及原阶段未命中分别记录原因。

## 验证记录与发布门槛

隔离 MySQL 测试覆盖停售、在售、断货、待上架、运营状态缺失、同 MSKU 多店铺、原阶段保留、重复执行、状态变化、来源 ID 冲突和原子发布。另覆盖证据字段篡改拒绝发布、跨年收货与未来收货不充当起点。审查发现的证据输入核对遗漏已经修正并复核。

代码测试通过不等于业务批次已发布。真实运行必须先验收 DWD 来源的原 V47 两日基线，再从完整历史起点独立计算新版本，验收并原子发布最近两期。后台日志、成功日期及 `dashboard_label_local_publication` 的实际版本与商品键覆盖是最终依据；任何失败均保留原看板批次。共享本地库存表不修改。
