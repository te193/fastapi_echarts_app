# 生命周期标签覆盖缺口排查

## 结论

2026-10-07 页面数据与本地标签快照一致：销售角色覆盖 6,380 个 MSKU、8,419 条国家类别＋店铺＋MSKU 记录；生命周期覆盖 2,943 个 MSKU、3,064 条记录；运营状态覆盖 6,370 个 MSKU、8,384 条记录。生命周期比销售角色少 3,437 个去重 MSKU，以及 5,355 条店铺商品记录。

这不是页面的周期过滤导致。生命周期快照已经包含全部合法周期：测款期 30d（25 条）、新品期 90d（104 条）、成长期 6m（2,493 条）、成熟期 long_term（442 条），合计 3,064 条。页面覆盖卡按各父标签的全部周期统计；若真的只取 30d，生命周期只会剩 25 条。

## 代码依据

用户提供 V47 的 `tmp_first_receiving`（647 行起）按国家类别＋基础店铺＋原 MSKU 匹配 `lx_fba_shipment`，取不晚于标签日期的最早有效 `receiving_time`。生命周期写入（1686 行起）对该临时表使用内连接；没有有效首次收货日期的商品被排除，没有“生命周期未知”兜底。

生命周期区间为首次收货后 0–30 天测款、31–120 天新品、121–300 天成长；超过 300 天根据销售角色健康程度和前序成熟标签判定成长／成熟。销售角色和运营状态没有相同的“必须有首次收货日期”前提，因此覆盖数量不能直接要求相等。

## 业务源核对

以页面发布批次的缺失商品为对象，使用已复制的当前完整货件业务源，按 V47 的国家类别、店铺前缀、MSKU 和日期解析条件核对：

| 原因 | 缺失店铺商品记录 |
| --- | ---: |
| 按规则键未匹配到货件 | 5,269 |
| 有货件，但没有有效首次收货日期 | 85 |
| 首次收货晚于标签日期（GL111a） | 1 |
| 合计 | 5,355 |

缺失记录的已发布运营状态中，5,281 条为停售、20 条待上架、43 条断货中、2 条正常在售、1 条清仓中、7 条返厂品，另 1 条没有运营状态。说明大部分缺口位于停售商品池，也有少量在售商品需要继续核查货件身份映射。

以上原因数的粒度为店铺商品记录，不能直接相加解释去重后的 3,437 个 MSKU。一个 MSKU 可能在不同店铺或国家类别有不同覆盖。核对使用当前业务源，发布标签来自既有批次，不能声称还原了该旧批次全部源表的历史时点；但缺失记录全部符合原版首次收货前提未满足的情况。未匹配货件不等于现实中从未到货，仍可能涉及历史源覆盖、MSKU 别名或店铺映射。
