## 1. 本期目标

在普通标签看板 `/label-hub` 中新增“销售角色诊断”模块，承接远端新增的两类诊断标签：

- `15 全站点销售角色-产品问题标签`
- `16 站点销售角色-产品问题标签`

这两个标签不是新的基础分析大类，而是销售角色的解释层，用于回答：

1. 为什么一个店铺商品属于明星、潜力、瘦狗或问题产品。
2. 具体卡在低毛利、低日销、排名不足还是多项指标同时不足。
3. 问题覆盖了多少店铺商品、国家记录和国家。
4. 较上期增加或减少了多少。
5. 哪些记录证据完整，哪些只能确认远端标签事实、暂时不能确认规则原因。

首版只在普通标签看板实现，国家标签看板暂不扩展。

## 2. 核心产品决策

### 2.1 标签 15、16 的页面定位

标签 15、16 必须：

- 从“标签覆盖全景”隐藏。
- 不能成为“当前分析大类”。
- 不能出现在三个普通远端联动维度选择器中。
- 仍然可以作为筛选条件参与 URL 恢复、条件校验、明细筛选和跨类 AND 联动。
- 标签规则抽屉仍应能查看它们的详情。

因此后端分类必须拆成两套：

```python
COUNTRY_SCOPE_PARENT_IDS = {4, 7, 13, 14}
DIAGNOSTIC_PARENT_IDS = {15, 16}
EXCLUDED_ANALYSIS_PARENT_IDS = COUNTRY_SCOPE_PARENT_IDS | DIAGNOSTIC_PARENT_IDS
```

- `visible_analysis_categories`：排除 4、7、13、14、15、16，只用于覆盖板、当前大类和普通联动维度。
- `filterable_categories`：只排除国家口径的 4、7、13、14，保留 15、16，用于条件合法性校验和事实筛选。

### 2.2 模块位置

放在“当前分析标签”下方、“群体问题概览”上方：

```text
销售角色扩展分析
为什么处于这个销售角色
```

现有销售角色卡、群体问题、多维联动、矩阵、变化抽屉、国家画像和明细表行为不应被替换。

### 2.3 默认展开逻辑

- 当前大类为销售角色时，模块默认展开。
- 当前大类切换为生命周期、库存水平等其他标签时，模块默认收起。
- 如果 URL 或条件条中已经选择了 15/16，模块自动展开。
- 模块异步加载，不阻塞现有标签看板首屏。

### 2.4 角色与周期联动

模块顶部包含：

- 诊断范围：`全站点诊断 / 国家站点诊断`
- 诊断周期：`7d / 14d / 30d / 90d`
- 查看角色：`全部 / 明星产品 / 潜力产品 / 瘦狗产品 / 问题产品`

规则：

- 未选择销售角色时，展示全部角色的诊断汇总。
- 点击上方基础销售角色后，诊断模块自动切到该角色。
- 在诊断模块选择角色时，同步更新基础销售角色条件（父标签 1）。
- 基础角色变化后，自动清除与新角色不兼容的 15/16 条件。
- 诊断周期默认跟随经营周期；无法对应时使用 `30d` 并明确标注。

### 3.3 周期与证据

- 两类标签均可能存在 `7d / 14d / 30d / 90d`。
- 远端事实中已有 `evidence_json`，可包含：
  - `metrics`
  - `matched_rule`
  - `source_sales_role`
  - 其他标签特有指标
- 规则指标必须动态读取证据，不允许固定写成日销和毛利率。

示例：

- 销售角色可能展示日销、打标销售额、打标毛利润、打标毛利率。
- 库存类可能展示库存可支撑天数。
- 国家站点诊断可能展示小类排名、日销、毛利率。
- 未识别指标使用证据中的原始字段名，不丢失数据。

## 4. 页面设计

### 4.1 模块头部

```text
销售角色扩展分析                         [最新标签事实]
为什么处于这个销售角色        [全站点诊断 | 国家站点诊断]

诊断周期 [30d]   查看角色 [全部] [明星] [潜力] [瘦狗] [问题]
```

点击诊断原因：

- 加入父标签 15 或 16 的条件。
- 当前行显示浅蓝底和左侧蓝色标识。
- 再次点击取消。
- 同步更新顶部条件条和 URL。
- 不改变普通标签覆盖板自身的稳定基准口径。

### 4.2 全站点诊断

父标签 15 每个诊断原因一行，展示：

- 诊断原因。
- 店铺商品记录数。
- 当前角色内占比。
- 较上期增减。
- 销售额。
- 毛利润。
- 规则证据覆盖率。
- 查看明细。

### 4.3 国家站点诊断

父标签 16 每个诊断原因一行，展示：

- 诊断原因。
- 国家记录数。
- 涉及店铺商品数。
- 涉及国家数。
- 较上期增减。
- 销售额。
- 毛利润。
- 证据覆盖率。
- 查看明细。

必须使用“存在即命中”口径：

- 同一个店铺商品只要一个国家命中，即进入该诊断群体。
- 国家记录数可以多条。
- 销售额和毛利润必须按店铺商品去重后汇总一次，不能因多个国家重复放大。

### 4.4 当前最值得关注

不使用评分，只陈述事实：

- 增长最多的诊断问题。
- 规则证据不完整数量。
- 涉及国家或店铺范围最广的问题。

示例：

```text
低毛利持续扩大：286 条，较上期增加 12 条
涉及 8 个国家、43 个店铺商品
18 条证据不完整，变化原因暂不能确认
```

## 5. 筛选与 URL 规则

### 5.1 条件逻辑

- 同一个诊断父标签内多选：OR。
- 标签 15 和标签 16 之间：AND。
- 诊断标签与基础销售角色、其他普通标签、本地经营条件之间：AND。
- 诊断分布计算时忽略自身诊断条件，但应用其他所有条件，确保面板仍可继续探索。

### 5.2 URL

增加：

```text
diagnostic_scope=global
diagnostic_period=30d
conditions=1:102;15:1502;16:1605
```

角色选择仍使用父标签 1 的条件，不新增重复的角色状态参数。

## 7. 性能要求

- 主标签看板先加载，诊断模块异步请求。
- 复用现有最新日期事实缓存和详情缓存。
- 对 15、16 按父标签、周期、基础销售角色建立内存索引。
- 切换范围、周期和角色时只在缓存后数据上聚合。
- 模块收起且没有 15/16 条件时，不请求诊断明细。
- 缓存后诊断联动目标：`< 500ms`。
- 冷请求目标：`< 3s`。
- 不新增远端表或字段。
- 远端仍只读取标签表和标签详情表。
