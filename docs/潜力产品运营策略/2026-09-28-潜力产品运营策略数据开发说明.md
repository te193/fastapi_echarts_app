# 潜力产品运营策略数据开发说明

> 2026-09-30修订：取消价格动作、广告总动作、正向加投及首批提价候选的数量上限，同时取消库存分档中的动作数量限制。各对象独立满足条件即可同轮处理；保留路径、幅度、TACOS、预算、库存天数、先广告后价格、互斥、复盘及防重复约束。数量不限不表示可连续重复调价或叠加幅度；同一价格仍需形成唯一有效目标。本次仅更新文档及待建档规则，不代表已写库或上线。

## 毛利口径统一（2026-09-30确认）

问题产品、瘦狗产品和潜力产品的经营分流、调价、广告准入、路径切换及效果复盘统一使用**订单毛利率**。本文未单独限定的“毛利”“实际毛利”“margin”均指订单毛利率，不使用结算毛利率替代。

- 数据来自同一层、同一版本的产品表现日表；当前 DWD 为 `dwd_datasync.lx_statistics_product_performance`，订单毛利润字段为 `predict_gross_profit`，销售额字段为 `amount`。需要 ODS 复核时通过 `dwd.relate_id = ods.id` 对齐，不混拼两层金额。
- 经营分流使用最近完整 30 天：`订单毛利率 = sum(predict_gross_profit) / sum(amount)`；按国家＋店铺＋MSKU、同一窗口、同一币种汇总。日销为同窗口 `sum(volume) / 30`。
- 保留零销量日的订单毛利润及负值；不平均每日 `predict_gross_margin`，不再减一次广告费；`sum(amount) <= 0` 或必要数据缺失时输出待核，不当作零毛利率。
- 3/7/14 天等复盘保留原有窗口长度，但每个窗口均使用上述订单毛利率公式。阈值 5%/10% 等在计算中使用 0.05/0.10；标签 JSON 的百分数值须除以 100。
- `gross_profit`、`gross_margin` 属于结算口径，不参与本策略毛利判断；成本快照只用于成本项诊断，不能替代订单毛利率来源。P5/P10/P15/P20/P25/P30 等仍是定价模型价格线，不等于实际订单毛利率或调价后保证达到的毛利率。
- 本次统一毛利指标，不改变已确认的价格档位、调价幅度、库存、预算和历史动作约束；文档更新不代表生产计算已同步。

> 版本：potential_strategy_20260930_v9。面向数据开发、后端及测试。  
> 业务依据：[潜力产品运营动作建议](2026-09-23-潜力产品运营动作建议.md)，保留2026-09-28匹配方式阈值；2026-09-29简化预算判断、取消释放花费前置，并加入成熟30天产品TACOS的5%／10%加投分档。  
> 本文定义来源、时间、粒度、指标、判断和建议输出；本轮仅交付文档，没有建表、配置规则、开发执行器或下发动作。

> 当前复盘节奏：每日观察；每3天一次调整；整体观察期14–30天。适用于价格及广告；对象阈值、成熟30天窗口及7天归因等待不变。

## 1. 开发入口与实现范围

### 1.1 一条完整计算链

```text
确定批次和各来源完成日期
→ 301/current ∩ 1302/30d产品池
→ 建立国家／店铺／MSKU及广告实体映射
→ 重算经营30/14/7天及动作复盘3天、广告成熟30天指标
→ 查历史动作及观察状态
→ 经营路径分流
→ 同期产品TACOS分档，限制正向广告
→ 对象级广告止损／正向候选
→ 广告核清后判断异常价格
→ 库存、预算、保护、互斥及重复控制
→ 输出建议／保持／拦截／数据待核及证据
→ 按真实生效日建立复盘窗口
```

以下为已确定业务规则：潜力底价P25；价格异常偏离10%；单轮价格调整最多5%、正常间隔至少3天；手动词正向10／20点击；自动匹配方式正向15／30点击；四种自动匹配方式共用阈值、各自判断；产品TACOS≤5%按原路径选动作，5%<TACOS≤10%仅现有有效对象最多+5%，>10%不加投；成本只输出“疑似成本异常，后续纳入成本专题分析”。TACOS的5%／10%是2026-09-29业务设定，不声称经过潜力历史回测验证为最优值。

本文补充的日期对齐、去重、状态码、排序和预算核验接口属于**开发口径**。执行日志、语义审核和数据完成标识缺少已验证现成实现，见第12节；不能用默认通过掩盖缺失。预算直接按现行额度与实际花费检查，增量预测、基础花费预留和预占接口不再作为本版动作前置。

### 1.2 先禁止几种错误复用

- 不读取旧广告宽表的`suggested_bid`、`is_add_recommended`、`is_negative_recommended`作为本策略结论。
- 不用整组的点击、订单、ACOS去调整组内某一个自动匹配方式。
- 不把`gross_profit/gross_margin`结算毛利当订单毛利率，不从成本快照推导本策略毛利。
- 不用补货加权日销、销量÷可售天数替代本策略的自然日日销。
- 不把P25理解为样本价格的25分位数，也不把它理解为“调到该价格后订单毛利率必然25%”。
- 不引入瘦狗P5/P10/P15底价、自动bid 0.30规则或无销量预算兜底。潜力TACOS按本版明确的5%／10%分档处理，不照搬瘦狗各路径的动作组合。

## 2. 业务主键与统一映射

| 对象 | 唯一业务键 | 说明 |
|---|---|---|
| 产品 | country＋store＋msku | 七国DE、FR、IT、ES、NL、UK、US；国家名和代码先映射 |
| 正常在售标签301 | 标签日＋store＋msku＋label_id＋label_period | 301按店铺＋MSKU存在性关联，不要求其country等于站点国家 |
| 站点标签1302/1301 | 标签日＋country＋store＋msku＋label_period | 同一天的站点角色冲突时记录异常，不能随机取一条 |
| 手动关键词 | profile_id＋campaign_id＋ad_group_id＋keyword_id | keyword文字不能代替ID |
| 自动匹配方式 | profile_id＋campaign_id＋ad_group_id＋target_id | expression决定类型；target_id才是动作对象 |
| 搜索词证据 | 上述来源对象键＋search_term_normalized | 保留原词、来源类型；同词不同来源分别计算，不叠加复制订单 |
| 新精准词去重 | profile_id＋产品键＋normalized_keyword＋exact | 跨相关手动组核是否已有有效精准，不仅查来源自动组 |
| 共享库存池 | 已确认pool_id；可由国家类别＋店铺＋MSKU映射 | 国家类别只是候选分组，须验证真实共享关系 |

映射链：广告实体`sid`→`ods_datasync.lx_basic_seller.sid`→国家、完整店铺名；`profile_id`必须与sid保持唯一对应；`product_ads.sku/asin`及产品广告日报确认MSKU。再通过Listing建立完整店铺名、业务store与MSKU的映射。

业务store沿用标签的店铺前缀口径。旧代码存在按空格／连字符截断店铺、去`amzn.gr.`和截MSKU的逻辑；**本版不对任意MSKU机械截断**。原始值、标准值、映射规则和冲突状态都要保留。仅在已有映射能证明对应同一商品时合并别名。

### 2.1 广告归属必须过两道检查

1. 成熟窗口内，商品广告日报按profile＋campaign＋ad_group收集所有非删除商品的MSKU，必须只有一个。
2. 当前组内启用商品广告的MSKU也必须只有一个，且与窗口内相同。

多MSKU记录为共用广告、暂不支持单产品归属；历史变更、缺商品广告记录另记对应映射异常。不按销量占比分摊给产品。第一版共用广告的处理见2.2；实体映射失败仅阻断该对象，如其他证据已能独立确认产品广告全貌，则不扩大阻断。**若因此无法判断产品广告是否核清，价格动作仍需暂缓**，避免绕过广告优先条件。

### 2.2 多MSKU共用广告：第一版暂不生成具体动作

**第一版仅识别并保留共用关系及对象整体表现，不生成该共用对象的升降bid、否定或加精准词建议，不暂停现有广告。** 标注implementation_status为“共用广告策略暂未纳入第一版”，不能当作“未命中规则”或把已确认的多MSKU关系当作缺数据；其他可唯一归属的广告仍正常判断。

后续讨论方向如下，**仅记录思路，不作为本版规则或开发验收条件**：

| 动作 | 后续判断方向 |
|---|---|
| 降bid | 看共用关键词／自动匹配方式自身的整体表现，不用整个广告组表现替代；核对历史与当前关联产品范围、保护及未完成动作，不因某一个产品毛利低就认定共用对象低效。共用样本的阈值与幅度后续再定。 |
| 升bid | 对象效率达标，并且所有受影响产品的经营路径、库存和预算均允许加投，再取各产品允许涨幅中的最小值；不能只检查潜力产品。共用花费与预算占用不重复计算，具体核算后续讨论。 |
| 否定 | 对否定范围内所有产品均不相关，且保护通过，才考虑否定；对任一产品相关就不直接否定。 |
| 加精准词 | 不把共用搜索词的订单认定为某一个产品的订单；新增词的承接产品、广告组及证据要求后续讨论。 |

现有商品广告报表可以统计“产品×广告组”的表现，关键词／搜索词报表可以统计广告对象的表现，但尚未找到“关键词／自动匹配方式×MSKU”的原始表现明细。旧宽表的等比分摊结果不能替代真实归属，也不作为第一版放开共用广告动作的依据。

## 3. 时间选择：每一类数据用自己的时钟

### 3.1 批次日期

| 技术字段 | 选择方式 | 不能做什么 |
|---|---|---|
| run_at / run_date | 本次运行时间及业务日；写明Asia/Shanghai，站点报表日期仍按来源日历解释 | 不对仅有日期的报表再次做时区平移 |
| label_date | 不晚于运行日的最新**完整**标签日，301与1302同日；正常预期D−1 | 不为某个产品回退到它最后一次1302来继续留池 |
| business_end | 最新完整产品表现日，不晚于D−1；正常应与label_date一致 | 不把当天尚未完整销量算进30天 |
| price_date | 最新完整价格快照，正常预期D | 不用缺失产品的旧快照拼当前批次 |
| listing_snapshot_at | 最新成功同步的Listing快照 | `create_time`是同步时间，不是商品开售时间 |
| inventory_date | 最新完整库存同步日，正常预期D | 不逐行跨日期捞最新值再相加 |
| budget_date | 最新完整预算biz_date，正常预期D，且属于当前预算周期 | 不拿上周预算当本周预算 |
| ads_source_end | 本批涉及的关键词、搜索词、商品广告、广告组日报共同完整截止日；活动预算核验另须活动日报完成 | 不直接取所有表中最大的max(report_date) |
| ads_mature_end | ads_source_end−7天 | 归因等待不是只取最近7天 |
| ads_mature_start | ads_mature_end−29天 | 两端包含，共30个报表日 |

`max(date)`只证明存在该日数据，不能证明全部profile已同步成功。开发需读取ETL完成标识／源任务成功状态，或构建按来源＋profile＋日期的覆盖校验。当前查询仅核实可见日期；没有确认完整标识已经接入。

**2026-09-28实查：**标签和产品表现最大业务日为09-27；价格、Listing、库存、预算为09-28；五类SP日报最大report_date均为09-27。因此在完成校验通过的前提下，当批经营30天为08-29～09-27，广告成熟30天为08-22～09-20。这与阈值分析使用的09-22固定样本／08-17～09-15窗口不同，生产运行不能硬编码分析日期。

若标签和经营窗口不一致：分别保留日期，标明异步或陈旧。用于当前动作的经营指标不得伪装成标签打标原值；来源尚未完成时输出对应待核。历史复盘允许按历史窗口读取，不能为当前数值建议静默使用过期价格、库存或bid。

### 3.2 指标窗口表

| 用途 | 起止日期（均含首尾） | 分母 |
|---|---|---|
| 经营30天／14天／7天 | business_end−29／13／6至business_end | 固定30／14／7个自然日 |
| 动作前产品TACOS | mature_start至mature_end，与广告对象窗口完全相同 | 分子spend与分母amount均取该窗口；不混用business_end对应的最近30天 |
| 广告效率 | ads_mature_start至ads_mature_end | 累计点击或累计归因销售额，按指标不同 |
| 月预算实耗 | 当月1日至budget_spend_end | 不用成熟30天花费 |
| 周预算实耗 | 本周周一至budget_spend_end | 周一当天尚无本周完整日时，可确认为0 |
| 活动日均花费 | budget_spend_end−6至budget_spend_end | 7个完整日；用于与活动日预算比较，不用于未来花费预留 |
| 本轮价格／广告3日基线及效果 | 生效日−3至−1／生效日+1至+3 | 各3个完整日；生效当天排除 |
| 后续3日观察 | 未再次调整时，每3天取最新3个完整日 | 与本轮基线比较；新动作生效后另起本轮窗口 |
| 整体观察 | 本次策略首个动作生效日起14–30天 | 第14天综合评估，需继续观察则至第30天；保存期间每轮动作 |

budget_spend_end为最新完整实耗日，不晚于D−1。没有成功同步证据的缺行不补0；已确认完整同步、且来源明确省略零值记录时，才可在日期骨架上补0。产品经营窗口缺失则不除以“现有行数”。

### 4.1 日记录去重与币种

产品日事实先按country＋完整seller_name＋seller_sku＋start_date＋end_date选最新create_time，再用id打破时间相同的排序；关联ODS后检查delete_flag=0、日期一致及price_list身份。一个ODS记录若覆盖多个不同国家／店铺／MSKU，不能把整条amount、profit复制到每个拆分行；只有明确可分配的来源字段才可拆，否则该记录待核。

`price_list`可包含正常品及旧别名／退货品。没有确认映射时不能仅取数组第一个元素代表全量经营事实。不同Listing映射至同业务产品时，先确认数据互斥再汇总。

SP报表自然键：日期＋完整广告键；搜索词另加原始query。若存在重复，先判是否版本更新：完全相同记录去重，明确版本按最新update_time/create_time＋id选取，冲突且无法确定则待核。`delete_flag=0`先过滤。

实查产品表现样本amount、predict_gross_profit、spend为人民币口径，SP日报cost/sales和bid为站点币种。**产品表现已为人民币时不要再乘source_rate。**业务比率在同币种内计算；任何原币→人民币转换记录currency、汇率及汇率月份。没有明确币种时阻断金额比较。

## 5. 产品经营指标与标签核验

### 5.1 指标公式

以下均基于已去重、身份安全且窗口完整的产品日事实。百分比内部存0～1比例，如15%=0.15；不先四舍五入后再判断档位。

| 中文指标／建议字段 | 公式 | 空值／异常处理 |
|---|---|---|
| n天销量 sales_qty_n | `sum(volume)` | 不用订单数order_items代替销量；日记录缺失不直接补0 |
| n天日销 daily_sales_n | `sum(volume)/n`，n=7/14/30 | 固定自然日分母；不使用可售天数或补货daily_avg_sales |
| n天销售额 sales_amount_n | `sum(amount)` | 保留同币种；≤0时毛利率及TACOS不可算 |
| n天订单毛利润 order_profit_n | `sum(predict_gross_profit)` | **保留零销量日金额和负值，不用case volume=0 then 0** |
| n天订单毛利率 order_margin_n | `sum(predict_gross_profit)/sum(amount)` | 分母≤0→null；不直接平均predict_gross_margin，不减一次广告花费 |
| n天产品广告花费 product_ad_spend_n | `sum(spend)` | spend为广告费用组成项总计；不用SP对象汇总冒充全广告费用 |
| 动作前产品TACOS tacos_mature_30 | `sum(spend)/sum(amount)`，限定mature_start至mature_end | 同国店MSKU、同币种、完整30天；用于5%／10%加投分档。分母≤0或费用不完整→null，不能补0 |
| 经营／复盘n天TACOS tacos_n | `sum(spend)/sum(amount)`，限定对应经营／复盘窗口 | 用于观察及动作前后比较；与tacos_mature_30分开保存，不能混用 |
| SP预算实耗 sp_spend | 商品广告日报cost按产品归属汇总并换到预算币种 | 与经营表ads_sp_cost可对账，但两者不能相加；差异待核 |
| 小类排名 small_rank | 原标签核验读`evidence_json.metrics.small_rank`，同时取small_rank_stat_date | 当前排名可用最新有效日rank作观察，另记日期；不拿窗口平均冒充标签采用值 |
| 促销迹象 | `sum(promotion_volume)/sum(volume)`及promotion_discount／价格变更记录 | 只作干扰证据；不新增固定差异阈值，无促销信息≠确认无促销 |

**毛利公式核验：**2026-09-27标签的10个样本均覆盖30个日记录，累计原始predict_gross_profit与标签tag_gross_profit一致；剔除零销量日则出现差异。例如一个匿名样本原值1251.36、剔除后1547.46，不能用后者判断潜力路径。标签JSON的tag_margin_rate以百分数记录，读取时除以100。仓库旧打标SQL中的“零销量日置零”与本次证据不一致，不照搬；`predict_gross_margin`自身与上述比值也可能不同。

旧成本快照、旧调价分析中的结算毛利和“可比日均毛利额”均不参与本版判断。当前公式可用日数据重算3天复盘及14–30天整体观察窗口，不依赖滚动30天价格表中的毛利率。

### 5.2 入池SQL参考

`:label_date`为已通过完成校验的批次参数；以下是读取示例，不是调度或建表脚本。

```sql
select distinct t.country, t.store, t.msku
from dws_datasync.dws_标签表汇总 t
where t.data_date = :label_date
  and t.label_id = 1302
  and t.label_period = '30d'
  and t.country in ('德国','法国','意大利','西班牙','荷兰','英国','美国')
  and exists (
      select 1
      from dws_datasync.dws_标签表汇总 a
      where a.data_date = t.data_date
        and a.label_id = 301 and a.label_period = 'current'
        and a.store = t.store and a.msku = t.msku
  );
```

检查1301与1302同日冲突、标签证据窗口、指标单位及角色版本。原标签决定入池，最新完整经营指标决定动作；当前已经1301则退出潜力新动作。已发动作的复盘不能因为退出潜力池而丢失，应继续从动作历史队列跟踪。

### 5.3 路径判断顺序

日销和订单毛利率使用30天。以下不是重新打标签程序，退化只输出移交建议。

| 优先级 | 判断条件 | 路径与允许动作 |
|---:|---|---|
| 0 | 标签退出／同日角色冲突 | 退出新动作或标签待核；继续原动作复盘 |
| 1 | 完整销量=0 | 退化→问题产品；即使因销售额0而毛利率为空也可判此项 |
| 2 | 必需经营字段缺失／窗口不完整／日销<0 | 暂不分路、不调价不加投；对象事实完整的独立止损仍可判断 |
| 3 | 日销≤1且订单毛利率<5% | 退化→问题产品 |
| 4 | 未命中上一行，且0<日销<1且毛利率≥5%；或1≤日销≤3且毛利率<10%；或日销>3且毛利率<5% | 退化→瘦狗／利润修复；保留有依据的广告止损 |
| 5 | 日销>3且毛利率≥15%，或1≤日销≤3且毛利率≥25% | 经营达标：保持售价和有效广告，仅保留止损、标签核验 |
| 6 | 日销>3且5%≤毛利率<15% | 利润待提升：止损→低价修复；不降价、不加投 |
| 7 | 1≤日销≤3且15%≤毛利率<25% | 销量待提升：广告正向／明显高价修正 |
| 8 | 1≤日销≤3且10%≤毛利率<15% | 双短板：有低效广告则减投；预算满足且效率、库存通过，可同轮各符合条件的已有对象最多+5%；不调价、不加精准、不做零花费动作 |

经营达标后：排名51～100仅观察，不加bid；排名≤50且标签仍1302输出“经营已达标，标签同步待核”。排名缺失／异常只标排名证据不足，不私自把完整经营指标改为失败；最新标签是否重分类交给标签链路。

## 6. 广告指标、条件与动作

### 6.1 先聚合对象，再计算比率

| 指标 | 计算公式／要求 |
|---|---|
| 曝光、点击、花费 | 同对象成熟30天`sum(impressions/clicks/cost)`，分别求和 |
| 广告订单 | 同对象成熟30天`sum(orders_7d)`；不是产品销量，也不是sum(same_orders_7d) |
| 广告销售额 | 同对象成熟30天`sum(sales_7d)` |
| ACOS | 花费÷广告销售额；花费>0且销售额>0才用于效率分档 |
| 转化率CVR | 广告订单÷点击；点击>0才计算，不×100存储 |
| 实际CPC | 花费÷点击；缺分母不生成初始bid |
| 来源每点击销售额 | 来源搜索词累计sales_7d÷累计clicks |
| 其他归因订单 | 对相同对象、相同报表日分别累计orders_1d/14d/30d；任一>0即不满足“各归因均无单” |
| 搜索词跨来源订单 | 同产品＋标准化词在其他安全来源对象中的已知订单；只做是否存在检查，不把订单加给目标对象 |

归因字段彼此重叠，**不能把orders_1d＋7d＋14d＋30d相加**。7天窗口已成熟不代表30天归因已完全成熟；30天字段用于“已观察到订单就拦截”，当前为0不等于未来不会回补。保存提取时间，后续有订单回补时重新评价，不重复套零单止损。

### 6.2 自动匹配方式取数及竞价

| expression内type | 业务名称 |
|---|---|
| queryHighRelMatches | 紧密匹配 |
| queryBroadRelMatches | 宽泛匹配 |
| asinSubstituteRelated | 同类商品 |
| asinAccessoryRelated | 关联商品 |

解析JSON，不按目标名称模糊判断。未知／多类型表达式标异常，不硬塞到四类之一。

本库当前未发现独立自动target表现日报；重算已验证可用搜索词日报按target_id回卷。开发规则：

1. 查询该组全部target的搜索词明细，不能先过滤当前启用target再做总量对账。
2. 按原始自然键去重；按完整target键汇总。检查target_id属于同账号、活动、组，且target_text类型与实体expression一致。
3. 将全部target汇总到组，与同窗组日报核对clicks、orders_7d、orders_30d精确一致；cost、sales_7d误差≤0.01站点币种单位。
4. 对账通过且两端数据完成，才使用各target自己的汇总结果；任一不通过则该组匹配方式表现待核，不能用组指标代替。
5. 对账通过也只是必要检查；应核报表日覆盖和缺行规则。没有明细的target只有在来源明确为完整零值省略时才认定0，否则为missing。
6. 完成以上步骤后，再筛当前启用及可核有效bid的target产生动作候选。

有效bid示意：

```sql
case
    when t.bid > 0 then t.bid
    when (t.bid is null or t.bid = 0) and g.default_bid > 0
        then g.default_bid
    else null
end as effective_bid
```

其中组连接必须包含profile_id＋campaign_id＋ad_group_id；负bid属于异常，不走默认继承。对象表中的create_time/update_time、平台last_updated_date只作来源时点证据，不用来伪造“历史某天bid”。

`suggested_bid_raw=effective_bid×(1+调整比例)`。输出到该target，不改组默认bid。记录`original_target_bid`、`effective_bid`、`bid_source=own/group_default`；撤回时有独立bid的恢复独立bid，原来继承的恢复继承设置，而非把旧默认价固定写成独立bid。

### 6.3 共用前置条件

- 活动、组、具体对象均启用，且当前未删除；当前商品广告也有有效归属。
- 当前有效bid>0、币种已知，平台最小单位及上下限可取得。取整后无变化则保持，不强行补0.01。
- 成熟表现完整、身份映射通过、无待复盘的同对象动作、保护检查通过。
- 已下调对象不能因同一批旧花费每天滚动一日就再下调；至少原动作复盘完成，且有原动作生效后新成熟表现支持，才进入下一轮。
- 保护按动作适用：品牌／核心类目／新品／自有ASIN及保护信息缺失必须阻断直接否定；零单降bid亦须保护通过。其他动作按已确认保护策略；保护范围不能从“没命中旧推荐”推断。
- 相关性是独立证据：已确认相关／已确认不相关／未知。低转化不能推导“不相关”。记录审核来源、时间、理由和产品上下文版本。

现有搜索词宽表有保护字段可做事实输入，其新品保护实现使用上架90天内。该90天是既有保护版本的口径，不是本次重新校准的潜力广告阈值。保护版本更新应重新生成证据；不能拿旧搜索词快照的保护标志永久沿用。

### 6.4 手动词与自动匹配方式规则表

点击、订单、ACOS、转化率全部是该行对象自身成熟30天指标。同一对象先判数据及保护，再判止损，再判正向；二级优先一级。

| 对象 | 条件（并且） | 原始动作比例 |
|---|---|---:|
| 手动关键词 | 订单=0、点击≥10、正花费、其他归因及同来源没有已知订单 | −8% |
| 手动关键词 | 订单=0、点击<10 | 保持 |
| 自动匹配方式 | orders_7d=0、clicks≥30、cost>0；其他归因及同来源没有已知订单，保护及对象前置通过 | −8% |
| 自动匹配方式 | orders_7d=0、clicks<30 | 保持 |
| 二者分别判断 | 订单=1、点击≥15、ACOS≥40% | −8% |
| 二者分别判断 | 订单≥2、ACOS≥40% | −20% |
| 二者分别判断 | 订单≥2、30%≤ACOS<40% | −10% |
| 手动关键词二级 | 点击≥20、订单≥3、ACOS≤15%、CVR≥20% | +8% |
| 手动关键词一级 | 点击≥10、订单≥2、ACOS≤20%、CVR≥13% | +5% |
| 自动匹配方式二级 | 点击≥30、订单≥5、ACOS≤15%、CVR≥15% | +8% |
| 自动匹配方式一级 | 点击≥15、订单≥2、ACOS≤20%、CVR≥10% | +5% |
| 其余 | 完整数据但未命中 | 保持，no_rule_hit |

正向动作还须经营路径允许，并通过下列产品TACOS分档。销量待提升在TACOS≤5%时可用两档；双短板在TACOS≤10%、预算满足且效率、库存通过时，各符合条件的已有对象最多+5%，不要求先释放花费或等另一对象止损复盘；利润待提升、经营达标、退化均不因命中效率表就加投。库存7～不足14天时再将已有对象正向动作限为+3%。同一对象未完成复盘仍不得重复调整。

自动零单降bid按匹配方式自己的成熟30天累计值判断，恰好30点击命中；30以上仍固定−8%，不新增重档。TACOS仅限制正向广告，不阻断符合条件的零单止损。target有独立bid取其值，否则取同组默认bid作基数，`suggested_bid_raw=effective_bid*0.92`，只更新该target。其他归因有已知订单、保护未通过、数据不完整或同对象仍在复盘时不新发零单下调；不能拿同一旧窗口每天重复降8%。

#### 产品TACOS加投门槛

取产品表现日事实计算`tacos_mature_30`，范围必须与广告对象的mature_start／mature_end相同。分子为产品全部广告费用spend，分母为同期产品总销售额amount，不使用广告归因销售额，不把关键词／搜索词花费相加替代产品总费用，不减重复一次广告费。

| 未取整的tacos_mature_30 | 正向广告处理 |
|---|---|
| 0≤TACOS≤0.05 | 优先区间；可按原路径与对象效率选择+5%／+8%、加精准、零花费或开启／恢复；其他限制仍须通过 |
| 0.05<TACOS≤0.10 | 各已存在且达到一级效率条件的对象可升bid，幅度上限0.05；不加精准、不做零花费、不开启／恢复，不允许+8% |
| TACOS>0.10 | 正向广告blocked；保留证据完整且通过对象规则的止损，不自动对全部对象降bid |
| null、金额异常、窗口不完整／不一致或币种不明 | 正向广告data_pending；不能以缺值为0放行，独立止损按自身证据判断 |

**零值与缺失必须分开：**完整成熟窗口内产品全部广告费用已确认合计为0、同期amount>0且币种一致时，tacos_mature_30=0；未开广告本身不会使TACOS无法计算。spend为null／未同步、amount≤0或日期覆盖不明时保留null。只有来源已确认完整且明确省略零值记录时，才允许按零值省略规则补0；不能直接coalesce未知花费为0。仅确认“当前未开SP”不能证明成熟窗口无历史花费，也不能证明其他广告类型花费为0。

现有对象最终涨幅取对象档位、经营路径、TACOS档位、库存限速允许值中的最小值；仍须满足对应一级效率条件。恰好5%归优先区间，恰好10%归限制区间，10.01%不能先四舍五入成10%后放行。10%是动作前的加投判断上限，不是花费预测或对动作后结果的保证。

TACOS所需产品事实缺失时，不单独改用最近30天，也不为一个指标另移广告窗口；本批记录相应缺项。原广告窗口以共同最新完整报表日减7天为截止，再向前取30天，产品总花费和总销售额一起切到该窗口。

数值建议采用Decimal运算。价格按第7节取整；bid建议采用不超过名义幅度的保守取整：上涨向下、下降向上，步长由站点／实体规则取得。再检查上下限、方向和实际幅度；不合法则阻断，不能靠强行钳制到平台界限产生额外涨幅。该取整方式属于本版技术约定，不影响策略原始档位。

### 6.5 搜索词否定与加精准

新增精准须销量路径允许且tacos_mature_30≤0.05；否定仍按相关性、保护及对象证据判断，不由TACOS高低直接触发。

原词保留；匹配键可用Unicode规范化、去首尾空格、合并连续空格、小写。ASIN去空格并统一大小写。不得用分词／词干将不同含义词直接合并；先原始日键去重，再标准化聚合。

| 动作 | 条件 | 计算／结果 |
|---|---|---|
| 文字词精准否定 | 订单=0、点击≥10、已确认不相关、保护完整且无保护、无其他归因／安全来源订单 | negative_exact；明确落在哪个来源广告组或活动。范围未确认时不扩大到整个活动 |
| ASIN否定商品投放 | 同上且搜索内容已确认为ASIN | negative_product_target；不把10位普通词自动当成有效ASIN |
| 新增手动精准词 | 自动来源；点击≥10、订单≥2、ACOS≤20%、CVR≥13%；相关、唯一归属、无同词有效精准；销量路径及预算库存通过 | 按每条合格搜索词独立判断，不设每轮新增词数量上限；目标手动活动／组必须已有或有明确建设方案 |
| 初始bid | 来源词完整CPC和销售额可核 | `min(cost/clicks, sales_7d/clicks*0.20)`；币种一致并按限制取整 |

加精准条件已有ACOS≤20%时，上述min通常等于该来源词CPC；保留原公式便于审计。来源必须是这条搜索词自身，不用组平均CPC、不借其他产品客单价。保留来源自动广告，不自动否定来源；复盘同看来源词＋新精准，防止把内部转移当增量。

同词多个有效来源：分别算候选，不相加跨组表现伪造新来源。选一个来源提供竞价依据；同一产品最终只创建一个该词精准候选。若否定与加精准证据冲突，标记相关性冲突，不能同时输出两个动作。

### 6.6 零花费、未开广告

**当前是否开启与历史是否有花费分开计算。**先从当前实体结构识别该产品的全部SP链路，再左连接成熟窗口表现；不能以关键词／搜索词日报、旧宽表或经过唯一归属过滤后的候选集是否有行判断是否开广告。

实体来源：`ods_datasync.lx_advertising_sp_product_ads`按sku／asin及店铺映射产品，沿profile_id＋campaign_id关联`lx_advertising_sp_campaigns`，再以profile_id＋campaign_id＋ad_group_id关联`lx_advertising_sp_ad_groups`和`lx_advertising_sp_keywords`／`lx_advertising_sp_targets`。当前完整快照中，活动、组、商品广告与至少一个适用投放对象均启用且未删除，才确认有启用链路；所有关联均保留完整业务键。

| 建议逻辑状态 | 判断依据 | 本轮处理 |
|---|---|---|
| 已开启SP | 至少一条已确认的完整启用链路；有无花费单独判断 | 进入对象表现判断；不能因当前无曝光／花费就归为未开 |
| 确认未开启有效SP | 当前结构及产品映射完整，确无启用链路；另记未建或已建但暂停 | 销量路径、tacos_mature_30≤0.05且预算库存等通过，才给开启／恢复建议 |
| 已启用但投放受限 | 实体启用，但已有明确投放资格／服务状态限制 | 先核限制，不自动按零花费提bid处理，也不当作没建广告 |
| 当前状态未知 | 未发现已确认启用链路，且实体同步、关联或状态信息不完整 | data_pending；不能据此输出开启／恢复或零花费提bid |

存在共用MSKU链路也算该产品已有SP广告；该链路暂不参与第一版对象动作，不能因此误报未开广告。同一产品有已确认启用链路、另有结构不明链路时，可确认已开，但不声称广告全貌已核清；数据缺项按影响范围拦截。

- 已开启不代表必然可投放。零花费提bid要求目标链路启用、投放资格可核、映射唯一、完整成熟窗口cost=0、有效bid可核，且处于销量路径、tacos_mature_30≤0.05、预算库存等通过；各符合条件的对象+5%，每日观察、每3天复盘调整。
- 有点击却cost=0／缺失先按数据异常处理。无日报只有在已确认同步完整、对象覆盖及来源零值省略规则时才能认定为0；否则是missing。对象不存在不能计算+5%。
- 产品TACOS按6.4区分0和null；当前暂停／未建不覆盖历史花费，SP零花费不替代全广告费用。产品总销售额≤0时TACOS不可计算，且须先按经营规则判断退化。
- 零花费及开启／恢复动作仍按8.2检查预算；没有可参照初始bid或目标结构不明时不生成数值，不因历史花费为0默认预算通过。

输出中分别记录当前启用状态及原因、实体快照时间、对象成熟窗口花费是否已确认、产品TACOS值及缺失原因。这些是建议接口内容，不表示已有同名数据库列或检测程序已上线。

### 6.7 组合动作：按路径整体判定，不能把对象档位独立下发

运营动作卡第4节为组合入口；6.4的对象阈值只产生候选，最终动作必须同时通过经营路径、产品TACOS、当前广告状态、库存、预算和互斥条件。价格另须通过7.1的`ads_cleared`，不能由“没有加投结果”直接推定广告已核清。

| 经营路径 | TACOS与广告状态 | 本轮广告结果 | 本轮价格结果 |
|---|---|---|---|
| 利润待提升 | 任意TACOS | 仅命中对象止损，不生成正向候选 | 广告未核清则保持；已核清且现价≤0.90×P25、近7／14天日销均>3及7.2其余条件通过→提价≤5%；否则保持 |
| 销量待提升 | TACOS≤0.05；现有对象满足一级／二级效率 | 手动10／20点击档、自动15／30点击档按6.4完整条件选+5%／+8%，正向动作不设数量上限 | 本轮选中正向广告→保持售价；广告动作全部结束或确认没有适用动作后，才检查7.2高价降价条件 |
| 销量待提升 | TACOS≤0.05；符合加精准、已启用零花费或未开启条件 | 分别按6.5／6.6逐词新增精准、各符合条件的对象+5%或开启／恢复建议；与其他正向候选分别核验，不设数量名额 | 同上一行；数据不足为待核，不能跳过广告前置降价 |
| 销量待提升 | 0.05<TACOS≤0.10；现有对象满足一级效率 | 各符合条件的已有对象+5%，二级也封顶5%；不加词／零花费／开启或恢复 | 本轮加投则保持；广告已核清后仍可按7.2检查高价 |
| 销量待提升 | TACOS>0.10，或无适用加投动作 | 不加投；独立判断有证据的止损 | `ads_cleared=true`、现价≥1.10×P35及7.2其余条件通过→降价≤5%、最低P25；无额外TACOS价格门槛 |
| 双短板 | TACOS≤0.10；现有对象达到一级效率 | 预算、库存通过→各符合条件的已有对象+5%封顶；可并行另一对象止损，不要求释放花费 | 始终保持价格 |
| 双短板 | TACOS>0.10、不可核，或无合格对象 | 仅命中对象止损，不加投 | 始终保持价格 |
| 经营达标／退化 | 任意TACOS | 不新增拉量；独立判断有证据的止损，退化按5.3路径和第9节处理已有动作 | 不生成本策略新调价；既有动作回退按第9节 |

上表的“一级／二级”使用6.4全部点击、订单、ACOS、CVR条件，不仅检查点击数；路径字段取5.3的路由结果。所有正向动作先过库存、预算、保护、归属和历史检查：库存7至不足14天只能对一级合格现有对象+3%；不足7天／不可核不加投。价格库存必须≥14天。

合并顺序：先按5.3选唯一经营路径→生成共用广告止损候选→生成该路径允许的加投候选→按TACOS及库存限幅／拦截→检查预算等前置→按8.4互斥去重及排序→汇总本轮广告处理状态→仅在7.1全部前置通过后计算新调价建议。止损不受TACOS加投分档和预算不足限制；止损数量不阻断符合条件的正向动作。不同对象止损与加投可以同轮进行，但同对象不同时升降bid。

**本轮选中任何广告动作、仍有待处理／顺延广告，或旧广告动作仍在观察中，都保持售价，不进入新调价分支。**上轮广告复盘完成也不能覆盖本轮新选动作。规则配置的31／32只是价格／广告分类，不能按rule_code升序先算价格；更不能将价格表与广告表独立产出后直接合并为可执行建议。价格异常可预先记录为诊断数据，但广告前置未通过时，不填可执行目标价。

必须保留原因：无对象命中、数据待核、TACOS／库存／预算拦截、共用对象暂不支持分别记录；不能都折算为“没有广告动作”，更不能都将`ads_cleared`设为true。TACOS缺失只拦截正向广告；是否影响价格仍根据缺失是否导致广告无法核清判断。

## 7. 价格判断与取整

### 7.1 取值与前置状态

同一price_date＋country＋store＋msku唯一匹配价格行：现价=`listing价格`，P25=`25毛利润价格`，P35=`35毛利润价格`。三者必须为同一站点币种、有效正数，P25≤P35；全价格阶梯反向／异常备注涉及模型不可用时阻断价格，不用max聚合吞掉重复冲突。

价格快照须与当前Listing／成功调价历史核对是否已有更新；快照之后已调价却仍拿旧现价计算，属于price_stale。历史销量均价、product_performance.price以及price_list里的换算价格都不能代替当前可下发售价。

`ads_cleared`不是一个现成字段，必须在本轮广告候选完成前置检查、互斥去重后派生。先检查未完成项，再判断是否已核清；不能仅凭广告结果表为空或旧动作已复盘就设为true。

| 广告状态 | ads_cleared |
|---|---|
| 本轮已经选中任一广告动作（减bid、否定、加bid、加词、开启／恢复） | false，本轮只出广告动作，价格保持 |
| 仍有待处理广告，或有进行中／待复盘广告调整 | false，先处理／观察；不因建议数=0而放行 |
| 本轮评估未完成，或广告映射／状态／相关预算等不清，无法确认广告全貌 | unknown，暂缓价格 |
| 已做调整且完成至少3个完整日的可比复盘；本轮重新评估完整，且上述所有未完成项均不存在 | true，可按所属路径判断价格 |
| 本轮广告结构及数据已核清，没有适用动作，且上述所有未完成项均不存在 | true；不制造无效调bid来“完成先广告” |

以下为开发判断示意，输入均为本轮广告汇总的派生状态，不是新增数据库列。`pending_ad_count`包括尚未处理的适用广告动作；已确认被预算／TACOS限制排除的加投，不算待处理动作。`ad_review_pending`只有在旧动作复盘完成且没有继续观察事项时才为false。

```python
def derive_ads_cleared(*, evaluation_complete, selected_ad_count,
                       pending_ad_count, ad_review_pending,
                       unresolved_ad_state):
    if selected_ad_count > 0 or pending_ad_count > 0 or ad_review_pending:
        return False
    if not evaluation_complete or unresolved_ad_state:
        return None  # unknown：不能进入价格分支
    return True

def may_evaluate_new_price(path, ads_cleared):
    return path in ("利润待提升", "销量待提升") and ads_cleared is True
```

`may_evaluate_new_price=true`只是进入7.2的许可，仍须满足价格偏离、库存及其余条件，才可生成310101／310201建议。False／unknown时保持售价，建议目标价为空；如保留价格诊断候选，必须标明blocked／data_pending原因，不进入可执行结果。原动作恢复价格／竞价按第9节独立判断，不套新调价入口。

预算数额不足本身不阻止价格；预算及广告数据未知而不能判断ads_cleared时，按广告前置不清处理。价格史缺失不等于执行历史接口不可用：前者可以确认没有历史，后者不能确认是否存在进行中动作。

### 7.2 条件与公式

| 动作 | 同时满足 | 未取整目标 |
|---|---|---|
| 低价修复提价 | 利润路径；30天日销>3、5%≤订单毛利率<15%；近7和14天日销均>3；现价≤0.90×P25；ads_cleared=true；DOS≥14；无进行中价格／广告动作；无未排除断货／促销结束干扰 | `min(现价*1.05, p25)` |
| 明显高价降价 | 销量路径；1≤日销≤3、15%≤订单毛利率<25%；现价≥1.10×P35；ads_cleared=true；DOS≥14；无进行中价格／广告动作；模型及当前价格完整 | `max(现价*0.95, p25)` |

以货币最小价格单位price_step计算：

```text
提价目标 = floor(未取整目标 / price_step) * price_step
降价目标 = ceil(未取整目标 / price_step) * price_step
实际变动比例 = (目标价 - 现价) / 现价
低价偏离 = 1 - 现价 / p25
高价偏离 = 现价 / p35 - 1
```

必须再次检查方向正确、实际幅度≤5%、降价目标≥P25、提价目标≤P25。取整后等于现价则保持。七国常用货币EUR/GBP/USD的报价精度仍应由有效站点价格约束提供，不能用汇率小数位当报价精度。

正常两次调价至少间隔3天，并且上轮D+3价格复盘已完成、全部条件重新通过。历史自身调价只作参考，缺历史不阻止降价；历史提价曾日销跌至≤3或订单毛利率未提高时，需先记录原因核验结果，不能自动重复原动作。不设首批同国家＋店铺提价候选数量上限；同一产品仍需完成复盘才可再次调整。

恢复原价必须引用原动作ID及原价，属于rollback；原价低于P25也只能作为该次撤回，不产生新的低价策略。撤回不受正常3天间隔限制，但须检查当前价格是否仍为本动作设置值，避免覆盖后续独立调整。

## 8. 库存DOS、预算与动作数量

### 8.1 共享库存池

```text
共享池FBA可售 = 最新完整库存快照中，该池去除共享展示重复后的afn_fulfillable_quantity
共享池当前日销 = 池内所有实际消耗该库存的国家／MSKU近30天销量之和 / 30
DOS = 共享池FBA可售 / 共享池当前日销
```

分母包括同池非潜力产品及七国外的实际消耗站点，不能只加本次潜力候选。欧洲多个国家展示同一池库存时只计一次：完全同一共享库存复制可取一次／经验证的max；不同物理仓或不同独立库存才sum。英国、美国是否另池按实际共享关系判断，不因都叫某国家类别就合并。

分子不含FBA在途、入库中、预留、不可售、FBM及本地库存。池映射不清、库存过期或成员销量窗口不完整→DOS未知。若分母=0，不自动设无穷大来放开广告；该产品通常已进入退化，同时输出库存覆盖不可判。

| DOS | 最终限制 |
|---|---|
| 未知／无可售／<7 | 不调价、不正向广告；有证据的止损可保留 |
| 7≤DOS<14 | 仅已有、各符合条件的对象+3%；不调价、不新增精准、不做零花费动作 |
| 14≤DOS<28 | 按各路径独立判断拉量候选，不设同日动作数量上限；价格与广告仍互斥 |
| DOS≥28 | 按业务路径及各对象条件，不放宽价格底线或效率条件 |

池内多个国家的新增消耗要统一核验，不能每国都占用全部库存。现行主策略没有“每个池额外最多几条”的数值，不在开发中自行加一条新门槛；无法估计共同消耗时保留库存容量待核。

### 8.2 预算公式与周期

商品预算键：budget_date＋country＋seller_name_new＋seller_sku_adj。原币额度或人民币额度择一统一使用；建议保留两者及exchange_rate_cny。现有预算代码以月初／周一更新并在周期内保留额度，虽然预测销量用30／7天，实耗比较仍按自然月／自然周。

预算池total_budget_pool_cny为共享库存组额度，site_total_budget_cny为站点额度，均可能在明细行重复。取唯一池／站点值，若同一池值冲突则待核；不能把重复值累加成更大余额。预算代码中的5%是额度生成参数，**不是潜力TACOS门槛**。

| 派生项 | 公式 |
|---|---|
| 商品月剩余 | 商品月预算−本月已发生SP花费 |
| 商品周剩余 | 商品周预算−本周已发生SP花费 |
| 活动日均SP花费 | 最近7个完整日该活动全部产品SP花费／7 |
| 产品预算满足 | 月／周预算有效且均大于0，商品月剩余>0且商品周剩余>0 |
| 活动预算满足 | 当前daily_budget有效且大于0，活动日均SP花费<daily_budget |
| 预算可用判定 | 产品预算与对应活动预算均满足；已有同周期池／站点预算限制也须通过，不能重复累加共享额度 |

**2026-09-29确认：直接检查预算是否满足。**本版不再计算未来基础花费预留、其他动作预占扣减或已释放花费，也不以增量花费预测接口缺失阻断动作。实际花费、预算周期、关联范围或币种不清时，预算状态为unknown；已确认预算用尽或额度无效时为false。剩余额度用于判断当前预算是否满足，不等于承诺后续花费不会超额。

共享活动按活动全部产品实际花费统计，不能只统计目标产品；“多MSKU共用广告对象第一版暂不出动作”的边界仍按2.2执行。跨月／跨周后使用新周期预算与该周期已发生花费重新判断，不能沿用上周期余额；新周期数据未到齐则待核。

bid+5%不代表花费必然+5%，不得用该比例伪造花费预测。新增词、零花费及开启广告仍需预算检查，不能因为历史花费为0就默认预算通过；本版不要求提供`expected_incremental_spend_by_date`。

预算不足只阻断正向广告，不阻断有依据的止损，也不作为价格幅度的额外门槛。不生成提高站点总预算或预算迁移动作。

### 8.3 双短板：直接检查预算，不要求先释放花费

有低效广告则按既有条件减投；没有低效对象就直接判断加投。tacos_mature_30≤0.10、预算满足且对象达到一级效率条件，库存、保护、归属、历史均通过时，可同轮各符合条件的现有对象升bid，最高5%；库存7～不足14天时仍限为3%。TACOS>0.10或不可核时不加投。

不要求先完成减投、不等待另一对象止损复盘、不计算实际释放额。预算不足或不清、效率不达标或库存不通过时不加投。同一对象不得同时升降bid，已有未完成动作仍受复盘与重复控制限制；不调价、不加精准、不做零花费动作。

### 8.4 互斥、排序及重复控制

1. 不设置产品每轮价格、广告总动作及正向加投数量上限；四种自动匹配方式分别满足条件时可同轮处理，分别保存target及证据。
2. 同产品本轮新调价与任何广告动作仍互斥；先处理广告，完成复盘且本轮通过7.1后才进入新调价。取消数量上限不改变此顺序。
3. 同对象提bid与降bid互斥；同一对象只选一个方向和一档幅度，不叠加。新词和来源调整关联记录、联合复盘；同词去重，不重复创建。
4. 已有有效对象、新增精准、零花费等候选分别核验路径、TACOS、预算、库存及历史。排序仅用于展示和执行组织，不按前1项或前2项截断；未通过者保留原因。
5. 止损优先，可按花费降序及完整实体键排序；符合条件的止损与其他对象加投可同轮处理，止损数量不占用加投名额。
6. 当前日已生成／已批准／已生效的同一动作保持幂等，不重复下发。仍在复盘的动作不得因run_date改变而重复；同一价格仍只有一个有效目标，完成复盘后重新判断。

## 9. 复盘：每日观察；每3天一次调整；整体观察期14–30天

### 9.1 生效日、调整周期与整体起点

`effective_at`取实际平台生效或成功回读确认时间，转换到业务报表时区；不取建议、审批或提交时间。失败／未生效动作没有效果观察窗。

- 每日更新动作生效状态、日销、订单毛利率、广告花费、TACOS及库存。
- 价格和广告均每3天进入一次调整判断。令本轮实际生效日为D0，首次比较D0−3至D0−1与D0+1至D0+3，均为3个完整日，排除D0。未再调整时，D+6、D+9等节点取最新3个完整日与本轮基线比较。
- 正常二次调整须距离该对象上次生效至少3天、本轮复盘完成、动作条件重新通过；撤回及异常处理按原风险结论处理，不机械等待下一轮。
- 本产品本次策略首个动作生效日另存为整体观察起点。第14天综合评估，需继续观察时跟踪至第30天。二次调整重置该动作本轮D0，整体起点保留；尚未完成的原轮窗口标记被后续动作打断，不将多轮效果归给单次动作。
- 到期但该日未结束或数据未齐，输出waiting_data；不得提前填满3日。09-20生效的首轮后窗为09-21至09-23，若任务只取前一天数据，最早09-24运行判断。

**每3天是决策周期，不改变广告归因等待。**动作前对象点击、订单、ACOS、CVR及产品TACOS继续使用同一成熟30天窗口。使用动作后对象orders_7d／ACOS判断时，要求`ads_source_end >= 观察窗末日+7天`；尚未成熟的0单不用于再次减投。每轮可先根据已齐的经营日数据判断维持／撤回；依赖未成熟归因的追加候选单独待核。不得复用同一旧窗口重复下调。

### 9.2 同口径比较

本轮用前后各3日：日销=sum(销量)÷3；订单毛利率=sum(predict_gross_profit)÷sum(amount)；复盘TACOS=sum(spend)÷sum(amount)。仅有滚动30天值不能代替本轮3日值；分母无效或日数不足按缺失处理。

```text
日销变化 = 动作后3日日销 - 本轮基线3日日销
订单毛利率变化 = 动作后3日订单毛利率 - 本轮基线3日订单毛利率
TACOS变化 = 动作后3日TACOS - 本轮基线3日TACOS
```

比例用原始小数差或百分点，不擅设容差。复盘TACOS使用实际观察窗，不再前移7天；动作前TACOS仍用成熟30天。价格复盘不新增TACOS效果门槛。每次加投还须通过当批成熟30天TACOS分档。

先核同期价格／bid变化、促销、断货、预算／投放状态变化。干扰未排除或缺可比指标时输出confounded／waiting_data，保持、不追加。

### 9.3 每3天的判断出口

| 原动作／观察条件 | 输出结论 |
|---|---|
| 提价：日销>3且订单毛利率>调前 | 维持；仍在利润路径、现价≤0.90P25、间隔≥3天且全部前置通过，可下一轮最多+5% |
| 提价：日销≤3或订单毛利率≤调前，且无干扰 | 停止追加，恢复本轮原价建议 |
| 降价：日销>调前且订单毛利率≥15% | 维持；仍在销量路径、现价≥1.10P35、间隔≥3天且全部前置通过，可下一轮最多−5%、最低P25 |
| 降价：日销≤调前或订单毛利率<15%，且无干扰 | 停止追加，恢复原价建议 |
| 涨bid／加精准：日销>调前、订单毛利率≥调前、TACOS≤调前，库存预算通过 | 维持；下一轮回到第6节重新判对象、经营路径，不直接重复原幅度 |
| 涨bid／加精准：日销≤调前，或订单毛利率<调前，或TACOS>调前，且数据可比 | 恢复原bid／暂停本轮新精准；保留原来源 |
| 零花费提bid：仍无有效投放，或有花费但经营未改善 | 恢复原设置，核投放资格与预算等 |
| 降bid：日销≥调前且订单毛利率≥调前 | 维持，记录花费、点击及曝光变化；下一轮减投仍须新有效证据 |
| 降bid：日销<调前或订单毛利率<调前，且无干扰 | 恢复原设置建议 |
| 数据不完整／所需归因未成熟／有干扰 | waiting_data或confounded；保持，不追加相关动作 |

整体14–30天观察记录经营指标、TACOS、排名及各轮调整。完整30天经营数据用于重选路径，3日结果不直接改角色标签。第30天汇总结论；未成熟证据单独列明，不伪造成功／失败。

- 同对象进行中／观察中，阻断新的同对象设置变化，保留复盘／撤回候选；防止止损建议也每天重复下发。价格或广告本轮3日复盘已完成且下一轮条件通过时，结束该轮追加阻断；14–30天整体跟踪不单独阻挡下一轮。数据不足、归因待核或原动作效果未清时，相关候选仍阻断。
- 历史服务不可用时，不输出可直接执行的数值动作；仍可展示“条件命中但历史待核”的候选。止损业务条件可继续算，但不能假装已排除重复。

| 相关性及保护 | 搜索词宽表已有部分保护事实 | 自有ASIN范围、保护版本、相关性结论与来源、关键词对象保护 | 阻断依赖这些证据的否定／零单止损等 |
| 预算核验 | 商品／池预算、活动daily_budget及SP实际花费来源已存在 | 同周期实际花费、当前预算、币种及关联范围，按8.2计算 | 预算不足或不清时阻断正向广告；不要求增量预测、基础预留或预占接口 |

以上是缺接口／缺证据，不是把点击、价格和bid幅度重新交给人工选择。业务阈值已经写死在本版策略；只有这些条件确实无法计算时，按依赖范围输出缺项。

### 15.4 用现表时必须明确的边界

1. **结果表是建议数据，不是执行流水。**本次样例中存在history_source_unavailable；历史未核清时，潜力应按第11节标记待核，不能只看命中编号或manual_review_required就判为可执行。
2. **两张结果表本次均未查到唯一索引。**生成潜力结果时须按“业务批次＋产品＋规则版本＋rule_code＋动作对象／范围”去重并保证重跑幂等；幂等的具体写入实现由开发选择，不能直接追加造成重复。后续索引方案须先检查现有数据与调用方。
