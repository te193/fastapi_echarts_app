# 补货导出销量异常标黄规则说明

## 1. 文档目的

补货计划导出时，系统会对部分补货行整行标黄，提醒业务人员复核销量是否存在异常。

黄色只是风险提示，不会因为标黄而重新计算或修改以下内容：

- 日均销量；
- 补货层级；
- 补货需求量；
- 最终补货数量；
- 补货箱数；
- 补货货值。

当前黄色提醒由两条规则共同组成：

1. 规则一：近期销量集中；
2. 规则二：MAD 单日爆单识别。

两条规则相互独立，任意一条命中都可以触发黄色提醒。

---

## 2. 所有标黄规则的共同前提

系统先判断当前导出行是否属于需要人工复核的有效补货行。

只有同时满足以下条件，才可能标黄：

1. 补货层级为“紧急补货”“建议补货”或“计划补货”；
2. 最终导出的补货数量大于 0。

以下情况不标黄：

- 库存充足；
- 日销为 0；
- 最终补货数量为 0；
- 同 ASIN 合并后没有承接补货量的链接；
- 被跟卖、MOQ 或其他业务规则拦截后补货数量为 0 的行。

系统的最终判断顺序可以概括为：

```text
是否属于有效补货层级？
        ↓ 是
最终补货数量是否大于0？
        ↓ 是
是否命中MAD爆单提醒？——是→标黄
        ↓ 否
是否命中3天/7天销量集中？——是→标黄
        ↓ 否
不标黄
```

---

## 3. 规则一：近期销量集中

### 3.1 业务目的

这条规则用于识别：最近 7 天的销量是否过度集中在最近 3 天。

即使没有某一天达到“单日爆单”的程度，如果最近几天突然集中出单，当前日销也可能被短期销量拉高，因此需要人工复核。

### 3.2 判断条件

同时满足以下两个条件时标黄：

```text
7天销量 ≥ 10

并且

3天销量 ≥ 7天销量的70%
```

系统实际判断等价于：

```text
3天销量 × 10 ≥ 7天销量 × 7
```

### 3.3 为什么要求7天销量不少于10

如果不设置最低销量，例如 7 天只卖 1 件且这 1 件发生在最近 3 天，占比也是 100%，但业务意义很弱。

因此先要求 7 天销量不少于 10，再判断销量是否集中，可以减少低销量商品因偶发 1～2 件而频繁标黄。

### 3.4 MU0133g 示例

2026-08-07 快照中，`MU0133g` 的数据为：

| 项目 | 数值 |
| --- | ---: |
| 补货层级 | 建议补货 |
| 最终补货数量 | 93 |
| 3天销量 | 17 |
| 7天销量 | 17 |
| MAD状态 | normal |
| MAD标记 | 0 |

最近完整销售日的销量为：

| 日期 | 销量 |
| --- | ---: |
| 2026-08-04 | 8 |
| 2026-08-05 | 0 |
| 2026-08-06 | 9 |

计算结果：

```text
3天销量 ÷ 7天销量
= 17 ÷ 17
= 100%
```

100% 高于 70%，并且 7 天销量为 17，不少于 10，因此命中规则一并标黄。

该产品没有命中 MAD 单日爆单规则。这里的黄色含义是“近期销量集中”，不是“系统认定发生了单日爆单”。

---

## 4. 规则二：MAD 单日爆单识别

### 4.1 业务目的

这条规则用于识别：某一天的销量是否明显高于产品自己的正常水平，并且高得不像正常波动。

规则不会简单规定“超过平时 3 倍就是爆单”，因为不同产品的销量水平和正常波动差异很大。

例如：

- 平时每天卖 1 件的产品突然卖 15 件，可能已经非常异常；
- 平时每天卖 50 件的产品卖 60 件，可能仍属于正常波动。

因此系统先让每个产品和自己比较，再参考同销量体量产品的历史经验确定异常门槛。

### 4.2 识别维度

MAD 规则按以下产品组识别：

```text
国家分组 country_category + ASIN max_asin
```

同一国家分组、同一 ASIN 下如果有多条销售链接，系统会先按日期合计真实销量，再识别产品组是否发生爆单。

识别结果会传递给组内链接，但导出时只有最终补货数量大于 0 的实际补货目标行会标黄。

### 4.3 日常识别窗口

系统每天使用最近 30 个完整销售日进行判断。

当前销量数据是 T+1 口径，因此：

- 2026-08-07 导出时，最新完整销售日是 2026-08-06；
- 规则可以识别最新已经同步完成的销售日；
- 不能实时识别当天尚未同步完成的订单。

如果有效历史不足 14 天，系统不会强行使用 MAD，而是仅由规则一兜底判断。

---

## 5. MAD 怎么理解

### 5.1 先找产品平时一天卖多少

系统查看产品最近 30 个完整销售日，使用销量中位数作为正常销量基线。

中位数是把所有日销量从小到大排列后，位于中间位置的数。

例如：

```text
2、4、5、5、6、7、168
```

中位数是 5。即使其中一天卖了 168 件，正常基线仍然接近 5，不会像平均数那样被极端销量明显拉高。

在判断某一个候选日期时，该候选日会从基线样本中排除，避免当天的异常销量参与计算自己的正常水平。

### 5.2 再看产品平时波动多大

系统计算每一天销量与中位数相差多少，再取这些差值的中位数，这就是 MAD。

```text
MAD = 每天销量与销量中位数之差的绝对值的中位数
```

通俗理解：

- MAD 小：产品平时销量稳定，突然增加几件就值得注意；
- MAD 大：产品平时本来就波动较大，需要增加更多才算异常。

MAD 同样使用中位数，因此不容易被某一天的极端销量带偏。

### 5.3 1.4826 是什么

原始 MAD 与常见的“标准波动尺度”并不完全一致。

在常见的近似正态分布下：

```text
1.4826 ≈ 1 ÷ 0.6745
```

因此系统用 `1.4826 × MAD` 把 MAD 换算为更容易比较的波动尺度。

`1.4826` 是统计学中的通用尺度修正系数：

- 不是爆单倍数；
- 不是人为设定的业务阈值；
- 不代表销量必须达到平时的 1.4826 倍。

### 5.4 为什么波动尺度最小取1

部分低销量产品很多天的销量完全相同，MAD 可能等于 0。

为了避免除以 0，也避免少量销量变化产生无限大的异常分数，系统使用：

```text
正常波动尺度 = max（1.4826 × MAD，1）
```

即正常波动尺度最低按 1 计算。

---

## 6. 异常分数怎么计算

异常分数计算公式为：

```text
异常分数
=（候选日销量 - 产品正常销量中位数）
 ÷ max（1.4826 × MAD，1）
```

它表示：

> 候选日销量比产品自己的正常水平高出了多少个“正常波动单位”。

例如：

```text
正常销量中位数 = 10
MAD = 2
候选日销量 = 25

正常波动尺度 = 1.4826 × 2 = 2.9652
异常分数 = (25 - 10) ÷ 2.9652 ≈ 5.06
```

异常分数越高，说明候选日越不像该产品自身的正常波动。

需要注意：异常分数本身不是最终结论。系统还需要把它与 90 天历史校准出的 P99.5 阈值比较。

---

## 7. 为什么既和自己比，又要参考同批产品

当前规则分为两层：

### 第一层：产品和自己比

以下数据全部来自产品自身最近 30 个完整销售日：

- 正常销量中位数；
- MAD；
- 正常波动尺度；
- 候选日异常分数。

因此，某一天是否偏离正常水平，首先是产品和自己比较。

### 第二层：判断异常分数是否足够高

系统再使用同销量体量产品的 90 天历史分布确定阈值。

没有让每个产品单独使用 90 天数据计算 P99.5，是因为单个产品通常只有约 90 个日期样本：

```text
90 × 0.5% = 0.45个样本
```

这会让单个产品的 P99.5 几乎等于历史最大值。只要历史中出现过一次极端爆单，阈值就可能被抬得过高，后续异常反而识别不出来。

因此当前采用：

```text
正常水平和波动大小：产品和自己比
最终异常门槛：参考同销量体量产品的历史经验
```

## 8. 90天阈值怎么生成

### 8.1 90天只用于校准

90 天数据不参与每日正式识别，也不会每天动态重算阈值。

其作用是通过只读影子回放生成一份固定配置。每日运行时读取固定配置，并只分析最近 30 个完整销售日。

如果未来整体销量结构发生明显变化，可以重新执行 90 天校准，再更新固定阈值。

### 8.2 生成历史异常分数样本

对每个产品组、每个符合条件的历史日期，系统模拟一次当日识别：

1. 使用该日期之前最多 30 天的销量计算中位数和 MAD；
2. 至少需要 14 天有效历史；
3. 计算该历史日期的异常分数；
4. 同时记录该日期后 3 天的平均销量，用于校准回落标准。

本次校准数据为：

| 项目 | 数量 |
| --- | ---: |
| 产品组 | 3,400 |
| 滚动历史样本 | 248,106 |

### 8.3 按正常销量体量分组

低销量产品和高销量产品不能直接使用相同的绝对销量标准。

系统原计划按正常日销基线的 P25、P50、P75 分为 4 组。由于本次数据中大量产品的正常日销为 0，三个分位点发生重合，空分组自动合并，最终形成两个有效组：

| 正常日销基线 | 单日异常分数阈值 | 爆单后3天平均销量上界 |
| --- | ---: | ---: |
| 基线为0 | 18.000 | 0.667 |
| 基线大于0 | 10.117 | 8.667 |

这里的阈值来自历史数据，不是人工指定“几倍销量”。

---

## 9. P99.5 怎么计算

### 9.1 P99.5 的业务含义

P99.5 是第 99.5 百分位。

通俗理解：把历史向上波动的异常分数从小到大排列，找到接近最顶部 0.5% 的分界线。

```text
大约每1,000次历史向上波动中
只有最高的约5次能够达到或超过这个级别
```

P99.5 不代表识别准确率是 99.5%，而是表示系统只把历史分布中非常少见、非常突出的向上波动作为疑似爆单。

### 9.2 10.117 的实际计算过程

本次“正常日销基线大于 0”组共有 14,653 个正向异常分数。

将这些分数从小到大排列，P99.5 的位置为：

```text
位置 =（样本数 - 1）× 99.5%
     =（14,653 - 1）× 0.995
     = 14,578.740
```

这是从 0 开始计数的位置，换成日常理解的名次，就是位于：

```text
第14,579个分数
与第14,580个分数
之间74%的位置
```

两个位置的实际异常分数刚好相同：

```text
第14,579个 = 10.1173613921
第14,580个 = 10.1173613921
```

使用线性插值：

```text
P99.5
= 10.1173613921
  + 74% ×（10.1173613921 - 10.1173613921）
= 10.1173613921
```

报告中按三位小数显示为：

```text
10.117
```

这个分位位置距离排序顶部约 74 个样本，代表历史分布中极少见的向上波动；如果多个样本分数相同，实际达到阈值的数量可能略多于 74 个。

## 10. 爆单识别后的状态变化

### 10.1 疑似爆单 suspected

如果最新完整销售日的异常分数达到对应销量组的阈值，系统立即进入“疑似爆单”状态并标黄。

此时不需要等待后续 3 天，目的是让最新异常尽快进入人工复核。

### 10.2 确认回落 confirmed_recovered

系统观察爆单日之后的 3 个完整销售日。

同时满足以下条件时，认为这是一次性爆单后恢复正常：

1. 后续 3 天都没有再次达到单日异常阈值；
2. 后续 3 天平均销量不超过对应销量组的历史回落上界。

确认回落后继续标黄，因为这次爆单仍可能影响当前 7 天、14 天或 30 天日销，从而影响业务人员对补货结果的判断。

### 10.3 持续增长 sustained_growth

如果爆单后 3 天仍保持高位，则认为这可能是持续增长，而不是一次性爆单。

此时不再保留 MAD 的一次性爆单长期提醒。

但是，如果该产品仍满足规则一的“3天/7天销量集中”，依然可能因为规则一标黄。

### 10.4 正常 normal

最近 30 天未识别到单日爆单，或者有效历史不足时，MAD 状态为正常。

MAD 状态正常并不代表一定不标黄，还需要继续检查规则一。

### 10.5 什么时候解除MAD提醒

确认属于一次性爆单后，只要爆单日仍在最近 30 个完整销售日窗口内，就继续保留 MAD 黄色提醒。

爆单日离开 30 天窗口后，MAD 提醒自动解除。

## 11. JC029b 完整示例

产品组：

```text
国家分组：欧洲站
ASIN：B0CX51133J
原始链接：Joochees / JC029b
实际补货目标：meeloo / KQ-UFY7-HWK2
```

关键数据：

| 项目 | 数值 |
| --- | ---: |
| 正常销量中位数 | 5 |
| 爆单日期 | 2026-08-03 |
| 爆单销量 | 168 |
| 异常分数 | 54.970997 |
| 对应P99.5阈值 | 10.117361 |
| 爆单后3天销量 | 5、2、2 |
| 爆单后3天平均销量 | 3 |
| 回落平均销量上界 | 8.667 |

判断过程：

```text
异常分数 54.970997 > 阈值 10.117361
→ 识别为单日爆单

爆单后3天平均销量 3 < 回落上界 8.667
且3天内没有再次达到异常阈值
→ 状态为 confirmed_recovered
→ 在爆单日离开30天窗口前继续标黄
```

同 ASIN 产品组的补货结果保持不变：

| 链接 | 最终补货数量 | 导出结果 |
| --- | ---: | --- |
| Joochees / JC029b | 0 | 不标黄 |
| meeloo / KQ-UFY7-HWK2 | 2,295 | 整行标黄 |

黄色只提醒业务人员复核 168 件爆单对当前日销的影响，实际补货目标的 2,295 件没有被规则修改。

## 12. 两条规则的区别

| 对比项 | 规则一：近期销量集中 | 规则二：MAD单日爆单 |
| --- | --- | --- |
| 主要关注 | 最近销量是否集中在3天内 | 某一天是否明显偏离自身正常水平 |
| 观察窗口 | 3天和7天 | 日常识别最近30天 |
| 主要条件 | 7天销量≥10，且3天占比≥70% | 异常分数达到同销量体量组P99.5阈值 |
| 是否和产品自身比较 | 间接比较短周期占比 | 是，使用自身中位数和MAD |
| 是否使用90天数据 | 否 | 是，但仅用于校准固定阈值 |
| 提醒持续时间 | 每次导出重新按3天/7天判断 | 一次性爆单确认回落后可持续到30天窗口结束 |
| 典型案例 | MU0133g | JC029b |

## 13. 常见问题

### 13.1 标黄会增加或减少补货数量吗

不会。两条规则都只改变 Excel 单元格颜色，不参与补货计算。

### 13.2 为什么MAD状态为normal，导出仍然标黄

因为两条规则相互独立。MAD 未命中时，如果仍满足“7天销量不少于10且3天销量占比达到70%”，规则一仍会标黄。

`MU0133g` 就属于这种情况。

### 13.3 为什么不用固定3倍判断爆单

不同产品的正常销量和波动差异很大。固定3倍容易对低销量商品过度提醒，也可能漏掉高销量但平时非常稳定的商品。

MAD 会先考虑产品自身正常水平和自身波动，因此更稳健。

### 13.4 为什么不让每个产品单独计算P99.5

单个产品 90 天样本太少，P99.5 几乎等于历史最大值，容易被过去的一次爆单抬高。

因此当前用产品自身数据计算异常分数，再用同销量体量产品的整体历史确定最终门槛。

### 13.5 90天阈值每天都会变化吗

不会。90 天影子回放用于生成固定配置，日常 ETL 只读取配置。

只有业务决定重新校准并更新配置后，阈值才会变化。

### 13.6 今天自然日刚发生爆单能立刻识别吗

当前销量数据为 T+1。系统可以立即识别最新已经同步完成的销售日，但不能实时识别尚未同步完成的当天订单。

---

## 14. 面向业务的统一口径

可统一对业务人员说明为：

> 补货导出黄色提醒包括两种情况：一是最近7天销量过度集中在最近3天；二是近30天内出现明显偏离产品自身正常水平的单日爆单。单日爆单先与产品自己的正常销量和波动比较，再使用同销量体量产品的90天历史P99.5阈值确认。黄色仅提示人工复核，不会修改补货数量。
