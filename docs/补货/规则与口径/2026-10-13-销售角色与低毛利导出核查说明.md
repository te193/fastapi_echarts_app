# 补货销售角色与低毛利导出核查

状态：代码实现与本地验证；本地8001服务已重启加载，未部署远端、未重算远端补货快照。

本页是本次补货角色与导出核查变更的业务、开发和运维交接入口。仅适用于补货主页面、补货导出和补货跟踪，独立销售角色分析及站点角色打标不在本次范围。

## 一、业务判断

角色按国家类别＋店铺＋MSKU统计。7、14、30、90天分别计算，默认30天。180天分类选项移除；传入180或其他非法周期时回落至30天，原有180天销售、利润和库存指标列继续保留。

分类日均销量＝同一对象周期总销量÷固定周期天数。总指标包含当前国家类别的全部国家，不仅限于下述核查国家。毛利率＝周期毛利润合计÷销售额合计，不能平均各国毛利率。两项均不使用跟卖补偿、同ASIN合并的销量或可售天数。

| 角色 | 任一命中条件 |
| --- | --- |
| 明星 | 日销＞5且毛利率＞15%；或1≤日销≤5且毛利率＞25% |
| 潜力 | 日销＞5且5%≤毛利率≤15%；或1≤日销≤5且10%≤毛利率≤25% |
| 瘦狗 | 1≤日销≤5且5%≤毛利率＜10%；或0＜日销＜1且毛利率≥5%；或日销＞1且毛利率＜5% |
| 问题 | 日销＝0；或0＜日销≤1且毛利率＜5% |

角色证据缺失时显示未分类，分类日销、毛利率保留空值；已知日销为0时属于问题产品。补货计算使用的加权日销、跟卖承接、同ASIN合并、MOQ和补货数量计算保持原逻辑。

## 二、导出直接查看方式

只有总角色为问题或瘦狗，且总日销＞1、总毛利率＜5%的行进入国家核查。明星、潜力和其他未满足前提的行，两列留空。

核查跟随导出选定周期，并保持同一快照、店铺及MSKU。国家范围：欧洲站查德国、法国、意大利、西班牙、荷兰；英国站查英国；北美站查美国。不跨国家类别，不使用国家站点角色标签或小类排名。

| 场景 | 直接标注 | 核查单元格颜色 |
| --- | --- | --- |
| 任一指定国家日销＞1且毛利率＞5% | 总日均销量＞1件/天且总毛利率＜5%；当前类别有国家站点日均销量＞1件/天且毛利率＞5% | 绿色文字 375623 |
| 已有有效国家记录中没有同时满足上述两项条件的国家 | 总日均销量＞1件/天且总毛利率＜5%；当前类别无国家站点同时满足：日均销量＞1件/天且毛利率＞5% | 红色文字 9C0006 |

日销恰好1、毛利率恰好5%均不满足上述国家条件。2026-10-13用户修订：没有国家记录按该国未经营处理，直接跳过；无法形成有效日销和毛利率的国家记录也不参与本项核查。不再显示“缺失国家”或因未经营国家显示“国家核查数据不足”。没有任何国家同时满足上述两项条件时统一使用红色文字说明。此约定只用于导出核查，不回写源数据，也不改变总角色缺少证据时的未分类处理。

新增列为“低毛利核查说明”“日均销量＞1件/天且毛利率＞5%的国家”。说明直接写总维度和国家维度的标准，国家列列出具体国家及实际日均销量、毛利率。2026-10-14用户要求简化导出样式：低毛利两列改用加粗绿色/红色文字，不再叠加浅绿/浅红底色；保留整行销量异常、不补货店铺、跟卖底色和深蓝边框。导出行数、补货数量、箱数及货值均不因核查结果变化。

补货计划表末尾固定增加“导出标注”列，逐项显示实际触发的销量异常、禁补店铺、跟卖和低毛利说明；列选择不影响该提示列。原有业务列顺序和隐藏状态保留，深蓝框延伸到新的最后一列。表头加深蓝色、换行、冻结首行及前两列并开启筛选，长说明列设置宽度和行高。

每次导出固定在最后追加“颜色与标注说明”Sheet，包括黄色、红色、橙色、浅蓝底色、深蓝粗边框、绿色/红色文字、导出标注和空白的含义及触发条件，附国家核查范围与严格边界。底色优先级仍为橙色＞红色＞黄色＞跟卖浅蓝；跟卖蓝框可叠加，低毛利文字色不会覆盖底色。无颜色或空白只代表未触发对应提醒，不代表审核通过。

2026-10-14库容预警已完整接入主页面及导出，所有角色参与，只预警、不改数量、不新增底色。实际商品类型优先取FBA库存明细.仓储类型，体积优先最新Listing包装尺寸；已计算本行及店铺同类型全量补货合计、与剩余额度比较并显示超出量，不受筛选或分页影响。额度直接按店铺sid读取，当前月取最新版本、历史月取月底归档；默认当月开始发货。末尾说明Sheet同步公式、状态和数据不足条件，现行规则及交接详见[补货库容额度匹配与预警规则](2026-10-14-补货库容额度匹配与预警规则.md)。

## 三、实现与运维交接

- [共享角色与核查逻辑](../../../etl/replenishment_roles.py)：唯一的补货角色SQL表达式、周期标准化、原始国家指标聚合和导出核查函数。
- [补货服务](../../../app/services/replenishment_data.py)：页面展示、筛选、统计、历史流转、排序和导出统一使用国家指标聚合；导出按最多200个对象一批读取国家数据，避免逐行查询。
- [补货ETL](../../../etl/replenishment_update.py)：保存的30天默认角色采用可空原始 `role_sales_30 / 30` 和同周期毛利率。该字段仅用于过程表，保留缺失证据；原有补货销量的填零和加权表达式不变。
- 补货跟踪服务及汇总ETL使用同一个角色表达式。历史跟踪汇总读取时重新关联其最近补货日期的国家指标，不回退至旧版存储角色。

复用 `dashboard_replenishment_country_metrics`，不新增业务表字段。快照日期为补货结果日期，统计结束日期沿用国家指标中的 `period_end`，通常是快照前一天。不能把快照日当作额外的销售日。

部署后需先保证对应快照和周期的总角色指标存在。总角色缺少证据时不使用旧角色或补偿销量兜底，可检查 `country_metrics` 步骤；国家核查中未经营国家按上述新约定跳过。现有主页面和导出会按新规则读取已有国家指标，但ETL已保存的 `abcd_category` 与跟踪汇总字段仍需相应本地ETL刷新才更新。不能仅重跑 `replenishment_result` 就声称国家指标已同步刷新。

本次不执行远端SQL、不重算远端数据、不推送。需要部署或生产重算时，另行明确目标环境和范围。验收应同时比较导出角色、核查两列，以及修改前后同一快照的补货数量、箱数和货值。
