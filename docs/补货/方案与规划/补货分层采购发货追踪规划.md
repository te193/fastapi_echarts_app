# 补货分层采购发货追踪规划

> 目标：在现有每日补货看板基础上，新增“补货后是否有采购/发货动作”的追踪能力。本文只做字段和方案梳理，暂不改动代码。

## 一、追踪目标

现有看板已经能回答“哪些 MSKU 需要补货、属于哪个补货层级、建议补多少”。下一步追踪要回答：

1. 每个补货层级下，有多少 MSKU 已经进入采购/发货计划。
2. 计划采购/计划发货了多少。
3. 实际发货了多少、收货了多少、还有多少未发/未收。
4. 发货方式、物流渠道、物流商、货件状态是什么。
5. 能按补货层级、产品角色、店铺、国家类别、MSKU 下钻查看明细。

注意：这部分是“动作追踪”，不参与库存可支撑天数、补货层级、补货数量的计算。

## 二、建议粒度

### 1. 汇总粒度

用于看板指标卡和分层汇总：

```text
补货日期 + 国家类别 + 店铺 + MSKU
```

该粒度和当前补货结果保持一致，方便直接挂在补货层级下面。

### 2. 明细粒度

用于抽屉明细：

```text
补货日期 + 国家类别 + 店铺 + MSKU + 发货计划单号 + FBA货件号
```

如果一个 MSKU 有多个发货计划或多个货件，需要保留多行明细，汇总层再聚合。

## 三、字段来源

### 1. 当前补货结果，本地表

优先使用现有本地结果表作为主表：

| 表 | 用途 |
| --- | --- |
| `dashboard_pur_plan_replenish_data` | 当前看板补货结果、补货层级、产品角色、建议补货数量、补货货值、本地在仓/FBA可用/FBA在途等 |
| `dashboard_restock_daily_snapshot` | 本地补货建议快照，已有采购计划数、采购在途数、本地库存等同步字段 |

可直接复用的字段：

| 字段 | 含义 |
| --- | --- |
| `replenishment_level` | 补货层级 |
| `product_category` | 明星/潜力/瘦狗/问题产品 |
| `replenishment_qty` | 看板计算出来的补货数量 |
| `replenishment_value` | 看板计算出来的补货货值 |
| `sc_quantity_purchase_plan` / `purchase_plan_quantity` | 当前快照里的计划采购数 |
| `sc_quantity_purchase_shipping` / `purchase_shipping_quantity` | 当前快照里的采购在途数 |

结论：`lx_purchase_purchase_plan` 可作为“是否采购/采购了多少”的优先来源；`lx_fba_shipment_plan` 仍用于看 FBA 发货计划、运输方式和物流渠道。两者不要混用。

### 4. FBA 发货单明细，DWD 层

用于追实际货件、实际发货、收货、物流渠道、物流商、预计到达等。

主表：


```text
dwd_datasync.lx_inbound_shipment_detail_ShangPinLieBiao
```

推荐关联方式：

```sql
lx_inbound_shipment_detail.shipment_sn
= lx_inbound_shipment_detail_ShangPinLieBiao.shipment_sn
```

再用商品明细里的：

```sql
lx_inbound_shipment_detail_ShangPinLieBiao.shipment_order_sn
```

商品明细表可用字段：

## 四、建议指标口径

### 1. MSKU 级追踪指标

| 指标 | 建议口径 |
| --- | --- |
| 是否已采购计划 | `lx_purchase_purchase_plan.quantity_plan > 0` 或本地快照 `sc_quantity_purchase_plan > 0` |
| 采购计划数量 | 按 MSKU 聚合 `lx_purchase_purchase_plan.quantity_plan` |
| 是否已发货计划 | `lx_fba_shipment_plan.shipment_plan_quantity > 0` |
| 发货计划数量 | 按 MSKU 聚合 `lx_fba_shipment_plan.shipment_plan_quantity` |
| 已发数量 | 按 MSKU 聚合 `lx_inbound_shipment_detail_ShangPinLieBiao.quantity_shipped` |
| 已收数量 | 优先 `shipment_quantity_received`，为空时参考 `quantity_receive` |
| 未发数量 | `发货计划数量 - 已发数量` |
| 未收数量 | `已发数量 - 已收数量` |
| 发货完成率 | `已发数量 / 发货计划数量` |
| 收货完成率 | `已收数量 / 已发数量` |
| 运输方式 | 优先 `lx_fba_shipment_plan.method_name` |
| 物流渠道 | 优先 `lx_inbound_shipment_detail.logistics_channel_name`，为空再用 `lx_fba_shipment_plan.logistics_name` |
| 物流商 | `lx_inbound_shipment_detail.logistics_provider_name` |
| 最新状态 | 优先货件主表 `status_name`/`order_logistics_status`，计划阶段用计划表 `status_name` |

### 2. 分层级追踪指标

按当前筛选条件和补货层级聚合：

| 指标 | 说明 |
| --- | --- |
| 需补货 MSKU | 当前层级 MSKU 数 |
| 已采购计划 MSKU | 当前层级中已生成采购计划的 MSKU 数 |
| 未采购计划 MSKU | 当前层级中还没有采购计划的 MSKU 数 |
| 采购计划数量 | 当前层级采购计划数量合计 |
| 已发货计划 MSKU | 当前层级中已生成 FBA 发货计划的 MSKU 数 |
| 发货计划数量 | 当前层级 FBA 发货计划数量合计 |
| 已发数量 | 当前层级实际发货数量合计 |
| 已收数量 | 当前层级实际收货数量合计 |
| 未发数量 | 当前层级计划未发数量 |
| 未收数量 | 当前层级发货未收数量 |
| 主要运输方式 | 当前层级计划数量最大的运输方式 |
| 异常 MSKU | 计划后超过 N 天未发、发货后超过 N 天未收、计划数量明显低于补货建议的 MSKU |

## 六、匹配逻辑

### 1. 主匹配

```text
补货结果 seller_sku_adj = 计划/发货明细 msku
补货结果 seller_name_new = 计划/发货明细 sname
```

### 2. 国家类别匹配

DWD 表里多为国家 `nation`，当前看板主粒度是国家类别 `country_category`。需要补一层国家到国家类别映射：

```text
nation -> country_category
```

例如德国、法国、意大利、西班牙等归到欧洲站。这个映射可以复用当前产品表现或 listing 国家明细里的国家类别规则。

### 3. 店铺匹配风险

部分表里的店铺可能带国家后缀，例如 `ShChu-DE`，而看板店铺可能是 `ShChu`。需要在正式实现前确认店铺标准化规则：

1. 如果 DWD `sname` 和看板 `seller_name_new` 完全一致，直接匹配。
2. 如果 DWD `sname` 带后缀，需要做店铺清洗或维护店铺映射表。

## 七、看板展示建议

### 1. 分层卡片增加追踪小指标

每个补货层级行增加小指标：

```text
已计划 20 / 未计划 62 / 计划数 3,500 / 已发 1,800 / 已收 600
```

点击这些指标打开追踪抽屉。

### 2. 追踪抽屉

推荐分四个 Tab：

| Tab | 内容 |
| --- | --- |
| 总览 | 当前层级计划/发货/收货漏斗，运输方式占比 |
| 计划单 | 发货计划单号、计划数量、运输方式、物流渠道、计划状态 |
| 发货单 | 货件号、实际发货、收货、物流商、物流状态、预计到达 |
| 异常 | 未计划、计划未发、发货未收、超过时效未收 |

### 3. 明细列表字段

主表仍保持现有补货明细。新增一列：

```text
采购发货追踪
```

展示：

```text
已计划 / 已发 / 已收 / 运输方式
```

点击后打开当前 MSKU 的发货计划和货件明细。

## 八、待确认事项

1. “采购了多少”的业务定义需要确认：
   - 如果指采购计划数量，用 `lx_purchase_purchase_plan.quantity_plan`。
   - 如果指 FBA 发货计划数量，用 `lx_fba_shipment_plan.shipment_plan_quantity`。
   - 如果指真实采购订单或采购入库数量，需要继续定位采购订单/收货单链路。
2. 店铺名称是否需要统一清洗，例如 `seller_name_new` 与 `sname` 是否存在后缀差异。
3. 国家类别映射是否直接复用 listing 国家明细规则。
4. 发货方式展示优先级建议为：
   - `lx_fba_shipment_plan.method_name`
   - `lx_inbound_shipment_detail.logistics_channel_name`
   - `lx_fba_shipment.shipping_mode`
5. 追踪窗口建议先做 30 天，后续再加 7/14/60/90 天切换。
6. `supply_indicator_detail_sync(1).sql` 可作为参考，但不能直接复用其结果口径：
   - 它是缺货监控逻辑，不是补货分层快照追踪。
   - 它只保留 `available_total = 0` 的缺货记录，不适合当前补货全量池。
   - 它的粒度是 `MSKU + SKU`，当前看板主粒度是 `补货日期 + 国家类别 + 店铺 + MSKU`。
   - 它的时间窗口有写死值，后续追踪页面应以补货日期为起点动态计算窗口。

## 九、结论

本轮基础字段确认结果：

1. 发货方式在 DWD 层有字段，优先表是 `dwd_datasync.lx_fba_shipment_plan`，字段是 `method_name`。
2. 物流渠道和物流商在 DWD 层也有字段，优先表是 `dwd_datasync.lx_inbound_shipment_detail`，字段是 `logistics_channel_name`、`logistics_provider_name`。
3. MSKU 级实际发货/收货数量在 `dwd_datasync.lx_inbound_shipment_detail_ShangPinLieBiao`。
4. 采购计划在 DWD 层可用，优先表是 `dwd_datasync.lx_purchase_purchase_plan`，核心字段是 `plan_sn`、`plan_create_time`、`status_text`、`quantity_plan`、`expect_arrive_time`。
5. 现有本地表能提供补货层级和快照里的采购计划数/采购在途数，但要追到采购计划单、发货计划单、货件号和发货方式，必须补同步 DWD 采购计划、FBA 发货计划和货件明细。
6. 后续实现建议先落两张本地追踪表，再在看板上做独立追踪页面。

## 十、采购/发货数量口径拆分

追踪页里“采购了多少”不要只做一个单一口径，建议拆成两条链路同时展示：

```text
补货建议数量
-> 采购计划数量
-> FBA 发货计划数量
-> 实际发货数量
-> 实际收货数量
```

### 1. 采购计划数量

用于判断采购端是否已经响应补货需求。

优先来源：

```text
dwd_datasync.lx_purchase_purchase_plan.quantity_plan
```

建议展示字段：

| 指标 | 说明 |
| --- | --- |
| 是否已建采购计划 | 当前补货 MSKU 在追踪窗口内是否出现采购计划 |
| 采购计划 MSKU 数 | 已建采购计划的 MSKU 数 |
| 采购计划数量 | `quantity_plan` 按补货日期、国家类别、店铺、MSKU 聚合 |
| 采购计划单号 | `plan_sn`，多单号用列表展示 |
| 采购计划状态 | `status_text` |
| 预计到货时间 | `expect_arrive_time` |

该口径回答的是：采购有没有开始处理、计划采购多少。

### 2. FBA 发货计划数量

用于判断货是否已经进入发往 FBA 的计划链路。

优先来源：

```text
dwd_datasync.lx_fba_shipment_plan.shipment_plan_quantity
```

建议展示字段：

| 指标 | 说明 |
| --- | --- |
| 是否已建 FBA 发货计划 | 当前补货 MSKU 在追踪窗口内是否出现 FBA 发货计划 |
| 发货计划 MSKU 数 | 已建 FBA 发货计划的 MSKU 数 |
| FBA 发货计划数量 | `shipment_plan_quantity` 按补货日期、国家类别、店铺、MSKU 聚合 |
| 发货计划单号 | `order_sn`，多单号用列表展示 |
| 发货计划状态 | `status_name` |
| 运输方式 | `method_name` |
| 物流渠道 | `logistics_name` |
| 计划发货时间 | `shipment_time` |

该口径回答的是：是否已经安排发往 FBA、计划发多少。

### 3. 实际发货/实际收货数量

用于判断发货计划后续是否真正执行，以及货件是否已经收货。

优先来源：

```text
dwd_datasync.lx_inbound_shipment_detail_ShangPinLieBiao.quantity_shipped
dwd_datasync.lx_inbound_shipment_detail_ShangPinLieBiao.shipment_quantity_received
```

建议展示字段：

| 指标 | 说明 |
| --- | --- |
| 实际发货数量 | `quantity_shipped` 聚合 |
| 实际收货数量 | 优先 `shipment_quantity_received`，为空时参考 `quantity_receive` |
| 未发数量 | `FBA 发货计划数量 - 实际发货数量` |
| 未收数量 | `实际发货数量 - 实际收货数量` |

### 4. 看板展示建议

追踪页总览和分层卡片中建议同时展示：

```text
补货建议 35,308 / 采购计划 18,000 / FBA计划 12,000 / 已发 8,500 / 已收 4,200
```

不要把采购计划数量和 FBA 发货计划数量混成一个字段。两者分别代表不同业务阶段：

- 采购计划数量：采购端响应。
- FBA 发货计划数量：发往 FBA 的计划安排。
- 实际发货/收货数量：物流履约结果。
