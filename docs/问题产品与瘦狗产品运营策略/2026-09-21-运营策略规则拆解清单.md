# 问题产品与瘦狗产品动作规则拆解清单

更新：2026-09-21。状态：设计稿，未导入数据库。本版替代此前185条混合过程规则清单。

## 1. 入表范围

规则配置表只保存能产生具体调价或广告操作的动作规则。样本、路径、质量检查、护栏、互斥处理、复盘和成本诊断不再作为独立规则记录入表，也不生成产品动作标签。

本清单使用六位数字动作编号：角色1位＋模块3位＋模块内序号2位，例如100101=1/001/01。原文溯源使用source_refs_json；序号允许留空，不因删除条目重排编号。全部条目仍为draft，原文不明确的条目标为needs_confirmation。这里是业务拆解，不是可直接导入的完整JSON。

最终筛选使用固定action_type，不使用rule_code、rule_name或命中条件作为标签。一个产品命中多个候选后，统一计算流程先处理冲突和数量限制，仅选中的真实动作写入后续动作表。未命中、待核和过程状态保存在诊断明细中。

S=30天日销，M=实际毛利率，T=产品TACOS，P=当前价，C=成熟点击数，O=对应成熟订单数，A=ACOS，V=CVR，R=花费/60天SP搜索广告客单价（仅瘦狗现有规则使用）。各比例入库使用小数。

## 2. 动作的完整适用条件

下表是动作本身的判定分支。生成配置时必须把这里的共同条件合并进每条动作condition_json或由统一计算入口强制验证；不能仅凭一个点击/价格阈值输出动作。这里的条件说明不作为规则行入表。

- 问题产品：七国、301/current与1304/30d样本；S≤1，尚未退出或准备清货，且该轮允许产生新动作。价格动作满足P10底线；常规广告扩量满足T<10%、预算和对象效率；零花费曝光单独处理，不能把T缺失当0。
- 瘦狗产品：七国、301/current与1303/30d样本；按S、M决定当前允许的动作。利润修复只允许对应阶梯提价及止损；已达潜力不产生新的正向动作；下转产品不能继续使用瘦狗动作。
- 广告对象：有效、状态可用、映射唯一，指标窗口与归因口径一致。加精准必须有明确目标手动广告组，否词必须明确对象和作用范围。
- 否词保护：有订单、保护不完整、品牌/核心/新品保护、自有ASIN不输出否定动作。新增精准需相关、自动来源、未有同词有效精准且无否词冲突，保留来源自动词。
- 瘦狗正向广告：低销量且5%≤M<10%、T≤5%仅一个合格现有对象+5%；双目标且T≤5%仅第一档+8%及合格加精准；双目标5%<T≤10%仅在同MSKU确认等额回收后一个现有对象+5%；低销量M≥10%、T<10%才评估更高档及新增精准。M=10%的低销量边界待I05确认。
- 瘦狗库存：无可售/待核或基础DOS<7不产生拉量动作；7≤DOS<14仅一个第一档合格现有对象+3%；14≤DOS<28同日最多一个拉量动作；目标覆盖不足14天按原文进一步限制。上述限制不生成标签，也不能放开路径原本禁止的动作。
- 问题产品库存：常规合格bid/加精准不因库存硬拦截，曝光测试及断货价格例外按原文；未明确处见I06/I07。
- 缺少必要数据不生成数值动作；预算扣除未来基础消耗并按共享池统一分配；预计节省不得当作已确认释放额度。
- 价格向上取整并复核底线；自动对象bid可按原文补0.01，手动bid无有效变化不输出。
- 同对象先保留合格止损；同词否定优先；同方向多档选择和限幅完成后只输出一个最终值。每产品最多1个价格动作、2个广告原子动作，再叠加更严格的库存/路径数量限制。

## 5. 动作类型与最终筛选

| action_type | 展示名称 | 说明 |
|---|---|---|
| price_decrease | 降价 | 不按P25/P10、首轮/二轮拆成多个标签 |
| price_increase | 提价 | P5/P10/P15目标写在动作值和原因中 |
| bid_decrease | 降低竞价 | 不按点击区间或跌幅拆标签 |
| bid_increase | 提高竞价 | 普通扩量、曝光测试均属于提高竞价，测试原因作为详情 |
| keyword_add_exact | 新增精准词 | 指向目标手动广告组 |
| keyword_negative_exact | 否定关键词 | 文字词，须保护与作用范围通过 |
| target_negative | 否定商品 | ASIN，须保护与作用范围通过 |
| ad_enable | 开启广告 | 未开启广告产品的人工执行任务；新建/启用放在详情，不等同于提高现有bid |
| budget_reallocate | 预算调整 | 仅保留原问题产品明确提到的动作草稿；名额与边界I04未明确，不发布 |

一个搜索词规则如果分别支持文字和ASIN，实际导入时按对象类型拆成两条同源动作配置，分别使用keyword_negative_exact/target_negative；不能一条已发布配置填两个action_type。

瘦狗通用竞价扩量模块（004）在实际导入时，需把路径和库存带来的最终+3%/+5%/+8%/+15%/+20%分支展开为完整动作条件，或用已注册的bid计算模板在参数中明确每个分支。无论配置如何拆，结果统一筛选bid_increase，且同一对象只保留最终一条。不得把“限幅到+3%”作为第二条独立护栏规则入表。

同样，问题产品D+7二调仍属于price_decrease。复盘任务在达到真实生效时间和效果条件后，调用受控降价动作计算，不新增“D+7复盘”标签。

## 动作规则编码约定

固定六位：`RMMMSS`，即角色1位＋模块3位＋序号2位。`100101`拆为`1 / 001 / 01`，表示问题产品、调价模块、第01条动作。该划分取代其他临时位数描述。

| 编码段 | 含义 | 取值 |
|---|---|---|
| 第1位R | 产品角色 | 1=问题产品；2=瘦狗产品；其余保留，新增角色时登记 |
| 第2—4位MMM | 动作模块 | 见下表，跨角色保持相同含义 |
| 第5—6位SS | 模块内动作序号 | 01—99；00保留；序号不表示优先级 |

| 模块代码 | 模块名称 | 问题产品示例 | 瘦狗产品示例 |
|---|---|---|---|
| 001 | 调价 | 100101 | 200101 |
| 002 | 自动投放竞价 | 100201 | 200201 |
| 003 | 手动关键词竞价 | 100301 | 200301 |
| 004 | 自动/手动通用竞价扩量 | 当前未配置 | 200401 |
| 005 | 搜索词动作（加精准、否词/否定商品） | 100501 | 200501 |
| 006 | 零花费曝光测试 | 100601 | 200601 |
| 007 | 产品预算调整 | 100702，仍为待明确草稿 | 当前未配置 |
| 008 | 开启广告 | 100801 | 200801 |

模块是具体动作的分类，不新增护栏、路径或复盘规则。004用于原文中自动/手动共用的扩量分支；动作类型仍按action_type筛选，不能仅凭模块判断涨bid还是降bid。

存储使用`char(6)`，JSON中也使用字符串，例如`"rule_code": "100101"`。发布时校验六位数字、角色位与product_role一致、模块合法且序号01—99。版本变化不改规则编号；新增分支使用未占用序号，停用编号不复用。一个模块序号不足时登记新的细分模块，不延长编码或擅自换位数。

原有条目序号尽量保留，所以可能出现200103后接200106；这不表示缺失配置。I01等是文档待明确事项编号，不是动作规则编码，不改成六位数字。
