# 问题产品与瘦狗产品第一版数据开发与来源核对

## 范围与依据

本次开始第一版取数开发。规则依据当前《问题产品运营决策框架》《瘦狗产品运营决策框架》和《2026-09-21-运营策略规则拆解清单》，并服从用户最新确认。新增《产品运营建议通用数据开发流程》只提供来源表与字段线索，不继承其旧策略。

目标仍为 MySQL 三张业务表：规则配置表、调价动作表、广告动作表。规则配置仅保存具体动作；护栏、路径和复盘不作为规则记录或产品标签。第一版不开发效果评估、执行闭环和二轮复盘。

当前交付是**本地输入快照及关联核对**，不是三张表已上线。未执行数据库建表、写入或广告操作，52条动作配置仍为设计稿。输入文件不是新增的永久业务表。

### 广告宽表使用边界（2026-09-21 用户明确确认）

`dws_datasync.dws_sp_bid_object_snapshot_daily` 和 `dws_datasync.dws_sp_search_term_analysis_daily` 仅作为流量、经营指标和广告实体事实的输入来源。可以使用经口径核对的曝光、点击、花费、订单、销售额、观察窗口、归因窗口、实体ID及当前状态；当前竞价须确认对应执行对象，不能把广告组默认竞价当作独立自动投放对象竞价。

禁止复用这两个宽表中的旧建议竞价、加词/否词建议、动作类型、规则命中、推荐状态或旧规则生成的候选资格；也不得先按旧建议过滤记录，再套用新规则，以免漏掉新规则应覆盖的对象。

广告建议竞价、加精准词和否词，必须根据当前《问题产品运营决策框架》《瘦狗产品运营决策框架》及用户最新确认重新计算。《2026-09-21-运营策略规则拆解清单》用于追踪分支，不将其中待确认内容自动视为已确认。

宽表中的保护标记、成熟标记、映射状态等派生字段须核对其生成依据：只有与当前规则一致的数据质量或业务事实才可使用，旧策略判断不得作为新动作的准入或拦截依据。未核实的派生字段不等于用户要求取消保护，应从原始事实重新判断。

本次检查发现输入脚本已排除显式旧建议字段，但仍读取保护、成熟及映射等派生字段；因此尚不能宣称已完成所有旧规则依赖排查。后续补齐预算、实际竞价和词冲突核验时需一并检查。当前仍仅生成问题产品本地预览，不写数据库、不操作广告平台。

## 本次取数结果

有效批次：`data_v1/outputs/20260921-162402/`，以该目录的 `manifest.json` 为准。

- 七国：德国、法国、意大利、西班牙、荷兰、英国、美国。
- 样本：同日 `301/current` 与 `1304/30d` 或 `1303/30d` 的交集。
- 产品粒度：国家＋基础店铺＋MSKU，共3,381个；问题2,079个，瘦狗1,302个，无双角色重叠。
- 成本候选5,516行、定价候选5,928行、库存候选1,117行、竞价对象候选6,899行、搜索词候选62,360行、预算候选3,718行。
- 上述来源候选按样本MSKU提取，可能包含其他店铺/国家的数据，不能把候选行数当作已唯一归属的对象数量。
- 广告对象和搜索词成熟窗口均为2026-08-15至2026-09-13，完整30天；这不能证明产品60天客单价已具备。

已处理店铺名称差异：标签使用基础店铺，成本使用带站点的店铺。采用定价表明确提供的 `国家＋店铺名 → 新店铺` 映射，不通过删除后缀猜测。只有唯一关系用于关联，多对一来源重复保留诊断，不任意选第一条。

对齐后：成本匹配3,133个，248个未匹配；定价匹配3,360个，21个未匹配。两类缺失可能重叠，不直接相加。当前明确映射没有一对多冲突。不能把这些未匹配记录直接认定为源表不存在，仍需区分店铺映射覆盖不足与业务数据缺失。

`product_base.json` 保留全部样本、唯一匹配的成本/定价原值和未匹配原因，不因缺少某项输入丢弃整个产品。输入诊断不进入未来动作筛选标签。

## 重跑方式

使用安装了PyMySQL的Python运行：

```text
python data_v1/inspect_sources.py
python data_v1/extract_inputs.py
python data_v1/extract_inputs.py --rebuild data_v1/outputs/20260921-162402
python data_v1/validate_inputs.py data_v1/outputs/20260921-162402
python -m unittest discover -s data_v1 -p test_input_mapping.py -v
```

按项目要求，取数和验证均用无窗口后台进程启动，查看日志和输出文件；不要以前台阻塞运行。连接信息从现有用户环境读取，不在脚本、日志或报告中保存密码。每次取数使用新批次目录，没有 `manifest.json` 的目录视为未完成批次。
