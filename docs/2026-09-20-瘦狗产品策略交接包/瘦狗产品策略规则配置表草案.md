# 瘦狗产品策略规则配置表草案

## 自动广告调整对象确认（2026-09-30）

本方案自动广告的升bid、降bid和零花费曝光测试，均以四种匹配方式对应的投放目标为对象：紧密匹配、宽泛匹配、同类商品、关联商品。每个目标分别判断，不以整个广告组作为这四种方式的竞价调整对象。此处只明确对象与取数口径，原有阈值、幅度、库存预算及审核条件继续适用。

- 唯一动作键为`profile_id + campaign_id + ad_group_id + target_id`。从`ods_datasync.lx_advertising_sp_targets`取实体，限定`expression_type='auto'`，以`expression`识别方式：`queryHighRelMatches`为紧密、`queryBroadRelMatches`为宽泛、`asinSubstituteRelated`为同类、`asinAccessoryRelated`为关联；未知类型待核。
- 当前有效竞价：目标`bid > 0`取自身值；目标`bid`为空或0时，按`profile_id + campaign_id + ad_group_id`关联`ods_datasync.lx_advertising_sp_ad_groups`，取同组有效`default_bid`。默认值也缺失或无效、关联不唯一时待核；不能把空值或0作为零出价。
- 点击、订单、花费和销售额取该目标自身同一成熟窗口的数据，并从汇总值计算ACOS、CVR。若用搜索词日报回卷，须去重、按完整目标键汇总，并核验归属、完整窗口、币种及与同组同窗数据对账。不能将广告组汇总复制或平均分配给四个目标；缺少可靠目标表现时不输出数值竞价建议。
- `dws_sp_search_term_analysis_daily.default_bid_current`只是广告组默认竞价。该表当前没有目标独立bid字段；`match_type`也不能直接当作四种自动方式。使用其target_id定位目标后，仍须取目标实体及有效竞价，不能沿用旧宽表建议。
- 建议价写到具体`target_id`，不修改广告组默认bid，也不把一个目标命中扩展成四种方式同时调整。继承默认bid的目标调整后设置目标独立bid；撤回时恢复原独立值或原继承状态，不将旧默认值固定为独立bid。
- 结果至少保存完整动作键、匹配方式及expression、目标原bid、组默认bid、有效bid及来源（own/group_default）、数据日期和成熟窗口、目标表现、规则码、建议bid、实际变化率及拦截原因。核验活动、组、目标启用和产品归属；不得用`object_type=ad_group`、缺失匹配方式的记录冒充目标级建议。

文档明确不代表生产生成逻辑已同步，须以结果中的目标标识、竞价来源和目标表现逐条验收。

## 毛利口径统一（2026-09-30确认）

问题产品、瘦狗产品和潜力产品的经营分流、调价、广告准入、路径切换及效果复盘统一使用**订单毛利率**。本文未单独限定的“毛利”“实际毛利”“margin”均指订单毛利率，不使用结算毛利率替代。

- 数据来自同一层、同一版本的产品表现日表；当前 DWD 为 `dwd_datasync.lx_statistics_product_performance`，订单毛利润字段为 `predict_gross_profit`，销售额字段为 `amount`。需要 ODS 复核时通过 `dwd.relate_id = ods.id` 对齐，不混拼两层金额。
- 经营分流使用最近完整 30 天：`订单毛利率 = sum(predict_gross_profit) / sum(amount)`；按国家＋店铺＋MSKU、同一窗口、同一币种汇总。日销为同窗口 `sum(volume) / 30`。
- 保留零销量日的订单毛利润及负值；不平均每日 `predict_gross_margin`，不再减一次广告费；`sum(amount) <= 0` 或必要数据缺失时输出待核，不当作零毛利率。
- 3/7/14 天等复盘保留原有窗口长度，但每个窗口均使用上述订单毛利率公式。阈值 5%/10% 等在计算中使用 0.05/0.10；标签 JSON 的百分数值须除以 100。
- `gross_profit`、`gross_margin` 属于结算口径，不参与本策略毛利判断；成本快照只用于成本项诊断，不能替代订单毛利率来源。P5/P10/P15/P20/P25/P30 等仍是定价模型价格线，不等于实际订单毛利率或调价后保证达到的毛利率。
- 本次统一毛利指标，不改变已确认的价格档位、调价幅度、库存、预算和历史动作约束；文档更新不代表生产计算已同步。

## 1. 用途、边界与入库约定

本文件把《瘦狗产品运营决策框架》拆成可直接审核、可独立命中的原子规则，供后续写入通用规则目录 `dws_datasync.dws_product_strategy_rule_config` 前确认。它是**配置草案**，不是运行结果，也不授权建表、写库、调价或执行广告动作。

本草案采用以下公共配置值，表中不重复填写：

| 配置字段 | 草案值 | 说明 |
|---|---|---|
| `strategy_rule_id` | 建表后由主键生成 | 不以 `rule_code` 充当数据库主键。 |
| `strategy_scope` | `dog_product` | 仅标识本次瘦狗策略；后续问题、潜力等角色复用后五位编码，只变首位。 |
| `rule_version` | `dog-v1-draft` | 审核通过并落库后才改为正式版本，例如 `dog-v1.0`。 |
| `is_enabled` | `0` | 草案阶段全部禁用，验收样例通过后才逐条启用。 |
| `effective_start_date` / `effective_end_date` | 空 | 由正式发布流程填写，不能以文档日期替代。 |
| `source_document` | `瘦狗产品运营决策框架.md` | 每行以 `source_section` 标明可追溯章节。 |
| 审核方式 | `MANUAL_REVIEW` | 所有正向、价格及成本治理建议均需人工审核；本配置不直接执行。 |

每一行对应一个可审核的价格、成本或广告业务动作：`hit_condition` 只放该动作自身的业务触发；`threshold_definition` 仅把动作幅度、价格档位、对象门槛等参数保存成简短 JSON；`strategy_action` 和 `target_price` 是最终建议。样本准入、数据质量、历史执行状态、库存 DOS、预算与动作上限均不进入本表，不生成规则码或标签，而由运行引擎在候选动作之后统一处理。每日结果的来源日期、实际指标、放行/拦截原因写入 `evidence_json`，不在本文件定义固定 JSON 结构。

## 2. 编码、通用数据与优先级

规则码采用六位 `RDAAVV`：首位 `2` 为瘦狗角色；第 2 位使用 `1` 价格、`2` 成本、`3` 广告；`4–9` 均预留。样本、路径分流、数据质量、历史策略状态、库存、预算、动作上限和复盘均为引擎级控制，不生成独立规则配置记录。相同语义迁移到问题产品时只改首位为 `1`，不能改动后五位。

运行引擎在读取本表前后执行如下控制，它们不属于规则表字段或规则码：

- 样本：`301/current ∩ 1303/30d`；`301` 用 `store + msku`，`1303` 用 `country + store + msku`，不使用 `301.country`，不使用排名。
- 快照：标签、广告表现取运行日 `D-1` 的完整快照；价格、成本、库存、预算取 `D` 的有效快照。这是正常节奏，不应误报日期不一致。
- 正向动作：指降价、涨 bid、加精准词、零花费曝光测试等可能提升需求或占用预算的动作；必须依次通过数据、历史、库存、预算和动作上限检查。检查不通过时，不生成该正向动作，仅在产品结果的 `evidence_json` 记录原因。
- 止损动作：降 bid、否词、暂停；不受库存与预算扩量检查限制，但仍需广告映射唯一、来源完整以及动作本身命中。
- 同一产品同日：最多 `1` 个价格动作和最多 `2` 个广告原子动作；更严格的库存限制优先。成本诊断不占这三个动作名额。

优先级数值越小越先执行：`50–69` 止损，`70–89` 成本与价格，`90–109` 正向广告。冲突组相同的规则同日只保留优先级最高的一条。

## 7. 动作执行前公共判断（不进入规则配置表）

库存和预算是每条正向调价或广告动作的执行条件，不是可独立输出的产品标签，也不单独占用 `rule_code`。候选动作先命中价格/广告规则，再由引擎按共享库存池和预算可用性筛选：不满足则不落该条正向动作；产品级结果可保留“库存限制”“预算不可用”或“数据待核”的非执行结论，并把候选动作、计算值和拦截原因写入 `evidence_json`。补货预警由独立补货功能承接，本策略不生成独立库存预警标签。

| 公共检查 | 判断口径 | 对候选正向动作的处理 | 止损动作 |
|---|---|---|---|
| 库存数据 | 共享库存池映射唯一、可售库存非负、快照有效；在途和预留不计入可售 DOS。 | 不满足：不输出降价、涨 bid、加精准或零花费测试；产品表记录 `inventory_missing`/`inventory_blocked`。 | 降 bid、否词、暂停可继续输出。 |

## 8. 不进入规则配置表的控制逻辑

- 动作上限由通用引擎在候选规则命中后统一执行：同一产品同日最多保留 1 个价格动作和 2 个广告原子动作，止损优先；同一搜索词同时命中否词和加精准时保留否词。引擎按动作类型的固定优先级选择，其余候选仅记录拦截原因，不生成独立 `rule_code`。
- D+3、D+7、D+14 和广告成熟 30 天属于后续复盘功能。本期只在原动作的 `observation_period`、历史状态和 `next_review_date` 中保留观察信息，不生成独立复盘规则。
- `28xxxx` 与 `29xxxx` 暂时预留，不能出现在本期规则配置表和每日命中结果中。

## 9. 配置落库前必须确认的项目

以下不是“缺少阈值就自行补一个”的地方；在引擎中必须阻断相关正向动作或保持对应动作规则 `is_enabled=0`，直到业务明确：

1. 成本统计期、对账状态与允许舍入误差的具体口径；不满足时只阻断成本动作，不生成“成本数据待核”规则行。
2. `220401–220402` 的同品类、价格带、尺寸重量等横向可比字段和可用样本；这两条目前是暂定增强项。
3. `guqiao_service` 历史批次 `status` 的终态、观察态映射和复盘起点；明细只有 `outcome`，不能擅自把它当执行状态。
4. 各类广告实体到 MSKU 的唯一映射键、60 天 SP 搜索广告客单价口径。
5. `B_test` 公式所需的预算字段映射和未来基础消耗的预测口径。

## 10. 首次审核建议

先不要将全部规则一次启用。建议按以下顺序用《产品运营建议验收样例集》和只读试跑结果验证：

1. 先验证引擎级样本、数据、历史、库存、预算和动作上限控制，再启用止损广告规则。
2. 再启用利润修复的 `210101–210104` 和低销量 5%–10% 的维持价格结论，核验 P 线顺序与价格精度。
3. 在广告映射、FBA 共享池映射和预算口径完整后，启用正向 bid、加精准与降价规则；库存和预算只作为这些动作的执行条件。
4. 最后启用成本诊断；横向暂定规则应在可比字段验收完成后单独发布。
