# 瘦狗产品数据试跑结果

## 试跑范围

本次为只读预演，不建表、不落表、不执行价格或广告动作。

样本按运行日 D=2026-09-20 的既定节奏读取：`301/current ∩ 1303/30d` 标签和广告对象使用 2026-09-19（D-1）完整快照，成本、定价、预算和库存使用 2026-09-20（D）最新快照。这一日差符合规则，不构成日期异常；以下结果仍是只读预演，不是实际执行建议。

## 已验证的主链路

标签样本共 **1,981** 个国家 + 店铺 + MSKU，均成功经下列映射关联到成本和定价：

```text
标签 store
→ 定价表 新店铺
→ 定价表/成本表 店铺名（国家后缀真实店铺）
```

例如：`booyee → booyee → booyee-US`。直接使用标签店铺去关联成本表会得到零匹配，因此该映射是后续标准化层的必需步骤。

## 当前正式运行结论

本轮 D/D-1 快照节奏正确，**不应产生** `source_date_mismatch`。当前不能生成正式正向建议的原因如下：

1. `guqiao_service` 历史策略表不在当前只读连接可见范围内；必须标记 `history_source_unavailable`，不能等同于无历史。
2. `dws_datasync.dws_product_strategy_rule_config` 尚未实际创建；本次按规则文档内联预演，无法写入正式的 `strategy_rule_id`。
3. FBA 共享库存池映射覆盖率只有 2.3%，不足以支撑绝大多数拉量类动作。

历史策略接入和库存映射仍会继续阻断正向动作。可继续做只读的路径、成本、价格线、广告状态和待核清单演练；只有止损、提价、维持价格和成本诊断能在库存缺失时保留，但也须遵守历史同类动作闸门。

## 新 Codex 的下一步验证顺序

1. 接入并核验 `guqiao_service` 两张历史表的状态枚举、逻辑删除和 `selection_key`。
2. 固化标签/广告取 `D-1`、成本/定价/库存/预算取 `D` 的运行日策略，并将实际来源日期写入证据。
3. 补齐 FBA 与真实店铺、基础店铺、国家类别共享池的映射，并验算共享库存没有被多国家重复使用。
4. 建立并核验规则配置表，再将文档规则拆成受版本控制的 `strategy_rule_id + rule_code`。
5. 使用验收样例集先跑 10–20 条人工可核验样本，确认后才考虑结果表落库。
