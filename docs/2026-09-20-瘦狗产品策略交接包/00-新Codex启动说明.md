# 瘦狗产品策略交接包：新 Codex 启动说明

## 目标与边界

本目录用于让新的 Codex 读取瘦狗产品规则、完成只读数据试跑，并在所有闸门满足后再开发“产品级价格/成本建议”和“广告原子动作建议”两类结果。

本包不授权以下动作：建表、写入结果表、修改标签、修改价格、执行广告平台动作、回写审核或历史策略表。除非后续收到明确授权，所有数据工作都应只读进行。

## 必读顺序

1. [瘦狗产品运营决策框架](瘦狗产品运营决策框架.md)：业务路径、价格、广告、成本、库存与复盘规则的完整来源。
2. [瘦狗产品运营策略思维导图](瘦狗产品运营策略思维导图.xmind)：按顺序理解策略流程的简明视图。
3. [瘦狗产品策略规则配置表草案](瘦狗产品策略规则配置表草案.md)：将瘦狗策略拆成可独立命中的配置行、规则码、阈值、动作和互斥关系；建表前优先审核此文件。
4. [产品运营建议通用数据开发流程](产品运营建议通用数据开发流程.md)：通用表设计、规则编码、历史策略状态核验、数据标准化与实施顺序。
5. [瘦狗产品运营建议结果表数据开发设计](瘦狗产品运营建议结果表数据开发设计.md)：将通用框架落到瘦狗规则的具体口径。
6. [产品运营建议验收样例集](产品运营建议验收样例集.md)：首批人工核验样例、边界和已知来源日期差异。
7. [瘦狗产品数据试跑结果](瘦狗产品数据试跑结果.md)：本次只读试跑的已验证联接、路径分布与阻断项。

## 必须遵守的运行顺序

```text
源数据完整性与既定 D/D-1 快照节奏
→ 历史策略状态核验
→ 301/current ∩ 1303/30d 样本
→ 日销/实际毛利路径
→ 价格与成本判断
→ 广告状态与对象规则
→ 国家类别共享库存池 DOS
→ 预算与动作上限
→ 仅在授权后落结果表
```

前置闸门不通过时，不得把记录丢弃或视为无历史；应输出/展示相应的待核或阻断原因。止损类动作与正向动作必须严格区分。

## 已确认的数据口径

- 样本标签来源为 `dws_datasync.dws_标签表汇总`：`301/current` 按 `store + msku` 关联；`1303/30d` 按 `country + store + msku` 关联。`301.country` 可以为空，不能参与国家联接。
- 标签基础店铺需要映射到经营快照的真实店铺。例如标签 `booyee` 对应定价表 `新店铺=booyee`，而成本/定价事实店铺是 `booyee-US`、`booyee-DE` 等。不得直接把标签 `store` 与成本表 `店铺名` 相等联接。
- 成本来源为 `temporary_dwd.产品近30天八项成本_每日快照_v4`；定价来源为 `temporary_dwd.在库节点_输出定价表`。
- FBA 来源为 `dwd_datasync.lx_storage_fba_warehouse_detail`。库存按 `country_category + 基础店铺 + msku` 共享池汇总，不能按国家分别重复使用库存。
- 广告对象来源为 `dws_datasync.dws_sp_bid_object_snapshot_daily`；预算来源为 `dws_datasync.dws_monthly_ad_budget_detail`。
- 历史审核来源为 `guqiao_service.amazon_strategy_review` 与 `guqiao_service.amazon_strategy_review_item`。批次的 `status` 表示执行/观察状态；明细的 `outcome` 仅代表 SKU 复盘结果。不能假定明细存在独立执行状态或完成时间。

## 本次试跑后的第一优先级

标签和广告取 `D-1`、价格/成本/库存/预算取 `D` 是已确认的正常节奏，不是待解决问题。当前优先解决 `guqiao_service` 历史库接入、FBA 映射覆盖和规则配置表落地；它们未完成前，可继续做只读联接、质量检查与待核演练，但不能生成或执行正向调价、涨 bid、加词、降价或预算迁移建议。
