# 当前跟卖补货规则说明

本文整理当前测试分支中的跟卖补货规则，适用于补货结果表与页面展示逻辑。

## 1. 基础数据来源

### 1.1 店铺品牌映射

店铺品牌关系来自远端表：

```
opt_db.store_brand_relation
```

该表由最新 `data/店铺综合信息.xlsx` 清空重建生成。

生成规则：

1. 一个店铺只有一个有效品牌时，保存一条。
2. 英标和欧标相同时，只保存一条。
3. 英标和欧标不同且都有值时，保存两条。
4. `#N/A`、空值、`-` 等无效品牌不保存。
5. 店铺名会规范化，例如 `pingter-eu` 保存为 `pingter`。

### 1.2 自有 ASIN 同步

补货 ETL 会用店铺品牌映射表关联 listing：

```
dwd_datasync.lx_sales_mws_listing
```

匹配逻辑：

```
store_brand_relation.店铺名 = substring_index(listing.seller_name, '-', 1)
store_brand_relation.品牌名 = listing.seller_brand
```

匹配成功后同步到：

```
dashboard_replenishment_self_asin_sync
```

该表用于识别自有 ASIN、原始主链接、被跟卖链接。

## 2. 两个“主链接”的区别

当前规则里有两个不同概念：

| 概念 | 作用 | 是否一定相同 |
| --- | --- | --- |
| 原始主链接 | 判断谁是被跟卖点，谁是跟卖链接 | 不一定 |
| 补货目标链接 | 产品组需要补货时，最终承接补货数量 | 不一定 |

原始主链接可以被展示为被跟卖点，但不一定承接补货。

补货目标链接是 ASIN 合并后真正产生补货数量的那一行。

## 3. 原始主链接怎么识别

同一个 `country_category + ASIN` 下，原始主链接按以下规则识别：

1. 优先使用 `dashboard_replenishment_self_asin_sync` 中登记的自有 ASIN 链接。
2. 如果没有登记，则用 fallback 规则，在同站点同 ASIN 中选择销量最高的链接。
3. fallback 排序使用真实销量：
  - 30 天销量高优先
  - 14 天销量高优先
  - 7 天销量高优先
  - 3 天销量高优先
4. 仍并列时，按 `seller_name_new + seller_sku_adj` 稳定排序。

注意：fallback 主链接用于计算和合并，但只有登记在 `self_asin_sync` 中的原始链接才会稳定显示为“是否被跟卖=是”。

## 4. 跟卖链接怎么识别

同站点同 ASIN 下：

```
不是自有 ASIN 原始链接的其它链接 = 跟卖链接
```

页面字段：

| 字段 | 含义 |
| --- | --- |
| 是否跟卖 | 当前行是不是跟卖链接 |
| 是否被跟卖 | 当前行是不是被其它链接跟卖的原始链接 |
| 被跟卖方 | 跟卖它的店铺/MSKU |

## 5. 被跟卖原始链接怎么处理

被跟卖原始链接继续显示在补货明细里，但不承接补货。

固定规则：

```
replenish_qty = 0
replenish_box_qty = 0
replenish_cost = 0
replenish_block_reason = 被跟卖点不补货
```

如果该链接进入同 ASIN 合并，页面不再展示它自己的原始库存支撑和原始层级，而是与组内其它链接统一展示产品组库存支撑和产品组层级。“不补货原因”继续解释该链接为什么不承接补货量。

如果该链接没有进入同 ASIN 合并，则继续展示自身库存支撑和自身层级。

## 6. 跟卖链接销量怎么计算

跟卖链接用于单行展示和补货计算的短周期销量为：

```
跟卖链接自身真实销量 + 原始主链接真实销量
```

覆盖周期：

```
30天
14天
7天
3天
```

如果跟卖链接自身销量为 0，但原始主链接有销量，则跟卖链接仍会继承原始主链接销量。

## 7. 跟卖链接日销怎么计算

跟卖链接继承原始主链接销量时，也会继承原始主链接可售天数参与日销计算。

有效可售天数：

```
max(跟卖链接自身可售天数, 原始主链接可售天数)
```

这样避免出现“继承了销量，但自身可售天数为 0，导致日销分母异常”的问题。

## 8. 产品组销量怎么汇总

页面明细可以展示继承后的销量，但产品组补货计算不能把继承后销量重复相加。

错误方式：

```
主链接销量 12
4 个跟卖链接各继承 12
产品组销量 = 12 + 12 + 12 + 12 + 12 = 60
```

正确方式：

```
产品组真实销量 = 原始主链接真实销量 + 各跟卖链接自身真实销量
```

如果跟卖链接自身销量分别是 `3、8、0、5`，原始主链接销量是 `12`，则产品组销量为：

```
12 + 3 + 8 + 0 + 5 = 28
```

## 9. 产品组库存怎么共享

同站点同 ASIN 的多链接本质上按一个产品组判断库存。

产品组库存：

```
所有同 ASIN 链接的 FBA可用 + FBA在途 + 本地库存
```

不能因为某条跟卖链接自己的库存是 0，就让它单独进入补货池。

例如 `YP0309a`：

```
某条跟卖链接有 210 在途
则整个 YP0309a 同 ASIN 产品组共享这 210 在途
```

## 10. 什么时候进入 ASIN 合并

满足以下条件时进入 ASIN 合并：

```
同 country_category + max_asin 下 link_count > 1
并且存在跟卖链接或被跟卖原始链接
```

进入 ASIN 合并后：

1. 产品组销量只算一次。
2. 产品组库存共享。
3. 产品组补货需求只算一次。
4. 最多只有一个链接承接补货量。
5. 其它同 ASIN 链接继续显示，但补货量为 0。
6. 组内所有链接统一展示产品组库存支撑、采购交期、到货时支撑和产品组补货层级。

## 11. 产品组是否需要补货

先按产品组统一计算：

```
产品组日销
产品组共享库存
产品组支撑天数
产品组补货需求
```

如果产品组库存充足：

```
所有链接补货为 0
原因 = 同ASIN库存充足不补货
不选择补货目标链接
```

如果产品组库存不足：

```
整组只生成一份补货需求
只选择一个补货目标链接承接补货量
其它链接补货为 0
原因 = 同ASIN已合并至主链接
```

## 12. 补货目标链接怎么选

补货目标链接选择规则：

1. 被跟卖原始链接不承接补货。
2. 非被跟卖链接都可以作为候选目标。
3. `停售中` 不再硬排除，只作为排序降权。
4. 在售链接优先于停售链接。
5. 采购信息完整优先：
  - 有箱规
  - 有采购价
  - 有运输成本
6. 有库存或在途记录优先。
7. 最近有真实销量优先。
8. 仍并列时，按 `seller_name_new + seller_sku_adj` 稳定排序。

也就是说：

```
停售中链接可以承接补货，但只有在没有更优在售目标时才会被选中。
```

## 13. 补货目标的补货量怎么落行

如果某行是 ASIN 合并目标：

```
该行承接产品组补货量
asin_merge_reason = 产品组补货目标链接
```

如果某行不是目标：

```
replenish_qty = 0
replenish_box_qty = 0
replenish_cost = 0
asin_merge_reason = 同ASIN已合并至主链接
```

如果整组库存充足：

```
asin_merge_target = 空
asin_merge_reason = 同ASIN库存充足不补货
```

## 14. 当前典型案例

### 14.1 YP0309a：库存充足不补

```
SKU = YP0309a
ASIN = B0CRKQGBM7
站点 = 欧洲站
```

特点：

1. 1 条原始主链接，4 条跟卖链接。
2. 跟卖链接继承原始主链接销量。
3. 其中一条跟卖链接有 210 在途。
4. 产品组共享库存后库存充足。
5. 整组补货为 0。

结果：

```
原始主链接：被跟卖点不补货
其它跟卖链接：同ASIN库存充足不补货
```

### 14.2 XIE0258a：库存不足，跟卖链接承接补货

```
SKU = XIE0258a
ASIN = B0DP9V7DF2
站点 = 欧洲站
```

结果：

| 链接 | 角色 | 补货 |
| --- | --- | --- |
| QIKONG / QK043a | 被跟卖原始链接 | 0 |
| YuanJinRong / YJR024a | 跟卖链接，补货目标 | 50 |

### 14.3 DJ0027a：停售跟卖链接可承接补货

品牌映射更新后：

```
pingter / PT068a
```

可以正确识别为被跟卖原始链接。

当前结果：

| 链接 | 状态 | 角色 | 补货 |
| --- | --- | --- | --- |
| pingter / PT068a | 在售中 | 被跟卖原始链接 | 0 |
| Qipunike / 8F-8THH-F6H6 | 停售中 | ASIN合并目标 | 257 |
| Qipunike / 0U-87XW-DNZ5 | 停售中 | 合并到目标 | 0 |

这里体现的是最新规则：

```
停售中不再硬排除，只是排序降权。
当没有更优在售候选时，停售跟卖链接也可以承接补货。
```

## 15. 页面展示规则

页面保留 MSKU 明细行，不做 ASIN 级别折叠。

页面中的库存与补货层级使用以下口径：

```
进入同 ASIN 合并的链接
→ 组内所有行显示同一套产品组库存支撑、到货支撑和产品组层级

未进入同 ASIN 合并的普通链接
→ 显示自身库存支撑和自身层级
```

产品组层级只代表整组补货紧迫度；补货数量仍只落到补货目标链接。其它链接通过“不补货原因”和“ASIN合并原因”说明为什么最终补货量为0。

新增/关键字段：

| 字段 | 展示含义 |
| --- | --- |
| 是否跟卖 | 当前链接是不是跟卖链接 |
| 是否被跟卖 | 当前链接是不是被跟卖的原始链接 |
| 被跟卖方 | 跟卖当前原始链接的链接数量或明细 |
| 不补货原因 | 最终为什么不补货 |
| 是否ASIN合并 | 当前行是否进入 ASIN 合并逻辑 |
| ASIN合并目标 | 整组补货承接链接 |
| ASIN合并原因 | 当前行在 ASIN 合并下的原因 |

长文本列会在页面中截断显示，完整内容通过 tooltip 查看，避免覆盖右侧列。

## 16. 当前安全校验

当前测试库验证过：

1. 被跟卖原始链接不会有正补货量。
2. 同一个 ASIN 合并组最多只有一个正补货目标。
3. 补货目标不会同时是被跟卖原始链接。
4. 普通单链接 MSKU 不进入 ASIN 合并逻辑。
5. 停售链接只降权，不硬排除。
