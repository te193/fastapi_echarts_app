# 产品运营建议结果表数据开发设计（以瘦狗规则为首个接入场景）

## 自动广告调整对象确认（2026-09-30）

本方案自动广告的升bid、降bid和零花费曝光测试，均以四种匹配方式对应的投放目标为对象：紧密匹配、宽泛匹配、同类商品、关联商品。每个目标分别判断，不以整个广告组作为这四种方式的竞价调整对象。此处只明确对象与取数口径，原有阈值、幅度、库存预算及审核条件继续适用。

- 唯一动作键为`profile_id + campaign_id + ad_group_id + target_id`。从`ods_datasync.lx_advertising_sp_targets`取实体，限定`expression_type='auto'`，以`expression`识别方式：`queryHighRelMatches`为紧密、`queryBroadRelMatches`为宽泛、`asinSubstituteRelated`为同类、`asinAccessoryRelated`为关联；未知类型待核。
- 当前有效竞价：目标`bid > 0`取自身值；目标`bid`为空或0时，按`profile_id + campaign_id + ad_group_id`关联`ods_datasync.lx_advertising_sp_ad_groups`，取同组有效`default_bid`。默认值也缺失或无效、关联不唯一时待核；不能把空值或0作为零出价。
- 点击、订单、花费和销售额取该目标自身同一成熟窗口的数据，并从汇总值计算ACOS、CVR。若用搜索词日报回卷，须去重、按完整目标键汇总，并核验归属、完整窗口、币种及与同组同窗数据对账。不能将广告组汇总复制或平均分配给四个目标；缺少可靠目标表现时不输出数值竞价建议。
- `dws_sp_search_term_analysis_daily.default_bid_current`只是广告组默认竞价。该表当前没有目标独立bid字段；`match_type`也不能直接当作四种自动方式。使用其target_id定位目标后，仍须取目标实体及有效竞价，不能沿用旧宽表建议。
- 建议价写到具体`target_id`，不修改广告组默认bid，也不把一个目标命中扩展成四种方式同时调整。继承默认bid的目标调整后设置目标独立bid；撤回时恢复原独立值或原继承状态，不将旧默认值固定为独立bid。
- 结果至少保存完整动作键、匹配方式及expression、目标原bid、组默认bid、有效bid及来源（own/group_default）、数据日期和成熟窗口、目标表现、规则码、建议bid、实际变化率及拦截原因。核验活动、组、目标启用和产品归属；不得用`object_type=ad_group`、缺失匹配方式的记录冒充目标级建议。

文档明确不代表生产生成逻辑已同步，须以结果中的目标标识、竞价来源和目标表现逐条验收。

## 毛利口径统一（2026-09-30确认）

问题产品、瘦狗产品和潜力产品的经营分流、调价、广告准入、路径切换及效果复盘统一使用**订单毛利率**。本文未单独限定的“毛利”“实际毛利”“margin”均指订单毛利率，不使用结算毛利率替代。

- 数据来自同一层、同一版本的产品表现日表；当前 DWD 为 `dwd_datasync.lx_statistics_product_performance`，订单毛利润字段为 `predict_gross_profit`，销售额字段为 `amount`。需要 ODS 复核时通过 `dwd.relate_id = ods.id` 对齐，不混拼两层金额。
- 经营分流使用最近完整 30 天：`订单毛利率 = sum(predict_gross_profit) / sum(amount)`；按国家＋店铺＋MSKU、同一窗口、同一币种汇总。日销为同窗口 `sum(volume) / 30`。
- 保留零销量日的订单毛利润及负值；不平均每日 `predict_gross_margin`，不再减一次广告费；`sum(amount) <= 0` 或必要数据缺失时输出待核，不当作零毛利率。
- 3/7/14 天等复盘保留原有窗口长度，但每个窗口均使用上述订单毛利率公式。阈值 5%/10% 等在计算中使用 0.05/0.10；标签 JSON 的百分数值须除以 100。
- `gross_profit`、`gross_margin` 属于结算口径，不参与本策略毛利判断；成本快照只用于成本项诊断，不能替代订单毛利率来源。P5/P10/P15/P20/P25/P30 等仍是定价模型价格线，不等于实际订单毛利率或调价后保证达到的毛利率。
- 本次统一毛利指标，不改变已确认的价格档位、调价幅度、库存、预算和历史动作约束；文档更新不代表生产计算已同步。

> 使用边界：结果表结构、通用上游字段字典、历史策略状态核验、幂等规则和开发流程，以 [产品运营建议通用数据开发流程](2026-09-20-产品运营建议通用数据开发流程.md) 为准。本文件仅保留瘦狗产品作为首个策略接入场景的规则示例；后续问题产品、潜力产品等应提供各自规则文档并复用通用表，不再复制或新建同构结果表。

## 1. 目标与实施边界

本设计将已经确定的瘦狗产品运营规则作为首个接入场景，落为两张**通用产品运营建议每日快照表**。它们的职责是将“某产品今天应做什么、为什么做、是否被历史/库存/数据质量拦截”交给人工审核或后续执行链路；不是直接执行价格、广告、预算或标签变更。后续问题产品、潜力产品或其他产品策略可复用同一套结果表，不需另建同构表。

本期只交付表设计、取数口径、判定链路和验收标准：

- 不实际创建表，不写入 `dws_datasync`。
- 不回写审核状态、执行状态、价格平台、广告平台或 `1303/1302` 标签。
- 成本诊断不另建第三张成本治理表，而是在两张结果表以稳定标记字段输出。
- `evidence_json` 是证据容器，不在本设计中固定 JSON 的层级、键名或完整内容；开发人员应按实际业务场景保存命中指标、来源快照、阈值、计算证据和拦截原因。

建议表所属库为 `dws_datasync`，按自然日保留快照：

| 表 | 粒度 | 作用 |
|---|---|---|
| `dws_product_price_cost_decision_daily` | 策略范围 + 国家 + 店铺 + MSKU + 规则版本 + 数据日期 | 一条产品级价格/成本/角色决策。它也承接维持价格、成本诊断、下转、运营达标、数据待核以及“库存/预算条件不满足”的非执行结论。 |
| `dws_product_ad_action_daily` | 策略范围 + 一个广告原子动作 + 规则版本 + 数据日期 | 一条可独立审核的广告动作，例如调 bid、否词、暂停、加精准词。通用表结构可兼容预算动作，但瘦狗本期不单独输出预算动作。 |

两张表均只写入“当前尚待人工处理的建议或拦截结论”。历史实际执行及完成状态始终以 `guqiao_service.amazon_strategy_review` / `guqiao_service.amazon_strategy_review_item` 为准，建议表不承担执行流水职能。

## 2. 设计原则

### 2.1 样本与业务边界

运行样本是七国范围内的：

```text
标签 301 / current（正常在售，按 store + msku 关联）
∩
标签 1303 / 30d（站点瘦狗，按 country + store + msku 关联）
```

`301` 是国家类别标签，当前源表记录的 `country` 可以为空。因此不得错误地以 `301.country` 参与关联；结果中的国家以唯一命中的 `1303` 站点标签及其后续业务快照为准。排名不进入样本、动作、预算或运营达标计算。

运营路径继续以最近完整 30 天的日销和订单毛利率判定：

| 路径 | 准入条件 | 核心处理 |
|---|---|---|
| 下转问题产品 | 日销 `=0`，或日销 `≤1` 且订单毛利率 `<5%` | 产品表输出下转结论；不生成瘦狗正向扩量动作。 |
| 利润修复 | 日销 `>1` 且订单毛利率 `<5%` | 优先价格阶梯修复、广告止损和成本核验；不扩量、不新增预算。 |
| 低销量保利 | `0<日销<1` 且订单毛利率 `≥5%` | 先把日销稳定到 `≥1`；价格和广告动作受毛利、TACOS、库存和预算共同限制。 |
| 双目标提升 | `1≤日销≤3` 且订单毛利率 `5%–10%` | **不调价**，只从广告效率、受控扩量和成本诊断推进至日销 `>3`、毛利 `≥10%`。 |
| 运营已达潜力 | `1≤日销≤3` 且订单毛利率 `≥10%`，或日销 `>3` 且订单毛利率 `≥5%` | 停止激进拉量，等待标签升级为 `1302`；若仍为 `1303`，只保留轻量利润优化/异常修复。 |

### 2.2 固定字段与弹性证据的分工

用于筛选、主键、审核流转、执行定位、增量更新的内容必须是独立稳定字段；`evidence_json` 只保存随规则场景变化的证据。该分工避免把关键筛选条件藏在 JSON 中，也避免为每一个新广告或成本诊断场景频繁改表。

`evidence_json` 只要求是合法 JSON；本设计**不规定**必须出现的对象结构、字段名、数组层级或完整示例。开发可按业务场景自行决定保存哪些指标与来源证据，但不得以 JSON 是否含某个约定键作为下游唯一判断依据。

### 2.3 正向动作与止损动作

正向动作包括会扩大需求或占用更多预算的动作，如降价、涨 bid、加精准词、零花费曝光测试。它们必须通过数据完整性、历史执行、库存 DOS、预算和动作上限检查；不通过时不输出该正向动作，产品表只保留原因结论及证据。

降 bid、否词、暂停等止损动作优先级更高，且可在库存不足或预算不足时输出；历史无法关联时是否允许，仍须由角色规则明确。价格提价为利润修复动作，但为了避免重复调价，仍须通过同类价格历史策略状态核验。

## 3. 逻辑模型与结果表

### 3.1 产品级价格/成本决策表

表名：`dws_datasync.dws_product_price_cost_decision_daily`

每个产品、每个运行日期、每个规则版本只保留一条产品级主结论。若同日同时命中“维持价格”和“成本诊断”，主结论使用成本诊断，价格方向为 `hold`；广告细项拆至广告表。

| 字段 | 建议类型 | 说明 |
|---|---|---|
| `data_date` | `date` | 本次运行日 `D`；标签/广告使用 `D-1` 完整快照，其余经营事实使用 `D` 最新快照。 |
| `country_category` | `varchar(20)` | 国家类别。 |
| `country` | `varchar(100)` | 站点国家；产品主键组成字段，不可由 `301` 标签的空国家替代。 |
| `store` | `varchar(255)` | 店铺。 |
| `msku` | `varchar(500)` | 产品 MSKU。 |
| `asin` | `varchar(100)` | 可为空；源端多 ASIN 时须先按既定映射规则唯一化。 |
| `product_name` | `varchar(500)` | 产品名称快照。 |
| `strategy_scope` | `varchar(64)` | 策略范围/产品策略域的可配置标识，用于区分不同策略接入场景；不预设或写死具体产品类型。 |
| `strategy_rule_id` | `bigint` | 逻辑关联 `dws_product_strategy_rule_config.strategy_rule_id` 的规则配置标识。 |
| `rule_code` | `int` | 本条决策命中的数字规则编码，例如价格修复、成本诊断、下转或运营达标。 |
| `strategy_period` | `varchar(20)` | 策略观测周期，当前瘦狗主口径为 `30d`。 |
| `decision_type` | `varchar(64)` | 见下方产品决策枚举。 |
| `current_price` | `decimal(20,6)` | 当前价格；仅用于价格判断，不可用时不输出数值建议。 |
| `suggested_price` | `decimal(20,6)` | 建议售价；无调价时为空。 |
| `price_direction` | `varchar(16)` | `increase`、`decrease`、`hold`、`none`。 |
| `cost_diagnosis_required` | `tinyint` | `1` 表示需做八项成本诊断，`0` 表示本条无该要求。 |
| `history_strategy_status` | `varchar(64)` | 历史策略状态核验结论，见第 4 节。 |
| `history_review_id` | `bigint` | 已关联的历史策略批次 `amazon_strategy_review.id`；无匹配时为空。 |
| `history_review_item_id` | `bigint` | 已关联的历史策略明细 `amazon_strategy_review_item.id`。 |
| `history_task_item_id` | `bigint` | 历史任务 SKU 快照 ID，即明细的 `task_item_id`。 |
| `history_batch_status` | `varchar(30)` | 批次物理 `status` 快照，是当前执行/观察状态来源。 |
| `history_item_outcome` | `varchar(30)` | 明细物理 `outcome` 快照，是 SKU 复盘结果而非执行状态。 |
| `history_status_time` | `datetime` | 批次 `update_time` 快照，不等同于单 SKU 的执行完成时间。 |
| `next_review_date` | `date` | D+3、D+7、D+14 或 30 天复盘窗口的下一检查日。 |
| `data_status` | `varchar(64)` | 数据质量、映射、库存和来源快照状态。 |
| `rule_version` | `varchar(64)` | 可追溯的规则版本；规则变更不覆盖历史版本快照。 |
| `created_time` | `datetime` | 建议生成时间。 |
| `updated_time` | `datetime` | 同日幂等重跑更新时间。 |
| `evidence_json` | `json` | 弹性证据容器，不固定结构。 |

产品决策 `decision_type` 建议受控为：`price_increase`、`price_decrease`、`price_hold`、`cost_diagnosis`、`transfer_to_problem_product`、`operation_qualified`、`inventory_blocked`、`data_pending`。枚举新增必须连同 `rule_code` 和 `rule_version` 变更登记。

主键与索引建议：

```sql
primary key (data_date, strategy_scope, rule_version, country, store, msku)
index idx_product_decision_status (data_date, data_status, history_strategy_status)
index idx_product_decision_rule (data_date, strategy_scope, rule_code)
```

主键与索引建议：

```sql
primary key (data_date, strategy_scope, rule_version, action_key)
index idx_product_ad_action_product (data_date, strategy_scope, country, store, msku)
index idx_product_ad_action_status (data_date, data_status, history_strategy_status)
index idx_product_ad_action_entity (profile_id, campaign_id, ad_group_id, ad_entity_id)
```

## 4. 历史策略状态核验

### 4.1 原则

新建议在计算业务规则前，必须先读取 `guqiao_service.amazon_strategy_review` 和 `guqiao_service.amazon_strategy_review_item`。数据字典已确认：批次表的 `status` 才是当前批次执行/观察状态，SKU 明细表没有独立 `status` 或完成时间，只有 `outcome` 复盘结果。不得因为批次到终态，就把所有明细误判为达成或可再次执行。

当前 `opt_lyt` 可查询连接未提供这两张历史表；开发上线前仍须接入截图所示数据连接，并完成状态枚举、逻辑删除值及 `selection_key` 生成规则的核验。适配层至少要输出下列业务语义：

| 必需语义 | 作用 |
|---|---|
| 历史批次标识、历史策略项标识 | 写入两张建议表并便于审核追溯。 |
| 批次 `status`、批次 `update_time`、`observation_started_at`、`observation_due_at` | 判断当前批次是否执行/观察中，以及历史观察窗口。 |
| SKU 明细 `outcome`、`reason_summary` | 保留 SKU 复盘结果；结果枚举映射须接库确认。 |
| 产品身份：国家、店铺、MSKU、ASIN（如有） | 价格/成本动作的历史关联。 |
| 广告身份：profile、campaign、ad group、实体、对象、搜索词/ASIN | 广告动作的细粒度历史关联；两张当前数据字典未展示这些字段时，必须另找可靠关联来源。 |
| 历史动作类型、建议值、规则来源 | 匹配“同类动作”，防止重复正向执行；若未在物理列或 JSON/关联表中唯一取得则待核。 |
| 批次终态与明细 `outcome` 枚举 | 明确哪些批次可结束阻断、哪些 SKU 结果可进入下一轮判断。 |

### 4.2 匹配优先级

价格/成本动作按产品身份匹配，匹配键优先级为：`country + store + msku`，再以 ASIN、动作类型和规则域收窄。广告动作在此基础上，必须进一步按 `profile/campaign/ad group/ad_entity/object/search_term` 中可用的稳定标识匹配。

同一候选若命中多条无法判定先后的历史项，或源端 MSKU/广告实体映射不唯一，均不得任选一条；应标记历史待核。搜索词参与匹配前应做大小写、首尾空格和匹配类型标准化，但原始文本仍保留在证据中。

### 4.3 历史状态处理

| 优先级 | 条件 | `history_strategy_status` | 对当前输出的影响 |
|---:|---|---|---|
| 1 | 历史来源不可用、字段未映射、产品或广告身份无法唯一匹配 | `history_source_unavailable` 或 `history_mapping_pending` | 禁止新正向动作；仍可输出降 bid、否词、暂停、预算回收等止损动作。 |
| 2 | 找到同类历史明细，所属批次 `status` 尚未映射为终态 | `waiting_history_complete` | 不生成同类新的正向动作，也不重复生成同类调价。保留必要止损动作。 |
| 3 | 批次已到终态，但未到角色规则复盘日或批次观察到期前 | `in_review_window` | 不生成新的正向动作；输出下一复盘日和观察结论。 |
| 4 | 批次已到终态、复盘窗口结束，且该 SKU `outcome` 已按确认枚举映射通过 | `eligible_after_review` | 用最新快照重新判断，可生成新的正向建议。 |
| 5 | 没有匹配的历史策略项 | `no_history` | 正常进入后续规则。 |

复盘窗口由动作域确定：价格/库存早期反馈可在 D+3 观察，常规价格/预算/广告效果在 D+7，路径与毛利结论在 D+14，对象级广告表现以归因成熟 30 天为准。若一个策略项同时携带多种动作，应按该项中最晚的必经窗口阻断对应新正向动作。

已完成不等于已经证明有效。复盘窗口结束后必须重新读取当天的销量、订单毛利率、TACOS、库存和对象表现；不得沿用完成前的旧指标重复给建议。

### 5.2 运行日与既定快照节奏

`data_date` 是运行日 `D`，不是强制所有来源使用同一天。瘦狗固定口径为：标签和广告对象/表现使用 `D-1` 的最新完整快照；价格、成本、库存、预算使用 `D` 的最新快照。该一日差是正常业务节奏，不得标记为 `source_date_mismatch`。运行前仍须记录每个来源的最大可用日期、实际采用日期和差异原因。

以下情况才不能用旧数据伪装成当天动作：

- 标签或广告未提供 `D-1` 完整快照，或价格、成本、库存、预算未提供 `D` 最新快照，且无明确的补偿口径；
- 同一 `country + store + msku` 在任一关键来源出现多对一或一对多映射；
- 成本对账状态异常，或当前价/P 线无法判断；
- 广告实体存在但产品映射、状态、花费或预算来源不完整。

此类记录保留在产品表或广告表的待核/拦截结论中，`suggested_price`、`suggested_value` 必须为空，不输出伪精确调价、bid 或预算金额。

## 6. 规则判定与两表分流

### 6.1 固定执行顺序

同一条候选必须严格按以下顺序执行；后序规则不能推翻前序拦截：

```text
数据完整性
→ 历史策略状态核验
→ 301/current ∩ 1303/30d 瘦狗样本
→ 日销/订单毛利率路径
→ 价格与成本判断
→ 广告状态与对象级规则
→ 库存 DOS
→ 预算
→ 动作上限与互斥
→ 产品表、广告表幂等落库
```

历史和数据闸门并不丢弃记录：它们决定是否允许数值化正向动作，以及把结论写成待核、观察或止损类动作。

### 6.2 价格与成本规则到产品表

| 业务情况 | 产品表结论 | 价格处理 |
|---|---|---|
| 日销 `>1`、订单毛利率 `<5%`、当前价低于 P15，且 P5/P10/P15 完整 | `price_increase` | 不按当前价百分比上涨；按定价阶梯直接提升至**下一档**，即 P5→P10→P15，最高不超过 P15。 |
| 日销 `>1`、订单毛利率 `<5%`、当前价已达/高于 P15 | `price_hold` 或 `cost_diagnosis` | 不再自动提价；先做广告止损。若价格和广告已稳定而毛利仍低，进入成本诊断。 |
| `0<日销<1`、毛利 `5%–10%` | `price_hold` | 不自动降价；先按广告状态拉升可验证流量。若当前价高于 P30 且毛利仍低，改为成本诊断。 |
| `0<日销<1`、毛利 `≥10%`、当前价高于 P30 | `price_decrease` | 建议直接调至 P30，不得跨过 P30进入更低价位。 |
| `0<日销<1`、毛利 `≥10%`、P15 与 P30 之间且需价格竞争力测试 | `price_decrease` | 每轮最多下调 5%，且不得低于 P15；仍须通过库存、历史和动作上限。 |
| `1≤日销≤3`、毛利 `5%–10%` | `price_hold` | **禁止调价**，该路径只走广告和成本方向。 |
| 运营已达潜力但仍为 `1303` | `operation_qualified` | 不自动降价、不激进扩量；仅保留异常修复与标签同步观察。 |
| 日销为 0，或日销 `≤1` 且毛利 `<5%` | `transfer_to_problem_product` | 不生成瘦狗价格或正向广告建议。 |

成本诊断的触发不应被“价格很高”掩盖：对于高于 P30、订单毛利率仍低的产品，应直接标记 `cost_diagnosis_required=1`，而不是简单标记为“高价待人工复核”。对于双目标路径，价格、销量和广告经过既定观察仍稳定但毛利未达 10% 时，也应在 D+14 或广告成熟 30 天后进入八项成本归因。

成本诊断使用八项成本的对账质量、单位成本、成本率、相对变化、绝对变化与连续有效日，定位采购、头程、FBA、佣金、税费、广告、退款退货、仓储及其他中吞噬毛利的主因。横向同类对比当前仍是暂定能力：若没有可确认的同类映射，只能输出纵向异常或待核，不能伪造横向结论。

### 6.3 广告状态与对象规则到广告表

广告不是直接开始涨/降 bid。每个 MSKU 应先路由广告状态：

| 广告状态 | 判定 | 输出方向 |
|---|---|---|
| `ad_not_enabled` | 数据完整且没有可映射的已启用 SP 对象 | 只输出人工确认是否建立结构，不自动创建广告组或加词。 |
| `ad_mapping_pending` | 存在广告实体但与产品映射不唯一，或状态/花费来源缺失 | 输出待核；不生成数值 bid 或预算建议。 |
| `zero_spend_blocked` | 已开广告、成熟 30 天无花费，但不满足低销量保利、预算或基础 DOS 条件 | 输出观察和阻断原因；不涨 bid。 |
| `zero_spend_exposure` | 已开广告、30 天无花费，`0<日销<1`、毛利 `≥5%`，预算与基础 DOS 均通过 | 毛利 `5%–10%` 对 1 个既有可映射对象做一次 bid `+5%`、7 天测试；毛利 `≥10%` 可做一次 bid `+12%` 测试。 |
| `ad_waste` | 产品 TACOS 高，或对象命中高点击零单、高 ACOS、低 CVR 等止损条件 | 生成降 bid、否词、暂停或预算回收；不得同时生成正向扩量。 |
| `ad_structural_optimize` | 有花费且 `5%<TACOS≤10%`，存在首档有效对象 | 先回收低效花费；双目标路径最多对 1 个有效既有对象做 bid `+5%`，且只能等额迁移本产品当天回收预算。 |
| `ad_effective_expand` | 有花费，TACOS 和对象效率均通过当前路径门槛 | 生成对象级 bid `+8%/+15%/+20%` 或自动来源有效词转精准，仍须库存、预算和历史通过。 |

自动与手动对象的成熟 30 天阈值沿用最新瘦狗规则版本：止损以点击 `15/25` 为两档，正向扩量以点击/订单/ACOS/CVR 的三档效率组合决定 `+8%/+15%/+20%`。双目标提升路径的放量限制更严：

- `TACOS>10%`：只允许降 bid、否词、暂停和预算回收；
- `5%<TACOS≤10%`：不新增预算，只能把同一 MSKU 当日回收金额等额迁移给 1 个有效既有对象，bid 最多 `+5%`；
- `TACOS≤5%`：对象通过首档效率后，可执行规则规定的 bid 调整；预算测试上限为 `B_test × 50%`；
- 双目标路径无论 TACOS 如何，均不输出价格调整。

加精准与否词冲突时否词优先；同一搜索词不应在同日同时输出互相矛盾的动作。广告成熟 30 天前不把未成熟短期表现当作最终对象结论。

### 6.4 库存与预算限制

库存只限制会提高需求的正向动作，不阻断止损、提价、维持价格或成本诊断。基础 DOS 与目标覆盖 DOS 的公式为：

```text
基础 dos = fba 可售库存 ÷ 当前日销
低销量保利目标覆盖 dos = fba 可售库存 ÷ 1
双目标提升目标覆盖 dos = fba 可售库存 ÷ 3
```

基础 DOS 决定首轮是否可拉量；目标覆盖 DOS 仅输出补货风险和限制下一轮扩量，不调用补货执行功能。执行限制如下：

| 基础 DOS | 正向动作限制 |
|---|---|
| 库存缺失、FBA 可售为 0 或 `<7` 天 | 禁止降价、涨 bid、加精准词、曝光测试和预算迁移/增加。 |
| `7–<14` 天 | 仅 1 个已验证对象可 bid `+3%`；不新增预算、加词、降价或零花费测试。 |
| `14–<28` 天 | 同日最多 1 个拉量动作，不得叠加“降价 + 正向广告”。 |
| `≥28` 天 | 可按路径、对象和预算规则执行。 |

`目标覆盖 DOS<14` 时输出补货预警，且 D+7 前不做第二轮正向扩量，除非新 FBA 可售库存使其重新达到 14 天。该预警不自动创建补货任务。

预算只能在站点/国家总预算池内重分配。开发计算 `B_test` 时应预扣未来基础消耗，并以月/周剩余额、可再分配池和既定比例上限中的最小值为准：

```text
月可新增额 = 月预算余额 − 预计未来基础消耗
周可新增额 = 周预算余额 − 预计未来基础消耗
可再分配池 = 释放预算 + 总预算池未分配余额
b_test = min(月可新增额, 周可新增额, 可再分配池, 月配置预算 × 10%, 周配置预算 × 25%)
```

## 7. 生成、幂等更新与版本管理

### 7.1 建议生成过程

1. 读取每个上游的可用日期和质量状态，确定共同 `data_date`。
2. 生成 `301/current ∩ 1303/30d` 样本，并记录所有标签/指标冲突。
3. 关联成本、定价、库存、广告对象、搜索词、预算和历史执行适配层。
4. 先写入产品级路径与历史策略状态核验结论；只有允许时才计算数值价格或广告正向动作。
5. 根据产品路径路由广告状态和对象级规则，先保留止损，再选择有限的正向动作。
6. 在候选正向动作上依次施加基础 DOS、目标覆盖 DOS、预算和动作上限。
7. 输出产品表一条主结论、广告表零到两条原子动作；未通过闸门的原因写入稳定状态字段和 `evidence_json`。

每个产品每天最多 1 个价格动作与 2 个广告原子动作。若库存或路径规则规定更少，按更严格者执行。广告表的止损动作优先级高于正向动作；同一产品剩余动作额度不足时先保留止损。

### 7.2 `action_key` 生成

`action_key` 必须稳定、可重复计算且能区分同产品不同广告对象。建议取规范化后的下列字段拼接并做 SHA-256：

```text
data_date | strategy_scope | rule_version | strategy_rule_id | country | store | msku | action_type |
profile_id | campaign_id | ad_group_id | ad_entity_type | ad_entity_id |
object_type | object_id | normalized_search_term
```

空值统一采用明确占位符参与哈希，搜索词先标准化再参与哈希。不能仅用 MSKU 或活动 ID 作为键，否则同一活动多个关键词会互相覆盖。

### 7.3 同日重跑和留存

- 产品表以 `data_date + strategy_scope + rule_version + country + store + msku` 幂等更新。
- 广告表以 `data_date + strategy_scope + rule_version + action_key` 幂等更新。
- 同日同规则版本重跑更新 `updated_time`、稳定字段和证据；不得重复插入。
- 跨日期或跨 `rule_version` 一律保留，便于还原当日规则、证据和建议差异。
- 规则修改必须提高 `rule_version`，并在 `dws_product_strategy_rule_config` 维护对应 `strategy_rule_id + rule_code`；新版本也不得绕过未完成或仍处在复盘窗口的历史策略项。

## 8. 数据状态、审核与执行边界

建议使用以下 `data_status` 作为可筛选状态，而不是只在 JSON 中描述异常：

| `data_status` | 含义 | 数值正向动作 |
|---|---|---|
| `ready` | 来源、映射和关键计算均完整 | 可按历史、库存和预算闸门继续判断。 |
| `source_date_mismatch` | 来源未满足既定 D/D-1 快照节奏，或角色未配置可比滞后口径 | 禁止。 |
| `mapping_ambiguous` | 店铺/MSKU、ASIN 或广告实体无法唯一映射 | 禁止。 |
| `cost_reconciliation_failed` | 成本快照或对账异常 | 禁止；可输出成本待核。 |
| `pricing_pending` | 当前价或 P 线缺失/异常 | 禁止价格动作。 |
| `inventory_missing` | FBA 可售或库存日期缺失/异常 | 禁止拉量；止损、提价和成本诊断可输出。 |
| `ad_mapping_missing` | 广告实体、花费或对象映射不完整 | 禁止数值广告动作。 |
| `budget_pending` | 预算余额或共享活动归因不可用 | 禁止新增/迁移预算。 |
| `history_source_unavailable` | 历史策略表无法读取或适配未完成 | 禁止正向动作；止损可输出。 |

结果表不是审核表。人工审核、实际执行、失败、撤销、完成、平台回执和复盘结论不回写到这两张结果表；它们应继续进入既有 `guqiao_service.amazon_strategy_review` 与 `guqiao_service.amazon_strategy_review_item` 流程，并在下一次建议运行时用于历史策略状态核验。

## 9. 开发验收与边界用例

### 9.1 功能验收

| 场景 | 预期结果 |
|---|---|
| 无历史记录 | 候选通过其他前置条件后正常生成建议，`history_strategy_status=no_history`。 |
| 同类历史明细所属批次未到终态 | 不生成新的同类正向价格/广告动作，状态为 `waiting_history_complete`。 |
| 批次已到终态但仍在 D+3/D+7/D+14/30 天窗口或观察到期前 | 不生成新的正向动作，写入 `in_review_window` 与 `next_review_date`。 |
| 批次已到终态、复盘窗口结束且 SKU `outcome` 映射通过 | 用最新数据重新计算，状态为 `eligible_after_review`。 |
| 历史表不可读或产品/广告身份不唯一 | 禁止正向动作，保留降 bid、否词、暂停、预算回收等止损动作。 |
| 同日同规则重跑 | 两表主键数不增加，稳定字段和 `updated_time` 更新。 |
| 规则版本升级 | 新版本新增独立快照，但不绕过旧项未完成/复盘中的闸门。 |
| 双目标：日销 1–3、毛利 5%–10% | 产品表为 `price_hold`，`suggested_price` 为空；广告/成本方向照规则输出。 |
| 高价低毛利 | 输出 `cost_diagnosis_required=1`，不把“高价”仅写成人工复核。 |
| 库存小于 7 天或缺失 | 不产生拉量动作；可产生止损、提价、维持价格或成本诊断。 |
| 广告止损与加词同日冲突 | 否词、降 bid、暂停优先；总动作数不超过上限。 |

### 9.2 数值边界

至少覆盖：日销 `0`、`0.99`、`1`、`3`、`3.01`；订单毛利率 `4.99%`、`5%`、`10%`；当前价在 P15 以下、等于 P15、P15–P30、等于 P30、高于 P30；TACOS `5%`、`10%`；基础 DOS `0`、`7`、`14`、`28`；以及“运营已达标但标签仍为 1303”。

还应覆盖价格阶梯：当前价格处于 P5 时建议 P10，处于 P10 时建议 P15，处于 P15 时不再自动上提；任何降价建议不得低于 P15，且高价价格竞争力修复不跨过 P30。

## 10. 上线前待确认项

1. 接入 `guqiao_service.amazon_strategy_review` / `guqiao_service.amazon_strategy_review_item` 数据连接，确认批次 `status` 终态、SKU `outcome` 枚举、`selection_key` 生成规则和广告对象字段的可靠来源。
2. 确认各广告源对店铺、profile、活动、广告组、对象和搜索词的唯一映射规则，尤其是共享活动与多 MSKU 场景。
3. 确认 FBA 库存快照的最终表名、时区、可售库存口径与成本/广告快照的日期对齐策略。
4. 将本设计中的 `strategy_rule_id`、`rule_code`、`rule_version`、动作类型和状态枚举纳入配置或数据字典，并与人工审核系统做一次字段映射演练。

在以上项未完成前，开发可以实现只读取数、数据质量检查和待核/止损输出，但不得上线数值化正向调价、bid 或预算建议。
