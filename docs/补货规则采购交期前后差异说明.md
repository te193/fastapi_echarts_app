# 采购交期导致补货数量增加的原因说明

## 一、先说结论

本次使用2026年8月3日快照，对比旧规则和测试分支新规则的最终补货数量。

为保证数据可以直接比较，本报告采用以下口径：

- 只比较新旧结果中都存在的同一批商品。
- 新旧规则都使用最终补货数量 `replenish_qty`，不混用计算量和可执行量。
- 已补齐FBA接收次数和订单利润来源数据，新旧预测日销差异为0。
- 最终纳入比较的同一批商品共3,691条。

在这个口径下：

| 指标 | 旧规则 | 新规则 | 差额 |
|---|---:|---:|---:|
| 最终补货数量 | 7,691件 | 14,762件 | **增加7,071件** |

增加7,071件，主要不是因为原来补货的商品统一多补了10天，而是因为一批原来不补货的商品，在新规则下提前进入了补货层。

## 二、增加的7,071件是怎么组成的

| 类型 | 商品数 | 旧规则补货量 | 新规则补货量 | 增减 |
|---|---:|---:|---:|---:|
| 旧规则不补，新规则补 | 38个 | 0件 | 5,692件 | **+5,692件** |
| 新旧规则都补 | 58个 | 7,537件 | 9,070件 | **+1,533件** |
| 旧规则补，新规则不补 | 3个 | 154件 | 0件 | **-154件** |
| 新旧规则都不补 | 3,592个 | 0件 | 0件 | 0件 |
| **合计** | **3,691个** | **7,691件** | **14,762件** | **+7,071件** |

计算关系为：

```text
新增7,071件
= 原来不补、现在补的5,692件
+ 新旧都补时多出的1,533件
- 原来补、现在不补的154件
```

## 三、为什么旧规则不补，新规则会补

这38个商品一共新增5,692件，其中：

- 36个商品是因为加入采购交期后，从“库存充足”提前进入计划补货或建议补货，合计新增5,392件。
- 另外2个商品合计新增300件，是同ASIN补货目标链接发生变化，不属于采购交期提前分层的直接影响。

因此，可以明确归因于“采购交期使商品提前进入补货层”的数量为：

```text
36个商品，新增5,392件
```

旧规则使用当前库存可支撑天数判断分层：

```text
当前库存可支撑天数 S = 当前库存 ÷ 日销
```

当 `S > 90天` 时，商品属于库存充足，本次不补货。

新规则使用到货时库存可支撑天数判断分层：

```text
到货时库存可支撑天数 R = 当前库存可支撑天数 S - 采购交期 L
```

例如商品当前可以支撑95天、采购交期10天：

```text
旧规则：95天 > 90天 → 库存充足 → 不补货
新规则：95 - 10 = 85天 → 计划补货 → 开始补货
```

所以这部分增量的核心原因是：**新规则把采购动作提前了，原来本次不下单的商品，现在进入了本次补货池。**

实际商品 `PP023a`：

| 指标 | 数值 |
|---|---:|
| 日销 | 10.52件 |
| 当前库存 | 1,249件 |
| 当前可支撑天数 | 118.77天 |
| 采购交期 | 45天 |
| 到货时可支撑天数 | 73.77天 |
| 旧规则补货量 | 0件 |
| 新规则补货量 | 440件 |

旧规则看到118.77天，判定库存充足；新规则扣除45天交期后只剩73.77天，因此提前进入计划补货，最终新增440件。

## 四、新旧规则都补货时为什么还会增加1,533件

有58个商品在新旧规则下都会补货：

```text
旧规则合计补货：7,537件
新规则合计补货：9,070件
合计增加：1,533件
```

这部分商品不涉及“原来不补、现在开始补”，而是补货数量的计算起点发生了变化。

旧规则按照当前库存直接补足120天：

```text
旧补货需求 = 120天销量 - 当前库存
```

新规则先扣掉采购等待期间会销售的库存，再补足120天：

```text
到货时预计库存 = 当前库存 - 采购交期 × 日销

新补货需求 = 120天销量 - 到货时预计库存
```

只要库存能够支撑到货，新规则相对于旧规则增加的基础需求约为：

```text
采购交期 × 日销
```

实际商品 `YY082a`：

| 指标 | 旧规则 | 新规则 |
|---|---:|---:|
| 日销 | 8.71件 | 8.71件 |
| 采购交期 | — | 10天 |
| 最终补货量 | 216件 | 324件 |
| 箱规 | 108件/箱 | 108件/箱 |

10天交期内预计销售约87件，使补货需求跨过了一个整箱，新规则由2箱变为3箱，最终增加108件。

## 五、交货期间预计断货怎么判断

判断公式为：

```text
到货时库存可支撑天数 R
= 当前库存可支撑天数 S - 采购交期 L
```

判断规则：

```text
R >= 0：现有库存能够支撑到新货到达
R < 0：新货到达前预计会断货
```

当 `R < 0` 时：

```text
预计断货天数 = L - S
到货时预计库存 = 0
预计损失销量 = 预计断货天数 × 日销
基础补货需求 = 120 × 日销
```

例如：

```text
当前库存可支撑9天
采购交期10天

到货时可支撑天数 = 9 - 10 = -1天
```

这表示预计会在新货到达前断货1天。负数不是数据库里的负库存，因此到货时库存最低按0计算；这1天的预计损失销量只作为风险提示，不会重复加入采购数量。

数据同步完整后，共有35个商品被判断为交期内预计断货，预计损失销量合计约529.46件。其中3个商品可以正常补货，合计补货225件；其余32个商品受到现有后置规则限制：

| 不补货原因 | 商品数 | 最终补货量 |
|---|---:|---:|
| 可正常补货 | 3个 | 225件 |
| 被跟卖点不补货 | 16个 | 0件 |
| 同ASIN库存充足不补货 | 15个 | 0件 |
| 同ASIN已合并至主链接 | 1个 | 0件 |

这说明“交期内预计断货”只是风险判断，不会越过跟卖和同ASIN规则强制生成采购数量。

## 六、数据同步检查结果

此前371条日销不一致，是因为独立测试库缺少FBA接收次数表，导致接收次数变成空值，部分老品被误判为新品。现已补齐：

| 补齐的数据 | 同步数量 |
|---|---:|
| FBA接收次数 | 3,139条 |
| 订单利润来源 | 1,394条 |

重新回算后，新旧结果的预测日销差异为0；本报告当前数据不再包含日销不同造成的异常增量。

## 七、最终说明口径

数据同步完整后，新规则净增加7,071件，原因可以概括为：

1. **36个原本库存充足的商品，因为扣除采购交期后提前进入补货层，新增5,392件，这是最主要的增量。**
2. **58个新旧规则都会补货的商品，因为补回交期内预计销量，合计增加1,533件。**
3. **2个同ASIN目标链接变化的商品增加300件，不直接归因于采购交期。**
4. **3个商品由原来补货变为不补货，减少154件。**
5. **交期内预计断货通过“当前可支撑天数小于采购交期”判断，但仍服从跟卖、同ASIN合并等现有拦截规则。**

## 八、未配置交期按 0 天后的差额复核

本次继续使用 2026 年 8 月 3 日快照，并且只比较新旧结果中都存在、日销完全一致的 3,691 个商品。

结论是：**未配置交期改为按 0 天处理后，整体仍比旧规则增加 7,071 件。** 当前 ETL 本来就将未配置交期按 0 天计算，因此这次只是把页面展示和文档口径明确下来，没有再次改变补货结果。

| 交期状态 | 商品数 | 旧规则补货量 | 当前规则补货量 | 差额 |
|---|---:|---:|---:|---:|
| 已配置交期 | 2,319 个 | 6,614 件 | 13,685 件 | **+7,071 件** |
| 未配置交期（0 天） | 1,372 个 | 1,077 件 | 1,077 件 | **0 件** |
| 合计 | 3,691 个 | 7,691 件 | 14,762 件 | **+7,071 件** |

对应补货货值由 268,955.02 元增加到 469,335.97 元，增加 200,380.95 元；这部分货值增量同样全部来自已配置交期的商品，未配置商品的货值差额为 0 元。

也就是说，现有 7,071 件增量全部来自真实配置了采购交期的商品；未配置商品没有被补上虚拟的 10 天销量，也没有因为本次口径确认而新增补货。交期内预计断货商品仍为 35 个，全部属于已配置交期，其中 3 个最终可补货，合计补 225 件；其余商品继续受到跟卖、同 ASIN 合并等规则拦截。
